---
description: 対話の文脈から実装可能な task.md を起票する（実装・完了処理はしない）
argument-hint: <タイトル / 起票したい内容の要約>
---

`$ARGUMENTS` を、直前までの対話と調査を知るこのセッションが起票する。

1. 現在の HEAD と依存を読み、変更対象を end-to-end で確認する。外部境界がある場合は、設定値・port・address・probe などの各入力について供給元と消費先を特定する。複数の妥当な選択肢が残る設計判断は、実装タスクを起票せず、未決定事項・影響範囲・決定に必要な情報を報告する。
2. `npm run tasks:new -- <category> "<title>" [--slug=<slug>]` で雛形を作る。
3. `tasks/AUTHORING-CHECKLIST.md` を目安に、背景、検証可能な完了条件、変更範囲、既存コードとの整合、必要なテストと文書同期先を `task.md` に記す。局所変更に高リスク統合向けの表や不変条件を要求しない。
4. ユーザーが独立レビューを求めた場合、または複数の所有者・状態機械・外部境界をまたぐ高リスク変更の場合だけ `task-reviewer` を呼ぶ。既存の正本から一意に補える `AUTO_FIX` は起票者が反映して `APPROVED` とし、公開契約・責務・設定供給方式を選ぶ必要がある欠落だけを `NEEDS_REVISION` とする。結果は `review.md` と `meta.yaml` の `review` に記録する。
5. 作成したタスクのパスと要点を報告する。

起票だけではコミット、実装、評価、完了処理を行わない。
