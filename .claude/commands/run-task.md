description: タスクを現在のコードで確認し、実装・検証・完了処理まで進める
argument-hint: <task-dir>
---

`$1/task.md` を実行する。`meta.yaml` は `tasks:set` / `tasks:close` 経由でのみ更新する。最初に `tasks/AUTHORING-CHECKLIST.md` の区分で通常・統合・高リスクを選ぶ。

## 1. 着手確認

- `task.md`、未完了の依存、関連コードを現在の HEAD で確認する。既存のタスク文書から一意に決まる不足は `AUTO_FIX` として補完し、作業を継続する。公開契約、責務、利用者が求める結果を変える選択が必要な場合だけタスク改訂へ戻す。
- 根拠のない性能値、網羅試験、複数環境対応を見つけた場合は完了条件から外す。タスクの目的を変えない縮小は自律補完として扱う。
- ユーザーが独立レビューを求めた場合、または複数の所有者・状態機械・外部境界をまたぐ高リスク変更の場合だけ `task-reviewer` を呼ぶ。通常の局所変更は親がこの確認を行う。

## 2. 実装経路

- **通常変更**: 親が現在のワークツリーで直接、最小の変更と対象を絞った確認を行う。変更した文書は整形してから確認する。`npm run gate`、専用ワークツリー、サブエージェントは使わない。
- **統合変更**: 複数コンポーネントの必要な結合確認を行う。並行作業や既存変更との分離が必要な場合だけ実装ワークツリーと `task-implementer` を使う。全体ゲートは変更範囲を横断する回帰を検出できる場合だけ使う。
- **高リスク変更**: 実装ワークツリーと `task-implementer` を使い、対象確認に加えて `npm run gate` と必要な実環境確認を行う。

`impl.md` は、設計判断、仕様からの逸脱、未実行確認、残リスクがある場合だけ使う。

今回の差分が原因の必須確認失敗は修正・再検証する。変更前からある不整合、変更範囲外の失敗、任意確認の失敗は警告として記録し、今回の変更が悪化させていなければ完了を妨げない。高リスクな実環境確認の失敗だけは、揮発する証拠を環境復旧前に採取する。

Biomeの助言的な警告は検査失敗と区別する。`tasks/README.md` の「Biomeの警告の扱い」に従い、具体的な影響がなければコミット・完了報告・タスク成果物への定型的な記載は不要とする。

## 3. 検証

- 親が受け入れ条件、差分、変更範囲に対応する確認結果を確認する。
- Markdownを変更した場合、親が `documents/rules/coding-md.md` に従って変更した文章を点検する。コピー、移動、改名、正式文書への昇格では文書全体を点検し、最終報告に `文書点検: PASS` と記す。
- 本番コードを変更した場合、親が `documents/rules/source-comments.md` に従い、変更したシンボル・処理群・判断と直接の変更理解範囲を全件点検する。必須コメントの欠落・説明不足・陳腐化したコメントは、既存コード由来でも解消するまで完了しない。監査台帳は作らず、最終報告に `コメント点検: PASS` と記す。
- ユーザーが独立評価を求めた場合、または高リスク変更の場合だけ `impl-evaluator` に同じ `<wt>` を読み取り中心で評価させる。評価専用ワークツリーは作らない。
- 不合格なら、原因と具体的な不足を実装担当へ戻して同じワークツリーで修正・再検証する。仕様変更が必要なら実装を続けずタスク改訂へ戻す。
- 評価担当は今回の差分が生んだ必須失敗をPASSにしない。変更範囲外の既存不整合は残課題として分離する。

## 4. 完了

- **通常変更**: `tasks:set status=done verdict=PASS attempts=1`、`tasks:index` を実行し、実装、必要なタスク記録、索引を1コミットにまとめる。
- **ワークツリーを使った統合・高リスク変更**: 実装ブランチをマージし、`tasks:close`、`tasks:reindex`、ワークツリー削除の既存手順で完了する。
- 今回の目的を達成できない外部要因がある場合だけ `blocked` にする。任意評価を実行できないことをブロック要因にしない。

最終報告は変更概要、確認結果、文書・コメントの点検結果（対象外の場合はその旨）、失敗原因、未実行事項、残リスクだけを簡潔に示す。メトリクス集計と次タスク提案はユーザーが求めた場合だけ行う。
