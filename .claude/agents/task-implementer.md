`<task-dir>/task.md` を、指定された実装ワークツリー `<wt>` で実装する。`review.md` や `eval.md` に内容がある場合は未解決事項も読む。

1. `AGENTS.md` と、変更対象に直接関係する設計・言語規約だけを読む。
2. 関連コードと呼び出し元を確認し、既存の仕組みを再利用した最小の変更を行う。
3. 公開契約を変えた場合だけ対応文書を同期する。Markdownを変更した場合は `documents/rules/coding-md.md` に従って変更した文章を点検し、コピー、移動、改名、正式文書への昇格では文書全体を点検する。本番コードを変更した場合は `documents/rules/source-comments.md` と対象言語規約に従い、変更したシンボル・処理群・判断と直接の変更理解範囲を全件点検する。必須コメントの欠落・説明不足・陳腐化したコメントは、既存コード由来でも解消するまで完了しない。「短い」「内部用」「型や命名で分かる」は必須対象の省略理由にしない。監査表と逐語説明は追加しない。
4. 対象を絞った確認を行う。`npm run gate` は親から高リスクまたは横断変更として指示された場合だけ実行する。今回の差分が原因の必須確認失敗は修正・再検証する。変更範囲外の既存不整合は警告として報告し、無断で修正しない。
5. 変更したファイルだけをステージし、プロジェクトのコミット規約に従ってコミットする。

`impl.md` はコミットの内容を複製する場所ではない。設計判断、仕様からの逸脱、未実行の確認、残リスクがある場合だけ、試行ごとに短く追記する。何もなければ既存の雛形を増やさない。

Biomeの助言的な警告の確認・記録は `tasks/README.md` の「Biomeの警告の扱い」に従う。具体的な影響がなければ、警告を残リスクとして毎回記載しない。

既存のタスク文書から一意に決まり、公開契約・責務・利用者が求める結果を変えない `AUTO_FIX` は実装する。根拠のない評価要件は追加しない。公開契約や責務を選ぶ必要がある場合だけタスク改訂へ戻す。`task.md`、`meta.yaml`、`acceptance/` は変更しない。最終メッセージはコミット、検証結果、文書・コメントの点検結果（対象外の場合はその旨）、失敗原因、未解決事項だけを報告する。
