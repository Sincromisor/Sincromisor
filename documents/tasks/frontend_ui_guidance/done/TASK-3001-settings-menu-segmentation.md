# TASK-3001 設定メニューの細分化と情報設計の再構成

- 作成日: 2026-04-19
- ステータス: Done
- 優先度: High

## 目的

現状の「設定パネル」に集約されている多数の設定項目を、ユーザーの目的と利用頻度に基づいて再構成し、一般ユーザーが迷わず目的の設定へ到達できるメニュー構造へ整理する。

## 背景

- 現在のメニューは実質的に `Debug Console` と `設定パネル` の 2 系統だが、設定パネル側に会話、音声、表示、起動時設定など性質の異なる項目が混在している。
- 一般ユーザーにとっては「どこで何を変えるべきか」が分かりにくく、設定項目が多いこと自体が認知負荷になっている。
- `Debug Console` は開発者向けの診断 UI として残しつつ、一般ユーザー向けの設定群は目的別に分ける必要がある。

5. `開発者向け`

## 各メニューの役割

### 会話設定

- 会話体験そのものに関わる設定をまとめる。
- 例:
  - タイトル
  - トークモード
- ユーザーにとっては「会話の見え方・ふるまいを変える場所」として理解しやすい構成を目指す。

### 音声設定

- 音の入り方や聞こえ方に影響する設定をまとめる。
- 例:
  - マイク選択
  - ノイズ抑制
  - エコー抑制
  - 音量自動調整
  - 発話検出関連
- 日常的にもっとも触られやすい設定群として、上位導線に置く。

### 表示設定

- キャラクター表示やカメラ連動など、視覚的な挙動に関する設定をまとめる。
- 例:
  - キャラクター表示
  - 視線連動
  - AutoMute
- Looking Glass など特定ページでのみ意味を持つ設定は、通常の表示設定とは分けて、対応ページでのみ追加表示する構成を検討する。

### 起動オプション

- ページ起動時や再起動時の挙動に影響する設定をまとめる。
- 例:
  - Talk
  - Inspector
  - VR
- 常時利用する設定ではないため、一般設定とは分けて「必要な人だけ開く」位置づけにする。

### 開発者向け

- 開発者や検証担当が診断や切り分けに使う UI をまとめる。
- 例:
  - Debug Console
  - 接続状態
  - WebRTC / Audio / Gaze / SDP 情報
  - Inspector などの開発支援項目
- 技術用語や詳細ステータスは許容するが、一般ユーザー向け設定 UI と混同しない構成にする。

## 情報設計の基準

- `誰が使うか`
  - 一般ユーザー向けか、開発者向けかを先に分ける。
- `何の目的で触るか`
  - 会話、音声、表示、起動時挙動、診断のどれに属するかで分類する。
- `いつ触るか`
  - 日常的に触る設定か、起動前にだけ意味がある設定かで分ける。

## 分割ルール

1. 毎回触る可能性が高い設定は上位階層に置く。
2. 再起動しないと反映されない設定は `起動オプション` に寄せる。
3. 一般ユーザーが理解しにくい開発用・診断用設定は `開発者向け` に寄せる。
4. ラベルは略語ではなく、設定結果が分かる表現を優先する。
5. 特定ページでしか意味を持たない設定は、そのページでのみ表示する。

## 現状セクションからの再配置案

- `BasicSettingsSection` → `会話設定`
- `MicSettingsSection` → `音声設定`
- `CharacterSettingsSection` → `表示設定`
- `StartupSettingsSection` → `起動オプション`
- `DiagnosticsStatusCards` / `debugConsole.html` → `開発者向け`

## 検討事項

- 上位メニューを完全分離した複数パネルにするか、`設定` 配下のタブ/セクション切り替えにするか
- `Looking Glass 設定` を `表示設定` の一部に含めるか、対応ページ限定の独立カテゴリにするか
- `Inspector` を `起動オプション` に残すか、`開発者向け` に寄せるか
- 起動前ダイアログと常設設定 UI で同じカテゴリ分けを適用するか

## 実装タスク

1. 現行メニューと各設定項目を棚卸しし、推奨構成案へマッピングする。
2. 新しいメニュー階層またはタブ構成の UI 案を作成する。
3. 一般ユーザー向けカテゴリと開発者向けカテゴリの導線を分離する。
4. 既存の設定セクション component を新カテゴリに沿って再配置する。
5. 各カテゴリ名と項目名を一般ユーザー向け文言へ見直す。
6. ページ限定設定の表示条件を整理する。
7. `documents/design/frontend_ui.md` に新しいメニュー構成方針を追記する。
