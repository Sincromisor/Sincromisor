# TASK-3006 simple-vrm の設定UI再整理と安定したサイドメニュー配置

- 作成日: 2026-04-19
- ステータス: Done
- 完了日: 2026-04-19
- 優先度: High

## 目的

`simple-vrm` を最優先対象として、初回セットアップと開始後の設定パネルにおける情報設計とレイアウトを見直し、`迷わず探せるカテゴリ構成`、`固定位置で安定したサイドメニュー`、`操作対象と状態表示が混同しないUI` を実現する。

## 背景

- `TASK-3004` と `TASK-3005` により、初回セットアップウィザードと設定シェルの共通骨格は導入されたが、実装後レビューでは `カテゴリ分けの不自然さ`、`要約カードの過多`、`説明文の多さ`、`レイアウトの不安定さ` が残っている。
- 特に `simple-vrm` では、`音声` に `視線用カメラ` が含まれており、ユーザーが `マイク` と `カメラ` を同じ場所で探したくてもカテゴリ名から予測しづらい。
- `起動` カテゴリは対象ページによっては実質的に空に近く、独立メニューとしての意義が弱い。
- ページごとに summary カード数や高さが変わるため、サイドメニューと本文の位置関係が揺れ、切り替え時に視線移動が大きくなっている。
- 状態カードや確認項目がボタンのように見える一方で、実際には操作できない要素も多く、`押せそうに見えるが押せない` UI が混ざっている。
- その結果、設定の探索、確認、開始までの流れが素直につながらず、レビュー時に強いストレス要因となっている。

## スコープ

- `simple-vrm` の初回セットアップウィザードと開始後設定パネルのカテゴリ構成見直し
- `入出力デバイス` カテゴリ新設と、マイク/視線用カメラの整理
- `起動` カテゴリの廃止、吸収、または表示条件の見直し
- サイドメニューと本文領域の位置安定化
- summary / status / checklist 表示の役割整理
- ボタンと非ボタン要素の視覚的分離
- レイアウトと表示ルールの設計文書反映

## 非対象

- WebRTC シグナリングや音声処理ロジック自体の変更
- `vrm360`、`looking-glass-vrm` など他ページへの全面展開
- チャット画面本体や3D表示そのものの全面刷新
- 開発者向け Debug Console の構造変更

## 対応方針

1. まず `simple-vrm` を対象に、初回セットアップと開始後パネルのカテゴリを同じ意味で再整理する。
2. `マイク` と `視線用カメラ` は、`音声` や `表示` に分散させず、`入出力デバイス` として独立カテゴリ化する。
3. `起動` は、simple-vrm で独立カテゴリとして価値が弱い場合、`会話` や `接続` など適切なカテゴリへ吸収するか、カテゴリ自体を非表示にする。
4. サイドメニューは `カテゴリ一覧` として固定位置に整然と配置し、カテゴリ切替時に上端や本文開始位置が大きく揺れないようにする。
5. 状態表示は必要最小限に絞り、`説明`、`確認`、`操作` が別の役割として見える面構成へ整理する。
6. 非操作要素は押せる見た目を避け、主ボタン・補助ボタン・状態表示の視覚差を明確にする。

- [ ] サイドメニューの外枠位置、上端、幅をカテゴリ切替時に固定する

## 実装タスク

1. `simple-vrm` の初回セットアップと開始後設定パネルのカテゴリ棚卸しを行い、最終的なカテゴリ順序を定義する。
2. `入出力デバイス` カテゴリを新設し、マイクと視線用カメラの選択 UI をここへ移す。
3. `音声` カテゴリからカメラ選択を外し、音声前処理中心の構成へ整理する。
4. `表示` カテゴリからデバイス選択責務を減らし、キャラクター表示や VRM モデル設定中心へ整理する。
5. `起動` カテゴリの必要性を `simple-vrm` 基準で再評価し、廃止・吸収・条件付き表示を実装する。
6. `SettingsShell` の summary / content 構造を見直し、カテゴリ切替時でもサイドメニューと本文の位置が安定するようにする。
7. summary カードや checklist のデザインを見直し、非操作要素がボタンに見えない表現へ修正する。
8. 説明文・補助文・警告文を再棚卸しし、行動につながる情報へ絞り込む。
9. dialog 側と simple-vrm 側で分散しているレイアウトルールを整理し、必要なら共通クラスや共通部品へ寄せる。
10. `documents/design/frontend_ui.md` に、simple-vrm 優先で更新したカテゴリ構成、サイドメニュー安定化方針、非操作要素の見せ方を反映する。
