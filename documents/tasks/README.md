# タスク管理

この文書は、Sincromisor の作業タスク、検証ログ、コミット単位の運用正本である。

## 基本方針

- タスクは作業の入口であり、実装経緯と確認結果を残す場所である。
- 設計の現在仕様は `documents/design/` に置き、作業ログを設計本文へ溜め込まない。
- 最低限、1 タスク 1 コミットを基本とする。1 タスク内でも差分が大きい場合は複数コミットに分ける。
- コミットメッセージには関連する TASK ID を含める。

## 配置

タスクは大分類ごとに次の構成で管理する。

```text
documents/tasks/<大分類>/
  open/
    TASK-<yymmddhhmmss>-<概要>.md
  done/
    TASK-<yymmddhhmmss>-<概要>.md
```

- 作業開始時は `open/` に作る。
- 完了後は `done/` へ移動する。
- 既存の大分類に合わない場合は、責務が分かる kebab-case または既存ディレクトリの命名に合わせた名前で大分類を追加する。
- 古いタスクディレクトリに snake_case が残っていても、既存履歴は必要な時だけ触る。

## タスク ID

- 形式: `%y%m%d%H%M%S`
- 例: 2026 年 4 月 1 日 23:59:00 に起票した場合は `260401235900`
- ファイル名例: `TASK-260401235900-update-agents-guide.md`

## 推奨テンプレート

```md
# TASK-<yymmddhhmmss>-<概要>

## 目的

-

## 変更範囲

-

## 確認

- [ ]

## 結果

-
```

## 完了条件

- 実装、設定、compose、設計文書の必要な同期が終わっている。
- 実行した確認と結果をタスク文書に残している。
- 実行できなかった確認がある場合は、理由と残リスクをタスク文書に残している。
- タスクファイルを `done/` に移動している。
- 関連する TASK ID を含むコミットを作成している。
