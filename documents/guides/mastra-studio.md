# Mastra Studioで会話の設定を変える

## 目的と前提

サーバー管理者が、キャラクターの話し方や指示を編集し、通常の会話へ反映するためのガイドである。
READMEに従い `chat` を含む構成を起動済みであることを前提とする。配布設定の `full,chat` はこの条件を満たす。
初回はモデル取得・ロードが終わるまで待つ。以下のコマンドは、サーバーを動かすPCのリポジトリルートで実行する。

## 管理画面を開く

サーバーを動かすPCのブラウザーで [Mastra Studio](http://127.0.0.1:4111) を開く。
既定ではこのPC自身からだけ接続できる。別PCで `localhost:4111` や `127.0.0.1:4111` を開いてもサーバーにはつながらない。
一般利用者の会話画面とは別の管理画面であり、利用者向けの公開先へ転送しない。

## サインインする

アカウント登録は不要である。Sign in画面では、次の値を入力する。

| 欄       | 入力する値                           |
| -------- | ------------------------------------ |
| Email    | `admin@example.test`                 |
| Password | 稼働中のサーバーが使う管理者トークン |

Emailは形式上必要な欄であり、この構成ではメール認証やメール送信を行わない。管理者かどうかはトークンで判定する。
Passwordにはメールアカウントのパスワードを入力しない。

ルート `.env` の `SINCRO_AGENT_ADMIN_TOKEN` を空欄にしている場合は、管理者が次のコマンドで自動生成値を確認し、Passwordへ貼り付ける。

```sh
docker compose exec agent-server cat /run/sincromisor-auth/token
```

このコマンドは秘密を端末に表示するため、画面共有や端末記録をしていない管理者用の環境で実行する。表示値をGit、画像、ログ、共有資料へ残さない。
自動生成値は保存され、通常の再作成では変わらない。

`.env` に `SINCRO_AGENT_ADMIN_TOKEN` を手動指定して起動した場合は、その値を使う。手動指定値が自動生成値より優先され、上のファイルの値とは一致しないことがある。
`.env` を編集しただけでは稼働中の値は変わらない。変更が必要な場合は [管理者トークンの変更](../design/backend/services/agent-server.md#管理者トークンの変更) を参照する。

## 指示を編集して試す

1. サインイン後、Agentsを開き、「Sincromisorのキャラクター」を選ぶ。
2. Editorを開き、現在の指示を確認する。
3. 話し方や役割に関する指示を編集する。例えば「返答は短い日本語で、落ち着いた口調にする」のように、期待する振る舞いを具体的に書く。
4. Save New Versionで下書きを保存し、Editorの会話試行で短い入力を送って応答を確認する。
5. 意図と異なる場合は指示を直し、保存・試行を繰り返す。

指示や試行の入力へトークンなどの秘密を入れない。保存した下書きは、まだ通常の会話へ公開されていない。
試行の会話履歴は通常の会話とは分かれている。ここで話した内容を、通常画面のキャラクターが引き継ぐ前提にしない。

## 通常の会話へ公開する

反映したい版を確認してPublishを実行する。公開後、通常の会話画面へ戻り、新しい発話で話し方を確認する。
これは稼働中の会話設定を変更する操作である。共有しているサーバーでは、利用中の人への影響を考慮して実行する。

通常の会話は公開済みの指示を優先する。コード側の初期指示を書き換えても、公開済みの設定があればそちらが使われる。
公開済みの指示と会話履歴は専用の保存領域に残り、通常のコンテナ再作成では消えない。保存領域を削除して反映を試みない。

## うまくいかないとき

| 症状                     | 確認すること                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面が開かない           | サーバー自身のブラウザーか、URLが4111番かを確認する。`docker compose ps agent-server llama-server` で稼働・準備状況を確認する。`chat` が未選択ならREADMEの構成を見直す。                    |
| サインインできない       | Emailの形式、Passwordに貼り付けた値の前後の空白・改行を確認する。手動指定値と自動生成値を混同していないか、設定変更後に再作成したかを確認する。トークン変更後は新しい値でサインインし直す。 |
| 試行が応答しない         | `llama-server` の準備完了を確認する。初回取得・ロード中や停止中は生成できない。[ログガイド](logging.md)で `agent-server`、`llama-server` の失敗を調べる。                                   |
| 通常の会話へ反映されない | 対象が「Sincromisorのキャラクター」か、保存だけでなくPublishまで終えたかを確認する。公開した版と通常画面の新しい応答を比べる。                                                              |

監視・フィードバックの一部は採用版の保存領域が未対応で、開発者コンソールに501が出る場合がある。これだけでEditorの保存・公開が失敗したとは判断しない。
認証・保存・公開済み設定の優先関係やMCP接続の管理は [AgentServer設計](../design/backend/services/agent-server.md) を参照する。
