# 設定UIの設計

## 要約

- 起動前ダイアログと開始後の基本設定は、同じ設定フィールド、分類、設定スナップショットを使う。
- 値・操作可否・案内はアプリ制御の `settingsStore` から取得し、設定変更を一括適用してから通知する。
- 実行中に反映する値と、会話の再接続・Looking Glassの再開始を要する値を区別する。
- 個々の値、表示条件、操作は[設定UIの項目一覧](settings-items.md)で確認する。

## 対象範囲

起動前設定、開始後設定、Looking Glass設定、および設定に付随する状態表示を扱う。デバッグ専用の調整値は[デバッグUIの項目一覧](debug-items.md)、通信形式は[RTC契約](../../contracts/frontend-rtc.md)で扱う。

## 画面構成

| 画面                          | 分類と内容                                                  | 固有の操作                                      |
| ----------------------------- | ----------------------------------------------------------- | ----------------------------------------------- |
| 起動前ダイアログ              | 会話、デバイス、音声、表示、接続                            | VRMファイルの選択・ドロップ、開始、トップへ戻る |
| 開始後の基本設定              | 会話、デバイス、音声、表示、接続                            | 初期調整の再試行、接続の開始・停止、状態カード  |
| Looking Glassページの基本設定 | 先頭の「会話」を「Looking Glass」に置換し、残りの分類を共有 | 立体表示の開始・停止、表示設定とプリセット      |

`createCoreSettingsPages` は本文が渡されていない分類を作らない。現行の通常画面は5分類を提供する。「詳細設定」という独立した分類は現行実装にはなく、診断専用調整はデバッグUIに置く。

起動前後で項目を一致させること自体を目的にせず、VRM選択、初期調整、Looking Glassのように利用場面が異なる操作は各画面が所有する。Looking Glass用の先頭分類はトークモードを含み、タイトル入力は表示しない。起動前には通常の「会話」がある。

## 設定の更新と購読

1. Reactは `settingsStore` の同じスナップショットから値、操作可否、案内を取得する。
2. 入力変更をアプリ制御の設定適用窓口へ渡す。利用者の数値入力は定義された範囲と刻みに正規化する。検証済み保存値の復元は丸め直さない。
3. `SincroAppSettingsModel` は通常設定の変更をまとめ、題名補正・操作制限・視線と自動ミュートの連動を確定する。ダイアログは同じ通知から開始案内だけを更新する。
4. 更新後の関連スナップショットを一度通知する。取り付け前の変更も初期取得へ反映する。

操作不可の項目と、機器ID以外の `undefined` は変更しない。機器IDを明示した `undefined` はブラウザー既定への復帰を表す。空の題名は `Sincromisor` へ補正する。React側に操作可否や案内の判断を別途複製しない。

有効なアプリ制御が変わった場合、Reactのイベント購読と設定購読を新しい制御へ切り替え、初期状態から同期する。解除時には設定購読も解放する。RTC停止だけではアプリの外部イベント購読を解除せず、停止後も設定通知を受け取る。

Looking Glassの値は専用の実行時設定へ反映し、設定スナップショットにも読み出す。設定値の更新と描画セッションへの適用は別であり、反映待ちの項目と再開始の必要性を専用状態で示す。

## 保存と復元

通常設定は `localStorage` の `sincromisor:settings:<ページ識別子>` に `{ version: 1, settings: { ... } }` として保存する。ページ識別子は `simple-vrm`、`vrm360`、`looking-glass-vrm` の3種類で、末尾スラッシュや `index.html` に依存しない。会話・機器・音声・表示の通常入力とLooking Glassの7項目が対象で、一般UIにない `enableTalk`・`enableInspector`・`enableVR` は含めない。

利用可否確定後、共通既定値、ページ既定値、保存した利用者設定、有効なURL設定の順で反映し、最終的な利用可否制約を適用する。購読・シーンへの初期反映と手動・OBS開始より前に同期的に復元する。現行のURL入口は `simple-vrm` の `talkMode=chat|sincro`。未指定・不正値では保存値を使い、URL適用自体は保存した選択を書き換えない。

保存は利用者の適用済み入力だけを差分で行い、視線に付随する自動ミュート解除や音声デバッグからの会場プリセット解除も含む。初期化・復元・環境通知、操作可否・案内・接続状態、タブや配置は保存しない。機器のブラウザー既定はJSON上の `null` で表し、一時不在の機器IDは消さず既存の案内と開始制限を使う。

読み取り時は既知キーの型・許容値・有限な数値と範囲を検証し、不正な項目だけを無視する。不正JSON・未対応の版は既定から起動する。保存領域の読み書き失敗はログへ通知し、現在の設定で動作を続ける。保存値は入力刻みで丸め直さず、未変更の `0.72`・`0.68` も維持する。VRM本体・サムネイルは既存のCache Storageを引き続き使う。音声デバッグ調整の保存対象とプリセット優先順位は[音声調整の保存](debug-design.md#音声調整の保存)、視線と姿勢強度の優先順位は[視線・姿勢調整の保存](debug-design.md#視線姿勢調整の保存)を参照する。

## 全設定の初期化

起動前ダイアログと開始後の基本設定の末尾に「全て初期設定に戻す」を置く。実行前に全ページの設定・デバッグ調整と保存VRM・サムネイルの削除、再読込による会話終了を確認する。取消時は変更しない。

対象は3ページの `sincromisor:settings:<ページ識別子>` 全体と、`file-cache` 内の既知のページ経路・ルート経路の `sincroVrmFile` / `sincroVrmThumbnail`。デバッグ調整は同じページ別JSONの `audio`・`gaze`・`pose` に含める。無関係なキー・キャッシュ、権限、配信素材、バックエンドのデータ、元のローカルVRMファイルは操作しない。破損JSONや未対応形式でもキーごと削除する。

保存通知とVRMの新規書込みを停止し、開始済み書込みを待ってから削除する。遅れて完了するサムネイル変換・VRM選択も再保存しない。削除成功後だけ `talkMode` をURLから解除し、無関係なクエリーとハッシュを保って再読込する。共通・ページ既定値と利用可否、診断の既定値で起動し、OBS自動開始は維持する。

失敗時は再読込せず、部分的に削除済みの可能性と保存停止を表示して再実行を許す。失敗後も保存停止を再読込まで維持し、古い状態の再保存を防ぐ。他タブを停止する制御は持たない。

## 反映タイミングと利用条件

| 分類                           | 反映の扱い                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| タイトル                       | 表示へ反映                                                                                                     |
| トークモード                   | キャラクター動作へ反映。RTCへ渡すモードは再接続時に反映                                                        |
| マイク・カメラ                 | 実行中は対象入力を再取得する。マイクは送信用トラックも差し替える                                               |
| 音声補正                       | 実行時に反映を要求する。ブラウザー側の適用結果は診断コンソールで確認                                           |
| キャラクター表示・追跡・動作量 | 実行時の表示・追跡・動作へ反映。追跡条件変更に応じてカメラ処理を再構成                                         |
| 開始時設定                     | `enableTalk`、`enableInspector`、`enableVR` は開始時の適用値との差を検出。ただし現行画面には操作を出していない |
| Looking Glass                  | 次のLooking Glass開始で反映。実行中なら停止して再開始する案内を表示                                            |

現行の `SincroVRMInitializer` は開始時設定3項目の対応可否をすべて `false` とする。`StartupBehaviorFields` には対応ページ向けのVR入力があるが、型や部品があることを現在の利用可否と混同しない。

キャラクターや視線が利用不可になった場合は対応する値もオフへ戻す。自動ミュートは視線に依存し、視線無効時にオフへ戻して操作不可にする。視線を再度有効にしても自動ミュートの値は戻さない。一括指定では視線と利用可否を先に確定し、自動ミュートを適用してから通知する。ページと端末の利用可否は両方を満たす必要がある。姿勢追跡・各動作量の入力は、必要な表示・追跡設定が有効な場合に操作できる。

`forceSincroPoseTracking` は通常の表示分類に実在するが、低性能端末でのデバッグ用である。通常利用では `pose_inference_too_slow` による顔追跡のみへの自動降格を優先する。

## 失敗時の案内

- 機器一覧の取得失敗、未対応ブラウザー、権限によるラベル未解決、選択機器の不在を機器欄に表示する。
- マイク取得機能がない場合、選択済みマイクが見つからない場合、視線有効時に選択済みカメラが見つからない場合は、開始を無効化して理由を示す。
- 接続状態と詳細、設定の反映待ち、VRM読込状態、初期調整の案内は各所有者が作った状態を表示する。
- 開始後の接続分類にはVADやICEなどの状態カードも現存する。高度な調整操作はデバッグUIに置く。

## 変更時の確認

- 設定追加時は[項目一覧](settings-items.md)を更新し、起動前、通常の開始後、Looking Glassページでの扱いを決める。
- 既定値・制約は `sincroAppSettingsDefaults.ts` を更新し、設定モデルや表示部品へ重複した値を増やさない。
- 実行時適用と再開始の区別を入力の案内・状態表示・利用側で確認する。
- 外枠変更は `src/app/shell/react/overlay/` と `overlay.css`、ページの変更は[共通枠組み](../app-shell.md)と[ページ構成](../pages.md)を確認する。
- 文書だけの変更は変更MarkdownのPrettier確認と相対リンク確認を行う。実装変更の検査範囲は[タスク管理](../../../../tasks/README.md#確認コマンド)に従う。
