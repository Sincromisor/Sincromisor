# 設定UIの設計

## 要約

- 起動前ダイアログと開始後の基本設定は、同じ設定フィールド、分類、設定スナップショットを使う。
- 値・操作可否・案内はアプリ制御の `settingsStore`から取得し、設定変更を一括適用してから通知する。
- 実行中に反映する値と、会話の再接続・Looking Glassの再開始を要する値を区別する。
- 個々の値、表示条件、操作は[設定UIの項目一覧](settings-items.md)で確認する。

## 対象範囲

起動前設定、開始後設定、Looking Glass設定、および設定に付随する状態表示を扱う。デバッグ専用の調整値は[デバッグUIの項目一覧](debug-items.md)、通信形式は[RTC契約](../../contracts/frontend-rtc.md)で扱う。

## 画面構成

| 画面                          | 分類と内容                                                 | 固有の操作                                                                         |
| ----------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 起動前の概要                  | 体験、現在のキャラクター、マイク、追跡有効時のカメラ       | VRM選択・ドロップ、詳しい設定、開始                                                |
| 起動前の詳細                  | 体験、キャラクター、マイク・音声、カメラ・動き、画面・保存 | 概要へ戻る、VRM選択、固定された開始操作                                            |
| 開始後の基本設定              | 起動前の詳細と同じ5分類                                    | 現在モデルの確認、起動前設定へ戻る、初期調整の再試行、固定された接続状態・開始停止 |
| Looking Glassページの基本設定 | 共通5分類にLooking Glassを追加                             | 立体表示の設定・状態・開始停止                                                     |

`createPurposeSettingsPages`が通常入力の所属を共有し、`createCoreSettingsPages`が名称と順序を決める。体験の表示名は「キャラクターと話す／キャラクターになる」で、内部値は `chat` / `sincro`を維持する。

起動前は概要と詳細の2表示を切り替える。表示切り替えは設定を複製せず、同じ購読値と操作窓口を使う。必須ウィザードは設けない。起動前の概要・詳細は同じVRM選択部品を使い、形式の短い表記、選択ボタン、現在モデルと拒否理由を一つの破線の枠内へ置く。ドラッグ中は枠を強調する。ドロップ受付はダイアログ全体を維持する。VRM選択は起動前だけに置き、常設側の「キャラクターを選び直す」は接続を停止して既存ダイアログを開く。Looking Glass専用分類は開始後の対応ページだけに追加し、共通の体験や画面タイトルを置き換えない。

起動前・開始後とも、カテゴリは一列に表示する。`SettingsNavigation`が表示領域とタブの自然幅を `ResizeObserver`で測定し、収まらないときは名前付きのカテゴリ選択欄へ切り替える。ラベルやカテゴリ数が変わっても複数段へ折り返さない。矢印キーとHome/Endは選択とフォーカスを同時に移し、Tabで現在の本文へ進む。選択欄の `aria-controls`で本文と関連付ける。本文は `SettingsShellPage.title`をアクセシブル名に使い、タブが非表示でも命名を保つ。選択名と同じ本文見出しは重ねない。

外枠は画面内の高さを確保し、見出し・カテゴリ操作・起動前の開始操作を固定する。スクロールは `SettingsShell`の本文領域が所有し、分類ごとの補助操作も同じ領域へ置く。全設定の初期化は「画面・保存」に置く。狭幅でも外枠全体のスクロールへ切り替えない。開始後の閉じる操作は外枠が固定表示する。

タイトル・トークモード・機器選択・動作量には見えるラベルを関連付け、説明ボタンにも対象項目名を付ける。動作量は保存値をそのまま表示するためHTMLのrangeを `step="any"`とし、利用者入力の正規化だけを設定モデルの0.01刻みで行う。百分率も保存値の小数部分を保持する。

## 説明と状態の表示

起動前と常設設定はBIZ UDPGothic、14pxの本文、共通の入力・ボタンを使う。設定の外枠だけに単色の背景と境界線を適用し、ページ本文とセクションで階層を示す。主操作は明るい塗り、通常操作は控えめな背景、全設定の初期化は専用の境界線と文言で区別する。選択カテゴリは背景と線、フォーカスは輪郭線で示す。

用途は短い項目名・チェック状態・数値・配置で示す。項目名の言い直しや一般的な利用例は常時表示しない。判断に必要な制約と無効理由だけを入力の近くへ表示し、`aria-describedby`で関連付ける。調整の目安は既存の補足へ置く。「?」は補足を開くボタンとし、フォーカスでも開き、Escapeで閉じる。操作不可は入力の無効状態だけに頼らず、設定モデルの案内や既存の依存条件に対応する理由を直下に示す。長文とエラーは本文幅で折り返す。

自動保存は描画・通信への適用完了を意味しない。体験は選択名で示し、折り返し・サンプル音声の固有情報だけを入力の直下へ添える。起動前は再接続案内を置かず、常設設定の接続操作付近に開始準備中・実行中だけ再接続手順を一度示す。Looking Glassは開始・停止操作の近くで状態を一度示し、専用状態に反映待ちがあるときだけ再開始または次回開始の手順を一度表示する。設定群の「次回開始時の設定」で適用時点を示し、変更のない通常時には反映案内を置かない。通常の項目名・選択名・状態名は日本語とし、障害コードと開発者ツールの原表記は保持する。

## 設定の更新と購読

1. Reactは `settingsStore`の同じスナップショットから値、操作可否、案内を取得する。
2. 入力変更をアプリ制御の設定適用窓口へ渡す。利用者の数値入力は定義された範囲と刻みに正規化する。検証済み保存値の復元は丸め直さない。
3. `SincroAppSettingsModel`は通常設定の変更をまとめ、題名補正・操作制限・視線と自動ミュートの連動を確定する。ダイアログは同じ通知から開始案内だけを更新する。
4. 更新後の関連スナップショットを一度通知する。取り付け前の変更も初期取得へ反映する。

操作不可の項目と、機器ID以外の `undefined`は変更しない。機器IDに明示的に指定した `undefined`はブラウザー既定への復帰を表す。空の題名は `Sincromisor`へ補正する。React側に操作可否や案内の判断を別途複製しない。

有効なアプリ制御が変わった場合、Reactのイベント購読と設定購読を新しい制御へ切り替え、初期状態から同期する。解除時には設定購読も解放する。RTC停止だけではアプリの外部イベント購読を解除せず、停止後も設定通知を受け取る。

Looking Glassの値は専用の実行時設定へ反映し、設定スナップショットにも読み出す。設定値の更新と描画セッションへの適用は別であり、反映待ちの項目と再開始の必要性を専用状態で示す。

## 保存と復元

通常設定は `localStorage`の `sincromisor:settings:<ページ識別子>`に `{ version: 1, settings: { ... } }`として保存する。ページ識別子は `simple-vrm`、`vrm360`、`looking-glass-vrm`の3種類で、末尾スラッシュや `index.html`に依存しない。5分類の通常入力とLooking Glassの7項目が対象で、一般UIにない `enableTalk`・`enableInspector`・`enableVR`と、ページ内だけで保持する`muteMicrophone`は含めない。

利用可否確定後、共通既定値、ページ既定値、保存した利用者設定、有効なURL設定の順で反映し、最終的な利用可否制約を適用する。購読・シーンへの初期反映と手動・OBS開始より前に同期的に復元する。現行のURL入口は `simple-vrm`の `talkMode=chat|sincro|echo|playback`。未指定・不正値では保存値を使い、URL適用自体は保存した選択を書き換えない。

保存は利用者の適用済み入力だけを差分で行い、視線に付随する自動ミュート解除や音声デバッグからの会場プリセット解除も含む。初期化・復元・環境通知、操作可否・案内・接続状態、タブや配置は保存しない。機器のブラウザー既定はJSON上の `null`で表し、一時不在の機器IDは消さず既存の案内と開始制限を使う。

読み取り時は既知キーの型・許容値・有限な数値と範囲を検証し、不正な項目だけを無視する。不正JSON・未対応の版は既定から起動する。保存領域の読み書き失敗はログへ通知し、現在の設定で動作を続ける。保存値は入力刻みで丸め直さず、未変更の `0.72`・`0.68`も維持する。VRM本体・サムネイルは既存のCache Storageを引き続き使う。音声デバッグ調整の保存対象とプリセット優先順位は[音声調整の保存](debug-design.md#音声調整の保存)、視線と姿勢強度の優先順位は[視線・姿勢調整の保存](debug-design.md#視線姿勢調整の保存)を参照する。

姿勢調整はアプリ専用の `SincroPoseSettingsModel`が正本となり、診断表示なしでも通常強度に保存調整を重ねてシーンへ渡す。通常強度の同値操作は診断側の保存強度を解除する。同期は保存せず、診断入力で指定した項目だけを正規化後に保存する。全設定初期化は既存の保存停止・削除・再読込でモデルを作り直す。

## 全設定の初期化

起動前の詳細と開始後の「画面・保存」に「全て初期設定に戻す」を置く。実行前に全ページの設定・デバッグ調整と保存VRM・サムネイルの削除、再読込による会話終了を確認する。取消時は変更しない。

対象は3ページの `sincromisor:settings:<ページ識別子>`全体と、`file-cache`内の既知のページ経路・ルート経路の `sincroVrmFile` / `sincroVrmThumbnail`。デバッグ調整は同じページ別JSONの `audio`・`gaze`・`pose`に含める。無関係なキー・キャッシュ、権限、配信素材、バックエンドのデータ、元のローカルVRMファイルは操作しない。破損JSONや未対応形式でもキーごと削除する。

保存通知とVRMの新規書込みを停止し、開始済み書込みを待ってから削除する。遅れて完了するサムネイル変換・VRM選択も再保存しない。削除成功後だけ `talkMode`をURLから解除し、無関係なクエリーとハッシュを保って再読込する。共通・ページ既定値と利用可否、診断の既定値で起動し、OBS自動開始は維持する。

失敗時は再読込せず、部分的に削除済みの可能性と保存停止を表示して再実行を許す。失敗後も保存停止を再読込まで維持し、古い状態の再保存を防ぐ。他タブを停止する制御は持たない。

## 反映タイミングと利用条件

| 分類                           | 反映の扱い                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| タイトル                       | 表示へ反映                                                                                                    |
| トークモード                   | キャラクター動作へ反映。RTCへ渡すモードは再接続時に反映                                                       |
| マイク・カメラ                 | 実行中は対象入力を再取得する。マイクは送信用トラックも差し替える                                              |
| 音声補正                       | 実行時に反映を要求する。ブラウザー側の適用結果は診断コンソールで確認                                          |
| キャラクター表示・追跡・動作量 | 実行時の表示・追跡・動作へ反映。追跡条件変更に応じてカメラ処理を再構成                                        |
| 開始時設定                     | `enableTalk`、`enableInspector`、`enableVR`は開始時の適用値との差を検出。ただし現行画面には操作を出していない |
| Looking Glass                  | 次のLooking Glass開始で反映。実行中なら停止して再開始する案内を表示                                           |

現行の `SincroVRMInitializer`は開始時設定3項目の対応可否をすべて `false`とする。`StartupBehaviorFields`には対応ページ向けのVR入力があるが、型や部品があることを現在の利用可否と混同しない。

キャラクターや視線が利用不可になった場合は対応する値もオフへ戻す。自動ミュートは視線に依存し、視線無効時にオフへ戻して操作不可にする。視線を再度有効にしても自動ミュートの値は戻さない。一括指定では視線と利用可否を先に確定し、自動ミュートを適用してから通知する。ページと端末の両方で利用可能である必要がある。姿勢追跡・各動作量の入力は、必要な表示・追跡設定が有効な場合に操作できる。

`forceSincroPoseTracking`は開発者ツールの `Sincro`タブに置く。設定ストアと保存形式を維持し、表示・顔追跡・姿勢追跡の依存条件に従う。通常利用では `pose_inference_too_slow`による顔追跡のみへの自動降格を優先する。

## 失敗時の案内

- 機器一覧の取得失敗、未対応ブラウザー、権限によるラベル未解決、選択機器の不在を機器欄に表示する。
- マイク取得機能がない場合、選択済みマイクが見つからない場合、視線有効時に選択済みカメラが見つからない場合は、開始を無効化して理由を示す。
- 接続状態と詳細、設定の反映待ち、VRM読込状態、初期調整の案内は各所有者が作った状態を表示する。
- ICE・顔座標・VAD確率は既存の開発者ツールで確認する。カメラ品質の改善案内と初期調整の再試行は「カメラ・動き」に残す。

## 初期較正の開始と中断

パネルは較正状態を購読し、段階別の再試行を要求する。開始・中断条件、アプリと追跡世代の検査は[共通枠組みの初期較正](../app-shell.md#初期較正の開始と中断)を参照する。

## 変更時の確認

- 設定追加時は[項目一覧](settings-items.md)を更新し、起動前、通常の開始後、Looking Glassページでの扱いを決める。
- 既定値・制約は `sincroAppSettingsDefaults.ts`を更新し、設定モデルや表示部品へ重複した値を増やさない。
- 実行時適用と再開始の区別を入力の案内・状態表示・利用側で確認する。
- 外枠変更は `src/app/shell/react/overlay/`と `overlay.css`、ページの変更は[共通枠組み](../app-shell.md)と[ページ構成](../pages.md)を確認する。
- 文書だけの変更は変更MarkdownのPrettier確認と相対リンク確認を行う。実装変更の検査範囲は[タスク管理](../../../../tasks/README.md#確認コマンド)に従う。

## 開始前のデータ利用

開始前の概要・詳細に、音声の接続先への送信と、通常体験での認識音声・文章のサーバー保存を示す。「データの扱い」から、会話履歴のサーバー保存、カメラ映像のブラウザー内追跡、VRM・設定のブラウザー保存を確認できる。概要の「カメラを使う」で追跡とカメラ選択を無効化でき、開始せずトップへ戻る導線を維持する。

## 体験全体と接続の停止

通常画面の「体験を終了」は機器・推論・較正・音声処理・RTCを終了する。機器状態は実トラックの所有者から取得し、終了後に設定を変更しても機器を再取得しない。設定と選択モデルを保持し、明示的な開始操作で再開する。設定内の「接続を停止」はRTCだけを停止する診断・再接続用の操作として維持する。詳細な所有境界は[共通枠組み](../app-shell.md#体験の終了と機器の使用)を参照する。
