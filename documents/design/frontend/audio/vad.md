# フロントエンド VAD

## 要約

- 通常会話（`chat` / `sincro`）は発話終端の判断をサーバーへ集約する。通信量節約用の軽量無音ゲートを任意で利用でき、既定は無効とする。フロントはRMS / Peakによる軽い表示を維持する。
- `echo` / `playback`の音声診断では、保存済みの送信ゲートと学習VAD設定を利用できる。
- VADはUIではなく音声 / メディア制御の一部として扱う。
- 診断値は診断Consoleの音声 / 状態から確認できるようにする。

## 対象範囲

- 対象
    - フロント側VADモード
    - VADパラメータ
    - 診断Console観測項目
- 非対象
    - サーバー側のSpeechExtractor
    - 音声認識モデル

## 責務

- `src/features/media/userMedia`
    - マイク / カメラストリーム、機器制約、トラック生存期間、音声プロファイルを置く。
- `src/features/media/vad`
    - Silero VAD処理担当、学習済みVADクライアント、音声処理実行時、発話状態を置く。
    - Workerは `onnxruntime-web/wasm`のWASM専用入口を使う。Viteが出力するWASMと `/3rd_party/silero-vad/silero_vad.onnx`を同一オリジンから取得し、推論失敗時は既存のRMS判定へ移る。
- `src/features/media/devices`
    - メディア機器リストサービスを置く。
- UserMedia / 音声処理
    - マイクストリームから音量の包絡線を計算する。
- VAD状態
    - 発話中 / 無音 / 不確実などの状態をアプリ制御へ渡す。
- UI
    - VAD状態を通常UIと診断Consoleへ表示する。

## 会話モードによる実効処理

`SincroAudioInputController`は設定復元・マイク取得前から会話モードを音声処理へ伝える。
`chat` / `sincro`では学習VADのWorkerとPCM転送を停止し、`enableVadGate`が有効な場合だけAudioWorklet内で軽量無音化する。
入力の全チャンネル・全サンプルを確認し、絶対値0.001以上の音が一つでもあれば、そのブロック全体を遅延なく通す。
閾値は既存の診断用RMS下限と同じ振幅だが、通常会話ではRMS平均ではなく全サンプルの絶対値に適用する。
閾値未満が続いた場合も180msは通してから閉じる。保持はサンプル数で測り、端数は1ブロック未満だけ長くなる。
これは既存の学習VAD標準保持時間に合わせた初期値で、実音声で最適化した値ではない。
閉じても同じ長さのゼロPCMを出すため、サーバーが無音時間を測る時間軸を維持する。
音声を先に出してからメインスレッド通知でゲートを開く方式は通常会話では使わず、追加の先読み遅延も設けない。

診断用の方式・閾値・厳格設定は保存したまま、`echo` / `playback`でだけ適用する。
診断ではWorkletの軽量ゲートを停止し、選択したVADとGainNodeによる従来のゲートを使う。
通常会話の軽量ゲートには診断用の強い閾値を適用しない。モード変更・マイク再取得時はゲートを開いて始める。
学習用PCM転送はWorklet生成時から無効とし、診断で要求したときだけ開始する。
明示的なマイクミュートと既存の視線ミュートは、この無音ゲートとは別に維持する。

通常設定の「無音時の送信を抑える」は全モードで利用でき、保存値を適用する。
開発者ツールの学習VAD・閾値調整は診断モードだけで表示する。通常会話の診断表示はRMSを使い、保存された学習方式が稼働中であるようには表示しない。
RMSの発話表示は無音化の開閉を示すものではない。通常会話のゲートは全サンプルの振幅を別に確認する。

ゲート有効時は閾値未満の小声や弱い語頭を消す可能性があり、サーバーでは復元できない。設定画面で小声が欠ける場合は無効にするよう案内する。
通信量・端末電力の削減量と実音声品質は未測定である。評価は[品質評価タスク](../../../../tasks/performance/task-261107202017-smart-turn-quality/task.md)へ残し、既定有効化や改善実証とは扱わない。

## 学習VADのモデル契約

同梱Silero ONNXは16kHzの512サンプルごとに、直前64サンプルを前置した576サンプルと
`state [2,1,128]`、スカラーの `sr` を受ける。`output` と `stateN` は出力順に依存せず取得する。
停止・再開で状態と文脈を初期化し、停止前の非同期結果は無効にする。

発話確率の既定閾値は開始0.5、終了0.35とする。これは
[Silero v6.2の公式実装](https://github.com/snakers4/silero-vad/blob/v6.2/src/silero_vad/utils_vad.py)
（2026-11-07参照）を基準とする値で、特定のマイク・会場への最適化値ではない。
保存済みの開始・終了閾値が0.01未満なら、以前の状態未更新に依存した値として既定へ戻す。
開始の入力範囲は0.01〜0.99、終了は0.01〜0.98とし、終了を開始より低く制限する。

## 連続入力と通知

Workletから受けたPCMは、ブロック間の補間位置と端数を維持して16kHz・512サンプルへ変換する。
全フレームを順に推論し、発話保持時間は音声の時刻で測る。`minReportIntervalMs` は定期通知の間隔だけを
制御し、発話状態の変化は即通知する。旧設定の `minInferIntervalMs` は読み込まず、通知間隔の既定値を使う。
プリセットの `low_cpu` は通知控えめ、`high_accuracy` は通知頻度と保持時間を増やす設定であり、
推論フレーム数はどのプリセットでも同じである。

未処理音声が1秒を超えた場合は、古い判定がゲートへ届き続けることを避けるため系列を破棄し、
診断に理由を通知して既存WorkletのRMS判定へ切り替える。モデル失敗時も同様に古い学習判定を無効にする。
学習VADの再有効化で再試行する。停止・サンプルレート変更では補間端数、キュー、モデル状態を初期化する。

## モード

- RMS / Peak
    - 軽量で、即時反応が必要な表示に使う。
- 学習VAD
    - ノイズ耐性が必要な発話判定に使う。
- 厳格判定
    - 誤検出を抑えたい場面で使う。

## 変更時の確認

- VADパラメータを変更したら診断Consoleの表示と設定UIの文言を確認する。
- 音声機器切替時にVAD状態が古いストリームを参照していないか確認する。
- サーバー側のSpeechExtractorの仕様変更とは別文書で扱う。

## 音声折り返しによる確認

[RTCの起動手順](../../../../sincromisor-server/sincro-rtc/README.md)に従い、Consulと下流を使わずRTCを起動する。ブラウザーの「体験を選ぶ」で「入力音声を折り返す」を選び、ヘッドホンを使用して接続する。

1. 音声設定で「無音時の送信を抑える」を無効にし、入力音声が返ることを確認する。
2. 同じ設定を有効にし、診断ConsoleのVAD判定と返却音声を比較する。必要に応じて既存の手動閾値・学習VAD設定で発話と非発話を比較する。
3. 「マイクをミュートする」で送信を止め、解除後に音声が戻ることを確認する。停止・再接続も確認する。

無音ゲートの初期値は全モードで無効である。マイク→フィルター→Worklet→GainNode→送信用トラックの配線は共通で、通常会話はWorklet、診断はGainNodeで無音化する。視線による自動ミュートはecho／playback接続中には適用しない。

この診断で確認できるのはブラウザーの入力処理とRTCまでの音声往復である。サーバー側の区間抽出・認識・応答生成・合成は実行せず、認識文やモーラも生成しない。入力はRTCで復号・再サンプリング・再符号化されるため、元の音声ビット列の一致を確認する用途には使わない。

## 固定音声の繰り返し再生による確認

「サンプル音声を繰り返す」（`playback`）は、下流を使わず固定音声・テロップ・口形を再生する。
マイクのフィルターとVADは通常どおり動くが、入力は再生内容へ影響しない。
返却音声はブラウザー入力VADを通らないため、VADゲートの直接確認にはechoを使う。
playbackでは返却経路の同期と、スピーカー再生中の入力側VAD判定を確認できる。
再生素材の準備・出典・配置は[RTCのREADME](../../../../sincromisor-server/sincro-rtc/README.md#再生素材の準備と差し替え)を参照する。
