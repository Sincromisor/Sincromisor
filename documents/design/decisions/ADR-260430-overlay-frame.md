# ADR-260430 重ねて表示する画面の外枠の責務

## 状態

- 採用済み

## 背景

起動前ダイアログ、右側設定パネル、診断 Console の表示面、閉じるボタン、スクロール、z-index、画面幅に応じた表示幅が各コンポーネント / CSS に分散し、見た目の小修正が別重ね表示へ波及しやすかった。

## 決定

- 重ね表示の外側装飾は専用フレームコンポーネントと共有 CSS トークンが所有する。
- `SettingsShell` は情報設計とカテゴリ案内に専念する。
- 診断 Console と設定パネルは内容に専念し、位置や閉じる操作を持たない。

## 検討した選択肢

| 選択肢                                         | 利点                       | 欠点                                                     |
| ---------------------------------------------- | -------------------------- | -------------------------------------------------------- |
| `RightToolFrame` / `StartupDialogFrame` へ集約 | 外枠責務が一箇所にまとまる | フレームと内容の境界を守る必要がある                     |
| 各コンポーネントで個別調整                     | 局所変更が速い             | 閉じるボタン / スクロール / z-index のズレが再発しやすい |
| `SettingsShell` に外枠も持たせる               | コンポーネント数は減る     | 設定情報設計と重ね表示実行環境境界が混ざる               |

## 影響

- 右側ツールの位置、幅、スクロール、閉じるボタンは `RightToolFrame` が持つ。
- 起動前ダイアログの表示面 / 背面 / スクロールは `StartupDialogFrame` と `overlay.css` が持つ。
- 旧形式 CSS は代替処理に縮退し、現行 React 重ね表示の見た目責務を取り戻さない。

## 見直し条件

- 重ね表示種別が増え、現在のフレーム抽象では用途差を表現できなくなった場合。
- 標準のダイアログの実行環境制約が変わり、別構成の方が単純になった場合。
