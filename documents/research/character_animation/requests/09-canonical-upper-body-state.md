# CanonicalUpperBodyState / 座標系調査依頼

## 目的

Sincromisor の `sincro` モードで、MediaPipe 由来の観測値を、IK、時系列推定、意味に基づく動作動作、VRM 姿勢適用が共有できる `CanonicalUpperBodyState` へ変換するための座標系、値域、入力優先順位、デバッグ表示を設計する。

この調査は、後段の IK、フィルタ、評価指標、VRM 適用で語彙と単位がずれないようにするための中核である。MediaPipe 特徴点を直接 VRM ボーンへ渡すのではなく、体幹基準の意味量へ正規化する設計を固めてほしい。

## 背景

Sincromisor は、ブラウザ上で 3D キャラクターと音声対話するサービスである。`sincro` モードでは、単眼 Web カメラで撮影したユーザーの上半身、頭、腕、手首、指の動きを、VRM 1.0 / VRoid Studio 系キャラクターへ反映する。

既存資料では、MediaPipe Pose / Hand / Face / Gesture の出力を「骨格姿勢の正解値」ではなく「不確実な観測値」として扱い、次の流れで最終動作を作る方針としている。

```text
MediaPipe 観測値
  -> 信頼性の対応表
  -> 身体のローカル座標系での標準状態
  -> 時系列状態推定
  -> 動作意図 / 表現調整
  -> アバターの調整情報
  -> IK / FK / VRM 姿勢
```

`CanonicalUpperBodyState` は、このうち身体のローカル座標系での標準状態を担う。ここが曖昧だと、腕の `forwardness`、IK 目標、フィルタの単位、評価指標の意味、AvatarMotionProfile の倍率が後段ごとにずれる。

## 前提技術

- 入力: MediaPipe Pose / Hand / Face / Gesture 観測値
- 入力品質: `ReliabilityMap` による関節 / 部位ごとの重み
- 出力: IK、TemporalStateEstimator、MotionIntent、AvatarMotionProfile が共有する中間状態
- 実行環境: Web ブラウザ
- 対象: 頭、体幹、肩、腕、手首、指
- 非対象: VRM ボーンの回転の最終適用、全身 IK、下半身歩行

## 調査してほしいこと

### 座標系

MediaPipe の画像座標、ワールド座標の特徴点、カメラ空間、体幹ローカル空間、VRM 正規化済みローカル姿勢を混同しないための座標系を定義してほしい。

調査してほしい論点は次である。

- カメラ / 画像 / MediaPipe ワールド座標 / 身体のローカル座標系の / アバターのローカル座標系の責務分離。
- 各空間の軸方向、単位、原点。
- 左右反転、カメラ鏡像表示、VRM 表示側反転の扱い。
- ワールド座標の特徴点の z をどこまで使うか。
- 身体寸法の倍率正規化に肩幅 / 腰幅 / 体幹高さのどれを使うか。

### 体幹の座標系

体幹基準は、腕、頭、手首、意味に基づく動作動作の全ての基準になる。

調査してほしい論点は次である。

- `shoulderCenter`、`hipCenter`、Face 行列、前フレームを使った体幹の座標系推定。
- `U`、`R`、`F` 軸の定義。
- 身体ヨー、身体前反転、横向き時の安定化。
- 肩 / 腰が欠落した場合の代替処理。
- 継続的なキャリブレーションで中立姿勢ヨーをどこまで更新してよいか。

### 腕の意味量

既存資料では、腕を絶対手首位置ではなく、身体のローカル座標系で表す意味量に落とす案を挙げている。

主に定義したい値は次である。

- `elevation`
- `openness`
- `forwardness`
- `elbowFlexionHint`
- `reach`
- `side`
- `armConfidence`

調査してほしい論点は次である。

- それぞれの計算式。
- 値域。例: 0-1、-1-1、ラジアン、正規化済み長さ。
- Pose 手首、Pose 肘、Hand 手のひら、ワールド座標 z、手サイズ変化の優先順位。
- 「前に出す」と「横に広げる」の判定。
- 腕が伸び切った場合や画面端に近い場合の信頼性反映。

### 頭部 / 手首 / 手入力優先順位

部位ごとに、どの観測値を主入力にし、どれを代替処理とするかを明確にしたい。

調査してほしい論点は次である。

- 頭部は Face 変換行列を主入力、Pose 鼻 / 目 / 耳を代替処理にする設計。
- 手首位置は Pose 手首を主入力、Hand 特徴点を向きと指の補助入力にする設計。
- 手首向きは手のひらの基底から作るが、ロールを弱く扱う設計。
- 指は曲げ / 指の開き / 対向運動の低次元値へ落とす設計。
- Hand / Face が欠落した場合、Poseのみで残すべき値。

### データ構造

後段が共有できる TypeScript 向けの型を提案してほしい。

含めたい要素は次である。

- 時刻 / フレーム ID
- 体幹の座標系
- 頭部状態
- 左 / 右腕状態
- 手首 / 手のひら状態
- 指状態
- 部位信頼性
- 較正メタデータ
- デバッグ値

型は実装コードそのものではなく、責務と単位が分かる設計メモでよい。

### デバッグ表示と評価指標

`CanonicalUpperBodyState` は診断用スナップショットと再生で確認できる必要がある。

調査してほしい論点は次である。

- motion-debug で表示すべき標準化した値。
- 値域外、急変、左右入れ替えを見つけるデバッグ表示。
- 評価指標へ渡すべき値。
- 再生ログに保存すべき値と、再計算でよい値。
- IK / 時系列 / 意味に基づく動作から見て説明しやすい名前。

## 期待成果物

- 座標系定義。
- 体幹の座標系の推定方法。
- `CanonicalUpperBodyState` の TypeScript 型案。
- 腕の意味量の計算式、値域、信頼度反映。
- 頭部 / 手首 / 手 / 指の入力優先順位表。
- 診断用スナップショットと motion-debug 表示項目。
- 後段の IK、TemporalStateEstimator、MotionIntent、AvatarMotionProfile へ渡す契約。
