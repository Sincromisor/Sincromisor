# モーションソルバ / IK / 関節制約調査依頼

## 目的

Sincromisor の `sincro` モードで、単眼 Web カメラ由来の不確実な観測値から、VRM 1.0 キャラクターの上半身を破綻なく動かすためのモーションソルバ、IK、関節制約、補正アルゴリズムを検証する。

特に、肘反転、肩崩れ、腕の伸び切り、手首ロール暴れ、指のちらつきを避けるための具体的な設計と初期パラメータを知りたい。

## 背景

Sincromisor は、ブラウザ上で 3D キャラクターと音声対話するサービスである。`sincro` モードでは、ユーザーの上半身の動きを単眼 Web カメラと MediaPipe で推定し、VRM 1.0 / VRoid Studio 系キャラクターへ反映する。

目的は人体の完全再現ではなく、キャラクターとして自然で破綻しにくい「ものまね」である。既存資料では、腕には自前の 2ボーンの解析的IK を使う方針だが、IK は中核ではなく、信頼性、CanonicalUpperBodyState、TemporalStateEstimator、AvatarMotionProfile を経た後段の姿勢適用器に近い位置づけとしている。

## 前提技術

- 入力: MediaPipe Pose / Hand / Face / Gesture の観測値
- 中間表現: 身体のローカル座標系で表す標準化した上半身状態
- 出力: VRM 1.0 人型骨格の正規化済みローカル姿勢
- 描画: Three.js + `@pixiv/three-vrm`
- モデル: VRoid Studio 系を主対象とするが、一般的な VRM 1.0 も考慮する

## 調査してほしいこと

### 腕 IK

既存資料では、腕は 2ボーンの解析的IK を主方式にする案としている。次を具体化してほしい。

- 肩 / 肘 / 手首ボーン列の IK 解法。
- 到達距離制限の設計。
- 肘の曲がる方向ベクトルの計算、保持、代替処理。
- 腕が伸び切った場合の曲がる方向安定化。
- 肩、肘、手首の緩やかな制限。
- 左右腕での符号・軸差分の扱い。

### 肘反転の防止

肘反転は最優先で避けたい破綻の一つである。既存資料では、実測曲がる方向、前フレーム曲がる方向、代替処理曲がる方向を状態に応じて合成する案を挙げている。

調査してほしい論点は次である。

- `Stable`、`Uncertain`、`Extended`、`Lost`、`Recovering` それぞれの曲がる方向合成比率。
- `dot(measuredPole, previousPole) < 0` のような急反転検出の妥当性。
- 角速度や肘屈曲を使った除外条件。
- キャラクターらしい外向き肘偏りの補正の初期値。

### 肩・鎖骨・胸の補正

VRoid 系モデルでは、`upperArm` だけを動かすと肩・胸・袖まわりが破綻しやすい。次を調査してほしい。

- 腕を上げる角度に応じた肩 / `upperChest` / 胸 / 背骨への分配。
- 片腕上げ、両腕上げ、手を前に出す、腕を横に広げる場合の補正差。
- 肩ボーンがないモデル、`upperChest` がないモデルの代替処理。
- 顔や胸への手・腕のめり込みを避ける簡易侵入禁止領域。

### 手首・前腕ねじれ

手首ロールは単眼カメラで特に暴れやすい。次を調査してほしい。

- Hand 手のひらの基底から信用できる軸と捨てる軸。
- 手首ピッチ / ヨー / ロールの反映比率。
- 手ボーンと `lowerArm` ねじれへの分配。
- 手が横向き、顔前、遮蔽、小さく写る場合の代替処理。

### 指制御

既存資料では、指は各関節の 3D 回転を直接推定せず、曲げ / 指の開き / 対向運動の低次元制御から始める案としている。

調査してほしい論点は次である。

- 最初に実装すべき指制御の粒度。
- 親指 / 人差し指 / 中指 / 薬指・小指の分け方。
- 曲げを基部 / 中間部 / 末端へ分配する比率。
- 指の開きを入れるべき指と上限角。
- Gesture Recognizer と指の曲げの整合。

## 期待成果物

- 腕 IK、曲がる方向ベクトル、到達距離制限、緩やかな制限の設計メモ。
- 部位別の初期パラメータ表。
- VRoid 系モデルで避けるべき破綻と対応策。
- 肩 / 胸 / `upperChest` / 背骨の分配規則。
- 手首ロールと前腕ねじれの推奨分配。
- 指制御の段階的実装計画。
- 実装時に記録すべきデバッグ値。
