# キャリブレーション / UX ガイド調査依頼

## 目的

Sincromisor の `sincro` モードで、単眼 Web カメラによる上半身モーションを安定させるための初期キャリブレーション、継続的なキャリブレーション、カメラ品質ガイド、失敗時 UX を設計する。

調査では、ユーザーに高度な専門用語を見せず、短時間で姿勢同期を開始でき、問題がある場合はユーザーが直せる行動として案内できることを重視してほしい。

## 背景

Sincromisor は、ブラウザ上で 3D キャラクターと音声対話するサービスである。`sincro` モードでは、単眼 Web カメラで撮影したユーザーの上半身動作を、VRM 1.0 / VRoid Studio 系キャラクターへ反映する。

単眼カメラでは、ユーザーの肩幅、腕長、カメラ距離、正面基準、手の大きさ、顔の向きが曖昧になりやすい。既存資料では、T ポーズではなく「正面自然姿勢 + 軽い A ポーズ」を初期キャリブレーションに使い、オンラインでは人間側の観測基準だけを低速更新する方針としている。

## 前提技術

- 入力: Web カメラ + MediaPipe Pose / Hand / Face
- 対象: 上半身、頭、肩、腕、手首、指
- 出力: ユーザー較正、カメラ品質、画面内の構図案内、AvatarMotionProfile への補助値
- 実行環境: Web ブラウザ
- UX: 通常ユーザー向け表示とデバッグ表示を分ける

## 調査してほしいこと

### 初期キャリブレーション

既存資料では、4-6 秒程度で次の姿勢を取ってもらう案がある。

| 手順 | 姿勢                         | 取得する値                       |
| ---: | ---------------------------- | -------------------------------- |
|    1 | 正面自然姿勢                 | 中立姿勢体幹、肩幅、頭部中立姿勢 |
|    2 | 軽い A ポーズ                | 上腕 / 前腕の長さ、肘平面        |
|    3 | 胸から腰の高さで軽く開いた手 | 手倍率、指中立姿勢               |
|    4 | 任意で顔を少し左右に向ける   | 頭部ヨー代替処理                 |

調査してほしい論点は次である。

- この手順がユーザーにとって許容されるか。
- より短い手順にできるか。
- T ポーズを避ける判断の妥当性。
- 較正成功 / 失敗の判定。
- 途中で失敗した場合のリトライ UX。

### 継続的なキャリブレーション

既存資料では、人間側の観測基準だけを高信頼度・中立姿勢に近い時に低速更新し、アバター側の構造値は固定する案としている。

調査してほしい論点は次である。

- 安全に更新してよい値。
- 更新してはいけない値。
- 継続的なキャリブレーションの速度。
- ユーザーが姿勢を変えたのか、推定が外れたのかの判定。
- 長時間利用で徐々に生じるずれしないためのガード。

### カメラ品質ガイド

内部ではカメラ品質スコアを持つが、ユーザーには直せる行動として表示したい。

調査してほしい論点は次である。

- 肩が入っていない。
- 手が画面端に近い。
- 手が小さく写っている。
- 顔だけ大きい。
- 露出不足。
- 動体ぶれ。
- 正面を向いていない。
- 手や肘が隠れている。

それぞれについて、通常ユーザー向けの短い文言、デバッグ向けの詳細、表示優先順位を整理してほしい。

### 設定 UI

ユーザーが調整できる項目は増やしすぎると扱いづらい。一方で、キャラクターや環境差分を吸収する逃げ道は必要である。

調査してほしい論点は次である。

- 通常 UI に出すべき設定。
- デバッグ UI にだけ出すべき設定。
- `sincro` 動きの強さのような単一スライダーで吸収できる範囲。
- 自動調整に任せるべき項目。
- キャラクター別調整情報をユーザーに見せるべきか。

### 失敗時 UX

カメラ権限拒否、MediaPipe モデル / wasm 配置漏れ、低性能端末、カメラなし、暗い部屋などがあり得る。

調査してほしい論点は次である。

- `sincro` を無効化してチャットモードへ戻す条件。
- 代替処理中もキャラクターが不自然に見えない動作。
- ユーザーに再試行させるべき場合と、設定変更を案内すべき場合。
- 警告を同時にいくつまで表示するか。

## 期待成果物

- 初期キャリブレーションフロー。
- 較正成功 / 失敗の判定基準。
- 継続的なキャリブレーション方針。
- ユーザー向けカメラ品質の案内文言集。
- 通常 UI / デバッグ UI の情報分離案。
- 失敗時代替処理 UX。
- `sincro` モードを安心して開始できる最小 UX。
