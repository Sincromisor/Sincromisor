# Gate3試験をRTC統合試験の名称へ整理する

## 背景

Pion移行の段階3に由来するGate3という名称が、移行完了後も現役のブラウザー統合試験に残っている。会話1往復を確認する試験は維持し、現在の用途が分かる名前へ揃える。

## 完了条件

- [x] Playwright設定とフロントエンド試験ディレクトリを`rtc-integration`へ改名し、Go側の起動参照を同期する。
- [x] Go試験基盤を`internal/rtcintegration`、ビルドタグを`rtcintegration`、環境変数を`SINCRO_RTC_INTEGRATION_*`へ揃える。試験内部の識別子と固定音声名も同期する。
- [x] 現在設計、README、コードコメントをRTC統合試験の用途に合わせる。模擬下流サービスを使う範囲と実行前提を明記する。
- [x] 過去の移行文書とタスク記録の判定・実行履歴は保持する。改名で壊れるMarkdownリンクの参照先だけは更新する。
- [x] 改名後のGo試験・静的検査とPlaywright設定読み込み・1件の一覧取得を確認する。変更前からの失敗は比較結果を記録し、改名による回帰と区別する。

## 範囲と互換性

既存試験の配置・名称・案内を整理する。試験の合否条件、RTC通信契約、起動順、終了処理は変更しない。通常の`npm run gate`への統合や新しい検証基盤は追加しない。

試験用の設定名・環境変数・ビルドタグは互換エイリアスを残さず変更する。ローカルの実行コマンドは新名称へ更新が必要となる。本番の環境変数には影響しない。

## 確認方法

Goモジュールで新タグ付きの試験基盤の単体・契約試験、ブラウザー試験のコンパイル確認、対象の`go vet`を行う。Playwrightは新設定で`--list`を実行する。外部実行ファイルが揃い専用Consulのポートが空いていれば、ブラウザー結合試験を1回実行する。環境が不足する場合はその事実と未確認範囲を記録する。

変更したMarkdownの整形、旧名の残存箇所と移動先リンク、固定音声の同一性、タスク管理の整合性を確認する。

## 確認結果

Goの`process`、`harnessenv`、`pipelinecontract`の新タグ付き試験、`browser`のコンパイル確認、対象の`go vet`が成功した。新しいPlaywright設定の`--list`で既存の1件を取得でき、TypeScriptのBiome検査も成功した。固定音声は改名前とバイト単位で一致し、移動先リンクと現役コードの旧名残存を確認した。

`consuldev`の120msの起動期限による失敗は変更前のHEADでも再現したため、既存の環境依存として扱った。実ブラウザー結合試験はConsul・FFmpegの実行ファイルがPATHになく、新環境変数での実行環境も未準備のため未実行。詳細は[確認上の制約](impl.md)を参照する。

変更したMarkdownの整形、タスク状態・索引の整合性、コメント点検を実施した。旧名からの変更は[RTC統合試験の実行手順](../../../sincromisor-server/sincro-rtc/internal/rtcintegration/README.md)へ記載した。
