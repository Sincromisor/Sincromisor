# sincro-rtc の肥大化レビュー

## 対象と判断

変更前の `9b9238ec36ad4f932c3cf46e09d8d03c874dd0cb` を基準に、起動、シグナリング、RTCセッション、音声入出力、下流クライアント、会話処理の主要経路と呼び出し元を確認した。全関数の正しさを証明する監査ではなく、重複した処理・状態と読み進めにくい構造のレビューである。

Goコードは207ファイル、28,217行である。内訳は本番84ファイル・10,074行、試験105ファイル・16,228行、Gate 3などの試験補助と生成処理18ファイル・1,915行。コメントと空行を含むため、行数だけを不要コードの量とは扱わない。

## 指摘と実行タスク

1. **中: 不要な完了済みID集合が増え続ける。** `internal/pipeline/conversation.go` の `closed` は最後の発話IDと単調増加検査で代替できる。`finalized` は最終応答で `requests` を削除するため、通常の呼び出し経路で判定に到達しない。どちらも世代の再初期化まで要素を保持し、状態の理解とメモリー使用を増やす。[集合削除](task.md)で対応する。
2. **中: 下流4クライアントの共通処理が重複する。** `internal/pipeline/client/{extractor,recognizer,processor,synthesizer}.go` は同じ中断可能な結果配送と `Events`・`Close` を複製する。3種類には初期化なしの `Connect` 転送もある。既存の `baseClient` に共通操作を集め、型ごとの入力検証を残す。[共通処理の整理](../task-260906040101-deduplicate-pipeline-clients/task.md)で対応する。
3. **中: 出力の世代判定が二重実装されている。** `internal/rtc/outbound.go` の `applyGeneration` と `applyGenerationError` はロック、世代比較、音声・文字・テロップ破棄が同じである。将来の修正で片側だけ変更されると古い出力が混ざり得る。現時点の不具合を再現したものではなく、保守上の問題である。[世代判定の統合](../task-260906040101-unify-outbound-generation/task.md)で対応する。
4. **低: ファイル分割で説明が対象から離れている。** `cmd/sincro-rtc/main.go` のログ関数に `serveBoundary` の説明が付き、`startup.go`・`shutdown.go`・`server.go` の末尾に別ファイルの宣言を説明するコメントが残る。ファイル数を減らす前に、読む順序と説明の対応を直す。[起動処理の説明修正](../task-260906040102-repair-startup-code-guidance/task.md)で対応する。

## 維持する構造

- `rtc.Manager`、`Session`、Offer登録簿は同じものの三重実装ではない。セッションの所有、メディア処理、要求の再送と候補収集を分担し、終了期限や重複拒否を支える。これらの統合は今回の改善に不要である。
- MessagePackの手動検証は、必須キー、`nil`と空配列、整数幅、元の合成要求の保持という通信契約を扱う。構造体への単純な復号だけでは同じ拒否条件を満たさない。
- 音声の変換、送信時計、有限キュー、世代をまたぐ破棄は実際の入力と出力を支える。試験件数やファイル数の多さだけを理由に削除しない。
- `Manager.closed` はプロセス中の未知IDと終了済みIDを区別する404/410契約のため保持する。会話処理の不要な集合とは異なり、削除には通信契約の変更が必要になる。
- 再送、終了競合、入力境界の試験は既存動作を守る根拠である。試験補助は本番コードと区別して評価し、一括削除や新しい共通基盤の導入は行わない。

## 確認上の制約

通常のサンドボックスではGoの既定キャッシュへの書き込みとローカルソケット作成が拒否された。キャッシュを `/tmp/sincro-rtc-review-go-cache` に移し、ソケットを使う試験は権限拡張して実行する。実ブラウザーと下流の推論サービスを使う実環境試験は今回の局所整理の対象外とする。各タスクの結果は対応する `task.md` に記録する。
