# RTC統合試験の設定をVSCodeで読み込めるようにする

## 背景

ルートのPlaywright設定がTypeScriptプロジェクトに含まれず、VSCodeで`process`の型が解決されない。また設定読み込み時に環境変数を必須としているため、環境未設定ではテスト一覧取得も失敗する。

## 完了条件

- [x] ルートに専用設定を対象とする`tsconfig.json`を置き、Node型を明示する。型定義の依存関係もルートに宣言する。
- [x] 環境変数が未設定でも設定読み込みと既存1件のテスト一覧取得が成功する。
- [x] Chromium、接続先、音声入力の必須チェックはブラウザー起動前に行い、不足時にはGo試験からの実行を案内する。
- [x] Go側の起動・環境検査と既存テストの合否条件を維持する。
- [x] 型検査、実行前検証の正常・不足経路、設定の整形、実行案内を確認する。

## 変更範囲と確認方法

ルートのTypeScript設定・依存宣言、Playwright設定と試験用環境変数の検証、RTC統合試験READMEを対象とする。VSCodeへの機種固有パスの登録やブラウザーからのサービス起動は追加しない。

`tsc --project tsconfig.json`、環境変数を除去したPlaywrightの`--list`、環境不足時の実行失敗を確認する。必須入力が揃った検証関数の正常終了も確認する。ブラウザー・Pionを起動する結合試験は今回の設定読み込み修正の必須確認にはしない。

## 確認結果

ルートの`tsc --project tsconfig.json`が成功し、Playwright設定と環境検証がNode型を使って型検査されることを確認した。`@types/node`は既存と同じ26.6.4をルートの直接依存へ追加し、ロックファイルの変更は依存宣言1行のみとなった。

`SINCRO_RTC_INTEGRATION_*`をすべて除去した環境で、Playwrightの`--list`が成功し、既存の1件を検出した。同じ環境で実行すると`globalSetup`が不足している3入力とGo実行コマンドを示して終了コード1を返し、ブラウザー起動へ進まないことを確認した。3入力が揃った検証関数の正常終了と、各入力を1つずつ除いた場合の拒否も確認した。

Biome、Markdown整形、タスク状態・索引の整合性、コメント点検を確認した。Go側と会話テスト本体は変更していない。VSCode画面上での確認と、実サービスを起動するブラウザー結合試験は実行していない。
