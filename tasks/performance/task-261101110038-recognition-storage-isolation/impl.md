# 認識記録の保存分離

## 実装判断

共有モデルのWorkerは認識結果と補正情報だけを返し、`RecognizerExecution`がモデルスレッドを解放した後に保存枠を待つ。保存サービスは予約中・待機中・実行中を合わせた32件・PCM 64MiBを上限とし、所有コピーは予約後に作る。受理済み保存は接続取消で捨てず、サービス終了時に回収して専用スレッドのS3クライアントを閉じる。

現行の累積音声には発話単体のサイズ上限がないため、単独で64MiBを超える保存要求は予約待ちを続けても受理できない。仕様レビューで承認された自律補完として、`audio_exceeds_capacity`の保存失敗を明示し、認識結果を返す。有限の保存枠を超える音声の分割保存や永続化保証は追加しない。枠の範囲内でも、保存が長く滞留すると当該接続の確定結果は受渡し待ちになる。

## 確認

- 認識パッケージ全体と関連WebSocket入口の対象試験は50件、補助事例7件が成功した。合成入口の4件は別担当の確認範囲として除外した。遅延保存中の返却と別接続の推論、件数・バイト上限、予約後コピー、取消、コピー失敗、保存失敗からの継続、終了時の回収順序、単一のOpus圧縮、単発の容量超過を確認した。
- Python型検査は実装ワークツリーのパッケージを優先する `--extra-search-path`を指定して成功した。変更ファイルのRuff整形・静的検査、設計文書のPrettier確認を実施した。既存の大文字モジュール名と既存試験の多重文脈管理に対する規則は対象静的検査で除外し、無関係なコードは変更していない。
- 通常の実行制限内では専用スレッドからイベントループへの通知が進まず、非同期試験が時間切れになった。同じ試験を制限外で実行し成功した。
- 一時のローカルS3互換受け口と一時ディレクトリへ、16kHz・1秒・440Hz・振幅5,000の人工音声と固定認識結果を保存した。実Opusは既存認識イメージの `opusenc`を一時コンテナで実行して生成した。ローカルとS3から取得したJSON 266バイト、Opus 6,636バイトが完全一致し、Opusの `OggS`ヘッダーとJSON内容を確認した。S3互換受け口の初回HTTP 500は保存領域の割当枠不足で、受け口の修正後に同じ保存処理が成功した。新しいイメージやモデルは作成・取得していない。一時コンテナは終了時に自動削除した。
