# 認識結果の返却と音声記録の保存を分離する

## 背景と目的

認識Workerは確定結果の返却前に、ローカルJSON・音声圧縮・S3保存を共有推論スレッド上で実行する。保存が遅いと当該発話の返答と他接続の認識が待つ。ローカルとS3の両方がOpusを使う場合は同じ音声をそれぞれ圧縮している。

利用者の発話終端や認識内容を変えず、この保存待ちを対話経路から分離する。

## 設計判断

- 推論と補正が完了した確定結果を、保存専用の有限キューへ受け渡した後に返却する。保存の成功は応答成功の条件から外し、保存失敗を独立した診断として残す。これは従来のローカル保存例外が応答を失敗させる挙動からの変更として明記する。
- 保存処理とS3クライアントはサービス所有とし、接続切断後も受理済み保存を回収する。推論スレッドはモデルだけを所有し、保存待ちで占有しない。接続固有クライアントを背景処理へ貸し出さない。
- 保存要求はCPU音声・結果・補正情報の独立した所有コピーを持つ。受信バッファの再利用やテンソル解放と競合させず、GPUテンソルは渡さない。Opusが必要な場合は一度だけ圧縮し、既存の保存先へ同じ生成物を使う。
- 保存キューは予約中・実行中も含む件数と音声バイト数で制限し、枠を予約してから所有コピーを作る。満杯時はモデルスレッドを解放した状態で受渡しを待ち、取消で待ちを解除する。受理前の取消は未保存として記録し、受理済みは接続取消で捨てない。予約後の失敗でも枠を解放する。無制限投入・黙った破棄・自動再試行を追加しない。
- 正常なサービス終了では新規受付を止めて受理済み処理を回収し、最後に保存クライアントを閉じる。強制終了時の永続保証は追加せず、既存のS3接続5秒・読取り30秒・1試行と圧縮30秒の上限を維持する。

## 完了条件

- [x] 保存を遅延させた条件で、キューに余裕があれば認識結果が保存完了前に返り、別接続の推論も進む。満杯時の待機はモデルスレッドを占有しない。
- [x] ローカル・S3の保存対象、形式、キー、確定時だけの記録を維持する。両方へのOpus保存で圧縮は一回となる。保存失敗と認識成功を区別して観測できる。
- [x] 受理前後の取消、接続終了、サービス終了、保存失敗で二重保存・使用後解放・受信配列の書換えによる音声破損が起きない。
- [x] 既存の `recognition_execution` が保存込み時間でなくなる影響を設計に記す。認識、保存の受渡し待ち、保存実行を別に計測し、過去ログと同じ意味の値として比較しない。

## 対象と同期先

[SpeechRecognizerNemoWorker](../../../sincromisor-server/speech-recognizer-nemo/src/speech_recognizer_nemo/SpeechRecognizerNemo/SpeechRecognizerNemoWorker.py)、`SpeechRecognizerS3Client.py`、`recognizer_execution.py`、`SpeechRecognizerNemoProcess.py`、既存の保存・取消試験を対象とする。

[認識設計](../../../documents/design/backend/services/speech-recognizer.md)へ所有者、保存の成功条件、満杯・取消・終了の扱いを反映する。WebSocketモデル、認識本文、辞書補正、発話終端は変更しない。保存先と資格情報は既存のProcess設定・サービス発見を引き継ぎ、新しい外部サービスを要求しない。

## 確認方法とリスク

遅い保存器と圧縮回数を数える偽物で結果返却・他接続の推論・受渡し上限・終了順序を確認する。人工音声を一時ディレクトリとローカルのS3互換受け口へ保存し、両方の内容と既存形式を確認する。対象Python試験と静的検査を行う。

保存責務と取消の生存期間を変える高リスク変更として、独立仕様レビューと実装評価を行う。キュー飽和時は返答待ちが残る限界を明記し、保存負荷を際限なく溜める解決にしない。

## 実行結果（2026-11-01）

保存をサービス所有の有限キュー・専用実行器へ分離し、モデルスレッド解放後に予約・コピー・受渡しを行う。予約中と実行中を含む上限、受理前後の取消、終了時回収、ローカルとS3でのOpus生成共有を実装した。単独で総容量を超える音声は永久待機せず保存失敗として記録し、認識結果を返す。

認識と関連入口の対象試験50件・補助事例7件、型検査・対象静的検査が成功した。人工PCMを実Opusへ変換し、ローカルと一時S3のJSON266byte・Opus6,636byteが完全一致した。独立評価はPASS。保存を含まない認識実行時間への意味変更、キュー満杯時の受渡し待ち、強制終了時の未保存保証なしを設計へ明記した。詳細は[実装・確認記録](impl.md)と[独立評価](eval.md)を参照する。
