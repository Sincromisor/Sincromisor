# 音声を欠落させず暫定認識の重複推論を減らす

## 背景と目的

現行は抽出器の差分音声を認識サービスで蓄積し、各暫定要求で発話先頭からエンコードする。共有モデルの推論は直列であり、実行が入力に追いつかないと、古い暫定認識の後ろで確定認識が待つ。発話を最後まで聞く動作を維持し、待機中の重複推論を減らす。

[既存の逐次認識調査](../../backend/task-261017195945-nemo-streaming-feasibility/task.md)は現行モデル・デコード方式のままの直接移行を非対応と判断している。本タスクはモデルを変更せず、Goからの認識要求の出し方だけを変える。

## 設計判断

- 一接続で認識へ送信済み・結果未受理の要求を1件に制限する。その間に届いた同じ発話の未送信差分を順序どおり結合し、結果受理後に最新の累積状態を認識できる次要求として送る。実行中のGPU処理を中断しない。
- 送信する音声は未送信差分だけとし、送信済み音声を再度結合しない。結合後の識別情報は末尾レコードの通番・確定状態を使い、同一セッション・発話・音声形式であることを検証する。
- 全Extractor入力の単調性検査と、実際にRecognizerへ送った要求の照合を分ける。未送信の通番について結果待ちを残さず、送信した要求には現行どおり1結果を要求する。
- 確定が届いたら、その発話の未送信音声をすべて含めて確定要求を送る。追加の間引きタイマーを置かない。発話境界を越えて結合・並べ替えず、次発話は別項目として受信順に保持する。
- 保留音声は世代が所有し、件数とバイト数を有限にする。既存送信上限を踏まえた上限を定義し、超過時は既存の異常通知・回復へ進む。黙って音声を削除して正常な確定結果を返す動作を追加しない。取消・再接続・送信失敗で待ちと照合状態を回収する。

## 完了条件

- [x] 認識が遅い人工条件で、推論要求数が減り、送信したPCMを連結した内容が元の全差分と完全に一致する。確定は発話ごとに一度で、次発話や旧世代が混ざらない。
- [x] 認識が追いつく条件では不要な待ちを足さず、暫定表示を継続する。送信済み要求だけを照合し、保持状態が完了・取消で解放される。
- [x] 既存の確定専用の固有名詞補正と、確定後だけのTextProcessor転送を維持する。固定日本語音声の確定認識が変更前と一致し、暫定表示の更新間隔と確定待ちを比較できる。
- [x] 推論回数、保留時間、既存の `queue_wait_ms` / `execution_ms` を区別する。認識器内部の待機だけでWebSocketの滞留が解消したとは判定しない。

## 対象と契約

[Go調停器](../../../sincromisor-server/sincro-rtc/internal/pipeline/runtime.go)、`conversation.go`、世代の終了処理と対応試験、[認識受信処理](../../../sincromisor-server/speech-recognizer-nemo/SpeechRecognizerNemoProcess.py)と既存受信バッファ試験を対象とする。

[音声パイプライン契約](../../../documents/design/contracts/audio-pipeline-websocket.md)、[RTC設計](../../../documents/design/backend/services/sincro-rtc.md)、[認識設計](../../../documents/design/backend/services/speech-recognizer.md)を同期する。スキーマは維持し、Go→Recognizerの通番がExtractorの一部を代表する意味を明記する。変更前のGo/Recognizerと変更後の組合せを固定データで確認し、互換性を失う場合は破壊的変更として同時更新する。

MediaPipeの判定周期、無音閾値、共有モデルの直列実行と候補再デコードは変更しない。

## 確認方法とリスク

遅い偽Recognizerで、暫定の連続到着、確定到着、連続する別発話、上限、取消、再接続を決定的に確認する。Goの対象試験はrace付きで行い、実受信処理へ結合差分を送り、既存NeMoで一つの固定日本語発話を比較する。

複数の状態機械と世代を扱う高リスク変更として、独立仕様レビューと実装評価を行う。低遅延のために音声の欠落、未確定での返答、過負荷の無言の隠蔽を許さない。

## 実行結果（2026-11-01）

未送信差分だけを結合する世代所有の保留と送信処理を実装した。全Extractor入力の検査と実送信済み1件の照合を分離し、上限超過は既存の異常通知・回復へ送る。確定時だけの補正・文章処理転送は維持した。

Goパイプライン全対象のrace試験、旧新Python受信処理へ通常/結合入力を送る互換試験、採用NeMoで25要求と2要求の最終PCM・確定本文一致を確認した。独立評価はPASS。推論単体の時間と待機・更新間隔は分け、冷始動を含む値から速度改善率を算出していない。詳細は[実装・確認記録](impl.md)と[独立評価](eval.md)を参照する。
