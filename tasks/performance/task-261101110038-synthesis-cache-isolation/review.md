# レビュー: task-261101110038-synthesis-cache-isolation

## 判定

APPROVED

## 理由・申し送り

- 現行ではS3命中時のRedis昇格と正常生成後の保存が配信・終端に先行する。正常WAVの検証とキャッシュ永続化の成功を分け、サービス所有の有限書込処理へ渡す設計はこの待機を除去できる。
- 満杯時に省略できるのは再生成可能なキャッシュ書込だけと明示され、途中失敗、取消、所有クライアント、Goの短音声と要求枠解放まで確認範囲に入る。読取失敗契約と通常のキャッシュ形式は維持され、期限は認識側に合わせた既存値を使う。予約中・実行中を含む上限とコピー・直列化前の枠予約も反映されている。

## 自律補完

- なし。通常の実装判断はタスクに示した根拠と確認方法に沿って具体化できる。

## 実行前の独立再確認

APPROVED。現行のS3命中時のRedis昇格と、生成後の正常終端前の保存は同期処理である。書込だけをサービス所有へ移し、接続読取・HTTP資源と共有しない方針は現行構造に対応する。

- 既存のS3昇格はWAV全体の検証より前に行われる。`AUTO_FIX`として「検証済み完成音声だけを保存する」を昇格にも適用し、逐次キャッシュの正常EOF後までRedis書戻しを延期する。不完全WAVをRedisへ昇格しない。
- 予約中・実行中を上限へ含め、保存用の追加コピー・直列化より前に予約する。予約後の例外で解放し、受理前取消と受理後の接続終了を区別する。単一ジョブの上限超過も固定理由で書込のみ省略する。
- 既存 `get_voice` の同期保存経路との関係を整理し、読取失敗の伝播、逐次キー、DTO、Redis期限を保つ。S3の接続5秒・読取30秒・総1試行は読取と書込の両クライアントへ明示する。
- 遅い書込器、失敗、上限、取消、終了の対象試験と、実Worker・Goの短音声結合、ローカルRedis/S3互換受け口への往復が必要である。正常終端と永続化の成功を区別する。
