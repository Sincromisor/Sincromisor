# 音声認識の待機と実行時間を分離して記録する

## 背景と目的

共有認識スレッドの待ち時間が見えず、recognition_processing の query_time は後続のローカル保存・S3転送を含まない。認識応答が遅い原因を推論だけと誤認し得る。

## 完了条件

- [x] 専用スレッドへ投入してから実行開始までと、保存を含む実行時間を分離する。
- [x] 成功・失敗を固定IDと時間だけで記録し、音声・認識本文・保存先を出さない。
- [x] 未開始取消を実行扱いせず、既存の直列実行・取消回収を維持する。

## 変更範囲

recognizer_execution.py の実行境界とテスト、SpeechRecognizer設計。推論方式・暫定結果の頻度・保存契約は維持する。

## 確認方法

固定時計と偽認識器で待機・実行・例外を確認し、既存の取消テストと対象のRuff・型検査を実行する。

## 実施結果

実行器の専用スレッド開始点で待機時間を確定し、Workerが保存まで戻る時間を別に計測するようにした。`recognition_execution` は待機・実行時間をミリ秒で記録し、既存の保存前までの秒数 `query_time` は維持する。本文や例外の自由文を追加せず、正常・失敗とも同じ診断項目を記録する。

固定時計による待機2000ms・実行3000ms、失敗時の再送出、未開始取消で記録しないこと、開始済み取消の回収とモデル設定復元を確認した。`test_recognizer_execution.py` と `test_receive_buffer.py` は計4件成功。対象のRuff・整形・型検査も成功した。試験途中の入力モデルに必須のstart_atが欠けていたため固定値を補い、再実行で成功した。

実行境界のコメントに保存前の既存計測との違いを追加し、単一スレッド所有・取消回収の説明を維持した。SpeechRecognizer設計へ単位・計測範囲・取消時の成功の意味を同期した。実GPU・実S3の所要時間は未計測であり、この変更自体は推論を高速化するものではない。
