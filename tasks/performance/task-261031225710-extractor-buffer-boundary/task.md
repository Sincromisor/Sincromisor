# 音声区間抽出の余分な入力待ちを解消する

## 背景と目的

`SpeechExtractorWorker.__get_audio_buffer` は最小長3200サンプルを超えるまで待つ。通常入力は16kHz・20ms・320サンプルなので、200ms揃った時点で処理できず220msまで待つ。無音600msの確定も3区間660msとなる。

## 完了条件

- [x] 3200サンプル到達時に分類へ渡し、次のフレームを待たない。
- [x] 途中フレームを失わず、次区間にも重複させない。
- [x] 既存の発話判定・先行音声・取消テストが成功する。

## 変更範囲と確認

入力バッファの境界比較とコメント、固定音声の回帰テストだけを変更する。SpeechExtractor設計へ判定単位を明記する。200ms未満へ短縮する調整や閾値変更、通信形式変更は含めない。

`uv run --no-sync pytest sincromisor-server/speech-extractor/tests` と対象のRuff・型検査で確認する。実モデルでの精度と端末からの応答時間は稼働環境がないため測定しない。

## 実施結果

3200サンプル到達時に返す条件へ修正した。修正前の境界テストは受信数11で失敗し、修正後は10フレームごとに順序どおり出力する。既存の可変長入力テストも新しい境界へ同期した。通常入力では判定区間220msから200ms、無音600ms設定の確定は660msから600msになる。これは入力サンプル数から決まる値で、実機総遅延の実測ではない。

`uv run --offline --no-sync --python .venv/bin/python pytest -q sincromisor-server/speech-extractor/tests` は7件成功。対象のRuffと整形、`ty check sincromisor-server/speech-extractor/src` は成功した。Ruffでは既存のPascalCaseモジュール名に対するN999だけをコマンド上で除外した。最初のパッケージ全体検査で見つけた対象外の既存PLR1711は変更していない。

コメントは最小長で返す理由を更新し、入力の所有・一度だけ結合する方針と先行音声の説明を維持した。設計索引から既存のSpeechExtractor設計へ辿れることを確認した。GPU・実音声・実端末の応答時間と精度は未確認。
