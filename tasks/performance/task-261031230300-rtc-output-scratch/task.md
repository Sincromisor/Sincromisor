# RTC出力フレームの反復確保を減らす

## 背景と目的

出力の nextFrame は無音中も20msごとに960サンプルの配列を確保する。セッション内の逐次符号化へ渡す一時音声なので、所有範囲を明記して再利用できる。

## 完了条件

- [x] 出力PCM作業配列をセッション内で再利用する。
- [x] 前回音声が無音や端数へ混入せず、口形・時刻・世代の既存テストが成功する。
- [x] 固定入力のベンチマークでフレーム配列の確保削減を確認する。

## 変更範囲

internal/media/output のフレーム生成・所有フィールド・試験。エンコーダーが保持するコピーと通信データの所有権は変更しない。

## 確認方法

変更前後の無音フレーム生成ベンチマーク、対象の go test -race・go vet を実行する。

## 実施結果

Processorが960サンプルの作業配列を所有し、nextFrameで全体を消去してから必要な音声を埋めるようにした。返却値は次回呼出しまでの借用であり、本番のwriteFrameがsendMuで同期符号化完了まで守る。エンコーダー内と通信境界のコピーは維持した。

`go test ./internal/media/output -run '^TestNextFrameClearsPreviousAudio$' -bench '^BenchmarkNextFrameSilence$' -benchmem -count=1` を変更前後に実行した。同じ環境の無音フレーム生成は、変更前465.7ns/op・2048B/op・1alloc/op、変更後38.29ns/op・0B/op・0alloc/opだった。毎秒50枠の配列確保をなくしたことを示す局所計測であり、会話全体の速度向上率ではない。

末尾の端数と次の無音への混入を新規テストで確認し、`go test -race ./internal/media/output` と同範囲の `go vet` も成功した。Pionのネットワーク生成を使う既存試験はサンドボックスの制約外で実行した。gofmtとタスク管理検査も成功した。

作業配列の所有・借用期間と消去理由をコメントに追加した。初期バッファ量・時刻・モーラ・通信契約は変えないため、設計変更はない。実機のCPU負荷と音声品質は未計測。
