# 逐次音声合成のS3命中をRedisへ昇格する

## 背景と目的

逐次配信の load_cached_voice はRedis未命中・S3命中でもRedisへ保存しない。通常の get_voice と異なり同じ音声を毎回S3から取得する。

## 完了条件

- [x] 検証済みのS3命中結果を既存のRedis書込みで保存する。
- [x] 二回目はRedisから取得し、S3取得を繰り返さない。
- [x] Redis書込み失敗でも取得済み音声を返し、取消時は追加書込みしない。

## 変更範囲

VoiceCacheManager.load_cached_voice と回帰テスト、VoiceSynthesizer設計。保存形式・キー・有効期限・通信形式は維持する。

## 確認方法

人工キャッシュで連続取得・Redis障害・取消・未命中を確認し、既存の逐次配信テストと対象のRuff・型検査を実行する。

## 実施結果

S3からモデルを復元した場合は既存のRedis書込みへ渡し、次回取得をRedisで完結させた。保存キー・7日間の有効期限・取得元診断を維持し、取消済みなら新たな書込みを始めない。Redis書込み失敗は既存の診断を出して取得済み音声を返す。

人工キャッシュを二回続けて取得し、S3は一回だけ、二回目の取得元はRedisになることを確認した。対象テスト `test_cache_promotion.py`、`test_streaming_audio.py`、`test_runtime_diagnostics.py` は43件成功。対象のRuff（既存命名のN999を除外）、整形・型検査も成功した。

昇格理由と書込み失敗時の扱いをコメントへ追加し、取消とキャッシュ所有の既存説明を維持した。設計索引から辿れるVoiceSynthesizer設計へ取得順序を追記した。実S3・Redisでの時間差は未計測。初回S3命中ではRedis書込みを一回追加するため、その所要時間は既存のキャッシュ操作ログで確認できる。
