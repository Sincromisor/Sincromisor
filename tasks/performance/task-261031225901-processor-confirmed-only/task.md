# 暫定認識による不要な履歴転送と保持を除く

## 背景と目的

Goの `recognizerLoop` は暫定認識にも会話履歴を複製してTextProcessorへ送信し、`conversation.requests` に保持する。Pythonは確定要求だけに応答するため、暫定要求は世代終了まで解放されない。長い会話ほど不要な通信・複製・保持が増える。

## 完了条件

- [x] 暫定認識は引き続き画面へ通知し、文章処理への要求と履歴複製を作らない。
- [x] 確定認識は従来どおり履歴へ追加し、一度だけ文章処理へ送る。
- [x] 暫定・確定の同じメッセージID、応答検証、終了・再接続を維持する。

## 変更範囲と確認

`internal/pipeline/runtime.go` の要求生成条件と関連テスト、TextProcessor設計を変更する。Pythonの確定要求のみ処理する実装とフロントのメッセージ更新を確認する。エンドポイント・送受信形式の変更はない。

対象パッケージの `go test -race`、`go vet`、整形を確認する。暫定要求を疑似的に処理していた既存テストを、実際のPython動作に沿った確認へ置き換える。

## 実施結果

暫定結果の画面通知直後に次の認識へ進み、確定結果だけで履歴複製・文章処理への送信・要求の照合用保持を行うようにした。3回の暫定と1回の確定で画面のメッセージIDを維持し、文章処理へ1要求だけ送り、保持中の要求も1件になることを確認した。従来は暫定回数分の履歴付き要求が応答されず残った。

`GOCACHE=/tmp/sincro-go-cache go test -race ./internal/pipeline/...` と同範囲の `go vet` は成功した。WebSocketを使う試験はサンドボックス内のローカル待受制約で実行できなかったため、同じ試験を制約外で実行した。変更ファイルはgofmt済み。

Pythonの `TextProcessorWorker.__process_requests` が確定要求だけを処理することを確認した。表示・認識の通信形式を変えず、既存の応答照合・再接続テストも通過した。コメントには暫定結果を表示で止める理由を追加し、確定履歴の所有説明を維持した。既存のTextProcessor設計を同期した。実GPU・LLM・ブラウザーでの総応答時間は未計測。
