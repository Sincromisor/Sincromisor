# 読み上げの自然さを保つ応答分割と無音配置にする

## 背景と目的

Mastra応答は句読点が届くまで保留され、各断片を別TTS要求として処理する。各要求に前後100msの無音を付けるため、細かな断片の境界には付加無音が重なる。一方、無条件に短く切ると語や数値の読み・韻律を壊す。意味のまとまりと自然な間を優先し、不要な断片化と無音の重複を減らす。

## 設計判断

- ユーザー発話の確定後だけ応答生成を始める現行境界を維持し、暫定認識による先行返答を追加しない。
- 現行の句読点分割を基準に、数字内の小数点、表情コード、読点だけの短い断片、句読点が遅い日本語回答を固定SSE入力で比較する。文字数や経過時間だけで単語途中を強制切断しない。
- 最初の自然な句は早く合成へ渡し、後続の短すぎる断片は次の自然な区切りまでまとめる。必要な保留上限と分割規則は固定例の読みと待ち時間を比較して決め、根拠を残す。内容や句読点を削除して速くしない。
- 同一 `speech_id` の先頭要求にだけ既存の前無音を付け、後続要求の重複した前無音を除く案を最小変更として比較する。末尾の既存後無音と句読点に由来する休止は維持し、一律に無音をゼロにしない。次発話・新接続では先頭判定を戻す。
- 先頭・後続の状態は合成接続が所有し、受理した要求の順序で更新する。現行キーは前後無音を含まないため、逐次合成のキー区分を更新して前後無音条件を含め、従来条件の音声を誤命中させない。旧キャッシュは削除せず、新経路から旧キーへの読取代替もしない。完全音声用の既存経路は維持する。
- SSE正常終端後だけ未完の末尾を配信し履歴を確定する。途中EOF、取消、生成失敗、送信失敗で保留断片を正常終了として出さない。

## 完了条件

- [x] 固定SSEの分割境界に依存せず、読み上げ本文の連結が元の可聴本文と一致する。小数・日本語の句・表情コードを壊さず、欠落・重複を生まない。
- [ ] 固定日本語文を実TTSで比較し、初回有声音までの時間と断片間の間を記録する。語の誤読、必要な休止の消失、音切れを生む案は時間だけ改善しても採用しない。
- [x] 同一回答の短い断片で不要な付加無音を減らし、次の回答では既存の先頭無音を保つ。キャッシュ命中時も同じ挙動になる。
- [x] 完了・異常・取消、連続発話の状態遷移と既存の履歴・表情・テロップ・口形同期を維持する。

## 対象と同期先

[mastra_worker](../../../sincromisor-server/text-processor/src/text_processor/mastra_worker.py)、[合成Worker](../../../sincromisor-server/voice-synthesizer/src/voice_synthesizer/VoiceSynthesizer/VoiceSynthesizerWorker.py)、`voice_stream.py` の逐次キャッシュ要求、`VoiceSynthesizerRequest`、既存の文章・モーラ・キャッシュ試験を対象とする。モデル、プロンプト、通信フィールド、発話終端の無音閾値は変更しない。

[TextProcessor設計](../../../documents/design/backend/services/text-processor.md)、[合成設計](../../../documents/design/backend/services/voice-synthesizer.md)を同期する。公開メッセージの意味を変える必要が生じた場合は、[音声パイプライン契約](../../../documents/design/contracts/audio-pipeline-websocket.md)と[フロントRTC契約](../../../documents/design/contracts/frontend-rtc.md)の生成側・利用側を同時に確認する。

## 確認方法と依存

固定SSEの分割・失敗試験、合成要求の無音設定とキャッシュキーの試験、実Engineでの短い日本語回答一例と句読点の少ない回答一例を確認する。口形はサンプル位置とモーラ総長で確認し、最後に同じ音声の聴取で間の自然さを比較する。

先頭区間と再生開始条件の整合、合成キャッシュ保存分離の完了後に実施する。それらによる待ちを文章分割の効果と混同しない。本文確定・合成状態・口形の境界を扱うため独立仕様レビューと実装評価を行う。

## 実行結果（2026-11-01）

小数・数値の桁区切りを保持し、先頭句はすぐ、後続の短い読点句は8文字以上の自然な区切りで合成へ渡すようにした。同一発話の後続要求だけ前無音を除き、後無音・句読点の休止を維持する。逐次キャッシュを無音条件付きの新しいキー区分へ分離し、旧キーの削除・読取代替や完全音声用経路の変更は行っていない。

対象Python207件、採用閾値の更新後の独立95件、型・静的検査・整形が成功した。固定実Engineの全断片でモーラ総長とPCMサンプル数が一致し、要求別到着列をRTCの本番再生処理へ通して全サンプル一致を確認した。短文は6要求から4要求、断片間の波形上の無音は約237〜269msから170〜175ms、再生完了は5,300msから4,720msとなった。初回有声音は420msから400msで、再バッファはどちらもなかった。数値の読みと句読点の少ない回答も確認し、12文字の候補は再バッファが出たため採用しなかった。

[比較記録](impl.md)と[独立評価](eval.md)に根拠を残した。設計文書2件を同期し、変更理解範囲のコメント点検も完了した。

実聴取だけは実行環境の能力上実施できず、比較WAVを提示してユーザーの判定を待っている。自然さ・誤読・休止不足・音切れを確認する受け入れ条件が未完了のため `blocked` とし、独立評価は現時点で `FAIL` とする。実装上の未解決不具合はない。聴取結果を受け、必要なら修正して再評価したうえで完了へ進める。
