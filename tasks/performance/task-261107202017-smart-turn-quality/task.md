# 発話終端の実音声比較と採用基準を整備する

## 背景と方針

サーバーSilero＋Smart Turnは設計上の第一候補であり、現行YAMNetより実音声品質が高いことは未確認。途中確定・語頭語尾欠落を速度より優先して比較する。

## 完了条件

- [x] 16kHzモノラルPCMとサンプル位置の注釈から、現行YAMNet方式と新方式を同じ音声で比較する再現手段を用意する。発話・途中の間・応答可能終端を扱う。
- [x] 途中確定、語頭語尾欠落、終端から確定までの音声上の時間と処理時間を分けて報告する。モデル・音声の識別情報を残し、未測定を0件にしない。
- [ ] 少数の利用許可済み日本語実音声（小声、息継ぎ、言いよどみ、短い返事、閾値前後の間）で実行し、現行方式との差と採否を記録する。同時接続時の入力処理停滞も実モデルで確認する。
- [x] 通常会話の軽量ゲート有効・無効による通信量・端末電力への影響は未測定なら明記し、負荷削減を実証済みとしない。

## 範囲と公開境界

評価用CLI・試験・一般的な評価手順を用意する。実音声や開発用環境の構成・履歴は公開しない。権利確認済みの音声と事前注釈がない場合は実音声条件を未完として保持し、実装済みと品質採用済みを区別する。既存task-261101110037-dialogue-endpoint-evaluationの未完条件を解消済みと扱わない。

## 実行結果と未完条件

同じWAVと事前注釈で旧YAMNet方式と新方式を比較するCLIを実装した。途中確定、話し途中の間、PCM欠落、未確定、音声上の終端遅延と逐次処理時間を分け、音声・注釈・モデルのハッシュを記録する。評価処理の12試験は成功した。人工無音で実モデルの読み込みとCLI実行も確認したが、この入力ではSmart Turnは起動せず、品質比較の証拠とはしない。実行方法は[サービスREADME](../../../sincromisor-server/speech-extractor/README.md#発話終端の比較評価)を参照する。

実モデルの2接続確認では、既知の発話開始状態だけを注入した後、各接続へ80個の20ms無音フレームを送り、各50回の実Silero推論が欠落なく25,600サンプルを処理した。実Smart Turnは各1回、確定は各1回であり、終端推論中もVADが進行した。これは合成PCMによる並行動作の機構確認であり、実会話負荷の上限や品質の測定ではない。

ユーザー回答により、評価用録音はまだない。利用許可済みの日本語録音とサンプル位置の事前注釈が揃うまで、実音声比較・採否判断を未完としてstatus=blockedにする。独立評価も比較手段の実装を確認した一方、実音声条件が未達のためタスク全体はFAILとした。録音入手後に同じ注釈で新旧比較を実行し、途中確定・欠落を優先して採否を記録する。

通信量・端末電力は未測定。ブラウザーの実機負荷削減や日本語音声の品質改善を実証済みとはしない。関連手順と変更理解範囲の日本語コメントを点検した。

[軽量ゲート復活の修正](../../frontend/task-261107222126-restore-lightweight-silence-gate/task.md)により、通常会話でも任意で無音化できる。実音声評価ではゲート有効・無効も比較し、小声・語頭語尾の欠落を確認する。通信量測定は録音入手に依存せず実施できるが、現時点では未測定のままである。
