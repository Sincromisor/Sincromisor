# 重要な通知をキャラクターに隠れない位置へ表示する

## 背景 / 目的

2026-10-24のUIレビュー指摘3。優先度は高。共通画面はチャットを `z-index: 2`、キャラクターを `3` に配置する。320px幅の `simple-vrm` で、機器・接続エラーがキャラクターに隠れ読めないことを再現した。原則§5・§8・§10に基づき、失敗と回復操作の視認性を演出より優先する。

## 完了条件（受け入れ条件）

- [ ] 重要なエラーと回復操作がキャラクター・背景・通常の会話に覆われず、320px幅でも全文と操作を確認できる。
- [ ] 起動前の失敗は起動前画面で確認できる。開いている設定・診断パネルに隠れる通知も、適切な表示先へ出す。
- [ ] 対応が必要な失敗は短時間で消さず、同じ通知を会話欄と専用領域に重複表示しない。
- [ ] 通知のためにキャラクター操作、設定、終了操作を不必要に遮らず、フォーカスを奪わない。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

重要な通知と会話演出の表示責務を分ける。最小の前面表示と必要な回復操作を使い、全面モーダル、常設の注意事項欄、説明を増やすだけの修正を避ける。既存の通知元・状態を再利用し、汎用通知基盤の新設を目的にしない。

原因の分類と再試行状態は[指摘2](../task-261024223620-recover-media-startup-failure/task.md)、会話を読み返す操作は[指摘5](../task-261024223621-make-conversation-history-readable/task.md)が担当する。本タスクは重要な情報の配置と可読性を担当し、現行エラーでも確認できる。通信形式は変更しない。

## 確認方法

Playwright CLIで機器取得失敗と接続設定取得失敗を表示する。320px幅と通常のデスクトップ幅、設定パネルの開閉時、文字拡大時に通知と回復操作が欠けないことを確認する。文字とキャラクターが重なる再現条件を含める。状態・通知の分岐を変更する場合だけ、その重複表示や解除の回帰テストを加える。対象の静的検査と型確認を行う。
