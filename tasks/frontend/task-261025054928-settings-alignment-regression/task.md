# 設定画面の整列をPlaywrightで回帰確認する

## 背景 / 目的

以前の配置確認は上下位置と到達性を扱い、左右端や操作の高さを検査していない。現在のカテゴリで繰り返し実行できる確認を通常のUIテストへ置く。

## 完了条件（受け入れ条件）

- [x] Playwrightテストに概要・詳細・基本設定の外枠と内側左端、角丸、操作の整列を検査する。
- [x] 広幅・狭幅、短い本文・長い本文、案内や接続状態の変化でも整列と到達性を確認する。
- [x] 共通3ページで設定表示を確認し、画像を目視して余白・優先順位の不備がないことを確認する。
- [x] 再実行コマンドと結果を記録し、不備があれば修正または追加タスクを実行してから完了する。

## 変更範囲と設計判断

tests/uiと設定設計の確認手順を対象とする。機器とバックエンドは模擬または未接続で扱い、実通信の成功を完了条件に加えない。過去の完了タスクは当時の記録として保持する。

[設定UI設計](../../../documents/design/frontend/setting-and-debug-ui/settings-design.md)を配置仕様の参照先とする。枠の外寸は共通の親で揃え、スクロールは枠内へ置く。既存の固定操作と機器制御の意味を維持する。

## 確認方法

新しい配置テストと既存focus.spec.tsを実行し、playwright-cliのスクリーンショットを目視する。画像はwork/private-artifacts/settings-alignment-261025/へ保存する。

## 設計文書の同期

設定UI設計に責務と確認方法をまとめ、共通枠組みから参照する。通信契約と保存形式への変更はない。

## 実装と確認結果

[配置テスト](../../../sincromisor-frontend/tests/ui/settingsAlignment.spec.ts)と[座標確認](../../../sincromisor-frontend/tests/ui/settingsLayoutAssertions.ts)を通常のUIテストへ追加した。枠の左右端、内容左端、角丸、画面内への収まり、固定操作位置、開始理由との関連付けと移動導線を確認する。

初回確認では３ページの基本設定で操作欄が動くことと、長い接続状態で画面下へはみ出すことを検出した。[追加修正](../task-261025055639-settings-fixed-footer-height/task.md)を起票・実行した。途中で試験側のLooking GlassカテゴリIDの誤りを訂正し、最終の配置テスト12件が30.6秒でPASSした。修正後の既存フォーカステスト１件もPASSした。
