# 実装記録

## 判断

音声取得の失敗は体験全体の停止と分け、アプリのライフサイクル所有者が分類済み状態と再試行可否を保持する。通常画面・設定欄の回復操作は音声だけに接続し、稼働中のカメラ・較正・開始フック・設定・モデルを維持する。権限変更と機器接続は画面内で代行できないため、その失敗時だけ短い案内を表示する。例外本文は既存の診断へ残し、初回取得エラーを会話・重要通知へ重複追加しない。

診断表示の初期同期は既存の音声調整結線へ集約し、音声入力制御を300行以内に維持した。通知の位置は既存のヘッダー計測値を再利用し、回復案内による高さ変更でも再試行と終了操作を覆わない。

初回の全体ゲートでは、RTC停止後の「会話を開始」まで音声だけの再試行へ振り分けたため、較正の既存回帰3件が失敗した。稼働中の音声失敗だけを振り分け、RTC停止後の開始は従来の再開始へ戻した。通常画面から音声だけを明示再試行する場合には、追跡を再実行せず接続表示を実行状態へ戻す。

## 確認と未実行範囲

- 既存の終了・較正・アプリ制御を含む対象18件に合格。権限拒否・機器不在・その他の失敗、再試行連打、設定とカメラ維持、終了後の旧成功・旧失敗の無効化、取得受理直後の終了を確認した。
- Playwright CLIと専用Chromeの模擬機器で、本番の取得・音声処理・RTCセッション開始経路を通した。初回は音声取得境界だけで拒否を返し、次回はブラウザーの実取得へ戻した。3連打でも追加音声取得は1回、カメラ再取得は0回、成功からのRTC開始は1回だった。設定・VRMは維持された。
- 同じブラウザーで終了した取得の後着成功も解放し、新世代だけが接続へ進むことを確認。全6生トラックが終了した。追跡は本番Worker経路を使った。
- 320px幅の回復操作と、別の重要通知との同時表示を確認した。ヘッダー下端186pxに対し通知上端202pxとなり、ボタン中心の `elementFromPoint`と実際の終了操作でも被覆がないことを確認した。文書・コメントを変更理解範囲まで点検した。
- 最終の全体ゲートに合格（テスト728件合格、既存3件スキップ）。コミット前のステージ済み差分への構造検査も合格し、新規の構造例外は追加していない。
- 実機の権限画面・機器表示と実バックエンドの接続成功は未確認。RTC設定は固定データ、Offer先は失敗応答の模擬とし、接続開始までの検証と区別した。
