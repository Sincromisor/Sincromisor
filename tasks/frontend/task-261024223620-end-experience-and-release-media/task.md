# 機器の使用状態と体験を終了する操作を通常画面に設ける

## 背景 / 目的

2026-10-24のUIレビュー指摘1。優先度は高。停止操作が設定・診断パネルの内側にあり、通常画面では機器使用状態を確認しにくい。アプリの `stop()` はRTCだけを停止し、元のマイク入力・音声処理・カメラ追跡を終了しない。体験の終了と機器使用の停止を通常画面から行えるようにする。原則§3・§9・§10が根拠。

確認基点は `d5eb90b4c0a546f37b459bfec871f767a71cb9d7`。機器解放の不足はコードで確認し、実機の停止表示は未確認。

## 完了条件（受け入れ条件）

- [x] 通常画面でマイク・カメラの実際の使用状態と終了操作を確認でき、設定や開発者ツールを開かずマウス・タッチ・キーボードから終了できる。
- [x] 終了によりRTC送受信、元の音声入力と加工済みトラック、音声処理、追跡用カメラと推論処理、実行中の較正を終了する。表示だけを未接続へ変えない。
- [x] 機器取得・切り替え・追跡初期化が未完了でも終了でき、後着した結果は解放される。設定購読による再取得も休止し、終了後に送信・機器取得・追跡が自動再開しない。
- [x] 終了の重複操作が安全で、明示的に再開始した場合だけ新しい体験が始まる。設定・選択モデルは保持する。
- [x] RTCだけの停止が必要な診断・再接続用途を維持し、全体終了との違いを操作名と配置で区別する。通常の終了に確認ダイアログを挟まない。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

複数の資源所有者と非同期処理の生存期間を扱う高リスク変更として独立レビュー・評価を行う。アプリ制御が体験の開始・終了世代を所有し、各所有者へ終了を委譲する。音声トラックは `UserMediaManager`、音声処理は既存の処理器、追跡はカメラ制御と追跡実行時、RTCは既存クライアントが解放する。画面から直接トラックを操作しない。

RTCだけを止める既存内部操作の意味は維持し、全体終了を区別して追加する。「停止しても機器は動く」という説明だけで対応しない。サーバー通信形式、ブラウザー権限の撤回、保存設定の削除、Looking Glass表示の独立した開始停止は対象外。

## 確認方法

- 所有者間の結合テストで稼働中の終了、取得完了前の終了、終了後の遅延成功、重複終了、明示的再開始を確認する。元の音声と加工済み音声、カメラ、追跡、RTCの解放と再開抑止を観測する。
- Playwright CLIで終了導線とキーボード操作を確認する。320px幅でも状態と終了操作が欠けないことを確認する。
- 開発環境のブラウザーで本番の機器取得経路を一度通し、終了時のトラック終了と機器使用表示、明示的再開始を確認する。実機が使えない場合は模擬確認と区別して残リスクを記録する。
- 実装時は高リスク変更に対応する全体ゲートと独立評価を行う。
