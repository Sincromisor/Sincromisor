# 通常会話で任意の軽量無音ゲートを利用できるようにする

## 背景と方針

サーバーへの発話終端判断の集約に伴い、通常会話のフロントVADゲートも一律無効にしたが、ユーザーは通信量節約のため無音化を残す方針へ修正した。サーバーのSileroとSmart Turnは維持し、通常会話では任意の軽量ゲート、音声診断では従来の調整可能なVADを使う。既定値は無効を維持する。

## 完了条件

- [x] chat/sincroで「無音時の送信を抑える」を操作でき、保存済みのenableVadGateを適用する。既定値はfalseとする。
- [x] 通常会話はAudioWorklet内の軽量な振幅判定で明らかに小さい入力だけを無音化する。診断用の強い閾値・learned・厳格設定を持ち込まず、学習WorkerとPCM転送を停止したままにする。
- [x] 入力ブロックを判定してから出力し、音が戻ったブロックをメインスレッド通知待ちで削らない。閉じるまでの保持時間をサンプル数で計測し、無音化時も同じ長さのゼロPCMを出して時間軸を保つ。ゲート無効時は追加遅延なく通す。
- [x] 診断モードとの切替、停止・再取得、ゲート解除で状態が漏れない。明示ミュート・視線ミュート・フィルターは維持する。
- [x] 設定と診断UI、関連設計を同期し、小声の欠落リスクと実通信量・端末電力の未測定を明記する。

## 実装判断と確認

既存の診断用RMS閾値下限0.001と同じ振幅を、通常会話では全入力サンプルの絶対値へ適用する。どれかが閾値以上なら入力を通し、連続して閾値未満の場合だけ閉じる。閉じるまでの保持は既存の学習VAD標準値と同じ180msを初期値とする。実音声で最適化した値ではなく、ゲートは任意・既定無効とする。新規モデル・依存・ネットワーク契約は追加しない。

対象はフロントのメディア処理・設定・診断と設計文書に限定する。実Workletを読み込むPCM試験、保存設定とモード遷移、UIの対象Vitest、型ビルド、変更ファイルの静的検査・整形・構造検査で確認する。録音未入手の実音声品質と実端末の通信量・電力はこの修正の実装成功と区別し、既存の品質評価タスクに残す。

## 実行結果

通常会話にもゲート設定を表示し、保存済みの選択を適用した。AudioWorklet内で全チャンネルの入力を先に確認し、閉じるまでの180ms保持、ブロック単位の即時開放、同じ長さのゼロPCM出力を実装した。診断の許可をdiagnosticVadEnabledとして軽量ゲートと分け、診断用の強い閾値・厳格設定・学習Workerを通常会話へ適用しない。Workletの学習用PCM転送も初期状態から停止する。

対象Vitestは10ファイル37試験が成功した。実WorkletのPCM確認では44.1kHzと48kHzでの保持時間、末尾サンプルで音が戻るブロックの保持、片側チャンネルの音声、ゲート解除、再有効化と転送停止を確認した。保存設定・会話モード遷移・Worker停止と再取得、通常会話での設定表示も確認した。TypeScriptとViteビルド、変更ファイルのBiome・Markdown整形、構造検査が成功した。Biomeの既存の複雑度警告2件、既存の構造例外とビルドのチャンクサイズ警告は悪化させていない。

関連設計を更新し、設計索引からの導線を確認した。コメント点検: PASS。独立レビューや配備を伴わないフロントの局所修正として、現在のワークツリーで実装と対象確認を行った。

ブラウザー実操作、実音声品質、実通信量・端末電力は未測定。閾値未満の小声を消す可能性は残り、既定無効と設定画面の説明を維持した。未完の品質評価タスクへゲート有効・無効の比較条件を反映し、品質改善や通信量削減を実証済みとは扱わない。
