# 設定の自動保存失敗を検知して保存を再試行できるようにする

## 背景 / 目的

2026-10-24のUIレビュー指摘8。優先度は中。保存例外はログへ出すだけで、画面は「設定はこのブラウザーに自動で保存されます」と表示し続ける。現在の設定が動いていても、再読込で失われることに気づけない。原則§4・§5・§6に基づき、適用と保存を区別し、保存失敗から回復できるようにする。

## 完了条件（受け入れ条件）

- [ ] 通常設定と同じ保存文書を使う調整の書き込み失敗を検知し、操作中の画面で未保存の状態を確認できる。起動前と開始後で状態が食い違わない。
- [ ] 失敗後も現在の設定と入力を保持し、保存成功と誤表示しない。失敗を短時間の通知だけで済ませない。
- [ ] 保存可能になった後に再試行すると、最新の設定文書を保存し、成功後に失敗表示が解消する。再読込でその値を復元できる。
- [ ] 全設定初期化で保存を停止した場合は、保存の再試行が削除済み設定を復活させない。
- [ ] 正常時に説明段落や成功通知を常時増やさず、必要時の短い状態と再試行操作で判断できる。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

保存所有者が結果を保持・通知し、UIは既存購読へ統合して表示する。現在の適用値とブラウザーへ保存した値を区別し、失敗後の再試行は最新文書に対して行う。通常設定と音声・視線・姿勢調整が同じ保存文書を使うことを維持する。

保存形式・キー・復元優先順位、全設定初期化の保存停止契約は変更しない。同期ストレージに不要な進捗表示、常時の「保存しました」、汎用再送基盤は追加しない。VRMのCache Storage保存は対象外。

## 確認方法

ストレージの書き込み例外を再現し、現在値保持、失敗通知、最新値の再試行成功、復元を対象テストで確認する。初期化後の保存停止が再試行でも守られることを確認する。Playwright CLIで起動前・開始後の失敗表示と操作を確認し、正常時に文言が増えていないことを見る。対象の静的検査と型確認を行う。
