# 設定画面の整列と操作配置の設計を定める

## 背景 / 目的

設定の本文・操作欄の幅、内側余白、角丸と起動前操作の高さが揃わない。調査では基本設定の枠幅に15px、1300px幅の詳しい設定に71pxの差があり、過去の確認は左右端の一致を扱っていなかった。ユーザーの根本修正要求に基づき、後続実装の共通基準を定める。

## 完了条件（受け入れ条件）

- [x] 設定UI設計に、起動前の概要・詳細と基本設定の共通基準線、枠、余白、スクロールの責務を記す。
- [x] トップへの移動と概要・詳細切替と開始の配置、狭幅・案内文表示時の整列を定める。
- [x] 左右端・操作位置の寸法確認と画面確認を変更時の確認へ追加し、設計索引から辿れる。

## 変更範囲と設計判断

既存の設定UI設計を更新する。通信・設定値・機器制御は変更しない。

[設定UI設計](../../../documents/design/frontend/setting-and-debug-ui/settings-design.md)を配置仕様の参照先とする。枠の外寸は共通の親で揃え、スクロールは枠内へ置く。既存の固定操作と機器制御の意味を維持する。

## 確認方法

Markdown整形と相対リンク、既存のUI原則・外枠契約との一致を確認する。

## 設計文書の同期

設定UI設計に責務と確認方法をまとめ、共通枠組みから参照する。通信契約と保存形式への変更はない。

## 実装と確認結果

設定UI設計へ共通の基準線、20px／狭幅16pxの余白、12pxの角丸、スクロール境界と起動前操作の配置を定めた。後続３タスクを起票し、実装・回帰確認を依存順に進める。Markdown整形と相対リンク、設計索引から設定設計への導線を確認した。本文だけがスクロールし主要操作は固定される既存契約を維持する。
