# 設定UIのタブ配置・スクロール・入力操作の不具合を修正する

## 背景 / 目的

設定UIの現状調査に基づき、カテゴリ切替と入力操作を安定させる。ユーザーから指摘されたタブのガタつき、および2026-10-10に `924d3462` の開発画面で再現した以下の不具合を対象とする。

| 対象                       | 再現結果                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| 常設設定、画面幅520px      | 「接続」だけが2段目へ折り返す。幅490pxではカテゴリ選択欄に切り替わる                         |
| 起動前設定、画面幅390px    | 5タブが縦積みになり、約215pxを占める                                                         |
| 起動前設定、1440×900       | カテゴリ切替でフッター上端が約572〜719pxの間を移動する                                       |
| 起動前設定、1100×900以下   | 「表示」の開始操作が画面下へ出て、ダイアログ全体のスクロールが必要になる                     |
| 共通タブ                   | 「会話」にフォーカスして右矢印を押すと「デバイス」が選択されるが、フォーカスは「会話」に残る |
| 表示設定のスライダー       | 表示は上半身72%、姿勢・目線68%だが、DOMの入力値は全て0.7になる                               |
| タイトル・モード・機器選択 | 見えるラベルが入力と関連付けられていない                                                     |

調査は `simple-vrm` の起動前と常設設定を対象に実施した。常設設定は機器を起動せずダイアログを閉じて確認しており、会話中の反映は未確認。バックエンド未接続による設定取得失敗は本タスクの不具合に含めない。

## 完了条件（受け入れ条件）

- [x] 起動前と常設設定で、タブを複数段や縦積みにしない。横一列に収まらない幅ではカテゴリ選択欄へ切り替わり、全カテゴリを選択できる。
- [x] カテゴリ切替でヘッダー・カテゴリ操作・主要操作の位置が動かず、長い本文だけをスクロールできる。開始ボタンと閉じる操作を見失わず、項目・初期化操作が切り落とされない。
- [x] 矢印キーとHome/Endで選択したタブへフォーカスが移り、Tabで表示中の内容へ進める。狭幅のカテゴリ選択にも名前があり、内容との関係を読み取れる。
- [x] タイトル・モード・機器選択・スライダーの入力に項目名が関連付けられ、説明ボタンの名前から対象項目を識別できる。
- [x] 動作量3項目の表示値、DOM値、設定ストア値が一致する。初期値0.72/0.68と保存済み値を未操作のまま丸めず、操作後と再読込後も一致する。
- [x] 共通部品を使う3ページの設定表示と、診断コンソールのタブ操作を壊さない。

## 設計判断

起動前と常設の幅判定は同じレイアウト方針に揃える。具体的な閾値は表示領域とラベル幅に合わせて実装時に決め、後続の分類変更でも多段化しない構成にする。表示枠の高さとスクロール所有者を整理し、入れ子の自動行サイズで主要操作が押し動かされる状態を解消する。

スライダーのUI刻みと設定モデルの正規化を一緒に確認する。既定値や保存値を70%へ変えることで帳尻を合わせない。既存の保存形式・範囲・通常設定と診断調整の優先関係を維持し、一致する刻み・入力方式を実装者が選ぶ。

## スコープ境界

共通設定の配置、キーボード操作、ラベル、数値入力の整合性を対象とする。分類の変更と意匠全体の刷新は[後続タスク](../task-261010185549-reorganize-settings-and-startup/task.md)へ分ける。通信契約、追跡処理、初期化で削除するデータの範囲は変更しない。
