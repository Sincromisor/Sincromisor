# 起動失敗を画面へ表示して回復操作を用意する

## 背景・目的

bootstrapSincroPageAppShellは操作パネルの読込・配置・初期化失敗をログへ記録するだけである。2026-11-14のChrome確認では操作パネルモジュールの要求を失敗させると、sincroPageRootが空のままになった。利用者が失敗を把握し、回復できる入口を用意する。

## 完了条件

- [x] 操作パネルの動的読込失敗、Reactの未処理描画失敗、ページ初期化失敗を、画面上で起動失敗として示す。利用者向け表示に例外全文を露出しない。
- [x] 「再読み込み」と「トップへ戻る」をキーボードでも操作できる。読み込めなかったモジュール自体へ失敗表示を依存させない。
- [x] 共通ログを維持し、失敗後に開始操作を受理したり、同一ページ内で初期化を重複実行したりしない。
- [x] 部分的に作成済みのアプリがある場合は既存の解除・終了処理へ接続し、入力機器や購読を失敗画面の背後で新たに起動しない。正常な起動には影響しない。

## 設計判断・範囲

回復は利用者によるページ再読込を基本とし、同一Reactルートや部分初期化オブジェクトの複雑な再利用は追加しない。アプリが未生成の段階でも表示できる最小の失敗表示を起動処理が所有する。モデルファイルの個別読込失敗、RTC再接続の案内は対象外とする。

## 主な変更箇所

[共通起動処理](../../../sincromisor-frontend/src/app/shell/bootstrapSincroPageAppShell.tsx)、必要に応じて共通の失敗表示・CSS、[ブラウザー起動試験](../../../sincromisor-frontend/tests/vrm/bootstrap.spec.ts)。

## 確認方法

loadControlPanelの拒否、描画例外、initializePageの例外を発生させ、失敗表示と重複開始抑止を確認する。Chromeで操作パネル要求を失敗させ、空画面にならず回復操作ができることを確認する。再読み込み後の正常起動も既存の起動試験で確認する。

## 文書同期

[共通枠組み](../../../documents/design/frontend/app-shell.md)と[設定UI設計](../../../documents/design/frontend/setting-and-debug-ui/settings-design.md)の該当する責務・挙動を同期する。外部RTC契約は変更しない。

## 実装・確認結果

共通起動処理が読込・描画・初期化の失敗を一度だけ受け取り、部分アプリの購読解除と機器終了後に回復画面を表示する。回復表示はネイティブDOMで配置し、失敗した操作パネルやReact描画へ依存しない。配置領域へ起動済み状態を保持し、同一ページで初期化を重ねない。

Chrome起動試験6件、型検査、対象Biome、変更Markdown、タスク整合性確認が成功した。動的読込拒否、React描画例外、初期化例外を注入し、例外全文を出さない表示、部分アプリの解除・終了、開始拒否、重複起動抑止、キーボードでの再読込・トップ移動、再読込後の正常起動を確認した。共通枠組み・設定UI設計を同期した。コメント点検: PASS。

指定Node/npm版では未確認。既存環境で確認し、機器取得は試験で置き換えた。
