# タイトル入力中の空欄を既定値で上書きしない

## 背景 / 目的

2026-10-24のUIレビュー指摘9。優先度は中。タイトルを全消去すると即座に `Sincromisor` が再入力され、削除して書き直す操作を妨げることを実画面で再現した。原則§4に基づき、入力途中を保持する。

## 完了条件（受け入れ条件）

- [x] タイトルを全消去した状態から、そのまま新しい文字を入力できる。再描画で空欄を既定値へ戻さない。
- [x] 日本語の変換中、貼り付け、全選択置換を妨げず、入力位置を不用意に移動しない。
- [x] 起動前と開始後で同じ編集動作になる。編集確定・カテゴリ移動後の表示と保存値が一貫する。
- [x] タイトルが空のときに画面タイトルを `Sincromisor` とする既存の表示上の保証を保つ。入力欄の空欄許容と表示側の補完を分ける。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

入力中の文字列と表示用タイトルを区別する最小の修正を選ぶ。入力確定時に補正する方式でも、表示側だけ補完する方式でもよいが、利用者の入力を途中で上書きしない。「空欄にできません」等の新しい説明やエラーで既存挙動を正当化しない。

タイトル編集・反映・保存に必要な範囲だけを変更し、他の設定の反映方法や汎用フォーム管理を追加しない。外部設定APIや保存形式の変更は不要。
