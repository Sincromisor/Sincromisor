# 開始時の架空の会話と固定音声案内を取り除く

## 背景 / 目的

2026-10-24のUIレビュー指摘10。優先度は中。開始時に利用者の「こんにちは!」、キャラクターの「こんにちは～!」、固定音声名の案内を会話履歴へ追加する。機器取得失敗時にも表示され、発話していない内容が認識・応答されたように見える。原則§5・§9・§10に基づき、履歴を実際の会話に一致させる。

## 完了条件（受け入れ条件）

- [ ] 開始処理だけでは利用者の発話・キャラクターの返答を履歴へ作らない。機器取得失敗時にも架空の会話が現れない。
- [ ] 実際の音声設定に基づかない固定音声名の開始案内を除く。代わりの説明メッセージを自動追加しない。
- [ ] 実際に受信する会話、エラー、必要な音声素材の出典表示は維持する。音声診断の既存の固有情報を削除しない。
- [ ] 再開始しても架空の会話が追加されず、シーン開始・ダイアログ開閉・モデルアイコン更新を維持する。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

本番の開始経路から架空の会話生成を削除する最小の変更とする。「これは会話例です」という注意書きや、常設の空状態説明に置き換えない。会話例が検証用に必要なら既存テストの固定データへ置き、本番に残さない。

固定音声名の削除前に素材の必要な出典表示との関係を確認し、出典が必要なら該当素材・音声情報の適切な表示先で実際の値を使う。新しい音声設定取得APIは追加しない。サーバー発話、トップの体験紹介、診断の既定素材の案内は対象外。

## 確認方法

既存の初期化テストで開始・再開始・取得失敗時に架空のメッセージを書かないことを確認する。Playwright CLIで開始直後の履歴を確認し、既存の受信メッセージ表示のテストを実行する。対象の静的検査と型確認を行う。

## 文書同期
