# 基本設定のカテゴリ切替で固定操作欄が動く不具合を修正する

## 背景 / 目的

設定整列の回帰テストで、基本設定の体験からキャラクターへの切り替えにより操作欄上端が約48px移動することを再現した。中間の配置要素が内容の高さへ縮み、旧CSSがパネル全体のスクロールを強制している。固定操作を維持する既存契約と今回の根本修正要求に基づき、追加で修正する。

## 完了条件（受け入れ条件）

- [x] 共通３ページの全カテゴリで、ヘッダー・分類・操作欄の位置が変わらない。
- [x] 本文だけがスクロールし、長い本文の末尾と固定された開始停止・閉じる操作へ到達できる。
- [x] 通知や長い接続状態がある場合も画面内に収まり、既存の左右端・内側余白の整列を保つ。

## 変更範囲と設計判断

共通画面の中間配置要素と設定外枠の高さの受け渡しを整理し、旧パネル全体スクロールの指定を削除する。通信・機器制御は変更しない。高さの制約は外枠が所有し、内容量から固定操作の位置を決めない。

## 確認方法

作成中の `settingsAlignment.spec.ts` で３ページの全カテゴリと長い接続状態を確認する。既存 `focus.spec.ts` で設定と診断の開閉を確認し、Playwright画像を目視する。変更CSSを解析し通常ビルドを行う。画像は `work/private-artifacts/settings-alignment-261025/` に保存する。

## 設計文書の同期

共通枠組みに高さ制約を中間要素から本文まで維持する責務を記す。設定UI設計の固定操作契約は維持する。

## 実装と確認結果

２つの中間要素を高さ制約を伝えるグリッドにし、パネル全体の高さ・スクロールを強制する旧指定を削除した。変更前に３ページともカテゴリ切替で約48pxの移動を再現し、長い接続状態では操作欄が740px画面の下へ32px出ることも検出した。修正後は `settingsAlignment.spec.ts` の12件がPASSし、３ページの全カテゴリで固定操作位置を維持した。修正後の既存フォーカステストもPASSした。

320×740の重要通知表示をplaywright-cliで別途確認し、本文をスクロールでき、操作欄下端は712pxで画面内に収まった。最終画像を目視し、CSS構文解析と通常ビルドも成功した。共通枠組みの高さ責務を同期し、コメントを点検した。実通信と機器取得は行っていない。
