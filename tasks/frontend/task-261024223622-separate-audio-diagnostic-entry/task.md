# 通常体験の選択と音声診断の導線を分ける

## 背景 / 目的

2026-10-24のUIレビュー指摘11。優先度は低。トップと開始設定は通常の2体験と音声診断2モードを同じ優先度の4択で示す。初回利用者にも診断用途の選別を求めるため、原則§1・§2に基づき主目的の選択を簡潔にする。

## 完了条件（受け入れ条件）

- [x] トップと共通の体験選択で「キャラクターと話す／キャラクターになる」が主要な選択として分かる。診断2モードは必要なときに開ける、名前の明確な補助導線へまとめる。
- [x] 診断も通常の画面操作とキーボードで発見・選択できる。内部URLの知識を必須にしない。
- [x] 保存値やURLで `echo` / `playback` が指定された場合、現在の選択が見え、通常体験へ勝手に変更されない。通常と診断の選択が同時に有効に見えない。
- [x] 4種類の内部値、URL引継ぎ、保存・復元、RTCへの反映時点を維持する。診断の安全上必要な注意・素材の出典だけは該当モードで確認できる。
- [x] 通常体験の言い直し、分類を説明する長文、診断を選ぶ前の確認ダイアログは追加しない。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

分類・配置・開閉状態で主従を付ける。新しい管理者モードや権限は作らず、補助導線の短い名前で診断へ到達できるようにする。表示方式の詳細は既存の入力部品を活用して決める。最近削除した冗長な補助ラベルを戻さない。

トップ、起動前概要・詳細、開始後設定の選択表示が対象。音声診断機能の削除、内部モードの改名、URL・保存形式・通信契約の変更は対象外。
