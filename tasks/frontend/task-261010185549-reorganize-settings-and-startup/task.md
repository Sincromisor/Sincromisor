# 設定項目を利用目的別に再編し起動前の導線を整理する

## 背景 / 目的

ユーザーが求める分類と粒度の統一に対応する。現状は「表示」にモデル・追跡・動作量・自動ミュート・デバッグ用強制設定が集中し、「会話」はタイトルとモードだけになっている。初期画面でモデル選択が見つけにくく、「接続」は診断値の下に主要操作がある。

2026-10-10、`924d3462` の共通分類、起動前・常設設定、診断カードの実装を確認した。関連する従来の設定UI整備・保存タスクは完了済みであり、本タスクは現在のUIを利用目的別に再編する。先行する[配置・入力修正](../task-261010185542-fix-settings-layout-and-controls/task.md)の共通部品を使う。

- [x] 起動前の最初の画面で体験、現在のキャラクター、必要なマイク・カメラを確認・選択して開始できる。細かい調整は「詳しい設定」から開き、元の開始画面へ戻れる。

## 設計判断

| 分類         | 所属する項目                                                                               |
| ------------ | ------------------------------------------------------------------------------------------ |
| 体験         | 会話モードとその説明                                                                       |
| キャラクター | VRMモデル、3D表示、会話時の上半身モーション量                                              |
| マイク・音声 | マイク選択、機器一覧更新、音声補正、無音時の送信、会場向け調整、自動ミュート               |
| カメラ・動き | カメラ選択、機器一覧更新、顔・姿勢の追跡、姿勢同期量、目線追跡量、初期調整、カメラ品質案内 |
| 画面・保存   | 画面タイトル、保存の説明、全設定初期化                                                     |

通常設定の全項目は[既存項目一覧](../../../documents/design/frontend/setting-and-debug-ui/settings-items.md)を照合元とする。保存は既存の自動保存を維持し、保存ボタンや新しい保存形式は追加しない。初期化の場所を移しても確認ダイアログ、全ページの設定・保存VRM削除、保存停止と再読込の手順を変えない。

起動前は概要と詳細設定の2つの表示を切り替える構成とし、複数段階の必須ウィザードは導入しない。設定値の所有者を増やさず、既存の `settingsStore` と操作窓口を使う。機器が利用不可の場合の理由と開始条件も既存モデルから取得する。

VRM選択は現在の起動前の操作を使う。常設側で現在モデルを確認できるようにし、交換を案内する場合は既存の起動前設定へ戻す導線を使う。実行中のモデル即時交換を新設しない。設定にない機能や利用不可の開始時オプションを分類の穴埋めのために追加しない。

## スコープ境界

`simple-vrm`、`vrm360`、`looking-glass-vrm`の共通設定、起動前の概要、必要な診断項目の移動と設計同期を対象とする。見出しの重複は構造変更と一緒に解消する。色・影・説明表示の仕上げは[後続タスク](../task-261010185549-refresh-settings-visual-design/task.md)で行う。

通信の形式、接続モードの意味、設定キー、保存形式、追跡や音声の処理、サービスの起動順序は変更しない。設定UIから操作する既存窓口を移設して使う。
