# レビュー: task-261114152036-fix-character-reselection-restart

## 判定

APPROVED

## 理由・申し送り

- 現在のstartUiSideEffectsOnceは初回以外にダイアログを閉じず、VRMCharacterManagerも生成時のURLしか読み込まない。再開始と選択反映の問題、対象コードは一致する。
- シーンとレンダラーを保持し、モデル管理が読込世代とモデル資源を所有する境界は、360度表示・Looking Glassの状態を保ちながら交換するために適切である。URL所有者を別タスクに分離した依存順も成立している。
- 読込成功前に旧モデルや旧制御処理を破棄せず、新モデルが利用可能になった時点で置換する。現在のattachLoadedVrmは直ちにthis.vrmや制御処理を更新するため、失敗時に旧モデルを保持する条件に合わせて読み込みと反映を分ける必要がある。
- 通常ページの本番読込経路と、3ページの既存初期化テストを組み合わせる確認範囲で実装可能である。外部通信契約の変更や実機の網羅試験は要求していない。

## 自律補完

- `AUTO_FIX`: 「開始成功時にダイアログを閉じる」は、同一モデルでは既存開始経路の成功、モデル交換時ではその開始世代での交換成功を指す。失敗時は旧モデルを保ち、反映失敗の表示から同じ選択を再試行できるようにする。保存済み選択と現在表示中モデルの違いを状態として示せば、保存形式は変えずに実装できる。
- `AUTO_FIX`: 旧モデル由来のサムネイル読込やcanvas.toBlobの後着結果も、モデル読込と同じ世代で検査する。新モデルにサムネイルがない場合は既定アイコンへ戻し、旧モデルの画像を残さない。根拠は、表示モデル・サムネイル・状態を一致させる完了条件である。
