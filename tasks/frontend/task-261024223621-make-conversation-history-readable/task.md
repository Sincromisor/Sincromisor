# 会話履歴を読み返せる操作を設ける

## 背景 / 目的

2026-10-24のUIレビュー指摘5。優先度は中。チャットは `overflow: hidden` と `pointer-events: none`、テロップも末尾へ自動追従する。保持済みの会話が領域から外れると通常画面で読み返せない。原則§5・§7・§8に基づき、会話へ集中する表示を保ちながら履歴を確認できるようにする。

## 完了条件（受け入れ条件）

- [x] 保持中の会話を通常の利用導線から読み返せる。長文、320px幅、文字拡大でも本文を切り捨てない。
- [x] マウス・タッチ・キーボードで履歴を移動できる。キャラクター操作との入力競合を避ける。
- [x] 過去の発話を読んでいる間、新着で閲覧位置・フォーカスを奪わない。最新へ戻る操作が分かり、末尾を読んでいる場合は新着へ追従する。
- [x] 同一IDの更新、最新30件の保持、モデル変更時のアイコン更新を維持する。保持上限で古い項目が抜けても、残る閲覧対象を不用意に移動させない。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

既存の履歴スナップショットを利用する。現在のチャットを操作可能にするか、必要時に開く履歴表示を設けるかは、キャラクターと操作が競合しない最小構成で決める。履歴の永続保存、検索、出力、無制限保持は追加しない。

テロップ自体を全文履歴へ改造する必要はなく、会話本文を読み返せる経路を確保する。重要な通知の配置は[指摘3](../task-261024223620-keep-important-notices-visible/task.md)、話者と新着の支援技術対応は[指摘6](../task-261024223621-announce-conversation-speakers/task.md)と責務を分ける。

## 確認方法

Playwright CLIで領域からあふれる長文と複数発話を表示し、過去を閲覧中に新着・同一ID更新・保持上限による削除を発生させる。閲覧位置の維持と最新への復帰を確認する。キーボード・狭幅・文字拡大で本文を読めることを確認する。追従判断には小さな回帰テストを加え、対象の静的検査と型確認を行う。

## 文書同期

[共通枠組み](../../../documents/design/frontend/app-shell.md)と[ページ構成](../../../documents/design/frontend/pages.md)へ履歴操作と追従条件を同期する。通信形式・履歴保持数は変更しない。

## 実施結果

通常メニューに会話履歴を追加し、既存外枠の排他表示を使って時系列の本文をスクロールできるようにした。新着・同一ID更新・保持上限による削除と文字の折り返しでは、残る発話の位置を維持し、末尾でのみ追従する。「最新へ」で本文へフォーカスを戻して追従を再開する。通常会話と履歴の描画を共有し、IDを分け、新着通知は常設の一箇所へ残した。対象Biome、ビルドと追加変更の型確認、会話関連テスト7件、Playwright CLIで1440px/320pxの長文・新着・同一ID更新・古い項目削除、位置とフォーカス維持、最新復帰、PageUp・模擬タッチ・文字拡大を確認した。
