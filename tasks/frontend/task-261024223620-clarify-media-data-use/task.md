# 開始前に音声と映像の扱いを判断できるようにする

## 背景 / 目的

2026-10-24のUIレビュー指摘4。優先度は高。開始画面は機器選択を提供するが、音声の送信・保存とカメラの処理場所を判断できない。トップのVRM保存説明だけでは音声・映像の扱いは分からない。原則§9に基づき、開始前の判断に不可欠な事実へ到達できるようにする。

保存設計には認識音声・認識結果・会話履歴の保存がある。ブラウザー診断に音声本文を含めないという契約を、サービス全体が保存しないという意味へ広げない。

## 完了条件（受け入れ条件）

- [x] 現行の実装・配備定義をたどり、マイク音声の送信・処理・保存、カメラ映像の処理、VRMと設定の保存先を区別した根拠をタスクの実装記録に残す。
- [x] 開始前に必要な影響を確認できる。機器の選択・有効状態・開始操作との関係で伝え、UIだけでは表せない送信・保存の重要な事実のみ必要な位置に短く示す。
- [x] 詳細が必要な利用者は開始前に開ける。内部サービス名・配備構成の羅列や長い規約を体験開始の必須手順にしない。
- [x] カメラを使わない選択や開始せず戻る操作を実際に選べる。権限拒否後に利用できる範囲と再設定方法は、その状態で必要な情報だけを示す。
- [x] 「ローカルだから送信しない」「一切保存しない」など、実装で保証できない断定や包括的な免責文を使わない。

## UIの判断基準

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)と、2026-10-24のユーザー指定「説明しなくても理解できるのがよいUI」を適用する。操作名、配置、まとまり、選択・処理状態、実際の動作で解決する。説明文、補助ラベル、免責文、確認ダイアログの追加を既定の解決策にしない。

追加する文言は、既存の表示から分からない利用条件・影響・失敗・回復方法に限る。追加時は、その文言が必要になる判断を実装記録に短く残す。項目名の言い直しや常時表示の注意書きは増やさず、操作名と支援技術の名前は保持する。

## 設計判断と変更範囲

情報の調査と、共通の開始前設定・必要な詳細表示が対象。常時説明を増やすことを完了条件にせず、既存のラベル・選択状態・配置で伝わる内容は削る。重要な送信・保存の事実を全てツールチップや詳細へ隠すこともしない。新しい同意チェックや確認ダイアログは既定では追加しない。

配備依存の値は既存の構成・契約で確認できる範囲を正確に示す。新しい設定API、同意管理基盤、保存方式・保持期間・データ削除機能の変更は対象外。既存情報では重要な事実を確定できない場合は、推測で表示せず、必要な値と供給元を特定して設計判断事項として報告する。安全な機器終了は[指摘1](../task-261024223620-end-experience-and-release-media/task.md)、取得失敗の状態は[指摘2](../task-261024223620-recover-media-startup-failure/task.md)が担当する。
