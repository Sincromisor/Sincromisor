## 背景 / 目的

依存調査で見つかった描画・推論・開発ツールの更新を取り込み、既存の画面と推論経路を維持する。

調査基準日は2026-10-11。以下は公式レジストリとロックファイルを比較した更新候補であり、動作確認済みの採用版ではない。実装開始時に公開状況と依存条件を再確認し、互換性を満たす安定版を採用する。更新を見送る候補は具体的な制約と理由を記録する。

## 完了条件（受け入れ条件）

- [ ] 更新候補を依存定義とロックファイルへ反映し、ロック済み依存から再導入・ビルドできる。採用版と見送り理由を記録する。
- [ ] MediaPipeの配信用WASMが採用したパッケージから生成され、ONNX Runtimeのモデル読込み・推論、Three.jsのVRM表示が従来どおり動く。
- [ ] 開発ツール更新後の型確認・既存単体テスト・対象の静的検査が通る。

## 設計判断と変更範囲

[開発ツール一元化タスク](../task-261011151020-unify-frontend-development-tools/task.md)を先行させ、その完了後のnpm workspaces配置を使う。ルートと[フロントの依存定義](../../../sincromisor-frontend/package.json)、ルートのロックファイルを更新し、廃止されたフロント専用ロックを復活させない。Biome・Prettierは移動後のルート側で更新する。

`@types/node`は先行タスクが採用するNodeメジャーに合わせる。調査時の22系候補を無条件に適用しない。Node/npmの選定・Dockerの依存配置変更は先行タスクの責務とする。

[素材生成スクリプト](../../../sincromisor-frontend/scripts/prepare-mediapipe-assets.js)、`src/features/`の推論利用箇所、`src/character/`の描画利用箇所は、更新で必要になる互換修正に限定する。公開通信契約、機能追加、無関係なリファクタリングは対象外。

## 確認方法

1. 先行タスクの手順でルートの`npm ci`、`build`、`test`、`check`を実行し、素材生成の既存テストを確認する。
2. 開発環境で主要ページのVRM表示、MediaPipeとONNX Runtimeを使う既存機能をそれぞれ一度動かし、WASM読込みと推論結果を確認する。ブラウザー操作時はPlaywright CLI利用ルールとスキルに従う。
3. 配信素材の欠落や依存配置の変更が生じた場合は、フロントのDockerビルドでも確認する。
