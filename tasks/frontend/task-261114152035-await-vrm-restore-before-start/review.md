# レビュー: task-261114152035-await-vrm-restore-before-start

## 判定

APPROVED

## 理由・申し送り

- 現在のDialogManagerは初期復元の完了を待たずに返り、bootstrapは直後にOBS開始を要求する。保存済みモデルと初回表示が食い違う原因、変更範囲、確認方法が現行コードと一致する。
- 復元状態は選択処理、開始要求の有効性はアプリ制御が所有する方針で実装できる。復元・URL解放・モデル交換のタスク分割と依存順に矛盾はない。
- 実装時は開始準備中の停止を、現在のstopRTCのidle早期returnやendExperienceの機器未使用時早期returnより先に受理する。開始要求だけを無効化し、共有される初期復元結果の保存まで破棄しない。
- 確認は復元待機・保存待機・停止後の後着結果と、Chromeでの最初のモデル要求に絞られており、実機や全環境の網羅要件は追加されていない。

## 自律補完

- `AUTO_FIX`: 現在の較正開始はstart内で直ちに行われる。初期復元・選択保存を待つ間は機器・RTC・較正を始めず、有効な開始要求が準備完了後に一度だけ既存の開始経路へ進むようにする。根拠は、待機中の取消しと3ページ共通の起動順序を保つ完了条件である。
- `AUTO_FIX`: 「独自の時間切れ仕様は追加せず」は、復元処理へ根拠のないタイムアウトを新設しない意味とする。既存Promiseの成功・失敗と、開始要求の取消しを扱えばよい。
