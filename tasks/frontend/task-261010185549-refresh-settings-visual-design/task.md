# 設定UIの装飾・説明・状態表示を統一する

## 背景 / 目的

ユーザーが指摘したデザインの古さに対応し、[分類・導線再編](../task-261010185549-reorganize-settings-and-startup/task.md)後の設定UIを、操作の重要度と意味が読み取りやすい表示へ整える。

2026-10-10の調査では、暗いグラデーション、影、枠付きカードの入れ子が重なり、項目数の少ない画面では空白が大きかった。開始操作は他のボタンに比べて目立たず、説明は小さな「?」へ偏っていた。実装上も共通CSS、起動前CSS、常設のインラインスタイルに装飾が分散している。

## 完了条件（受け入れ条件）

- [x] 起動前と常設設定の文字、余白、入力、ボタン、背景、境界線を共通の基準に揃える。フォントは既存のBIZ UDPGothicを基準にする。
- [x] 設定の外枠とセクションを中心に階層を整理し、装飾のためだけのカードの入れ子、繰り返す見出し、過剰な影・グラデーションを取り除く。
- [x] 開始などの主操作、通常操作、初期化操作が見分けられる。現在カテゴリ、フォーカス、無効状態も識別できる。
- [x] 体験選択、追跡、動作量、音声補正で、設定する判断に必要な短い説明を項目の近くに表示する。「?」には補足だけを置き、マウスを使わなくても説明へ到達できる。
- [x] 操作不可の理由と再接続・再開始が必要な案内を対象項目の近くに表示する。既存モデルの状態を使い、実際には反映待ちなのに適用済みと表示しない。
- [x] モード、カメラ、追跡などの文言を現在の機能と整合させる。技術的な内部値を利用者向けの選択名として露出させず、デバッグ用の原表記は保つ。
- [x] 長い説明、エラー、無効な機器、Looking Glass固有項目があっても、狭幅で横にはみ出したり主要操作を隠したりしない。
- [x] 先行タスクのタブ配置、本文スクロール、フォーカス、ラベル、数値入力の整合性を維持する。

## 設計判断

既存のUI共通変数と設定部品を活かし、落ち着いた背景、必要な境界線、主操作と選択状態のアクセントに整理する。具体的な色・角丸・間隔は実装時の画面確認で決める。新しいUIライブラリ、フォント配信、テーマ切替、アイコン素材の導入を前提にしない。

ページ見出しと同名の内側見出しを繰り返さない。短い画面を装飾で埋めず、前段で固定した主要操作の位置を維持しながら余白を整える。説明の常時表示は必要な項目に絞り、長文を全項目へ追加しない。

`settingHelp.talkMode` には現状の体験名と整合しない説明があり、カメラ説明も姿勢追跡を十分に含んでいない。設計と現在の利用側を確認して修正し、動作の変更で文言へ合わせない。設定の自動保存・再接続による反映・Looking Glass再開始の区別も既存契約に従う。

## スコープ境界

共通設定部品、起動前・常設設定、設定に付随する説明・状態表示・設計文書を対象とする。開発者ツールは共通部品変更による表示影響を確認するが、診断画面全体の再デザインには広げない。トップページ、3D表示、通信処理、保存方式、音声・追跡アルゴリズムは変更しない。

## 実装方針

- [UI共通変数](../../../sincromisor-frontend/src/styles/uiFoundation.css)、[共通設定部品](../../../sincromisor-frontend/src/features/settings/react/primitives/)、[設定外枠](../../../sincromisor-frontend/src/features/settings/react/shell/)を中心に装飾を揃える。共通変数の変更で他画面まで意図せず変わる場合は設定画面に範囲を限定する。
- [起動前設定CSS](../../../sincromisor-frontend/src/features/dialog/react/configurationDialogSettings.css)、[常設パネルの装飾](../../../sincromisor-frontend/src/app/settings/react/panelStyles.ts)、[重ね表示CSS](../../../sincromisor-frontend/src/app/shell/react/overlay/overlay.css)に重複する指定を整理する。
- [項目の説明](../../../sincromisor-frontend/src/features/settings/react/fields/settingsHelp.ts)と共通説明部品を見直し、短い説明と補足の役割を分ける。入力との関連付けを維持する。
- 適用待ち・操作不可の状態は既存設定スナップショットから導出し、UIに別の制約や適用状態を持たせない。

## 実装・確認結果

- 設定の外枠に限定した単色の背景と共通部品へ装飾を整理し、BIZ UDPGothic、入力・余白・境界線を揃えた。開始は明るい塗り、初期化は専用の境界線で区別し、現在カテゴリとフォーカスを明示した。
- 体験、追跡、動作量、音声補正の説明を常時表示し、入力へ関連付けた。操作不可の理由は既存の状態と依存条件から表示する。補足はスクロール枠の外へ描画して画面内に配置し、Tabで開く、Escapeで閉じる、自動スクロールへの追従を確認した。
- カメラ・追跡・Looking Glassの通常表示を日本語へ揃えた。設定の自動保存と再接続・再開始を区別し、Looking Glassの反映待ちは既存状態を使用する。保存形式、通信、アルゴリズムは変更していない。
- 変更TypeScriptのBiome、フロントエンド構造検査、変更MarkdownのPrettier、差分検査を実施した。設計2文書とコメントを同期・点検した。
- 設定・ダイアログモデルの既存テストは21件中20件成功。`dialogSettingsAccess.test.ts`の既定姿勢同期量を `0.7`とする期待値だけ失敗するが、変更前HEADを一時領域へ展開したテストでも同じ失敗を確認した。今回変更した案内文の期待値は更新して成功した。
- 通常ビルドは既存の型エラー7件で停止した。`Array.at`のライブラリー指定と `motionDebugReplayComputation.test.ts`の循環型推論について、変更前HEADの診断と全文が一致した。既存の公開素材リンク不在も避けるため、Vite APIの `build.copyPublicDir=false`で一時領域へ全ページをビルドし、変換・束ね処理の成功を確認した。
- `playwright-cli`の一時セッションで1440×900・520×900・390×900の概要、詳細全分類、常設全分類を確認した。横はみ出し、本文スクロール、固定された開始・停止、カテゴリ選択、操作不可の理由と機器不在の開始制限を確認した。
- 先行タスクの入力確認を現在の分類へ合わせ、矢印・Home・End・Tabのフォーカス、説明と入力・開始操作へのキー到達、保存小数値 `0.725`・`0.683`・`0.917`の維持、入力後の `0.83`への正規化とストア一致を確認した。開発者ツールのタブ操作と表示も確認した。
