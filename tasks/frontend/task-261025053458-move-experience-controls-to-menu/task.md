# 機器状態の常設バーを撤去し終了操作を右上メニューへ集約する

## 背景 / 目的

2026-10-25のユーザー指摘。通常画面の「マイク 使用中」「カメラ 使用中」「体験を終了」の横長バーがキャラクターより強く目立ち、文字情報を極力減らす方針に合っていない。右上の設定メニューから必要な状態と操作に到達できるようにし、通常時の会話画面からバーをなくす。

確認基点は `b31be6ec5804a8bad35829a2fb48bdcfac5799f8`。提供された画像、現在のコード、Git履歴を確認した。起票時のブラウザー操作・実機確認は行っていない。

バーは[機器使用と体験終了のタスク](../task-261024223620-end-experience-and-release-media/task.md)のコミット `00566bc2` で導入された。その後、[マイク取得失敗からの回復](../task-261024223620-recover-media-startup-failure/task.md)のコミット `c58b4f0a` で、失敗理由と「マイクを再試行」も同じ部品に追加された。バーだけを削除すると回復操作も失われるため、正常時の情報と失敗時の案内を分けて配置する。

## 設計判断

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)の「説明を足す前に、UI要素とレイアウトで伝える」と§9・§10を合わせて適用する。機器状態の確認と停止への到達性は維持するが、常時横長バーを表示することは原則の要求ではない。以前のタスクで定めた「設定を開かず状態を確認する」という配置条件は、今回のユーザー要求に沿って変更する。

採用する配置は次のとおり。

| 対象                     | 配置と振る舞い                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 正常時の会話画面         | ヘッダー下のバーと専用の余白を撤去する。代わりの常設アイコン列・バッジ・説明文は追加しない。                                                             |
| 体験の終了・再開始       | 右上の歯車メニューの第一階層に「体験を終了」を置き、終了後は「体験を開始」に切り替える。基本設定のカテゴリや開発者ツールへ潜らず操作できる。             |
| マイク・カメラの使用状態 | 「基本設定」のカテゴリに依存しない既存の固定領域へ、機器名と「未使用／取得中／使用中」を簡潔に表示する。カテゴリの切り替えや本文のスクロールを要しない。 |
| マイク取得失敗           | 失敗中だけ既存の重要通知領域で短い理由と「マイクを再試行」を示す。設定を閉じていても気付き、回復できる。設定内の既存の再試行操作も維持する。             |

終了を設定カテゴリの奥へ移す案は、停止へすぐ到達する要件を弱めるため採らない。バーをアイコンに置き換えるだけの案も、通常画面に不要な操作領域を残すため採らない。必要な操作名、状態名、支援技術が読める名前は保持し、説明文を一律に消す対応にはしない。

## 完了条件（受け入れ条件）

- [ ] 通常の3ページ（`simple-vrm`、`vrm360`、`looking-glass-vrm`）でヘッダー下のバーと空き領域がなくなり、正常時に機器状態・終了操作の代替常設表示を増やしていない。
- [ ] 右上メニューから体験を終了・明示再開始できる。機器取得中やRTC停止済みでも終了でき、確認ダイアログを追加しない。マウス・タッチ・キーボードで操作でき、実行後にメニューを閉じてもフォーカスを失わない。
- [ ] 基本設定を開くと、現在の実トラックに基づくマイク・カメラ状態が分かる。メニューや設定を閉じている間の変化も、再表示時に同期される。設定の有効値、ミュート、RTC接続状態から使用状態を推測しない。
- [ ] マイク取得失敗時の理由と再試行がバー撤去後も利用できる。同じ失敗通知を重ねて表示せず、再試行・成功・体験終了に応じて古い失敗表示が解消される。稼働中のカメラや設定・モデルを維持した音声だけの再試行を保つ。
- [ ] 終了時の機器・音声処理・追跡・較正・RTC解放と、自動再取得の抑止を維持する。設定とモデルを保持し、メニューの開閉だけでは開始・停止・再試行しない。設定・診断の「接続を停止」はRTCだけを止める意味を保つ。
- [ ] 狭幅でも右上メニューと設定の固定領域を操作でき、重要通知や右側パネルが操作を覆わない。関連する設計文書と既存のUIテストを新しい配置へ同期する。

## 変更範囲と実装の入口

UIの配置・購読・操作接続を変更する通常タスクとする。開始終了の状態機械、機器所有者、通信契約、保存形式、ブラウザー権限、Looking Glass固有の開始停止は変更しない。旧タスクで修正した機器解放処理を巻き戻さない。ホーム画面や会話内の接続案内の整理は対象外とする。

- [共通画面](../../../sincromisor-frontend/src/app/shell/sincroPageAppShell.tsx)と[ヘッダーCSS](../../../sincromisor-frontend/src/styles/sincroHeaderBox.css): バーと専用スタイルを撤去し、`--sincro-chrome-bottom` によるパネル・通知の配置を確認する。
- [既存の体験操作](../../../sincromisor-frontend/src/app/shell/react/sincroExperienceControls.tsx): `media_state`、`audio_input_state` の購読と `endExperience()`、`start()`、`retryAudioInput()` の呼び出しを移設する。表示のために別の状態所有者を作らない。
- [右上メニュー](../../../sincromisor-frontend/src/features/debug/react/rightToolMenu.tsx)と[キー操作](../../../sincromisor-frontend/src/features/debug/react/useRightToolMenuKeyboard.ts): 既存のメニュー構造へ終了・再開始を追加する。パネル選択と体験操作の意味を区別する。
- [共通設定パネル](../../../sincromisor-frontend/src/app/settings/react/sincroControlPanel.tsx)と[接続操作領域](../../../sincromisor-frontend/src/app/settings/react/sincroConnectionPage.tsx): 固定領域へ機器状態をまとめ、全体終了とRTC停止を混同させない。
- [重要通知](../../../sincromisor-frontend/src/app/shell/react/importantNotice.tsx): 既存の配置切り替えを利用して失敗時の案内・回復を表示する。設定保存失敗など別の重要通知を失わせない。

## 確認方法

- 変更ファイルの静的検査とフロントエンドの型確認・ビルドを行う。
- 既存の [sincroExperienceEnd.test.ts](../../../sincromisor-frontend/src/app/controller/__tests__/sincroExperienceEnd.test.ts) を実行し、終了・再開始・マイク再試行の既存動作を確認する。
- [startupHistory.spec.ts](../../../sincromisor-frontend/tests/ui/startupHistory.spec.ts) の機器状態参照と開始終了操作を新しい導線へ更新し、[focus.spec.ts](../../../sincromisor-frontend/tests/ui/focus.spec.ts) と合わせて対象確認する。新しい導線から正しい操作が呼ばれることと、メニューを閉じた後も最新状態を表示できることを確認する。
- 実装時は [Playwright CLI利用ルール](../../../documents/rules/playwright-cli.md) に従い、代表ページで通常幅・320px幅のバー撤去後の配置と、メニューのキーボード操作を確認する。残り2ページは共通配置と固有パネルが崩れないことを確認する。
- 開発環境で開始→メニューから終了→明示再開始を一度通し、実トラックの終了と状態表示の一致を確認する。取得失敗は模擬入力で案内→再試行→解消を確認する。実機が使えない場合は模擬確認と区別して記録する。

## 設計文書の同期

実装時に [共通枠組み](../../../documents/design/frontend/app-shell.md) の体験終了・音声取得失敗・重要通知、[設定設計](../../../documents/design/frontend/setting-and-debug-ui/settings-design.md) の状態・停止・回復導線、[診断設計](../../../documents/design/frontend/setting-and-debug-ui/debug-design.md) の「通常画面の体験終了」という記述を更新する。過去の完了タスクは当時の実施記録として残す。UI原則自体を緩める変更や、通信契約の変更は不要。
