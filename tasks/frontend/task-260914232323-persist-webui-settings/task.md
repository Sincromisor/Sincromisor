# 通常設定をブラウザーに保存してURL優先で復元する

## 背景 / 目的

WebUIで変更した値をリロード後も保持するユーザー要求に対応する。通常起動ではURL指定を保存値より優先することがユーザー決定済みである。
調査基点は `d3031df5`。通常設定の更新と購読は共通化済みだが永続化はなく、VRM本体とサムネイルだけがCache Storageに保存されている。
[視線設定の整合性修正](../task-260914232318-settings-gaze-consistency/task.md)の完了後に実装する。

## 完了条件

- [ ] 起動前ダイアログ・開始後パネルで変更した会話、機器、音声、表示の通常設定とLooking Glass設定が、同じページのリロード後にUIと実行時処理へ復元される。
- [ ] 優先順位は共通既定値、ページ既定値、保存した利用者設定、有効なURL設定の順とする。最終的な利用可否の制約は常に守る。
- [ ] `?talkMode=chat` でUIから `sincro` に変更しても、同じURLでリロードすれば `chat` になる。URL未指定・不正値では保存値を使う。URL適用自体は保存した利用者の選択を書き換えない。
- [ ] 復元は操作可否の確定後、手動開始・OBS自動開始・シーンへの初期設定反映より前に完了する。復元途中の値で開始しない。
- [ ] 初期化・復元・環境の利用不可通知だけで保存値を上書きしない。未変更の既定値 `0.72`・`0.68` も保存・再適用で丸め直さない。
- [ ] 読み出し時に型、許容値、数値の有限性・範囲を検証する。不正JSON、不正項目、未対応形式、保存領域へのアクセス失敗で起動を止めない。有効な項目は活用し、使えない項目は既定へ戻す。
- [ ] 機器のブラウザー既定への復帰を保存できる。不在の機器IDを復元した場合は既存の案内・開始制限を使い、一時的な不在だけで保存IDを消さない。
- [ ] 保存対象・形式・ページ別の扱い・URL優先・失敗時の挙動を設計文書に記載する。

## 設計判断と範囲

- 対象は共通のアプリ枠組みを使う `simple-vrm`、`vrm360`、`looking-glass-vrm` の通常設定。[現行一覧](../../../documents/design/frontend/setting-and-debug-ui/settings-items.md)を基準にし、一般UIにない `enableTalk`・`enableInspector`・`enableVR` は保存対象へ自動追加しない。
- ページ既定値の違いを保つため、利用者設定は既知のページ単位で保存する。URLの末尾表記ではなくページ識別子で区別する。これは起票時の補完判断であり、ユーザーがページ間共有を明示したものではない。
- 小さなJSONを `localStorage` に保存する。保存キーと形式の版を明示し、必要な既知キーだけを扱う。外部サービス、新規依存、汎用保存フレームワークは導入しない。
- 値の正本は既存モデルとし、保存するのは利用者の選択。ストア全体の無条件保存は避け、操作可否、案内、接続状態、ログ、URLやページ既定値の適用結果を保存しない。
- VRMの保存処理は維持する。デバッグ調整は[音声](../task-260914232333-persist-audio-tuning/task.md)と[視線・姿勢](../task-260914232333-persist-tracking-tuning/task.md)、初期化UIは[別タスク](../task-260914232327-reset-webui-settings/task.md)で実装する。
- トップページの体験選択、独立した実験ページの操作、表示カテゴリ、タブ、配置、追跡・較正結果の保存は対象外。タブ間のリアルタイム同期も追加しない。

## 主な変更箇所

[設定層](../../../sincromisor-frontend/src/app/settings/)に保存・検証処理を置き、[共通の適用窓口](../../../sincromisor-frontend/src/app/controller/sincroAppController.ts)と接続する。利用者操作と初期化・復元を区別する最小の接続とする。
[VRMページ初期化](../../../sincromisor-frontend/src/character/scene/sincroVrmInitializer.ts)、[URL設定入口](../../../sincromisor-frontend/src/pages/simpleVrm/mainVrm.ts)、派生ページの既定値の順序を同期する。
設定値の更新元には音声デバッグ操作による会場プリセット解除もあるため、React入力だけを保存して取りこぼさない。

## 確認方法

保存値の往復・検証・アクセス失敗、初期化とURLの優先順位、未変更の既定値と利用不可時の保存保持を対象テストで確認する。
開発ブラウザーで通常ページの起動前後の変更とリロード、URL優先、Looking Glass設定の復元を確認する。保存検証にLooking Glass実機は必須としない。
変更範囲の静的検査、フロントエンドの型確認・ビルドを行う。
