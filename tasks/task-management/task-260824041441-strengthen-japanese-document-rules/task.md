# 日本語文書規約とタスクフローを簡潔に強化

<!-- tasks/AUTHORING-CHECKLIST.md を目安に、変更のリスクに必要な項目だけ具体化する。 -->

## 背景 / 目的

日本語文書規約に主観的な例外と適用範囲の不一致が残り、タスク起票・実装・評価・文書昇格で英語混じりの文章を止められない。過剰な自動判定を増やさず、規約と既存フローの最小変更で再発経路を閉じる。

## 完了条件（受け入れ条件）

- [x] 日本語本文と許容する原表記の境界が一意になり、理由コメントや既存文書を根拠に回避できない。
- [x] タスク起票・実装・評価で、変更した文書の言語規約適合を確認する。
- [x] 新しいタスクの英語だけのタイトルを既存ツールが拒否し、既存タスクは壊さない。
- [x] 設計文書の雛形と文書運用ガイドが日本語見出しを生成する。

## 設計判断

自然言語の自動採点や英単語の禁止一覧は誤検出と保守負担が大きいため導入しない。ツールは新規タスク名の最低限の境界だけ検査し、本文は変更差分の文章点検で扱う。

## スコープ境界

規約、設計文書雛形、エージェント作業手順、タスク生成・更新ツールを対象とする。既存文書全体の翻訳や過去タスク名の改名は行わない。

## 実装方針

既存の Markdown 規約を正本とし、各作業手順から参照する。タスク名の検査は共有関数を `tasks:new` と `tasks:set` から再利用する。`.claude/` を修正後、既存の生成処理で Codex 用ファイルを同期する。

## テスト

- タスク名判定の単体テスト
- タスク管理検査と生成物同期検査
- 変更した Markdown の整形確認

## ドキュメント同期の要否

通信契約への影響はない。`AGENTS.md`、Markdown規約、タスク管理正本、設計文書運用ガイドと雛形を同期する。
