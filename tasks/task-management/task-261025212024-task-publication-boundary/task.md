# タスク成果物の公開範囲を統一する

## 背景 / 目的

公開リポジトリのタスク管理では、取得元に閲覧制限がある情報を公開成果物へ転記しない運用が必要である。ユーザー要求に基づき、起票から完了までの公開範囲を統一する。

## 完了条件

- [x] タスク名・メタデータ・本文・添付資料・独立確認・索引・コミットの件名・本文に同じ公開範囲を適用する。
- [x] 非公開記録の保存先と扱いを定め、起票・実装・独立確認・完了処理へ参照を追加する。
- [x] 既存の依存更新タスクを公開可能な変更内容・検証結果へ整理し、未公開の自分のコミットも修正する。
- [x] 生成物の同期、対象テスト、整形、タスク管理の検査を確認する。

## 変更内容

[タスク管理の公開範囲](../../README.md#公開成果物と非公開検証原本)を正本とする。入口のAGENTS.md、起票チェックリスト、Markdown規約、タスク雛形、完了処理の案内、Claudeのコマンド・エージェント原本から参照し、Codex用成果物を再生成する。詳細な規約を各スキルへ複製しない。

非公開記録には元サービスと既存のGit管理外領域を使う。公開範囲の点検は通常の直接コミットにも適用し、文章の機密性を機械検査だけで判定できるとは扱わない。非公開情報の省略を監査結果の解消と表現しない。

既存記録の整理では更新内容・実施した検証結果・元のタスク状態を保持する。公開済み履歴の書き換え、強制push、外部サービスへの記録追加は含めない。

## 確認結果

- タスク雛形の既存テスト: 最小構成の生成・検査と必須ファイル欠落の拒否が成功した。サンドボックス内の子プロセス起動で失敗した初回を、Node 26.12.1で再実行して確認した。
- 変更したスクリプト: Nodeの構文確認と、既存のスペース4文字・行幅100の設定を明示したBiome整形確認が成功した。処理ロジックの変更はない。
- `npm run gen:codex:check`と両スキルの`quick_validate.py`: 成功。
- Git管理外の保存先: `git check-ignore`で除外、`git ls-files`で追跡対象外、保存した原本の所有者限定権限を確認した。
- 変更MarkdownのPrettier、タスク状態・索引検査、`git diff --check`: 成功。

独立確認の指摘を反映し、既存記録と件名の扱いを修正した。詳細は[評価記録](eval.md)を参照する。公開済み履歴の書き換えとpushは実施していない。
