# 任意のタスク成果物を必要時だけ作成する

## 背景 / 目的

タスク作成が空の成果物を生成し、ローカルにあるだけで検査に通るため、通常作業のコミットから漏れていた。ユーザーの依頼に基づき、生成・検査・完了手順を必要な成果物だけ作る運用に揃える。

## 完了条件（受け入れ条件）

- [x] 起票は `task.md` と `meta.yaml` だけを生成し、その構成でタスク検査に通る。必須ファイルの欠落は引き続き検出する。
- [x] 任意の成果物を必要時だけ作成し、コミット前後に対象タスクの取りこぼしを確認する手順へ同期する。
- [x] 調査済みの未追跡の空ファイル44件を削除する。

## 変更範囲

タスク生成・検査、回帰テスト、運用文書と生成済みスキルを変更する。削除対象は未追跡かつ0バイトの任意成果物と `.gitkeep` に限定し、内容のある成果物や過去のコミット済みファイルは保持する。本番サービスの設計・通信契約は変更しない。

## 確認

`node --test scripts/tasks/__tests__/optionalTaskArtifacts.test.mjs` で最小構成の生成・検査と必須ファイル欠落を確認する。変更Markdownの整形、生成物の同期、タスクと索引の検査を行う。コミット済み内容だけを一時ディレクトリに展開し、同じタスク検査に通ることを確認する。

## 確認結果

回帰テスト、`tasks:check`（354件）、`tasks:index:check`、`gen:codex:check`、スキル検証、変更Markdownの整形確認が成功した。変更前HEADのコミット済みタスク353件を一時展開し、修正後の検査で成功することも確認した。文書・コメント点検は合格。本番サービスは変更していないため、ビルド・動作テストは対象外とした。

未追跡の空ファイルは9タスクから44件削除し、削除後に空になった補助ディレクトリも除去した。テストの子プロセス実行は制限環境で出力取得に失敗したため、制限外で再実行して成功した。
