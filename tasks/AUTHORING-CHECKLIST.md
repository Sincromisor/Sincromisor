# タスク起票チェックリスト

`task.md` を実装可能にするための目安。通常の局所変更では該当項目だけ確認し、表や監査台帳を増やさない。独立レビューを行う場合も同じ観点を使う。

## 必須

- [ ] 解決する問題と、完了時に観測できる結果が書かれている。
- [ ] 完了条件が一意で検証可能であり、重要な異常系・境界値を含む。
- [ ] 主な変更範囲とスコープ外が分かる。
- [ ] 関連コードを現在の HEAD で確認し、存在しない API や古い前提に依存していない。
- [ ] 実装結果を左右する設計判断だけが確定している。通常の実装判断や不採用案の網羅は実装者へ委ねる。
- [ ] 完了条件に対応するテスト方法がある。
- [ ] 必須確認が失敗した場合、記録だけで完了せず、証拠採取、原因特定、修正・再検証へ進むことが読み取れる。
- [ ] 公開 API、通信契約、公開挙動を変える場合は、同期する設計文書や利用例が具体的に示されている。

## 高リスク統合タスクだけ

複数のリソース所有者・状態機械・外部境界をまたぐ、または再試行、時間切れ、安全な終了、厳密な実行回数・順序を扱う場合だけ確認する。

- [ ] 独立して検証できる変更へ分割できないか検討した。
- [ ] 実際に関係する所有権、生存期間、失敗時の状態、時刻基準、観測点が決まっている。
- [ ] モックだけでは証明できない条件について、本番用アダプター後の確認方法がある。
- [ ] cleanupや環境復旧で失われる診断情報、共有環境を復旧する時点、原因不明時に保持するworktreeとtask状態が決まっている。
- [ ] ユーザーまたは第三者による独立レビュー・評価が必要か判断した。

## 実装時に直接適用する規約

コメント品質は task.md に監査表として複製せず、実装時に `documents/rules/source-comments.md` と対象言語の `documents/rules/coding-*.md` を直接適用する。ドキュメントだけのタスクにコード用の確認項目を追加しない。
