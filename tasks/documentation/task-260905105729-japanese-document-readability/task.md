## 修正方針

通常の文書変更として現在のワークツリーで進める。ファイル数を理由に専用ワークツリー、独立レビュー、実行時の全体検査を必須にしない。

ユーザーの指摘箇所は [RTCの説明](../../../sincromisor-server/sincro-rtc/README.md) の40–41行に存在する。

> 通常 build は `CGO_ENABLED=1` と C compiler を必要とする。`mediadevices` v0.10.0 に同梱された
> static libopus archive を使うため、`dynamic` build tagやsystem libopusは使わない。

修正例：

> 通常ビルドは `CGO_ENABLED=1` とCコンパイラを必要とする。`mediadevices` v0.10.0 に同梱された静的なlibopusアーカイブを使うため、`dynamic` ビルドタグやシステムのlibopusは使わない。

`dynamic` は実際のビルドタグなので綴りを変えない。バッククォートで囲むだけで普通名詞の英語表記を温存しない。例えば「session lifecycle」は「セッションの生存期間」、「build tag」は「ビルドタグ」、「stale comment」は「古くなったコメント」とする。`AppController` のような実装名と「アプリ制御」のような役割説明も区別する。

調査資料は出典リンクと引用を維持し、リポジトリ内の説明を整える。説明文全体を原文引用と扱って修正を免除しない。意味が曖昧な箇所は関連実装・契約で確認し、語の一括置換で制約を変えない。

生成文書の修正が必要になった場合は `.claude/` の生成元を直して `npm run gen:codex` を実行する。現時点では生成済みスキルの明確な違反例を抽出していないため、再生成自体を必須作業にはしない。

## 対象外

- 本番コード・コードコメント・通信契約・設定値・処理挙動の変更。
- 文書の構成刷新、移動・改名、設計上の古い判断や技術選定の更新。
- 英字を一律禁止する自動判定器や用語辞書の新設。
- 履歴保管領域、完了・中止・置換済みタスクと検証ログの一括翻訳。具体的な境界は一覧に記載した。

## 確認方法

1. 一覧の原文例を修正対象で検索し、各文書を通読して不要な英語交じりの説明が残っていないことを確認する。英字の残存件数を合否基準にせず、残した英語が既存規約の許容対象であることを確認する。
2. 差分でコマンド・識別子・固定値・数値・制約の維持を確認し、変更した見出しへの節リンクを `rg` で探して同期する。
3. 変更したMarkdownだけに既存の `sincromisor-frontend/node_modules/.bin/prettier` の `--write` と `--check` を適用する。索引再生成後は生成索引も確認する。
4. `npm run tasks:index`、`npm run tasks:index:check`、`npm run tasks:check` を実行する。生成元を変更した場合だけ `npm run gen:codex:check` も実行する。
5. 実行結果と未実行確認を本タスクに残す。文書表現のみの変更なので、音声・ブラウザ・サーバーの実行試験は不要である。
