# ログの準備・検索・記録設定を利用者向けガイドにまとめる

## 背景 / 目的

READMEの起動準備とログ検索の案内は、journalの準備、検索例、記録切替、回収、バックアップについてログ基盤と保存領域の設計資料を参照する。
利用者が内部の収集構成を理解しなくても、必要な準備と日常のログ操作を進められるようにする。
起票時はHEAD `b31be6ec`のREADME、ログ・保存設計、設定例とComposeの設定受渡しを確認した。

## 完了条件（受け入れ条件）

- [x] `documents/guides/logging.md`に、管理者向けのホストjournal準備、検索画面の開き方、期間・サービス・重大度・会話IDでの絞込み例を操作順に記載する。
- [x] サーバー自身で開く検索URLと、別PCのlocalhostでは接続できないことを説明する。検索例には実際の会話や認証情報を使わない。
- [x] 対話本文と音声生成詳細の記録は既定で有効であること、2つの設定の対象と変更箇所、設定ごとの再作成対象を具体的に示す。記録停止で保存済みログや機能用履歴・音声保存が消えると誤解させない。
- [x] ログが見つからない場合の確認、保持期間と容量の注意、停止中の回収、既存スクリプトによるバックアップと復元確認の手順をまとめる。既存データを削除・上書きせずに確認する条件を維持する。
- [x] READMEの起動準備・ログ検索・回収・バックアップのリンクをガイドの該当節へ変更する。ログ基盤と保存領域の設計には構造・契約・制約を残し、移した操作手順を重複管理しない。

## 変更範囲と方針

新規ガイド、READMEの起動準備とログ検索の節、ログ基盤・保存領域設計の対応節を対象とする。
手順移動時は既存の参照元を検索してリンクを同期し、必要に応じて設計索引の説明を更新する。
journal準備は管理者権限と各ホストへの影響を示し、値を一律に押し付けず既存の保存条件を保つ。
検索・記録設定を先に、回収・バックアップを後に配置する。内部のバッファ制御や診断イベントの網羅説明は設計資料へ残す。
ログ収集実装、保存形式、既定設定、公開ポートは変更しない。実ホスト設定の変更や稼働中の復元作業は本タスクに含めない。
他のガイド化タスクへの依存は設けず、READMEの担当節だけを更新する。
