# 別端末からの利用と分散配置の案内をガイドにまとめる

## 背景 / 目的

READMEは「LAN内の別端末から使う」と「処理を複数サーバーへ分散する」を同じCompose設計の見出しへ案内している。
その見出しだけでは、HTTPSの前提、RTCの広告先、ホストごとの設定をどの順で準備するかが分からない。
起票時はHEAD `b31be6ec`のREADME、Compose設計、既存VPS配備手順、設定例、フロント・RTC・分散用ComposeとCaddy設定を確認した。

## 完了条件（受け入れ条件）

- [x] `documents/guides/network-deployment.md`で「サーバー1台のまま別端末から使う」と「処理を複数ホストへ分散する」を分け、利用者が必要な経路だけを選べる。
- [x] 別端末利用は、信頼する証明書を持つHTTPS終端の準備、ブラウザーから到達可能な`SINCRO_PION_PUBLIC_IPV4`、メディアUDPの到達性、設定反映、接続確認の順を示す。標準Caddy設定にはHTTPSがなく、LANのHTTP URLだけでマイク・カメラが使えるとは案内しない。
- [x] HTTPS終端を管理者が用意する前提と、フロントへの転送先・証明書の信頼・アクセス確認を具体化する。localhost、ブラウザー用IP、Consul等の管理用IPを混同させない。
- [x] 分散配置は既存のRTC側と下流側の構成に沿って、ホストごとのプロファイル、Compose追加ファイル、管理ネットワークと接続設定、反映・確認先を案内する。既存のローカル開発・VPS配備手順は用途を説明して再利用する。
- [x] 画面が開かない、マイク許可が得られない、会話が接続できない場合の確認箇所を示す。IPv4・UDP直接到達とTURN未対応、管理サービスの公開制限を既存仕様に合わせる。
- [x] READMEの該当節からガイドを参照でき、Compose設計からも利用手順へ辿れる。実装の構造・公開ポート契約は設計に残し、操作手順を重複管理しない。

## 変更範囲と方針

新規ガイド、READMEの「別の端末から使う・処理を分散させる」、Compose設計の関連節を対象とする。
移動した手順への参照元と設計索引の説明は必要に応じて同期する。既存の開発・VPS配備文書は全文移動・複製せず、入口の不足をガイドで補う。
外部クラウドや特定の有料サービスを必須にせず、管理下のHTTPS終端・ネットワークを前提にする。
ネットワーク機能の追加、Composeやファイアウォールの変更、VPN・証明書の新規構築、実サーバーへの配備は本タスクに含めない。
Mastra Studioとログ検索のローカル限定公開を、一般利用者の別端末対応に合わせて広げない。
他のガイド化タスクへの依存は設けず、READMEの担当節だけを更新する。

## 確認方法

変更したMarkdownをPrettierで整形・確認し、リンク先と見出しを確認する。
各設定例の供給元・適用ホスト・公開先を現在のCompose・設定例と照合し、2つの利用経路をそれぞれ通読する。
文書作業のために実環境の公開範囲や証明書を変更しない。実機確認をしていない構成を検証済みと記載せず、必要な前提を明示する。
アプリ全体のビルド・テストや複数端末での網羅試験は要求しない。

## 実施結果

単一ホストを別端末から利用する経路と、RTC・下流を分ける経路をガイドへ整理した。HTTPS終端の転送先、証明書の信頼、ブラウザー向けIPv4・UDP、管理IPv4、プロファイルと追加Composeを区別した。既存の開発・VPS配備手順へ接続し、README・Compose設計・設計索引を同期した。

確認: 設定例、フロント・RTC・Consul・分散・管理用Compose、Caddy設定と既存配備手順を照合した。2つの利用経路を通読し、Prettier、相対リンク・見出し、タスク整合検査を通した。

実サーバーへの配備、HTTPS・証明書・ファイアウォールの変更、複数端末での接続試験は対象外として実行していない。ガイドはこれらを配置先で確認する前提を明記している。
