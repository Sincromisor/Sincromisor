# documents配下の資料を現行実装と照合して更新する

## 背景 / 目的

利用者から、`documents/`以下の資料の古い記述をレビューし、必要な修正を起票・実行する依頼があった。導入手順には廃止済みの設定・起動方式が残り、現在設計にも移行前の説明が混在している。

## 完了条件（受け入れ条件）

- [x] 資料の一覧、内部参照、現在仕様と履歴の区別を確認し、点検範囲と根拠を記録する。
- [x] 現在のコード・設定と食い違う記述を修正し、履歴資料には現在仕様への案内を付ける。
- [x] 更新する文章にyomiyasuを適用し、識別子・条件・未確認事項を保つ。
- [x] 変更Markdownの整形、内部リンク、タスク状態・索引を確認する。

## スコープ境界

対象は`documents/`の資料と本タスクの記録・索引。現在設計、契約、導入・運用手順は関連する実装と照合する。調査回答、過去の判断、アーカイブは当時の記録として扱い、現在仕様への案内と矛盾の有無を確認する。アプリの実装・設定・通信形式は変更しない。外部製品の最新動向の再調査や実機での再測定は含めない。

## 実装方針

- 導入手順は現在のREADMEとCompose設計へ接続し、存在しないコマンドや誤った通信説明を除く。
- 現行仕様は提供側・利用側と照合し、古い記述だけを修正する。
- 完了済み移行や旧不具合の記録は、現在の運用手順と区別する。
- 設計索引と関連資料も確認し、重複説明を増やさず既存文書へ案内する。

## 確認方法

- コード、Compose、依存宣言、タスク完了記録との静的照合。
- 相対リンク先と変更した見出し参照の確認。
- 変更MarkdownへのPrettier、yomiyasuのlint・差分検査・最終稿照合。
- `npm run tasks:index:check`、`npm run tasks:check`、`git diff --check`。

## ドキュメント同期

本タスクは文書を既存の実装へ合わせる。公開API・通信形式の変更はない。
