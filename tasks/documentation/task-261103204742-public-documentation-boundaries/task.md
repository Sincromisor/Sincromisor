# 公開文書の対象読者と記録範囲を整理する

## 目的

ルートREADMEを利用検討者の入口として整理し、公開成果物へ記録できる範囲を明確にする。
文書の配置替えや伏字化だけで公開可能と判断しない手順を、起票から完了まで適用する。

## 範囲と完了条件

- READMEを製品概要・必要環境・導入・使い方へ絞り、一般的な開発手順は専用文書にまとめる。
- 公開範囲に合わない文書・タスク・添付資料を除去し、混在する文書は製品仕様・再現条件・試験結果を残す。原本と確認一覧はGit管理外へ保全する。
- 公開範囲、文書運用、Compose作業の記録先、起票・完了前の点検を同期する。エージェント定義は編集元から再生成する。
- 参照元・索引・メタデータと変更文書の整合性、生成物の同期を確認する。

## 変更と確認

READMEと一般的な開発手順を分離し、公開範囲に合わない文書・タスク・添付資料を整理した。
製品の変更理由・再現条件・試験結果を残し、過去の判定を変更せずに公開用要約へ整理した。
規約と起票・実行手順を同期し、削除した参照先に依存していた利用者向けガイドを補った。

- 変更MarkdownのPrettier検査、差分の空白検査に合格した。
- HEADとの比較で、新規の相対リンク・見出し参照エラーは0件だった。
- `tasks:index:check`、`tasks:check`、`gen:codex:check`に合格した。
- 検証用Composeのイメージ指定を既存の公開設定方式へ揃え、配布サンプルでの `config --quiet`に合格した。
- 変更前原本はGit管理外の所有者限定領域に保全し、HEADとのバイト一致とGit除外を確認した。
- [独立評価](eval.md)はPASS。ステージ済み差分・ファイル名・索引・コミット文面の公開範囲を点検した。

## 対象外

アプリの動作、運用中サービス、公開済みGit履歴の書換えは変更しない。
現在のファイルからの除去は、過去コミットや既存の複製からの削除を意味しない。
