# レビュー: task-261108061451-recognition-storage-failure-isolation

## 判定

APPROVED

## 理由・申し送り

- S3生成とOpus圧縮がローカル保存より前にあり、例外で後続の保存を妨げることを現在の実装で確認した。保存を認識成功の条件から外す既存設計に基づく修正である。
- 保存受渡しは予約・所有コピー・投入の境界に限定し、受理済みジョブの所有者、単一実行器、上限、終了順序を維持する。通常例外を診断して認識成功を返し、取消と終了要求は伝播させる。
- 保存先の逸脱防止は、受信した会話IDをファイルパスへ使う境界で必要である。一時ディレクトリと固定入力で確認でき、実S3や評価音声は不要である。
- 必須の対象確認が今回の変更で失敗した場合は修正して再確認する。独立評価では、JSON・追跡情報・音声それぞれの保存先と、失敗後の枠解放・後続要求の継続を確認する。
- コメント品質の省略条件や根拠のない性能値は追加されていない。通信スキーマを変えず、挙動はサービス設計へ同期する範囲で実装可能である。

## 自律補完

- `AUTO_FIX`: 「設定配下から外への既存シンボリックリンクも拒否する」は会話ディレクトリだけでなく、既存のJSON・追跡情報・Opus・WAVファイルへのリンクも含む。ディレクトリだけの検査では既存ファイルリンク経由の逸脱が残るため、全保存対象を検査してから書き込む。保存領域を同時に書き換えるローカル攻撃者への耐性は今回の要求へ拡張しない。
- `AUTO_FIX`: コピー・投入失敗時は予約枠を一度だけ解放し、`recognition_storage` の受渡し失敗として本文や保存先を含めずに診断する。`CancelledError` などの通常例外以外は握り潰さない。既存のコピー失敗試験は、例外伝播の期待を新しい認識成功維持の期待へ更新する。
