# 音声認識実装のレビュー結果

## 対象と前提

抽出済みPCMをGoが結合・送信するところから、Recognizerの累積、NeMoの前処理・推論、固有名詞補正、結果送信、ローカル・S3保存までを確認した。
前後のSpeechExtractorとGoパイプライン、共有MessagePackモデル、設定クラス、ログ制御、既存テストと現行設計も照合した。
ローカル・オンプレミスでの会話利用を前提とし、外部推論APIや新しい依存を追加していない。
評価用音声は使わず、人工PCM・固定候補・一時ファイル・実スレッド・固定MessagePackで再現できる不備を修正した。

## 対応した指摘

| 優先度 | 再現条件と影響                                                                               | 対応                                                                                               |
| ------ | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 高     | 文脈補強が複数候補を返すと、文章全体の代替候補を連結し、重複文や混在した候補で採否を判断する | 先頭候補だけを比較し、空候補では元の結果を維持する                                                 |
| 高     | 受信int16をそのままNeMoの配列入力へ渡す。ReazonSpeechの正規化も整数PCMの振幅を変換しない     | float32へ変換して32,768で割る。正規化済み浮動小数点は縮小しない                                    |
| 中     | 辞書無効でもSudachiを生成し、初期化失敗で通常認識まで停止する                                | 空辞書では生成せず、初期化失敗を診断して補正を無効化する                                           |
| 高     | S3準備失敗やOpus失敗で、保存可能なローカルJSONや音声まで保存されない                         | 保存先ごとに障害を分離し、圧縮失敗時はWAVへ退避する                                                |
| 中     | 保存受渡しのコピー・投入失敗が認識の失敗として伝播する                                       | 枠を解放して失敗を診断し、認識結果を返す。取消は伝播する                                           |
| 高     | 認識サービスへ直接渡した会話IDや既存リンクにより、設定したローカル保存先の外へ書き込める     | 単一ディレクトリ名と全出力のリンクを、最初の書込み前に検証する。通常Go経路は会話IDを生成・照合済み |
| 中     | 16kHz以外のメタデータ、会話ID変更、重複差分、未確定発話中のID変更を受け入れる                | 累積前に形式・会話・通番・発話順序を検証する。結合による通番欠番は許す                             |
| 高     | 終端のない音声や多数の待機要求で、累積PCMと共有推論キューが増え続ける                        | 64MiB・32件に制限し、超過は接続異常とする。確定後の音声を解放する                                  |
| 高     | 推論待ち中はWebSocketの切断を読めず、未開始の推論が残る                                      | 受信と認識を並行に進め、切断・空フレーム終了で取り消す。開始済みは回収する                         |
| 中     | 未開始Futureの取消直後に枠を返すだけでは、実行器の内部キューに保持物が残る                   | 入力参照を即時に外し、内部の待ち項目を取り出してから枠を返す                                       |

指摘の優先度は実装上の影響を示す。実音声の誤認識率や遅延を測定した順位ではない。

## 確認した既存動作

| 領域             | 確認内容                                                                           |
| ---------------- | ---------------------------------------------------------------------------------- |
| 音声抽出との接続 | 16kHz差分PCM、同じ発話内の無音保持、確定後の発話ID増加                             |
| Goの送信と応答   | 未応答1件、未送信差分だけの結合、最終通番・確定状態の維持、応答照合と世代回復      |
| NeMoの段階別推論 | 通常認識と再デコードでのエンコード共有、例外時の設定復元、テンソル参照の要求内解放 |
| 固有名詞補正     | 一意読み補正、曖昧語の保留、確定時だけの候補再試行、失敗時の通常結果維持           |
| 設定とログ       | 設定クラスからWorkerへの反映、認識本文ログの無効化、保存内容と運用診断の分離       |
| 保存と終了       | 所有コピー、保存待ち中の別接続推論、有限枠、受理済み保存の回収、外部符号化の期限   |

確認で必要となった試験は各タスクの確認結果に記録した。保存境界と入力・取消の変更は仕様と実装を独立確認した。

## 未検証事項と限界

- 実音声の文字誤り率、固有名詞の過補正率、小声・雑音・方言・発話終端の品質は未評価。
- GPU実モデルの認識結果比較、遅延、同時接続時の実測容量は未評価。64MiBは保持量の上限であり、GPUがその長さを処理できる保証ではない。
- NeMoの非公開の準備・復元APIへの依存は維持している。更新時には実モデル比較が必要。
- 実S3と実際の音声符号化器への接続確認は行わず、失敗注入と一時保存で挙動を確認した。
- ローカル保存領域はサービス管理下を前提とし、同時にリンクを書き換えるローカル利用者との競合対策は対象外。

音声が未準備であることを理由に実装修正を保留せず、品質測定を修正済みの証拠として扱わない。
