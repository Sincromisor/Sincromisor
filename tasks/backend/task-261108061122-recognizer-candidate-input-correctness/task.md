# 音声認識の候補選択と入力正規化を修正する

## 背景 / 目的

音声認識全体のレビューで、文脈補強が上位候補を文章の断片として連結する不備を確認した。
`decode_candidates` は文章全体の代替候補を返すため、連結すると同じ発話が重複するか、別候補の同音異義語を混ぜて採否を誤る。
また、ReazonSpeechの `norm_audio` はサンプルレートとチャンネル数だけを正規化し、NeMoの配列入力も整数PCMの振幅を変換しない。
16ビットPCMを学習時の浮動小数点振幅へ変換する必要がある。
辞書無効時にもSudachi辞書を生成し、辞書初期化失敗で通常認識まで起動できなくなる経路も解消する。

## 完了条件

- [x] 文脈補強では先頭の認識候補だけを比較・採用し、代替候補を連結しない。空候補なら元の結果を保持する。
- [x] 16ビットPCMを `float32` の `[-1, 1)` へ変換し、既存の浮動小数点入力と前後0.5秒の余白を維持する。
- [x] 空辞書ではSudachiを生成せず、辞書初期化失敗時は診断して通常認識を継続する。
- [x] 人工PCMと候補列による回帰テスト、対象静的検査が通る。

## スコープ境界

SpeechRecognizerNemo、Workerの文脈補強、RecognizerPostProcessor、対応テスト、サービス設計とREADMEを対象とする。
通信形式、認識モデル、辞書列、優先度の重みは変更しない。
評価用音声がないため、日本語の認識精度・過補正率・GPU実モデル比較を完了条件にしない。

## 確認方法

対象pytestとRuff・ty、変更Markdownの整形、タスク管理検査を実行する。
モデルの代わりに固定候補を返し、PCMの端値・浮動小数点入力、複数候補・空候補、辞書無効・初期化失敗を確認する。

## 確認結果

- 認識パッケージのpytest: 43件と7件の副試験が成功。GPUモデルと評価用音声は使っていない。
- 対象のtyとRuff整形が成功。Ruffは既存のモジュール名・入れ子with・公開一覧順・末尾returnの指摘を除く対象検査で成功し、新規指摘は解消した。
- 候補が複数ある場合に一文だけが返ること、空候補時の保持、PCM端値と浮動小数点入力、辞書初期化の縮退を確認した。
- 実音声の認識精度、GPU実モデルでの比較は未実行。コメント点検はPASS。
