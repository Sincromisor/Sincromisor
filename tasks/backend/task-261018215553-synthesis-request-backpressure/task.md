# 音声合成の未完了要求上限で待機し会話切断を防ぐ

## 背景・目的

逐次音声対応の実環境配備で、LLMから音声本文が短時間に9区間以上届くと、Goの未完了合成要求上限8件を超え、パイプラインが再接続して音声が欠落した。初回合成完了前に9区間が到着する通常の会話で再現した。配備は旧版へ復旧し、本修正後に再試行する。

## 範囲・方針

`internal/pipeline/client/synthesizer.go`の要求予約を、枠が空くまで待つ処理へ変更する。未完了8件という容量、要求ID・発話ID・区間順序の検証を維持し、上限到達だけを接続故障として扱わない。完了受信・呼出元の取消・接続終了で待機を解放する。待機中に受信側のロックを保持せず、送信順を維持する。通信形式・Python・フロントの変更は不要である。

## 完了条件・確認

- [x] 8件が未完了の状態で9件目が待機し、最古の完了後に要求IDと送信順を維持して送れる。
- [x] 待機中の取消・切断で呼出元が終了し、要求枠を漏らさない。
- [x] 9件以上を送る実WebSocket結合テストで全要求が完了し、従来の順序検証と競合検査も通る。
- [x] 設計の上限制御の説明と対象コメントを同期する。

対象Goパッケージのテストとrace検査を行い、独立レビュー・評価を受ける。実環境の両入口での会話再確認は[配備タスク](../../deployment/task-261018214345-deploy-streaming-audio/task.md)で記録する。障害ログ原本と実接続先は非公開の運用領域へ保管する。
