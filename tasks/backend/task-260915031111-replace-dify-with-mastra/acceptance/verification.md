# 実環境の確認

確認日: 2026-09-15。実装 `82380738` と、前提のAgentServer `e16e051f` を使用した。
既存のConsul、Go RTC、音声区間抽出、NeMo音声認識、VOICEVOX合成を通した。
ブラウザーはplaywright-cliの一時セッション、入力はVOICEVOXで生成した検証用音声、VRMは公開サンプルを使った。
実録音・管理者トークン・認証済みブラウザー状態は公開成果物へ保存していない。

## 会話と公開設定

| 確認           | 実測結果                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| 通常会話       | マイクへ合成した挨拶を送り、認識文字列とMastraの日本語応答をtext_chで受信し、画面へ表示                              |
| 同じセッション | 認識された自己紹介「私の名前は青いです。」の後に「私の名前を覚えて。」へ「青さんですね！」と応答                     |
| 別セッション   | 前の名前を与えず新規開始し、名前を尋ねると「あなたの名前を知ることはできません」と応答。前の名前の混入なし           |
| MCP            | 合言葉取得を求め、検証MCPの実呼出し記録と「琥珀の月583」の回答を照合。固定値は事前にモデルへ渡していない             |
| MCPの読み上げ  | telop_chの音声列に「コハクノツキゴヒャクハチジュウサン」を確認。ツール引数・内部イベントは表示・読み上げへ混入しない |
| 音声受信       | inbound-rtpの受信296311バイト、7452480サンプル、totalAudioEnergy 0.54396を確認                                       |
| Studio公開     | 挨拶の指示を編集・保存・Publishし、新規ブラウザー会話で「こんにちは、設定を反映しました。」とexpression_code=4を受信 |
| 表情適用       | 既存診断で `code=4 preset=happy exists=true intensity=0.34` を確認。`^4` 自体は表示本文から除去                      |
| GPU共存        | RTX 5060 Ti 16GBでGemmaと音声認識を実行し、使用8884MiB・空き7169MiB。OOMなし                                         |

生成結果は確率的で、長い会話では新しい文体指示への追従が弱い例もあった。
公開した設定自体はAPIへ反映され、新規セッションで反映を確認した。
音声認識は合成入力を複数の発話へ区切り、「あおい」を「青い」と認識した。
検証は認識された文字列を基準に文脈の維持・隔離を照合した。

## 生成中の切断

ブラウザーから長い回答を求め、llama-serverの `is_processing=true` を確認した直後にPeerConnectionを閉じた。
`is_processing=false` への遷移と、llama-serverの `cancel task`、対象スロットの解放を照合した。
初回の検証スクリプトは停止ボタンの参照が失敗したため、RTCの実接続を直接閉じる方法で再確認した。

## sincro単独

AgentServerとllama-serverが `exited` の状態で、TextProcessorのMastra URL・トークン・エージェントIDを空にして再作成した。
ブラウザーからsincroを開始し、認識された「これは温泉。」を同じ本文で返し、telop「コレワオンセン」を受信した。
音声受信97527バイト、totalAudioEnergy 0.04318を確認した。Mastraへ接続せず動作した。
