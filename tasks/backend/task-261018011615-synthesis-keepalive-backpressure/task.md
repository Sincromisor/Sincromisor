# 音声合成WebSocketの受信停止と生存確認の競合を修正する

## 背景と目的

[原因調査](../../failure-diagnostics/task-261018011035-synthesis-keepalive-investigation/task.md)で、Uvicorn 0.54.0の `websockets-sansio` が要求滞留時にソケット受信を停止する一方、Ping送信とPongの期限判定を継続する問題を再現した。音声合成ワーカーは一要求ずつ処理するため、相手がPongを送っていてもサーバーが読めず、1011で切断して未完了の音声が欠ける。
起票時のHEADは `83dd90c8`。対象は音声合成接続のこの誤切断であり、合成HTTPの待機期限やブラウザーのWebRTC接続ではない。

## 修正方針

音声合成サービスのUvicornプロトコル層で、ローカルの受信停止と生存確認を連動させる。採用中のSansIO実装に必要最小限の補正を加え、VoiceSynthesizerProcessの `uvicorn.run` から明示的に選択する。Uvicorn全体の複製やプロセス全体への動的書き換えは行わない。

- 受信停止中は新しいPingを送らず、停止前に送ったPingの待機期限でも誤切断しない。
- 受信再開時に停止前の待機状態を整理し、新しいPingによる監視を再開する。遅れて届く古いPongを新しいPingへの応答として扱わない。
- 受信可能な状態では、現在と同じPing間隔・応答期限を使い、本当にPongを返さない相手を切断する。
- タイマーと待機中Pingは接続が所有し、同じイベントループの単調時計を使う。通常終了、相手の切断、サーバー停止では回収し、終了後に再開しない。停止・再開が重なってもタイマーを重複させない。

音声合成の逐次処理、同期I/Oのスレッド実行、取消時の回収、順序、既存の受信抑制とメッセージ容量制限を維持する。無制限の先読みや並列合成は追加しない。
恒久的な監視無効化、タイムアウト延長だけの回避、非推奨の `ws="websockets"` への切替では完了としない。依存内部へ接続する箇所は局所化し、採用理由と上流修正へ置換できる条件を実装コメントへ残す。

## 完了条件

- [x] 複数の合成要求が滞留して受信停止がPong期限を超えても、この競合による1011切断は発生せず、送信した全要求に対応する結果を順序どおり一度ずつ受信する。
- [x] Ping送信後に受信停止へ入る場合も誤切断せず、再開後は新しいPingへの応答を判定する。古いPongで新しい期限を解除しない。
- [x] 受信可能な状態の無応答は期限内に検出する。通常終了・切断・サーバー停止後にタイマーや待機処理を残さない。
- [x] 実際の起動処理が補正済みプロトコルを選択し、既存の合成処理・取消・資源解放と診断ログを維持する。
- [x] 実Uvicornと実ワーカーによる回帰確認、関連する既存テスト、設計文書の同期を完了する。必須確認の失敗は修正してから完了する。

## 変更範囲

- `sincromisor-server/voice-synthesizer/VoiceSynthesizerProcess.py` のWebSocketプロトコル選択。
- 同サービスの `src/voice_synthesizer/` 配下に置く、受信停止と生存確認を連動させる小さなプロトコル補正と対応テスト。
- `sincromisor-server/voice-synthesizer/tests/test_blocking_work.py` などの既存試験、および起動設定を確認する `sincromisor-server/sincro-config/tests/test_websocket_lifecycle.py` の関連箇所。
- [VoiceSynthesizer設計](../../../documents/design/backend/services/voice-synthesizer.md)の接続監視と同期処理の説明、[音声パイプライン契約](../../../documents/design/contracts/audio-pipeline-websocket.md)の時間切れ・監視の説明。

MessagePack、エンドポイント、音声形式、Goの再初期化・破棄方針は変えない。契約文書に残る「Goが10秒ごとに能動Pingを送る」という古い記述は、現行コードに合わせて修正する。GoへのPing追加は行わない。
他のPythonサービスへの一括展開、新しい設定キー、依存の一括更新、未完了音声の再送、VPS・検証環境への配備は対象外とする。

## 確認方法

原因調査の人工要求と再現条件を、公開可能な固定データによる回帰試験へ取り込む。非公開の調査スクリプトがない環境でも実行できる形にし、実会話・音声・接続先を持ち込まない。

1. 実ワーカーの合成処理だけを待機に置き換え、採用中の実UvicornとループバックWebSocketで8件をまとめて送る。短縮した期限で未修正プロトコルの誤切断を確認し、補正後は全8件を受信できること、受信再開後にもPing/Pongが成立することを確認する。
2. タイマーの境界は、Ping送信後の停止、停止と再開の繰り返し、古いPong、受信可能な状態でのPong無応答、停止中の接続終了を対象に絞って確認する。実時間を長く待つ代わりにイベント・単調時計を制御してよいが、実Uvicornを通る結合確認は省略しない。
3. 既存 `test_blocking_work.py` と接続終了の対象テストで、逐次処理・取消・資源解放の回帰を確認する。Pythonの対象検査と変更Markdownの整形・リンク確認も行う。

40秒を超える再現を毎回走らせること、実VOICEVOX・GPU・VPS・ブラウザー・長時間負荷の確認は必須にしない。再現で変更したプロトコル状態を、実ワーカーの送受信後まで検証する。

## 作業経路

時間切れと接続寿命を変更するため、起票時の独立レビューと実装後の独立評価を行う。実装は現在のワークツリーを基本とし、既存の利用者変更を保全する。

## 実装・確認結果

`BackpressureWebSocketProtocol` を音声合成の起動処理から明示選択した。上流の要求キューと受信抑制を保ち、受信停止時にPing予約・Pong期限・待機ペイロードを回収する。再開後は終了状態と既存予約を確認して監視を始め直す。通常のClose交渉でも監視を回収し、接続断とサーバー停止は上流の回収処理を使う。合成処理、通信形式、設定値、Go実装は変更していない。

- 実Uvicorn 0.54.0 / websockets 17.2と実ワーカーの比較試験: 合成を1件0.12秒の待機に置換し、Ping間隔・Pong期限各0.15秒で8件をまとめて送信。未修正版の受信停止中の1011、修正版の全8件の順序どおりの返却、全件返却後のPing/Pong再開、重複結果がないこと、診断ログと終了時の資源回収を確認した。
- 単調時計を制御した境界試験: Ping送信後の停止、複数要求のキュー、停止と再開の反復、古いPong、無応答の期限、通常Close・相手Close・接続断・サーバー停止、Pong期限なしの既存設定を確認した。
- 新規13試験と、音声合成の既存試験・`test_websocket_lifecycle.py`・`test_websocket_first_failure.py`・`test_synthesizer_serialization.py` は計80件PASS。既存の中央ログ結合専用試験1件は環境変数未指定のためスキップした。
- 変更PythonのRuff、整形、音声合成の変更本番コードのtyはPASS。Ruffは既存のCamelCaseファイル名に対する `N999` だけを除外した。変更Markdownを整形し、相対リンクと設計索引からの導線を確認した。コメント点検: PASS。
- [独立評価](eval.md)はPASS。評価者が対象37試験と型・整形を再確認し、上流実装との停止・再開・終了の対応も点検した。

検証はDockerの `default` 接続先にある既存イメージ `sincro-deps-python:verify`（ID `21ba118e3fbc`）を使用した。`sincromisor-server/` を `/opt/sincromisor/sincromisor-server/` へ読み取り専用で渡し、`--network none` の一時コンテナで `uv run --no-sync pytest`、`ty check`、`ruff check`、`ruff format --check` を実行した。ループバック以外の接続、イメージのビルド・取得、稼働サービスの変更は行っていない。一時コンテナは `--rm` で回収した。

実VOICEVOX・GPU・VPS・ブラウザー・長時間負荷の確認と配備は対象外として未実施。補正はUvicornの内部フックに依存するため、依存更新時には今回の回帰試験で停止・再開・終了の動作を確認する。
