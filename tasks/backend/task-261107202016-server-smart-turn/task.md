# SileroとSmart Turnでサーバーの発話終端を判定する

## 背景と方針

ユーザーは変更量の節約よりサービス品質と処理の合理性を優先し、端末負荷を増やさずサーバー側へ発話判断を集約する方針を承認した。基点は763492100315b42396b265fde69fd3e30666d1ec。MediaPipe/YAMNetをSilero ONNXへ置換し、Smart Turn v3.2 CPU版を休止時に実行する。Pipecat全体や外部推論APIは導入しない。

## 完了条件

- [x] Sileroの16kHz連続512サンプル入力と接続別状態、Smart Turnの直近8秒・先頭ゼロ埋め・公式相当特徴量を実装する。モデルは版・ハッシュ・ライセンスを固定し、起動時のダウンロードを不要にする。
- [x] 音声受信・VAD・終端推論の待機を分離する。入力順序と有限バッファを保持し、過負荷は黙って欠落させず接続失敗にする。再開発話・次発話・切断に跨る古い推論結果を採用しない。
- [x] 先行音声と発話内の無音を保つ。32msのVAD判定と約200msの認識向け差分送信を分離する。speech_id/sequence_id/confirmed、差分PCMの既存契約を維持する。
- [x] max_silence_msは現行のchat=1000、sincro=600を維持し、Smart Turnの初回判定待ちと推論失敗時の従来相当確定に使う。未完了なら同じ発話を継続し、連続無音3000msを待機上限とする。同一休止で繰り返し推論しない。これは品質評価前の保守的な初期方針であり最適値とはしない。
- [x] サービスがモデルと有限の推論実行器を所有し、切断・終了時に未開始を取消し、開始済みを回収する。音声や認識本文なしで確定理由・サンプル位置・推論時間を観測できる。
- [x] 依存ロック、モデル準備、Dockerfile、関連設計を同期する。実モデルのロード・前処理・推論と、偽モデルによる競合・PCM整合・代替動作を確認する。

## 範囲と確認

SpeechExtractor、モデル資材、Docker/speech-extractor、依存ロック、音声パイプライン契約と設計を対象とする。RTC/Recognizerの利用側との整合も確認する。新しいネットワークサービスや先行LLM生成は追加しない。

対象pytest、Ruff、ty、Go契約試験、全体ゲート、独立レビュー・評価を実行する。モデル品質の実音声比較は別タスクに置き、合成音声や無音の成功を品質証明にしない。本番環境の配備は含まない。

## 実行結果

Silero v6.2とSmart Turn v3.2 CPUを固定ハッシュ・ライセンス付きで導入し、モデル準備、依存ロック、Dockerfile、設計と契約を同期した。受信・VAD・終端推論・送信を分離し、接続別状態、有限キュー、差分PCM、休止ごとの判定、無音上限と障害時の扱いを実装した。通常会話のフロント設定と合わせて適用する。

独立評価で受信端数に含まれる再開音声を旧結果で確定する不具合を再現し、端数まで分類した境界で結果を採用するよう修正した。推論開始は32ms境界を保ち、採用に最大128msの整列待ちが加わる。初回評価FAIL後の再評価でPASSとなった。

- サービスpytestは実ONNXロード・推論、公式特徴量との一致を含む36件成功。旧YAMNet専用モジュールは通常実行で1件省略し、別実行の7件は成功した。
- Ruff、整形、ty、Go音声パイプライン4パッケージ、全体ゲートの静的検査・型ビルド・フロント試験が成功した。
- Dockerビルドとネットワークを遮断した実モデル推論が成功した。合成入力は推論動作の確認であり、発話品質の証明ではない。
