# レビュー: task-261107202016-server-smart-turn

## 判定

APPROVED

## 理由・申し送り

- サーバー側への判断集約、SileroとSmart Turnの役割分担、実音声品質を速度より優先する方針はユーザー要求に合う。既存の16kHz・モノラル・20ms入力と、発話内の差分PCMをRecognizerが累積する契約に整合する。
- 現行の抽出処理は分類と受信が直列で、送信後にPCMを消去する。受信の分離、推論用音声の保持、接続別のSilero状態、古い推論の無効化は実装に必要な要件であり、過剰な追加ではない。
- `max_silence_ms`は現在の無条件確定期限から、Smart Turnの初回判定待ち・推論失敗時の確定基準へ意味が変わる。音声パイプライン契約、SpeechExtractor設計、Goクライアントのコメントを同時に更新する。値とMessagePackの形式を維持しても、終端の挙動変更は明記する。
- 32msの判定単位で既存の600ms・1000msと3000msを扱うため、境界を越えた最初のフレームで判断し、閾値前には確定しないことを確認する。端数を丸めて無音を二重加算しない。
- 実モデルのロード・特徴量・推論成功と、日本語の終端品質の証明を分けている。品質タスクの未完を隠さず、今回の差分による必須試験の失敗は修正・再確認してから完了する。

## 自律補完

- `AUTO_FIX`: 時刻基準は既存の入力サンプル位置を使う。無音期間・発話再開の世代・モデルに渡した末尾位置を同じ基準で扱い、更新される`start_at`を終端遅延の計測に使わない。実行時間と待ち時間は単調時計で別に測る。
- `AUTO_FIX`: モデルの未配置・破損・ロード失敗は起動失敗として扱う。Smart Turnの実行失敗は当該休止を無音方式で確定できる縮退として観測し、Sileroの実行失敗は発話判断が成立しない接続異常として扱う。失敗を「未完了」という正常判定へ変換しない。
- `AUTO_FIX`: 16kHz・モノラル・16ビットPCMと正の無音閾値を境界で検証する。3000msの待機上限と矛盾する閾値は拒否し、有限キュー上限は実装定数と理由をコメントに残す。
- `AUTO_FIX`: 完了した推論の採用は受信済み音声の処理と整合させ、発話再開後の古い完了結果を確定へ使わない。3秒上限や縮退で確定した後の遅着結果も次発話へ適用しない。開始済みの推論を強制停止したことにはせず、サービス終了時に回収する。
