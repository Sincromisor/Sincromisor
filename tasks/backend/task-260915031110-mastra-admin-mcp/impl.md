# 実装と確認

管理者用 `/data/mcp.json` の採用は2026-09-15のユーザー指示に基づく。
採用版Studioに任意認証ヘッダーの保存欄がないため、ファイル入力を設定スキーマ・検証・接続から分離した。
将来の管理画面も同じ境界を使える。使用ツールは標準Editorから選択・公開する。

## 実装上の判断

- `@mastra/mcp` 1.17.3を固定し、接続と終了hookは標準クライアントが所有する。終了時の接続解放と要求単位の取消を区別し、独自の重複した終了hookは追加しない。
- 発見には全体期限も置く。SDKのSSE代替接続が取消後も待ち続ける再現を受け、期限到達で接続を解放する。
- ツールの失敗・時間切れは出力processorで中断する。下位例外の詳細と認証ヘッダーをモデル・公開ログへ流さない。
- Gemmaでは本文先頭の表情コードを必須にする長い指示がツール選択を妨げた。短い任意表情の指示で実ツールと `^4` 付き日本語回答を確認した。コード省略時の標準表情は既存契約どおり。

## 確認結果

- 最終イメージをMCP設定・保存DBなしで一時起動し、通常会話の本文と成功終端を確認。一時コンテナは停止した。
- TypeScript、対象5テスト、Biome、本番Studioビルド、Dockerビルドが成功。
- 無害な認証付きMCPの合言葉を事前にモデルへ渡さず、実呼出し記録と回答「琥珀の月583」を照合。公開ツールと設定はコンテナ再作成後も保持された。
- 実エラーと2秒の待機上限は `tripwire` で停止し、本文・成功終端なし。会話全体の再実行なし。
- 実 `/stream` のクライアントをツール開始後に切断し、MCP側の取消数が1件増えることを確認。通常のクライアント試験もAbortSignal伝播とdisconnect完了を確認した。
- 設定不正・権限・未配置、発見不能、認証、実呼出し、失敗、期限、取消は実行可能な対象テストに残した。
- 設計と変更したシンボル・処理のコメントを点検した。資格情報は非公開の一時設定だけに置いた。

## 制限

接続変更は再作成で反映する。サービス終了hookはローカル接続の解放を行い、進行中の遠隔処理まで必ず取消す保証ではない。
Studioのフィードバック一覧は採用libSQL未対応で500になる既知の制限がある。指示・ツール選択・公開・会話には影響しない。
