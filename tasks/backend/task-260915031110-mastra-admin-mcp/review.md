# レビュー: task-260915031110-mastra-admin-mcp

## 判定

APPROVED

## 理由・申し送り

- ユーザー承認により、任意ヘッダーをStudioへ保存する不成立な前提を、管理者専用ローカルJSONファイルへ置き換えた。現行Editorの保存スキーマや独自UI/APIを拡張せず、`@mastra/mcp` の `requestInit.headers` を使える。
- 設定をZod JSONスキーマと読込み・接続処理に分け、`MCPClient.listTools()` が得たコード定義ツールをMastraのツールレジストリへ登録する。Studioは既存のツール選択と公開だけを担い、接続URL・資格情報を扱わないため、保存済みMCPクライアントの任意ヘッダー非対応を回避できる。
- `MCPClient` と接続済みツールはAgentServerが所有し、要求取消はnative toolへ渡す。nativeの終了フックが `disconnect()` を待つため、外側に重複したシグナル処理を追加しない。20秒のサーバー操作上限と最大5ステップは、既存のPython無受信30秒より先に無応答を返す。会話全体の再実行は追加しない。
- 設定なしとサーバー単位の発見失敗は空または成功したツールだけでAgentServerを起動し、通常会話を維持する。固定値を返すローカルMCPで、実LLMの呼出し記録、失敗、取消、終了後の接続解放を確認できる。

## 自律補完

- `AUTO_FIX`: 設定ファイルがない場合は空のツール集合として起動し、ファイルのJSON・スキーマ不正は起動時にキー名だけを示して拒否する。接続・発見の失敗はサーバー名だけを記録して継続する。
- `AUTO_FIX`: `timeoutMs` は各MCPサーバーのnative timeoutと発見の上限へ同じ20秒として渡す。`listToolsWithErrors()` を使う場合も、成功したツールだけを登録する。
- `AUTO_FIX`: 設定ファイルは既存の管理者専用`/data`永続領域に置き、例示は資格情報なし、実ファイルはnode所有・0600とする。変更はコンテナ再作成で読み直し、ファイル監視や再読込みAPIは追加しない。
