# ローカル管理者のMCP接続をMastraから利用する

## 背景 / 目的

Difyの外部連携に代わり、ローカル管理者が構成したMCPのツールを利用する。
前提は [task-260915031110-mastra-studio-session-memory](../../backend/task-260915031110-mastra-studio-session-memory/task.md)。資格情報と権限は管理者のものを使い、会話ユーザーの識別は追加しない。

## 完了条件

- [ ] Studioで管理者がMCP接続と使用ツールを設定し、標準エージェントへ公開できる。
- [ ] Gemma 4 E2BがMCPツールを呼び、その結果に基づく日本語の回答を返す。
- [ ] MCP未設定でも通常会話でき、接続設定・ツール選択はコンテナ再作成後も保持される。
- [ ] 無応答・失敗したツール呼び出しが設定した上限で終了し、成功結果の捏造や会話全体の自動再実行を行わない。
- [ ] 管理者の資格情報を会話本文、モデルへの指示、公開ログ・検証資料に含めず接続できる。

## 設計判断

- Mastraの `MCPClient` とEditorの保存済み設定を使い、独自設定UIやマーケットプレイスは作らない。
- 必須の接続方式は管理下のStreamable HTTPとする。URLと必要な認証ヘッダーを管理者がStudioで設定し、前提タスクの永続領域へ保存する。秘密を含む保存領域も管理者のみが扱う。
- 検証には固定データを返す無害なローカルMCPツールを1件使う。適切な既存実装がなければ最小の検証用サーバーを作り、通常Composeの常駐サービスへ加えない。
- 特定SaaSは指定されていないため、アカウント作成、サービス別OAuth、書込みを伴う実サービス操作は完了条件にしない。
- 会話ユーザーは有効化されたツールを管理者権限で使う。この前提を手順へ明記し、ユーザー別資格情報・権限管理は追加しない。
- 任意のstdio実行環境の同梱や汎用インストーラーは対象外。stdioを使う場合は管理者が固定済みパッケージを同梱する運用として案内する。
- クライアント接続、要求単位の取消、サービス終了時の解放を所有者に結び付ける。ツール待ち時間と最大ステップ数を明示し、無期限に待たせない。
- 接続・発見失敗で通常会話の起動を不必要に止めない。利用ツールの失敗は生成側・呼出元へ伝える。

## 変更範囲と文書

- 前提タスクの `sincromisor-server/agent-server/` の依存、Editor・MCP設定、対象確認。
- `documents/design/backend/services/agent-server.md` に接続設定、ツール選択、管理者権限、失敗時の扱いを記載する。
- 環境変数が必要な場合だけ設定サンプル・Composeと同期する。
- Difyプラグイン変換、RAG、会話側の承認・再開UIは対象外。

## 確認方法

- 型確認と本番ビルド。
- ローカルMCPの一覧取得、実LLMからの呼び出し、結果を使った回答を1経路確認する。結果の固定値をモデルへ事前に渡さず、呼び出し記録で実行を確認する。
- 制御可能な検証MCPで無応答・エラー・取消の後始末を採用クライアント経由で確認する。
- Studioの設定・公開と再作成後の保持、MCP未設定の通常会話を確認する。ブラウザー操作にはplaywright-cliスキルを使う。
