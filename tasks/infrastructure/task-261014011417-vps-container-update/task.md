# VPSのコンテナ更新と必須サービスの稼働確認

## 目的

VPSを現行ソースに対応するコンテナへ更新し、RTC・サービス探索・ログ収集と公開画面の稼働を実機で確認する。
実接続先、配置固有値、原本ログと復旧データは非公開の運用メモと作業領域に保存する。

## 完了条件

- [x] 更新前のソース・設定・イメージを復旧可能な形で保存する。
- [x] 現行ソースに対応するRTCとログ収集のイメージ、Compose、配信フロントをVPSへ反映する。
- [x] VPSの6サービス、HTTPS、Consul参加と下流探索、中央ログ配送を確認する。
- [x] ブラウザーからRTCの診断再生を確認し、非公開の運用メモを実測結果へ更新する。
- [x] 通常会話の認識・応答・非無音の合成音声・テロップを確認する。

## 方針

VPS固有の旧ブランチを保持して配備用ブランチを作る。保存ボリュームを維持し、再作成前に既存セッションとポート占有を確認する。
配布中のRTCは現行より古く、ログ収集2イメージはレジストリで取得できないため、今回に限りコミット済みソースを開発環境でビルドし、SSHで直接転送する。
VPS側の非公開Compose上書きで版を固定する。レジストリへの公開や他ホストの更新には作業を広げない。

実施日: 2026-10-14 JST。公開可能な結果だけを記録する。配備ソースは `9b0dc36f1b1edc18a0caeb5436e57cdc92a19ffd`。

### 依存サービス復旧後の確認

初回は開発環境のConsul・音声処理4サービス・中央ログが停止していた。続く利用者の依頼により、[ローカル更新タスク](../task-261014014239-local-container-update/task.md)で開発環境を更新・起動した。Consulは両ホストを含む14メンバー全件alive、criticalは0件となった。VPSの6サービスは全件healthyである。

Vectorは既存読取カーソルに対応する原本消失を検知していた。不明区間は2026-10-11 18:23:45 UTCから2026-10-13 16:22:09 UTCまで、件数不明。診断・カーソルを退避し、現在のカーソルと中央への配送成功を確認して、確認済みの欠落マーカーだけを解除した。原本・カーソル・配送バッファは削除していない。新着ログを中央で検索でき、配送監視の破棄・エラー累計は0だった。過去の欠落が回収できたことを意味しない。

Chromiumの公開HTTPS画面で通常の `chat` を開始し、RTC/ICE connected、認識結果と応答文129件、テロップ1,716件、受信音声5,745パケット、累積音声エネルギー0.024352を確認した。音声要素は非ミュート・再生中、ブラウザーエラーは0件だった。リポジトリの診断音声を模擬マイクとして使い、実音声・実写は取得していない。検証用ブラウザーは終了した。

繰り返し入力では `VoiceSynthesizer` 起点のパイプライン再接続を1回観測した。1発話後に十分な無音を置いた再確認では、1認識・1応答、非無音の合成音声とテロップを受信し、再接続は0件だった。詳細と検証上の制限はローカル更新タスクに記録した。

同じVPS上の旧公開サイトも同じRTCポートへ転送する設定だった。旧公開サイトのAPIも新RTCへ接続するが、その旧画面の更新・互換確認は本作業では実施していない。
