# 実装と検証の補足

## 検証環境と試験範囲

- macOSでGo単体確認と全体ゲートを実施し、ユーザーが指定・転送承認した`malvales`のLinux Dockerで人工ログの隔離Composeを実行した。稼働中のリポジトリ・サービス・ボリュームは変更していない。検証用ソースと診断ログはリモートの`/tmp/sincro-log-socket-test.UiMuD7`に置き、`.env`や実ログは転送していない。
- 二つの収集構成はネットワークと状態ボリュームを分離し、中央VictoriaLogsだけを両ネットワークへ接続した。これは複数の収集元からの識別と配送の確認であり、別物理ホスト間の疎通確認ではない。
- 初回の複数収集元試験では、無関係な過去journalの全走査でCPU負荷が上がり、配送待ちが時間切れになった。後始末前に人工構成のログとリソース状態を確認した。試験用設定だけに試験開始1分前の固定`--since`を加え、再試験は成功した。`--since`はVectorの`--after-cursor`と併用できないため、最初のVector停止前に元設定へ戻す。再開後は本番と同じ設定・永続cursorで、停止中・削除済みコンテナの原本を回収する。

## 正常性確認の時間制限

初回の単一収集元試験では、Vectorの正常性確認が4秒の制限を超え、初期の正常判定に至らなかった。実journalを読取専用で測定すると末尾1件の確認に約2.6秒、確定カーソルの確認単体に約6.3秒かかった。確定カーソルがある場合の重複した原本読取を省き、確認処理を10秒、Docker側の制限を12秒、状態の有効期限を45秒へ変更した。空journal、欠落したカーソル、追尾停止を異常とする条件は緩和していない。

独立評価で不足が指摘された配送状態移行・累計・再作成・破棄・再試行・復旧のGoテストを追加した。さらに、指標取得中の再起動ID変更と、配送判定前の一時的な正常公開を修正・確認した。

結合試験の不備として、Consulのチェック状態を読むAPI、人工コンテナのjournald向けラベル指定、初回用`--since`とカーソル再開の競合も修正した。旧試験定義で始まった実行は診断を保存して中断し、専用構成を削除してから修正版を実行した。
