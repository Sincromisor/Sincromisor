# レビュー: task-260921221014-logging-delivery-recovery

## 判定

APPROVED

## 理由・申し送り

- 現行の `docker_logs` 入力は短時間コンテナを収集開始前に終了させる実測済みの欠落を満たせない。task.md は入力方式を目的ではなく回収契約で選ぶとしており、原本を残した短時間コンテナ、収集停止、ローテーション、再作成の連番照合を採用条件にしているため、方式を先に固定する必要はない。
- Docker journald ドライバーと位置を保存する journal 入力を候補にする場合、Docker の原本保持期間、Compose ラベルから project/service/container を得る方法、journal の読取権限、入力ごとの永続 cursor を隔離 Compose で確認する。journal の vacuum・boot 変更・保持超過・原本削除で cursor を継続できないときは、件数を推測せず回収不能または不明の区間として状態と診断に残す。
- ログドライバーを切り替える場合は、短時間の初期化コンテナを含む標準 Compose の全対象へ同じ原本契約を適用する。`vector` の自己収集は内部ログ経路だけに保ち、コンテナ原本とホスト診断の journal 行を重複転送しない。Docker 側の project/service 等のラベルは収集側の識別子として扱い、ログ本文の属性で上書きさせない。
- 原本保存の上限、Vector のディスクバッファ、中央受理を別境界として測定する。Vector 再作成後はバッファと cursor を残し、中央停止からの復旧・再送重複を実数で照合する。満杯・原本削除・同期前強制終了では、検知イベントと不明区間を残し、保存済みログの欠落件数をゼロと断定しない。
- 業務コンテナの標準出力は、ログ送信の停止やバッファ満杯によって停止させない。採用する Docker ドライバーの非ブロッキング時の上限・破棄の観測点を明示し、容量超過試験で本体の処理継続と欠落検知を同時に確認する。
- 中央バックアップは VictoriaLogs の停止または整合した方法で作成し、保存ボリューム外の隔離領域へ復元して人工行を検索する。バックアップ後の区間と同時ホスト故障は復元保証に含めず、`storage.md` とログ設計へ保持範囲を同期する。
- 確認は隔離 Compose の人工連番と小さい上限で足りる。実運用ログ、長時間試験、物理障害の再現を要求しておらず、ホスト journal の原本・cursorはホスト診断タスクと同じ配置前提を使う。
- `internal_logs` を廃止して Vector 自身も journald 原本から一度だけ回収する変更は、確認応答を待てない内部入力の起動前・停止中ログを回収する根拠がある。固定版 Vector 0.58.0 の `filter_matches` は `contains_match` で一致するフィールドのいずれかを採用するため、単一入力の `include_matches` に Compose コンテナ、Docker/containerd、kernel、systemd、試験行を並べられる。固定語彙化と中央成功時の件数安定、停止時の反復制限を実測し、実際の Docker 原本と無害な host probe の両方が流れることを確認する。

## 自律補完

- `AUTO_FIX`: 候補方式は、短時間コンテナ削除後・収集停止再開・原本ローテーション・Vector 再作成を連番で満たすものを隔離 Compose で一つ選ぶ。既存の `docker_logs` が回収を保証しない実測と、task.md の採用条件に基づく通常の実装判断である。
- `AUTO_FIX`: journal のカーソル喪失、原本の保持超過、送信待ちの破棄は回収成功として扱わず、固定の状態・理由と不明区間を記録する。task.md と棚卸し L05/L06/L09 の欠落検知契約に基づく。
