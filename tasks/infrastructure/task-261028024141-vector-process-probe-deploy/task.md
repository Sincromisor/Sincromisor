# Vectorのプロセス探索を軽量化して稼働環境へ反映する

## 目的と範囲

ユーザーが依頼した追加実装とVPSへの配備を行う。Vectorのヘルスチェックは`/proc`の各候補でcatを起動し、journalctlの引数確認にもtr・grepを使っている。この探索をBashのread組み込みへ置き換え、既存のinit・GNU timeoutによる終了処理と合わせて配備する。

変更対象は`Docker/logging/check-vector.sh`、対象テスト、ログ設計とタスク記録とする。接続先・実配備情報・診断原本は非公開台帳とGit管理外の作業領域だけに記録する。既存の未コミットデータを変更しない。

## 完了条件

- [x] プロセスごとの外部コマンド起動をなくし、journalctlの独立した`--follow`引数だけを正常と判定する。探索中のプロセス終了を異常終了にしない。
- [x] 正常な追尾、追尾なし、終了後の不在を対象テストで確認し、既存のカーソル・終了処理試験が通る。
- [x] 配備先のソース・選択構成・イメージ・保存先・コンテナ状態を確認・退避し、変更を限定して反映する。
- [x] Vectorだけを再作成し、同じイメージと永続領域を維持する。init有効、healthy、ゾンビ不在と複数周期での非増加を確認する。
- [x] 対象外サービスのコンテナIDが変わらずRTCの正常性を維持する。設計、配備記録、非公開台帳を更新する。

## 配備方法と復旧

配備先は既存の履歴を保持し、未コミット変更を上書きしない。対象ファイルの基点を確認し、前回修正`db84ea35`と今回の変更だけを適用する。イメージは既存の確認済み版を再利用し、取得・ビルド・ボリューム削除は行わない。Composeのファイル順序、プロジェクト名、プロファイル、既存のイメージ指定を維持する。

変更前の対象ファイル・Compose実効設定・コンテナ情報を非公開領域へ退避する。配備後に実効設定の差分がVectorのinitとヘルスチェックだけであることを確認する。バインドマウントを揃えてVectorだけを`up -d --no-deps --no-build --pull never --force-recreate vector`で再作成する。配備先のソースはコミットで識別し、作業履歴を破棄しない。

起動失敗時は状態と限定したログを非公開に保存し、対象ファイルを退避版へ戻して同じイメージ・保存領域でVectorを復旧する。RTCや他サービスの再作成、journal・カーソル・バッファの削除へ広げない。

## 確認方法

対象のシェル構文、Compose構成、JavaScript・Markdown整形と、既存Vectorイメージを使う隔離テストを行う。稼働環境への反映前に実装と配備範囲を独立確認する。配備後は数回の自然なヘルスチェックとプロセス状態を確認する。会話経路・通信契約は変更しないため音声会話の再試験は行わない。
