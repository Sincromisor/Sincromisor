# 実装と配備の判断

## 変更と確認

追尾プロセスの探索はBashのread・mapfileだけで行う。commを読んだ後にプロセスが終了する場合も、cmdlineを開く失敗を条件式で受けて次の候補へ進む。引数はNUL区切りの配列にし、改行を含む別引数を追尾フラグと誤認しない。

状態ファイルの保存処理は失敗を許容する条件式へ含めず、書込み失敗時の非ゼロ終了を維持した。実VectorのHTTP確認と人工journalを使い、追尾なし、紛らわしい引数、正常な追尾、追尾終了後の異常を検証した。既存のカーソル・時間切れ後の回収試験も通った。

## 配備の境界

配備先は既存の履歴へ対象の運用ファイル4本だけを追加コミットし、他のmainの変更は持ち込まない。実効設定はVectorのinitとヘルスチェックだけが変わることを機械比較し、同一イメージ・同一マウントを維持する。退避、接続先、配備SHA、診断原本と時刻は非公開台帳・作業領域へ記録する。

ローカルでは実装を先にコミットして配備対象を固定し、配備後のタスク完了記録だけを同じコミットへまとめる。実装差分の独立評価と稼働環境の反映確認を分け、配備結果を評価担当者へ渡す。

## 未実施事項

通信経路・会話処理は変更していないため、音声会話の再試験と中央への新着配送確認は行っていない。短時間の反映確認であり、日単位の連続稼働試験は行っていない。
