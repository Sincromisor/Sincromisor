# Composeだけでローカル会話を開始できるようにする

## 背景と目的

利用者にプロジェクトやLLMの知識を要求せず、既定設定で `docker compose up` を実行し、
同じホストの `http://localhost:8086/` から使えることを基本原則とする。
ユーザーの追加指示に従い、運用プロファイルは維持して配布する `.env` の既定値を設定する。
既存の `.env` と未追跡の固有名詞辞書は変更しない。

## 完了条件

- [x] `.env` サンプルは `full,chat`、広告IPv4は `127.0.0.1`、STUNは空欄とする。
- [x] 保存先の作成、会話用モデル取得・検証、内部認証情報の生成を初期化コンテナが担う。
- [x] 再起動時は既存モデルと認証情報を再利用し、取得失敗・破損を正常モデルとして扱わない。
- [x] READMEからモデルの選別・手動取得・手動権限設定を除き、起動と利用方法を案内する。
- [x] 構成・保存領域・関連サービスの設計と設定サンプルを同期する。

## 実装と確認範囲

`service-initializer` が認識キャッシュの権限と共有トークンを準備する。
`chat` 専用の `llama-model-initializer` が固定モデルを欠損時に取得し、
チェックサム確認後だけ完成ファイル名へ改名する。
AgentServerとTextProcessorは読み取り専用ボリュームから未指定の認証情報を読み込む。
独自の認証方式や依存ライブラリは追加せず、既存の環境変数へ渡す。

プロジェクトのイメージはComposeの `pull_policy: build` で自動ビルドする。
配布済みイメージを使う運用は `--no-build --pull missing` で選択できる。
HTTP・WebSocket・DataChannelの形式は変更しない。

## 確認結果

- `node --test scripts/tests/{service-initializer,llama-compose,nemo-compose,consul-compose}.test.mjs`: 7件成功。
  既定構成、運用プロファイル、公開範囲、初期化依存、キャッシュ・トークンの再利用、
  明示トークンの優先、認証ファイル欠損、取得失敗、破損モデルの拒否を確認した。
- 空の一時保存先へ実モデル約2.84GBを自動取得し、SHA-256検証と改名に成功した。
  再実行は `--network none` で成功し、ダウンロードを行わず再利用した。
- 検証専用AgentServerで、自動生成トークンによるAPI接続200と認証なし401を確認した。
  TextProcessorと同じUID 1001からも共有ボリューム経由で認証付きAPI接続200となった。
- playwright-cliで稼働中の `http://localhost:8086/` から会話画面へ遷移し、
  初期モードが `chat`、開始ボタンが表示されることを確認した。
  ブラウザーの外部STUN設定を空にして、ループバック候補で接続が `connected`、
  DataChannelが `open` になることも確認した。

- 変更MarkdownのPrettier確認、変更テストのBiome確認、シェル構文確認、
  `git diff --check`、`tasks:check`、`tasks:index:check`: 成功。
- 補助的なComposeのドライランは、並列時に存在する依存サービスを欠損と判定し、
  直列時は依存待ちで進まなかったため中断した。起動計画全体の成功確認には使っていない。
