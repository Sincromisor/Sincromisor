# Consulの長期停止後の起動拒否を防ぐ

## 背景 / 目的

検証環境を長期間停止するとConsulが起動できなくなるというユーザー報告への対策を起票・実行する。
調査時点のHEADは `a9011905309a883caec77ba395bb07e540a508e7`。
既存Composeは単一サーバーと永続ボリュームを使い、Consul標準の停止許容期間7日を変更していない。
現在の実環境は正常稼働中のため、過去の障害原因は断定せず、一時コンテナで同じ条件を再現する。

## 完了条件

- [x] 7日を超える停止を模したデータで標準設定の起動拒否と変更後の起動成功を確認する。
- [x] 既存データを削除せず、単一サーバーの停止許容期間を延長する。保存したKVが再起動後も読める。
- [x] Compose、環境変数例、設計文書を同期し、既存環境への反映方法と適用範囲を記載する。

## 設計判断 / 変更範囲

通常変更として親が直接実装する。`compose/consul-server.yml` の起動引数からConsul標準設定を渡し、
`examples/compose.env` に `SINCRO_CONSUL_SERVER_REJOIN_AGE_MAX` を追加する。
既定値は `87600h`（365日換算10年）とし、既存 `.env` の追記なしでも適用する。
根拠は長期休止後に再開したいというユーザー要求と、データ損失を避ける安全性である。
停止期間の検査そのものや永続化は無効化しない。複数サーバー対応、証明書期限切れ、イメージ更新は対象外。
設計文書は `documents/design/infrastructure/consul.md` を更新し、設計索引の既存リンクを確認する。

## 確認方法

- Composeの展開結果で未設定時の既定値と明示上書きを確認する。
- 一時コンテナでKV保存後に停止し、`server_metadata.json` の `last_seen_unix` を30日前へ書き換える。
  標準設定で起動拒否を確認し、新設定で再起動してリーダー選出とKV保持を確認する。
- 検証成功後、稼働環境のConsulだけに変更を反映し、正常性と登録サービスを確認する。
- 変更Markdownの整形・点検、タスク索引と整合性、コミット形式を確認する。
