# FFmpegと内部処理の失敗原因を安全に記録する

## 背景と目的

`internal/media/synthdecode/decoder.go`はFFmpegのstderrを受け取るが、失敗時に本文を保持せず、`internal/rtc/outbound.go`も分類中心のログとなる。
既存のJSON化だけでは失敗原因の診断は増えないため、[棚卸し](../task-260921221013-logging-coverage-inventory/task.md)で判明した内部処理の欠落を補う。

## 変更範囲と方針

- 最初の対象はGoの`synthdecode/decoder.go`、`runner.go`、エラー型、`rtc/outbound.go`と全呼出し元とする。
- FFmpegの起動確認・復号失敗で、実行段階、終了コード、取消/時間切れ、安全に抜粋したstderr、切詰めの有無、取得可能な会話/発話IDを内部運用ログへ残す。
- 既存の出力上限・時間切れ・部分結果破棄と固定のエラー分類を維持する。stderr取得のために追加の無制限実行や二重起動をしない。
- 現在はpayloadや自由文のCauseを観測境界へ出さない設計である。任意のerror全文をそのまま許可せず、診断用の限定項目と長さ制限・秘密除去を設け、関連する設計とテストを同時に修正する。
- 音声バイナリ、本文を含むメタデータ、トークン・接続資格情報を診断経由で出さない。内容ログ無効時も安全な失敗理由は残す。
- Python下流の例外、HTTP/WebSocket失敗、AgentServer/MCPの握り潰し箇所も表と照合し、相手先の識別・失敗段階・安全な原因が欠ける箇所を補う。全量の外部応答やツール入力を無条件で出さない。
- 追加領域が独立した大きな修正になる場合は個別タスクへ分割し、最終結合確認の依存へ追加する。FFmpegだけで全内部診断が揃ったと扱わない。

## 棚卸しで具体化した診断対象

[網羅性表](../task-260921221013-logging-coverage-inventory/coverage.md)のR01〜R07、C16〜C19/C34を実装対象とする。

- R02: `sincro-models/.../SpeechExtractorResult.py:to_opus`と`VoiceSynthesizer.py:encode`のopusenc/fdkaac、および認識のローカル/S3保存を含む全呼出し元を点検する。起動不能・非ゼロ終了・安全に制限したstderr・処理段階を残し、音声や本文を出さない。人工コマンド失敗で確認する。
- R03: `VoiceCacheManager.py`のS3読取失敗を通常のキー不存在と区別し、Redis/S3の取得・保存、音声生成例外、NeMoのファイル保存失敗に操作・相手先・取得可能なID・安全な理由を残す。403・接続断・書込拒否・破損キャッシュで確認する。
- R04〜R06: HTTP/SSE異常終端、MCP発見/実行の固定エラーへの置換、LLM/DB失敗を点検する。既存の秘密除去を維持して安全な段階・分類を加え、正常完了・取消・失敗を区別する。
- C16〜C19/C34、R07: `Docker/service-initializer/initialize.sh`、`with-token.sh`、`with-s3-secret.sh`、`Docker/seaweedfs/s3-bootstrap.sh`と登録シェルで、開始/完了、秘密やモデルの検証・権限・登録の失敗段階を出す。weed shellの秘密を含む出力は公開せず、安全な原因分類を残す。無言の`test`失敗や登録失敗後の成功表示、子プロセス正常終了時の空の終了コードも点検する。
- 初期化と登録の確認は隔離した保存先とHTTP/コマンド代役を使う。正常・再利用・不存在・書込拒否・登録先不通を確認し、秘密値がないことを検査する。短命コンテナの回収は回収タスクが担当する。
