# レビュー: task-260921221014-runtime-failure-diagnostics

## 判定

APPROVED

## 理由・申し送り

- R01 は `synthdecode` の実行境界で終了状態、取消、時間切れ、出力上限を確定し、`rtc/outbound.go` で会話 ID と音声 ID を付与する。FFmpeg の生の `stderr`、入力名、エラー文字列を公開エラーやログへそのまま渡さず、既知の診断だけを有限長で整形する。入力メタデータに由来する任意本文・URL・認証情報が混入しても出力しないことを、偽コマンドで確認する。
- `ExecRunner` とデコーダーが既に持つ停止、待機、部分結果破棄、出力上限の契約は変えない。診断のために別のプロセスを残したり、取消後に出力を待ち続けたりしない。外部 RTC 応答は従来の分類を維持し、内部診断だけを追加する。
- R02〜R06 は共通ロガーの例外記録と重複させず、各共有入口で段階、相手、識別子、結果、所要時間を安全な列挙値として記録する。認識・音声キャッシュ・SSE・MCP・LLM/DB の本文、キャッシュキー、URL クエリ、トークン、例外本文を診断項目に含めない。通常終了、取消、失敗を同じ失敗として数えない。
- R03 の S3/Redis/ローカル保存は、存在しないキャッシュ、認可拒否、接続失敗、書込み失敗、破損を区別して記録する。ただし cache-hit と生成への既存フォールバックやファイル保存の成否を、ログ追加だけで変更しない。
- R07 の初期化・登録シェルと ServiceDiscovery の観測点は、開始、成功、失敗段階を固定値で出す。環境変数、コマンド行、weed 出力、HTTP 本文を出力せず、既存の秘密を抑止するリダイレクトと登録・再試行の挙動を維持する。
- 受け入れ確認は R01 の偽実行器と隔離した FFmpeg、R02〜R07 の各共有入口の代表的な失敗分類、本文・認証情報を混ぜた入力での非出力、公開 RTC エラーの不変を対象にすれば一意に確認できる。稼働中の外部サービスや長時間試験は不要である。
- task.md に列挙された R02〜R07 のうち、既存タスクの実装範囲で完結しない独立した変更だけは、依存タスクへ分割して最終受け入れタスクの依存に追加する。分割を理由に対象を未確認のまま完了にしない。

## 自律補完

- `AUTO_FIX`: 「安全な stderr 抜粋」は自由文を許すと本文・秘密の境界を満たせないため、実装では既知の診断を選別して有限長の固定形式にし、未知の生出力は長さ・切詰め状態などの構造化情報だけを記録する。task.md の「安全に記録する」「本文・認証情報を出さない」という明示要件と既存の共通ログ契約に基づく。
