# 通常起動のプロファイル指定を環境設定へ移す

## 背景 / 目的

ユーザーは毎回の `--profile full` 指定を省略したい。現行構成は指定なしで対象が0件となる。
複数ホスト運用中のため、既存プロファイルを廃止せずホストごとの `.env` で選択する。

## 完了条件

- [x] サンプルの `COMPOSE_PROFILES=full` により指定なしで従来の24サービスを選択できる。
- [x] `COMPOSE_PROFILES=rtc` などホストごとの上書きが可能で、既存の選択範囲を維持する。
- [x] この作業環境の `.env` は既存の明示指定を尊重して補完し、READMEとCompose設計を同期する。

## 変更範囲 / 確認方法

通常変更。`examples/compose.env`、`README.md`、`documents/design/infrastructure/compose.md` を変更する。
Compose標準の環境変数を使用し、Pythonへの設定追加や新しい起動スクリプトは不要。
`docker compose config --services` をサンプル設定、明示full、環境変数rtcで比較する。
フロント単独構成の初期化依存不整合はNeMoモデル準備タスクで扱う。

## 確認結果

2026-09-07、サンプルの指定なしと明示fullが24サービスで一致し、環境変数rtcへの上書きは2サービス、空指定は0件となることを確認した。
このホストの既存 `.env` にプロファイル指定がなかったため `COMPOSE_PROFILES=full` を追記した。機密設定は表示・コミットしていない。
サービスの再作成は不要。既存のfrontend単独構成の不整合は今回悪化させず、モデル準備タスクへ引き継いだ。
