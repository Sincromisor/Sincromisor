# イメージ公開処理を現行Composeのビルド定義に対応させる

## 背景 / 目的

2026-10-18、HEAD `d9e4916b` で `node scripts/publish-images.mjs plan` を実行し、`未対応のビルド構成: log-observer` で終了することを確認した。
[公開スクリプト](../../../scripts/publish-images.mjs) はルートのコンテキストと省略またはlatestタグだけを許容するが、現行Composeにはサブディレクトリ、Dockerfile省略、固定タグの自作イメージがある。
AgentServerは `chat` プロファイルだけに属する。現行の全自作イメージを列挙できるかも、実際のComposeを使って確認する。
既存の模擬テストは成功しているが、現行構成との差異を検出できていない。

## 完了条件

- [x] コミット済みの `compose.yml` と `examples/compose.env` から全プロファイルの自作イメージを抽出し、AgentServer・Vector・VictoriaLogs・log-observerを含めて `plan` が成功する。
- [x] サブディレクトリのコンテキスト、そこを基準とするDockerfileの相対パス、省略時の `Dockerfile` を正しく解決してビルドへ渡す。
- [x] 公開先のリポジトリ名とCompose指定タグを分離し、全履歴タグの送信成功後に各Compose指定タグを更新する。タグ省略時だけ `latest` とする。
- [x] ダイジェスト照合と匿名取得確認もCompose指定タグを対象とする。既存のlatest指定サービスは従来どおり更新する。
- [x] 展開したソース外のコンテキスト・Dockerfile、想定外の公開先、未対応ビルド機能を拒否し、未追跡ファイルや運用中の設定を混入させない。
- [x] 全件ビルド成功後の送信、送信前のソース・アーキテクチャ照合、失敗時停止、現行パッケージの削除保護を維持する。
- [x] 実Composeを使う読み取り検査と模擬回帰テストが成功し、公開設計を新しいタグ選択へ同期する。

## 設計判断・変更範囲

対象は上記スクリプト、[回帰テスト](../../../scripts/tests/publish-images.test.mjs)、[公開設計](../../../documents/design/infrastructure/image-publishing.md)。Composeの既存コンテキストや固定タグをスクリプト都合で書き換えない。
履歴タグは従来の日時とコミット形式を各リポジトリに付ける。固定タグのサービスへ追加の `latest` は作らず、利用側のComposeが取得する参照を更新する。再開時も同じコミット・履歴タグを使用する。
公開対象は全プロファイルの `build` を持つサービスとし、外部配布イメージは対象外とする。対象リストは手書きで固定しない。
パスは正規化後も展開元に収まることを確認し、許可範囲外へ解決するシンボリックリンクも拒否する。Dockerfileがコンテキスト外でも同じ展開元内ならAgentServerの既存指定として扱う。
実公開、パッケージ削除、稼働環境への反映、並列化・外部キャッシュ導入は本タスクに含めない。

## 確認方法

- `node --test scripts/tests/publish-images.test.mjs` を拡張し、サブディレクトリとDockerfile省略、AgentServerの相対パス、固定タグ・省略タグ、拒否対象と既存の停止・削除保護を確認する。
- Docker・GitHubの書込みは模擬し、ビルド引数のパス、全件成功前にタグ更新しないこと、更新先と照合先がCompose指定タグであることを確認する。
- 実Composeのサンプル設定を読み取り、全プロファイルから得た対象と公開計画を照合する。秘密を含む実運用の構成全体をログへ出さない。
- `node scripts/publish-images.mjs plan` を実行する。スクリプトは作業ツリーの変更を使い、Compose等の入力はHEADから展開するため、今回のスクリプト修正はコミット前に検証できる。ビルド・取得・公開を伴う確認は不要。

## 実装・確認結果

`node --test scripts/tests/publish-images.test.mjs`は5件成功。Docker・GitHub書込みを模擬し、全件ビルド・送信・タグ更新の順序、ソース・アーキテクチャ不一致、送信・タグ更新・ダイジェスト・匿名取得の失敗、コンテキストとDockerfileの逸脱、リンク逸脱、未対応機能、固定タグを含む現行パッケージの削除保護を確認した。初回はサンドボックスの子プロセス起動がEPERMで失敗したため、同じ模擬テストを権限付きで実行して成功した。
