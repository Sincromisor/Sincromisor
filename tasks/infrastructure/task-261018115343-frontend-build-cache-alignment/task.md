# フロントエンドとRTCの共通ビルドでキャッシュを再利用する

## 背景 / 目的

2026-10-18、HEAD `d9e4916b` を調査した。[frontend](../../../Docker/sincro-frontend/Dockerfile) と [RTC](../../../Docker/sincro-rtc/Dockerfile) は同じフロントをビルドするが、frontendの `npm ci` にだけ `chown -R` があり、その地点から命令が一致しない。
共通の依存導入と生成処理で、同じビルダーのキャッシュを再利用できるようにする。

## 完了条件

- [ ] 同一入力・引数で両Dockerfileのフロントビルド部分が同じ処理となり、依存導入とフロントビルドのキャッシュを再利用できる。
- [ ] 既存のUID、npmキャッシュの所有者、Node.jsとnpmの版、ビルド引数を維持する。
- [ ] Caddy用とRTC同梱用に、従来と同じ公開ページ・素材を含む成果物を配置できる。

## 変更範囲・実装方針

上記2つのDockerfileの共通ビルド部分を揃える。`COPY --chown` とディレクトリ生成時の所有権で足りることを確認して重複処理を除く。
必要ならDockerfile構文指定も揃える。新しい共通配布イメージ、Bake設定、Composeのサービス間ビルド依存は導入しない。
Goビルド、Caddy・RTCの起動方式、配信先、依存版は変更しない。

## 確認方法

同一の入力・引数・ビルダーで一方のフロントビルド段階をビルドし、続いてもう一方の該当段階をビルドする。
後者で `npm ci` と `npm run build` がキャッシュを再利用し、生成物が一致することを確認する。比較のために `--no-cache` や全サービス再ビルドは使わない。
両最終段階のコピー元・配置先を確認し、今回の差分で必要になった場合だけ最終イメージまで検証する。
