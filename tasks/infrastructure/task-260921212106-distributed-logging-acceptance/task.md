# 複数ホストのログ集約と内容記録の切替を結合確認する

## 背景と目的

[導入全体](../task-260921212053-victorialogs-foundation/task.md)を組み合わせ、複数ホストで抽出・切替を確認する。
単一ホストのコンテナ名変更だけではホスト間到達を証明できない。結合確認と必要な修正・利用手順に絞る。

## 変更範囲と方針

- 2つのDockerホストを使う。仮想マシンでもよいがデーモンと接続先を分け、管理ネットワークで通信する。
- 配布設定の単一ホストと、担当設定済みの2ホストそれぞれで`docker compose up`だけを実行し、本体とログ基盤をまとめて起動する。別のログ用Composeプロジェクトや事前の収集起動を使わない。2ホスト環境がなければ必要な接続情報と未実行事項を記録し、本タスクを完了・PASSにしない。
- 各ホストの`.env`から担当・管理アドレス・ホスト識別・保持期間・内容設定が届くことを確認する。投入先はConsulで発見し、中央IPの手動受渡しなしで登録先変更に追随する。
- 公開範囲、ソケット権限、停止・復旧、内容制御が関係するため、結合仕様と結果を独立レビュー・評価の対象にする。
- 自前アプリに加えCaddy、VOICEVOX、llama-server、Consul、Redis、SeaweedFS、初期化、収集・保存自身を含む選択した全サービスを確認する。MediaMTXは選択時の対象であることを構成で確認する。
- [網羅性表](../task-260921221013-logging-coverage-inventory/coverage.md)のC/R/B/H/L/I/N各行IDを確認結果へ結び付け、確認日・対象コミット・構成/ホスト・人工入力・検索条件・結果を記録する。選択時対象は選択条件も残し、選択した場合は必須とする。ブラウザー、ホスト障害、チェックの失敗理由、内部処理の診断、回収・欠落検知も含める。未確認を対象外に移して完了させず、不足の修正タスクを起票して本タスクの依存へ加える。
- 人工データを使い、実環境の未加工ログはGit管理外で扱う。

## 完了条件

- [x] 単一コマンド起動、Consul登録・全収集インスタンスの死活監視、中央の再発見が単一・複数ホストの両構成で成立する。
- [x] ブラウザーの端末取得・RTC・描画障害、Docker/Consulのチェック理由、FFmpeg失敗、ホスト障害を中央から抽出でき、発生元を取り違えない。
- [x] 網羅性表の全必須項目に確認結果があり、未対応・未確認の必須項目と未完了の依存タスクがない。明示的な非収集項目には要件上の理由がある。
- [x] 別ホストの同名サービスを識別し、時刻・ホスト・サービス・イベントでJSONLを抽出できる。`curl`と`jq`の例が動作する。
- [x] 代表的な会話でRTC、認識、テキスト処理、AgentServer、音声合成を取得可能なIDで関連付けられる。存在しないIDや時刻だけから因果関係を捏造しない。
- [x] 未指定時に対話・音声生成の詳細が中央へ残る。両方有効、対話のみ無効、音声生成のみ無効、両方無効を人工的な本文で確認する。
- [x] 両方無効では中央の本文・構造付き項目・未解析の元行・URLエンコードされた要求URLから試験本文を抽出できない。自前サービスのローカル運用ログでも確認する。
- [x] 無効化後も会話・音声生成・機能用履歴・キャッシュが動き、一般のエラー・状態変化が残る。保存済みログは消去されない。
- [x] 中央停止中も会話が継続し、容量内で収集済みのログが復旧後に届く。収集停止中の残存ログ、ローテーションを挟んだ残存ログ、短時間コンテナを回収し、人工的な連番で欠落・重複を照合する。容量超過と回収不能区間を観測できる。
- [x] 中央再作成で記録が残り、バックアップを隔離先へ復元して検索できる。管理外の公開がなく、単一ノード・ホストディスクの物理故障などの残余リスクを説明する。

## 確認方法と成果物

成功済み単体確認を無条件に繰り返さず、2ホスト間の投入・検索と結合条件を確認する。
障害操作は隔離環境で行い、稼働環境の適用・停止が必要なら対象と影響を先に明示する。
ブラウザー操作が必要なら`playwright-cli`スキルを使う。ブラウザー別・長時間負荷試験は追加しない。
配置、バージョン、コマンド、未実行事項を記録する。容量は確認環境での実測と限界を示し、固定性能要件は設けない。

## 文書同期と対象外

`README.md`に起動・検索への入口を追加し、`examples/compose.env`と`documents/design/infrastructure/logging.md`、`compose.md`、`storage.md`を同期する。
内容を既定で残すこと、反映方法、設定の独立性、ローカル原本と中央保存の範囲、保持期間、JSONの型変換を説明する。
ブラウザー受信APIは担当タスクの契約と確認を引き継ぐ。音声バイナリの新規保存、Grafana、クラスタ化は含めない。保持容量外・同時物理故障・ブラウザー未送信など絶対的な無欠落を保証できない条件を明記するが、回収可能なログの取りこぼしを理由の記録だけで合格にしない。
