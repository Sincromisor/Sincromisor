## このタスクで実行した確認

- `docker compose --env-file examples/compose.env -f compose.yml config --format json`を、単一`full,chat`と分散用Composeを加えた担当設定で展開した。実行先IPを意味しない文書用`192.0.2.10` / `192.0.2.11`を使い、起動はしていない。
- 単一36サービス、中央側`backend,chat,logs` 32サービス、フロント側`rtc,frontend` 8サービス。全選択サービスはjournald / non-blockingで、Vector・router・observer・収集Consulを含む。中央は中央側だけにあり、異なる`SINCRO_LOG_HOST`と中央広告設定が届く。これは構成検査であり管理ネットワークの実到達は未確認。
- 先行の隔離中央（loopbackの試験用19430）でcurlとjqを実行した。`event:recovery_sequence`は最終時点170行・異なる連番85、`sequence`は文字列だった。容量試験時に別の新規cursor領域を使って同じ原本を再読取したため85行の再送重複がある。元cursorを維持した通常停止・再作成・強制終了試験の時点では85件・重複0であり、時点と試験条件を混同しない。
- 設計のjq例は日本語キーの引用がなく構文エラーになったため引用を修正した。修正後の投入・検索例は人工本文「日本語の確認」と文字列の連番「7」を返した。READMEに検索・独立した本文設定・回収・復元への入口を追加した。

```sh
curl --fail --silent --data-urlencode 'query=event:recovery_sequence' \
  http://127.0.0.1:19430/select/logsql/query \
  | jq -s '{"件数":length,"異なる連番":(map(.sequence|tonumber)|unique|length),"型":(.[0].sequence|type)}'
```

別DockerホストのSSH接続先またはDocker context、管理ネットワークIP、担当プロファイル、人工データ用保存領域が必要である。接続後に両ホストの永続journal・読取権限・時刻・必要ポートを確認する。
