# レビュー: task-260921221014-host-system-diagnostic-logs

## 判定

APPROVED

## 理由・申し送り

- 対象は棚卸しの H02・H03 と、既存の `vector`、`log-observer`、`SincroLogObserver` の状態契約に対応する。標準 `compose.yml` はすでに収集プロファイルを含むため、ホスト入力も同じ標準 Compose 起動で有効にする。
- Linux/WSL で確認済みの `/var/log/journal` と `/run/log/journal` を、それぞれ読取専用で収集コンテナへ渡す。ホストのルートファイルシステム、Docker API の追加公開、`privileged` は不要である。読取権限が足りないホストは、導入手順とサンプルで必要最小限の journal 読取権限を示す。
- journal 入力の再開位置は `vector-data` の永続領域に保持し、二つの原本を読む場合も入力ごとに混同しない。再作成後の再開を確認し、未読・権限拒否・原本不在・入力失敗を Vector の生存確認だけで正常と扱わない。既存の `SincroLogObserver` の診断・Consul 状態へ反映する観測点を持たせる。
- 収集対象は Docker/containerd・サービス管理とカーネルの OOM、GPU/デバイス、ディスク、ネットワーク障害に絞る。journal の任意本文や無関係な他アプリの環境を中央へ転送せず、既知形式を固定分類して、host、boot 識別子、unit/発生元、重大度、発生時刻だけを残す。サービスを特定できないカーネル行へ業務サービス名を補わない。
- 実読取はホストの `logger` 等で無害な一意の試験メッセージを journal に入れ、中央検索まで到達したことを確認する。OOM・GPU・ディスク・ネットワークは実障害を発生させず、原本を模した固定入力で分類・秘密除去・サイズ上限を確認する。この二つを同じ確認結果として扱わない。
- `configs/vector.toml`、Compose、環境サンプル、導入手順、ログ設計の同期先が task.md にあり、長時間試験や別 OS 対応を要求していない。回収・ローテーションの欠落検知は既存の回収タスクへ分離されている。

## 自律補完

- `AUTO_FIX`: journal 入力の正常性は Vector の HTTP 生存だけでは判定できないため、既存の `log-observer` と `SincroLogObserver` の状態経路へ「実原本を読めたか」を固定理由で反映する。task.md の未読原本を空入力の正常と扱わない要件と、既存の補助監視の責務に基づく。
- `AUTO_FIX`: 原本の可変 `MESSAGE` を保存せず、対象カテゴリを固定値へ分類して未知または無関係な行を除外する。task.md の秘密・他アプリ本文を収集しない要件と共通ログ項目の契約に基づく。
