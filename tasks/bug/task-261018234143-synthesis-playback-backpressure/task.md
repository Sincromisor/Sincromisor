# 長い会話応答の再生待ち上限による音声切断を修正する

## 背景・目的

最近のVPS会話で、回答本文が表示された後、読み上げ途中にRTC接続が切れる。2026-10-18 23:38:36 JSTのログでは要求13の正常終端の後、要求14の先頭でRTCが `output_backpressure` によりセッションを閉じ、Pythonの送信失敗が後続した。過去の合成要求上限・生存確認の障害とは区別する。原本と接続先は非公開の `work/` に保存する。

## 完了条件

- [x] ログと変更前の再現試験で直接原因を確認する。
- [x] 合成が再生より速い長い応答でも、上限到達だけで接続を切断せず、順序と音声・テロップを保って再生を続ける。
- [x] 保持量を有限に保ち、世代変更・終了で待機を解除する。待機が上流の配送期限や生存確認と競合して別の切断を起こさない。
- [x] 不正な区間・終端は従来どおり拒否する。回帰試験と対象のrace検査を通す。
- [x] RTC設計と必要な内部待機契約、コメントを同期し、確認結果と未実行事項を記録してコミットする。

## 範囲・方針

`internal/rtc`、`internal/media/output` と直接関係するパイプラインの流量制御、およびTextProcessorのPong期限を対象とする。既存の取消・世代境界を再利用し、ロック保持中の待機と無制限の音声蓄積を避ける。外部メッセージ形式、フロント、合成内容、キャッシュは変更しない。単に上限値を増やす修正にはしない。

受信待機を下流へ伝播する場合はCoordinatorの5秒配送期限、WebSocketのPing/Pong、Pythonの30秒送信期限との関係を確認する。複数の所有者の待機と終了に関係するため独立レビュー・評価を行う。

## 確認方法

変更前の再生待ち8要求超過を人工PCMで再現し、変更後は同じ入力が最後まで出力されること、取消と世代更新で旧音声を復活させないことを確認する。必要な所有者間の結合試験と対象Goパッケージの `go test -race`、`go vet` を実行する。実サービスを利用できる場合は既存の合成接続を使い長い応答相当を確認する。稼働VPSのログ取得を先に行い、配備操作は原因修正と検証結果が揃ってから判断する。

## 実装と確認結果

- VPSの23:37:15、23:38:36 JSTの2会話で、RTCの `output_backpressure` による切断を確認した。後者は13要求が正常終端まで届き、14要求目の先頭で失敗した。Python側の送信失敗はRTC終了の後であり、合成エンジン起因ではない。
- 変更前の `outbound.go` をGoの重ね合わせ機能へ指定し、`TestSynthOutputBackpressureWaitsThenPlaysEveryRequest` が9要求目で `speech queue is full` を返すことを再現した。
- 未再生PCMが300ms以上なら取り込みを待ち、Sessionが20ms間隔で世代を再検査して再試行する。区間は最大0.5秒なので、通常の保持量は0.8秒未満になる。終端受理、不正区間拒否、8要求・120秒の安全上限は維持した。
- 独立した実WebSocket試験で、合成の8要求待ちが文章処理接続のPongも止めることを再現した。TextProcessorだけ `ws_ping_timeout=None` とし、Ping送信を維持したままPong期限による誤切断を防ぐ。採用中Uvicornの実装と実通信で確認した。
- 人工PCMの24要求が順序どおり再生され、音声サンプルの欠落・重複なし、テロップ順序、有限保持、取消・出力終了・世代変更時の待機解除を確認した。
- `go test -race ./internal/media/output ./internal/rtc ./internal/pipeline/...` と、独立した同対象のrace検査・ `go vet` はPASS。
- 実Uvicornの旧Pong期限で1011切断、新設定では遅延Pongの受理と後続通信成功を確認した。Pythonの対象2試験、Ruff、整形、tyはPASS。
- 実VOICEVOX/PythonとPion/Opus接続で固定の人工文章を合成した。253区間、1,205,760サンプル（25.12秒）を受信し、生成完了前の有声音（開始141ms）と末尾までの再生、セッション継続を競合検査付きで確認した。
- 結合試験で既存の検証ブラウザーが音声入力を開始せず、10秒の準備期限で終了する問題を発見した。試験側で無音入力を開始し、セッション取消を成功扱いせず、末尾までの再生とRTP継続受信も確認するよう直した。
- RTC設計、音声パイプライン契約、TextProcessor設計を同期し、設計索引からの参照を維持した。外部メッセージ形式とフロントに変更はない。コメント点検: PASS。

原本、重ね合わせ用の変更前ソース、実接続先、検証ログは非公開の `work/private-artifacts/synthesis-interruption/` に保存した。公開成果物には固定入力の試験と匿名化した結果だけを残す。
