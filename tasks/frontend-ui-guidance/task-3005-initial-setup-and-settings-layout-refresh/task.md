# TASK-3005 初回セットアップと設定シェルのレイアウト刷新

- 作成日: 2026-04-19
- ステータス: Done
- 優先度: High

## 目的

初回セットアップウィザードと通常設定シェルのレイアウトを再設計し、`初回導線としての分かりやすさ`、`Discord 参照に近い情報密度`、`Sincromisor 全体との視覚的一体感` を両立させる。

## 背景

- `TASK-3003` では `左カテゴリナビ + 右詳細ペイン` の方向性を整理したが、実装結果は `中央モーダル` と `右サイドパネル` で骨格が分かれ、同じ設定体系なのに別アプリのように見えている。
- 現状の初回セットアップは、巨大なコンテナに対して内容が少なく、空白が `設計された余白` ではなく `未使用領域` に見える。
- 左ナビは `カテゴリ一覧` ではなく `小さなボタン列` に見え、Discord 参照が持つ現在地の強さや探索性を再現できていない。
- 右側本文も、状態表示、入力項目、補助文、主CTAの階層が弱く、どこから見て何を決めればよいかが伝わりづらい。
- 初回セットアップを中央モーダルで維持する方針自体は許容できるが、通常設定シェルとの共通デザインルールを欠いたままでは、プロダクトの成熟度を落とす。

## スコープ

- 初回セットアップウィザードのレイアウト骨格、サイズ、余白、ナビ、本文配置、CTA配置の再設計
- 通常設定シェルのレイアウト骨格、幅、密度、セクション構成、状態表示の再設計
- 初回セットアップと通常設定の共通トークン、共通シェル、共通フォーム面構成の整理
- カテゴリナビ、状態カード、フォーム、フッター導線の視覚階層の整理
- PC 主体のレイアウト基準と、狭幅時の縮退方針の定義
- 設計文書への反映

## 非対象

- WebRTC シグナリング仕様や設定ロジックの変更
- 設定カテゴリの意味そのものの変更
- 初回セットアップ必須方針の変更
- 3D キャラクター表示やチャットバブルの全面刷新
- モバイル専用UIの新規設計

## 対応方針

1. 初回セットアップと通常設定は `別の画面種別` として扱うが、グリッド、余白、面構造、タイポ、カテゴリナビの文法は共通化する。
2. 初回セットアップは `中央にある大きな開始フロー`、通常設定は `右側の常設ツールシェル` として役割を分ける。
3. どちらの画面でも、情報は `左ナビ -> 右本文 -> セクション -> フォーム -> CTA` の順で読めるようにする。
4. 空白を減らすのではなく、`密度の高い本文` と `明確なセクション境界` で Discord 参照に近い読み心地を作る。
5. 背景装飾より、コンテンツ面の階層、ナビの現在地、本文の整列で完成度を出す。

## レイアウト改善チェックリスト

### 1. 画面骨格

- [ ] 初回セットアップは `中央モーダル` を維持する場合でも、`横長の大きな板` ではなく `開始フローとしての読みやすいワークスペース` に見える比率へ見直す
- [ ] 通常設定は `狭すぎるツールパネル` ではなく、説明文とフォームを読める幅を持つシェルへ広げる
- [ ] 初回セットアップと通常設定で、左ナビと右本文の構造を共有する
- [ ] 画面ごとにレイアウト骨格が変わらず、カテゴリを切り替えても同じ読み順を保つ

### 2. サイズ基準

- [ ] 初回セットアップの外枠は、PC画面で `幅 960-1280px`、`高さ 620-780px` を目安に再設計する
- [ ] 初回セットアップ内の左ナビ幅は `180-220px` を基準にする
- [ ] 初回セットアップ内の右本文幅は `560-760px` を基準にする
- [ ] 通常設定シェルの横幅は、現状より広い `420-560px` を目安に見直す
- [ ] 通常設定シェル内でも、本文として読ませる領域を `320px` 未満にしない

### 3. 整列とグリッド

- [ ] 左ナビと右本文の上端を揃える
- [ ] フォームのラベル、入力、補助文の左端を揃える
- [ ] 余白は `4px / 8px` グリッドにそろえる
- [ ] セクション間、項目間、ラベルと入力欄の間に一貫した余白ルールを持たせる
- [ ] 横並びは `同じ種類・同じ重要度` の情報だけに限定する

### 4. 左ナビ

- [ ] 左ナビは `丸い小ボタン列` ではなく `カテゴリ一覧` と認識できる造形にする
- [ ] 選択中カテゴリの背景、境界、アクセントを強め、現在地が即認識できるようにする
- [ ] ナビ項目の高さは最低 `36-44px` を確保する
- [ ] 一般カテゴリと開発者向けカテゴリは余白か見出しで視覚分離する
- [ ] 初回セットアップと通常設定で、カテゴリ名の順序と表現をそろえる

### 5. 右本文

- [ ] 右本文は中央寄せではなく左揃えベースで構成する
- [ ] 冒頭に `カテゴリ名`、その直下に `1-2文の導入説明` を置く
- [ ] 本文は `概要ブロック -> 設定ブロック -> 補助ブロック -> フッター操作` の順に並べる
- [ ] 状態表示と編集可能フォームを分離する
- [ ] 状態カードを乱立させず、必要な箇所だけ `サマリーカード` または `通知バー` に絞る

### 6. セクション構成

- [ ] 各カテゴリページは、`セクション見出し + 説明 + 項目群` の繰り返しで構成する
- [ ] セクションごとに薄い区切り線か面差を付け、読み進める単位を明確にする
- [ ] 説明文のない設定群を残さない
- [ ] 状態確認だけのブロックと、値を変えるブロックを混在させない
- [ ] `音声` のような項目量が多いカテゴリは、`入力デバイス / 前処理 / 詳細調整` のように段を分ける

### 7. CTA とフッター

- [ ] 初回セットアップの主CTAは、本文の読了位置に配置する
- [ ] 主CTAは `幅 140-220px` 程度の存在感を持たせる
- [ ] 離脱導線は主CTAの直近に置く場合でも、視覚優先度を一段下げる
- [ ] 通常設定シェルで保存や反映が不要な項目は、不要なフッターボタンを置かない
- [ ] `トップへ戻る` などページ遷移を伴う導線は、`閉じる` と並列に置かない

### 8. 面構造と密度

- [ ] 背景グラデーションに頼らず、`背景 / シェル / セクション面 / 入力面` の4階層でUIを見せる
- [ ] 初回セットアップで空白が大きく見える箇所は、説明、サマリー、補助情報の再配置で密度を上げる
- [ ] 通常設定シェルは `詰め込みすぎた縦長フォーム` にしない
- [ ] セクション内の密度は高く、セクション間の余白は広く取る
- [ ] コンポーネントごとの角丸、枠線、内側余白を揃える

### 9. タイポグラフィ

- [ ] ページタイトル、セクション見出し、本文、補助文のサイズ差を整理する
- [ ] 補助文のコントラストを落としすぎない
- [ ] 英日混在ラベルの見え方をそろえる
- [ ] Discord 参照のように、見出しと本文の階層で読み順が分かるようにする
- [ ] 主CTA、ナビ、見出しのウェイトを必要十分に強める

### 10. 画面間の一体感

- [ ] 初回セットアップだけ別テーマに見える状態を解消する
- [ ] 通常設定シェルが、ヘッダーやチャットUIと視覚的に断絶しないようにする
- [ ] 設定UI全体で色トークン、影、枠線、フォントのルールを共有する
- [ ] 初回セットアップと通常設定の切り替え後も、同じカテゴリ体系を引き継いでいると分かる見た目にする

### 11. 狭幅時の縮退

- [ ] 横幅が足りない時は、初回セットアップ内の左右カラムを段階的に縮める
- [ ] さらに狭い場合は左ナビを上部タブまたは折りたたみナビへ縮退させる
- [ ] 通常設定シェルは狭幅時にオーバーレイへ寄せても、本文可読幅を確保する
- [ ] どの縮退段階でも主CTAが画面外に埋もれないようにする

## 実装タスク

1. 初回セットアップと通常設定の双方に適用できる、共通のレイアウトトークンとシェル部品を整理する。
2. 初回セットアップウィザードのコンテナ寸法、内部グリッド、左右カラム比率を再設計する。
3. 通常設定シェルの幅と本文領域を見直し、説明文とフォームが読める横幅へ広げる。
4. 左ナビの造形を `ボタン列` から `カテゴリ一覧` へ寄せ、選択状態の見え方を強化する。
5. 右本文のレイアウトを左揃えベースへ再構成し、導入説明、状態表示、設定項目、補助文、CTAの順に整理する。
6. 状態カードや小カードの使いどころを見直し、乱立している場合はサマリー表示へ集約する。
7. `音声`、`起動`、`接続` など項目量の多いカテゴリで、セクション分割と区切り表現を追加する。
8. 初回セットアップのフッター導線を見直し、主CTAと離脱導線の優先度差を視覚的に明確にする。
9. 通常設定シェルのフッターや補助操作を見直し、ツールパネル感が強すぎる構成を緩和する。
10. PC前提レイアウトと狭幅時縮退ルールを CSS に反映する。
11. `documents/design/frontend_ui.md` に、画面種別ごとのレイアウト基準、サイズ目安、縮退方針を追記する。

## 実施メモ

- 本タスクは `TASK-3004` が扱う `終了操作の意味統一` とは別に、レイアウト具体化に集中するための分離タスクである。
- 初回セットアップに中央モーダルを採用することは否定しないが、`中央に黒い板を置いただけ` に見える状態は避ける。

- 実装でレイアウトを変更した際は、`documents/design/frontend_ui.md` の更新が必要になる。
