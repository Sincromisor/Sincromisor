# TASK-3004 初回セットアップウィザードとダイアログ終了操作の統一

- 作成日: 2026-04-19
- ステータス: Done
- 優先度: High

## 目的

初回設定が必須である前提を保ちながら、ロード直後のセットアップ導線と通常設定ダイアログの役割を整理し、`戻る`、`閉じる`、`キャンセル` などの終了操作を一貫した意味で扱える UI に改善する。

## 背景

- `TASK-3003` では、設定UIを Discord ライクな `左カテゴリナビ + 右詳細ペイン` へ寄せる方針を整理したが、実装された初回設定画面は `中央モーダル`、通常設定は `右パネル` となっており、同じ設定体系なのに見え方と操作文法が揺れている。
- 本システムは初回設定が必須であり、ロード直後の導線そのものは必要である。一方で、通常の設定ダイアログと同じ `閉じる` 文法で扱うと、「今すぐ閉じられる補助UI」と誤認されやすい。
- 現在の初回セットアップウィザードにある `戻る` は、ウィザード内の前ステップ移動ではなく、`https://sincromisor.negix.org/simple-vrm/` から `https://sincromisor.negix.org/` へ戻るページ遷移である。
- このため、`戻る` を `閉じる` に置き換えると意味が不正確になり、逆に `戻る` のままでも「前ステップへ戻る」操作と衝突する。
- 各種ダイアログで `×`、`戻る`、`閉じる`、`キャンセル` の意味が揃っていないことも、UI全体の統一感を損ねている。

## スコープ

- ロード直後に表示する初回設定UIを、通常設定ダイアログとは異なる `初回セットアップウィザード` として再定義する
- 初回セットアップウィザードのページ骨格、見出し、説明文、主要ボタン、離脱導線を整理する
- 通常の設定ダイアログと開発者向けUIにおける `閉じる系操作` の命名と振る舞いを統一する
- `×` ボタン、ESC キー、オーバーレイクリック、フッターボタンの扱いを、画面種別ごとに整理する
- `トップへ戻る`、`閉じる`、`キャンセル`、`戻る` の使い分けルールを文言と挙動の両方で定義する
- 画面構造と操作ルールを設計文書へ反映する

## 非対象

- WebRTC シグナリング仕様や音声設定ロジックの変更
- 設定項目そのものの追加や削除
- 初回セットアップ必須というプロダクト方針自体の変更
- 3D表示やチャットUIの大幅なビジュアル刷新

## 対応方針

1. 初回表示は `閉じられる設定モーダル` ではなく、`開始前に通過するセットアップウィザード` として扱う。
2. 初回セットアップと通常設定はカテゴリ体系を共有しつつ、`離脱できるか` と `終了操作の意味` は明確に分ける。
3. `戻る` はウィザード内の前ステップ移動に限定し、ページ遷移による離脱は `トップへ戻る` または同等の明示的文言に置き換える。
4. `閉じる` はダイアログやパネルを畳む操作、`キャンセル` は未保存変更を破棄して閉じる操作、として意味を固定する。
5. 必須フローである初回セットアップでは、`×`、ESC、オーバーレイクリックによる不用意な閉鎖を原則禁止し、離脱させる場合は明示的なページ遷移操作に統一する。

## 修正チェックリスト

### 1. 役割分離

- [ ] ロード直後のUIが `初回セットアップウィザード` であることを、タイトルと説明文で明示する
- [ ] 通常設定UIは `あとから開ける設定ダイアログ / 設定パネル` として区別する
- [ ] 初回セットアップと通常設定で、同じカテゴリを同じ順序で見せつつ、終了導線だけは混同しない
- [ ] 初回セットアップの画面は `一時的な設定モーダル` ではなく `開始フロー` に見える構成へ寄せる

### 2. 終了操作の意味統一

- [ ] `戻る` は `前ステップへ戻る` の意味に限定する
- [ ] `https://sincromisor.negix.org/` へのページ遷移は `トップへ戻る` または `ホームへ戻る` と表記する
- [ ] 通常ダイアログを畳む操作は `閉じる` に統一する
- [ ] 変更破棄を伴う場合だけ `キャンセル` を使う
- [ ] `×` ボタンの意味を画面ごとに固定し、ページ離脱操作に流用しない

### 3. 初回セットアップ固有ルール

- [ ] 初回セットアップでは `×` を出さない、または押しても閉じずに離脱確認へ進む
- [ ] ESC キーでセットアップが消えないようにする
- [ ] オーバーレイクリックでセットアップが閉じないようにする
- [ ] 離脱導線を置く場合は `トップへ戻る` のように結果が分かる文言にする
- [ ] 主CTAは `次へ`、`確認して続行`、`開始する` など、前進が明確な文言にする

### 4. レイアウトと情報設計

- [ ] 初回セットアップは中央モーダルを維持する場合でも、`大きな空白の中に少量の部品が浮く` 構成を避ける
- [ ] 左ナビ + 右コンテンツの骨格を保ち、カテゴリ現在地がすぐ分かるようにする
- [ ] 右コンテンツは中央寄せではなく左揃え基調にする
- [ ] `概要 -> 設定項目 -> 補足 -> 主CTA` の順に縦方向へ読めるようにする
- [ ] 状態表示と編集可能項目を別ブロックに分ける
- [ ] `トップへ戻る` は弱い離脱導線として、主CTAと競合しない位置へ置く

### 5. 文言

- [ ] `戻る`、`閉じる`、`キャンセル`、`トップへ戻る` の定義を文言ガイドとして整理する
- [ ] 初回セットアップ冒頭に `何のための設定か` を1〜2文で説明する
- [ ] 途中離脱時の影響があるなら補助文で明示する
- [ ] `idle` など内部状態はそのまま見せず、人間向け文言へ変換する
- [ ] 英日混在ラベルや曖昧な内部用語を減らす

### 6. 見た目の統一

- [ ] 初回セットアップと通常設定で、色、タイポ、余白、ナビ造形のルールをそろえる
- [ ] `初回セットアップだから別アプリに見える` 状態を解消する
- [ ] 背景色よりもコンテンツ面の階層でUIを見せる
- [ ] 主CTAの視認性を十分に確保する
- [ ] 離脱導線は主CTAより弱く見せる

### 7. アクセシビリティと操作性

- [ ] キーボード操作で現在地と主要操作が辿れる
- [ ] フォーカス初期位置が妥当である
- [ ] ボタン名から結果が予測できる
- [ ] スクリーンリーダーでも `閉じる` と `トップへ戻る` が混同しない

### 8. 設計・実装整合

- [ ] 初回セットアップと通常設定の画面種別ごとの終了操作ルールを `documents/design/frontend_ui.md` に追記する
- [ ] 実装内のダイアログ共通部品で、閉じる可否や close reason を表現できるよう整理する
- [ ] 既存のダイアログ群に、今回決めた終了操作ルールと矛盾する文言が残っていないことを確認する

## 実装タスク

1. 初回表示UIを `設定モーダル` ではなく `初回セットアップウィザード` として再命名し、ヘッダーと導入説明を見直す。
2. 初回セットアップのフッター操作を `トップへ戻る` と `次へ / 開始する` 系へ再設計し、現在の `戻る` の意味衝突を解消する。
3. ウィザード内部に前ステップ移動が存在する場合のみ、`戻る` をステップ遷移専用として追加または整理する。
4. 初回セットアップでの `×`、ESC、オーバーレイクリックの扱いを見直し、必須フローに沿った close policy を実装する。
5. 通常設定ダイアログ、右側設定パネル、開発者向けダイアログの `閉じる`、`キャンセル`、`×` を共通ルールへ寄せる。
6. 初回セットアップと通常設定で、同じカテゴリナビと詳細ペイン構造を再利用できるよう、UIシェル部品の責務を整理する。
7. 初回セットアップの本文レイアウトを再構成し、左揃えベースの情報階層、状態表示、フォーム、CTA の順に整理する。
8. 離脱導線、補助文、状態文言を見直し、ページ遷移とダイアログ閉鎖が文言で混同しないようにする。
9. 既存ダイアログやオーバーレイの close reason を棚卸しし、必要なら共通ユーティリティや props を追加する。
10. `documents/design/frontend_ui.md` に、初回セットアップと通常設定の役割差、終了操作ルール、キーボード/オーバーレイ挙動を反映する。
