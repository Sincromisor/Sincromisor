# UI要素とレイアウトで伝える原則を明確にする

## 背景 / 目的

エージェントによるUI実装で冗長な補助ラベルが増えやすいというユーザーの指摘を受け、言葉による説明を追加する前に、UI要素とレイアウトで理解できるようにする原則を共通規約へ追加する。

## 完了条件（受け入れ条件）

- [x] UI要素、名前、配置、まとまり、選択状態で意味を伝える設計を優先する。
- [x] 補助ラベルは既定では追加せず、重複説明の例と、説明を残す判断基準を示す。
- [x] 操作名、入力ラベル、支援技術向けの名前、重要な影響や回復方法を保つ既存原則と整合させる。
- [x] 品質確認の問いに補助ラベルの重複確認を加える。

## 変更内容と対象範囲

[Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)の第2章に、説明よりUI要素とレイアウトによる理解を優先する節を追加し、第12章の確認観点へ反映した。説明が新たに伝える判断材料の有無で採否を決め、一律の文言削除やアイコン化、ツールチップへの移動を避ける。既存の操作・入力・アクセシビリティ・信頼の規則は保持する。

文書のみを変更する。既存UIの修正、適合調査、通信契約の変更は行わない。

## 確認結果

- 変更したMarkdownのPrettier確認、差分の空白検査、相対リンクの確認に合格した。
- `tasks:index:check`、`tasks:check`で状態と索引の整合性を確認した。
- yomiyasuによる文章検査、変更前との差分検査、依頼との照合、最終稿の照合を実行した。依頼に基づく原則の追加と、既存の必要な説明・アクセシビリティ要件の保持を目視で確認した。
- UI実装を変更していないため、ビルドと画面操作の確認は行っていない。
