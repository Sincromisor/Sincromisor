# 設計資料と規約の重複・追記構成を整理する

## 背景 / 目的

`documents/`の資料をレビューし、継ぎ足しによる重複や過剰な説明を必要に応じて整理する。ユーザーの依頼に基づき、文章の推敲にはyomiyasuを使う。

初期調査では、初期較正の開始・中断条件が3文書に同文で掲載され、設計文書の運用規則も方針・手順・チェックリストで重複していた。キャラクター設計などでは「参照」の後に仕様が追記され、本文の所属が分かりにくくなっている。

## 完了条件

- [x] 文書一覧、役割、重複候補を確認し、整理した箇所と残した箇所の理由を記録する。
- [x] 重複する詳細を担当文書へ集約し、利用側から参照できるようにする。
- [x] 追記された仕様を内容に合う位置へ整理し、条件・例外・数値・失敗時の挙動を維持する。
- [x] 変更した文章をyomiyasuで推敲し、原文との差分と最終稿を確認する。
- [x] 変更Markdownの整形、相対リンクと見出し参照、タスク管理の検査が通る。

## 範囲と方針

`documents/`全体を一覧・構成・重複候補の確認対象とする。現在の設計と規約を中心に本文を確認し、説明の重複、役割の混在、読みにくい追記を整理する。行数だけを理由に削除・分割せず、契約、識別子、設定値、安全上の注意は保つ。

旧設計、完了済み移行、調査原文、ADRは履歴としての役割を確認する。現在仕様との違いだけを理由に書き換えない。実装・通信契約の変更や外部資料の再調査は対象に含めない。未追跡の`volumes/proper-noun-dictionaries/`は操作しない。

主な変更対象は設計運用ガイド、Markdown規約、設計索引、フロントエンドの共通枠組み・設定・キャラクター設計とする。ほかの資料も確認し、同種の重複や節配置の問題があれば必要な範囲で整理する。文書を参照する側も検索し、リンクを同期する。

## 確認方法

- 原文と変更後の差分を読み、削った詳細が集約先に残っていることを確認する。
- yomiyasuの`run`と`verify`で変更文書を検査し、候補は文脈に照らして判断する。
- 変更MarkdownのPrettier確認と、相対リンク・見出し参照の存在確認を行う。
- `git diff --check`、`tasks:index:check`、`tasks:check`、コミットメッセージ検査を実行する。

アプリのコードと動作は変更しないため、ビルド・実機試験は行わない。

旧設計・完了済みPion移行・調査報告・調査依頼回答・`memo.md`は、履歴や調査原文としての役割と現在設計への入口を確認して保存した。ADRの判断理由、言語別規約の具体例、契約の数値・例外、動作・追跡の保存形式と判定表は、一律に重複として削らなかった。長いキャラクター設計の全面分割は行わず、今回確認した重複と追記配置に変更を絞った。

## 確認結果

- 変更した14文書にyomiyasuの`run`を実行し、lint・差分の候補を確認した。行数の目安、5分類の設定、較正の中断条件など、削除候補の詳細が参照先に残っていることを確認した。
- 14文書の`verify`で最終稿のハッシュが検査記録と一致した。箇条書きは責務・条件を比較するために残し、正本を示す語と必要な否定条件を機械的に言い換えなかった。
- リポジトリのMarkdown 1,831件を走査し、変更文書からの相対リンクと、変更文書へのリンク・見出し参照に不整合がないことを確認した。
- アプリのコード・通信契約・設定値は変更していない。既存の実VRMでの未確認事項を、今回確認済みとは扱っていない。

変更文書のPrettier確認、相対リンク・見出し参照確認、`git diff --check`、`npm run tasks:index:check`、`npm run tasks:check`は成功した。タスクは`done`、判定は`PASS`とした。
