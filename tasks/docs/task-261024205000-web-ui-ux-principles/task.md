# サービス全体のWeb UI・UX設計原則を定める

## 背景 / 目的

利用者の依頼に基づき、サービス全体に共通するWeb UI・UXの規約を `documents/rules/` に新設する。最高のUI・UXとして満たすべき体験を定め、現状維持や既存実装への適合を判断の前提にしない。将来の機能や表現方法を選べる柔軟さを保つ。

## 完了条件（受け入れ条件）

- [x] 目的達成、情報構造、操作、入力、状態、回復、アクセシビリティ、環境適応、信頼、美しさと没入を共通原則として記述する。
- [x] 満たすべき体験と変更可能な具体策を分け、競合時の判断、例外、原則の改訂、品質確認の方法を示す。
- [x] AGENTS.mdと設計索引から参照でき、現在実装の達成状況と混同しない説明を置く。
- [x] 変更したMarkdownの整形、相対リンク、タスク状態と索引の整合性を確認する。

## 設計判断と変更内容

- [Web UI・UX設計原則](../../../documents/rules/web-ui-ux.md)を新設した。特定のページ、部品、技術、配色、操作回数や性能値を普遍的な正解にしない。
- アクセシビリティの基準にはWCAG 2.2 AAを採用し、W3Cの一次資料、参照日、適用範囲を本文に記載した。これは設計上の要求であり、既存UIの適合を宣言するものではない。
- [AGENTS.md](../../../AGENTS.md)と[設計索引](../../../documents/design/index.md#フロントエンド)に、規約を読む目的とリンクを追加した。

## スコープ境界

文書の新設と参照の追加を対象とする。UI実装の変更、既存画面の適合調査、一括改修の計画は含めない。通信契約と現在実装の仕様に変更はない。

## 確認結果

- 対象MarkdownのPrettier確認、相対リンクの存在確認、`git diff --check`に合格した。
- `tasks:index:check`、`tasks:check`でタスク状態と生成索引を確認した。
- 日本語の推敲では、yomiyasuの文章検査、依頼文との照合、最終稿の照合を実行し、候補を目視で確認した。独立した規則を探しやすくする箇条書き、並列関係を示す読点、章番号、規格名・参照日は必要な表記として残した。
- 文書のみの変更のため、アプリのビルドと画面操作の確認は実行していない。
