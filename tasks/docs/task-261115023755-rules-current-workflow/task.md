# 規約の確認手順と表記を現行構成に合わせる

## 背景 / 目的

規約の棚卸しで、Pythonの依存グループ設定に追従していない確認コマンド、全体確認と対象確認の区別、古いパス例・命名例の不整合を確認した。現在の設定から実行できる手順と、一貫した表記に更新する。

[元タスク](../task-261115022740-rules-consistency-comment-safeguards/task.md)から、設定・手順・表記の修正を分割した。コメント品質は元タスク、行数基準は[構造検査タスク](../../frontend-tooling/task-261115023755-structure-check-targets/task.md)が担当する。

## 変更範囲と進め方

対象は `documents/rules/coding-{py,ts,go,md}.md` と `tasks/README.md` の該当節とする。設定・本番コードは照合元として扱う。

1. `pyproject.toml` の `default-groups = []` に合わせ、開発ツールには `--group dev`、サービス依存が必要な確認には対象グループを指定する。コマンドの実行場所を明記する。
2. Python・Goの確認手順を、通常は変更対象に絞り、横断変更などで全体確認を選ぶ運用へ揃える。実行範囲の判断はタスク管理へ集約し、言語別には確認手段を置く。
3. TypeScriptのPrettier設定とテスト配置の例を現行構成へ更新する。ルートでのフロントエンド確認と、AgentServerの独立した `package.json` による検査・テストを区別する。
4. Pythonの診断ログ例は必要最小限の診断値と認証情報の扱いを分けて説明する。認証情報については既存の生の値の出力禁止を適用する。
5. Markdownの命名は一般文書、ADR、`AGENTS.md`・`SKILL.md` などの規定名に分けて示す。
6. 旧 `TODO(TASK-...)` の現行利用を再確認し、新規記述の形式と履歴の扱いを整理する。旧タスクID・`Refs:`・移行ツールの互換性は既存の管理規則に従う。フック導入・整形・コミット形式の重複は、管理文書への案内へまとめる。

各変更は該当する既存の段落・例・表を更新して行う。判断に必要な説明を、その判断を扱う箇所へまとめる。

## 完了条件と確認

- [ ] 上記の手順・例が現行の設定とソース配置に一致し、通常の確認範囲と各コマンドの役割を判別できる。
- [ ] 設定・コマンド定義・リンク先を照合する。Pythonの実行確認は利用可能な依存の範囲で行い、未実行範囲を実施結果に記す。
- [ ] リポジトリルートで変更MarkdownのPrettier整形・確認、`npm run tasks:index:check` と `npm run tasks:check` が通る。

本タスクの確認は文書と設定の照合を中心とする。アプリ全体の試験やサービス起動は対象外とする。共有する言語別文書は他タスクの最新内容を読んでから編集する。
