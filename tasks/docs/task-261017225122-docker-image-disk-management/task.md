# エージェントのDockerイメージ蓄積による容量枯渇を防ぐ

## 背景と目的

ユーザーから、開発環境でエージェントが作成したDockerイメージが大量に残り、ディスクが溢れたインシデントが報告された。管理ルールへ容量確認・作成物の追跡・保持と後片付けの義務を追加し、再発を防ぐ。実環境の削除は今回の依頼範囲に含めない。

## 完了条件

- [x] ビルド・取得前と再試行前の容量確認、容量不足時の中止を定める。
- [x] タグ・イメージID・ビルダーを追跡し、タグ更新で残る旧イメージや失敗時のキャッシュも確認対象にする。
- [x] 一時イメージの削除、保持理由と削除条件、失敗・中断時の引継ぎを定める。
- [x] 共有・稼働中・復旧用の資源を保護し、削除許可と作業後の実容量確認を定める。
- [x] エージェントの参照入口に開発用ビルドと後片付けを明記する。

## 変更範囲と判断

[Docker Compose管理ルール](../../../documents/rules/docker-compose.md)に「開発用イメージとディスク容量」を追加し、[AGENTS.md](../../../AGENTS.md)の参照条件を更新する。`docker-build-strategies`と `docker-destructive-guardrails`、Docker公式の容量確認・イメージ削除・BuildKit回収設定を参照した。既存キャッシュの再利用と対象限定の削除を組み合わせ、ホスト全体の一括削除やボリューム削除は既定手順にしない。

共通の固定容量値は設けず、対象環境の空き容量と実測した増加量で判断する。イメージの保持とビルドキャッシュの回収を分け、保持条件のない増加を認めない。既存の公開・復旧用イメージの保持契約は維持する。
