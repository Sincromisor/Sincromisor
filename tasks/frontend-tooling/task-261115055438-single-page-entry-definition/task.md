# ページ定義からビルド入力と公開経路を生成する

## 背景 / 目的

優先度: 低。[Vite設定](../../../sincromisor-frontend/vite.config.js)にある `pageRouteAliases` と `buildInputMap()` は同じ6ページの生成元を別々に列挙している。ページ追加時に片方だけ更新して開発・ビルド後の公開経路がずれる余地をなくす。

## 変更範囲と方針

Vite設定内の既存ページ定義に必要なビルド入力名を持たせ、その一覧から入力マップ、開発経路の書き換え、ビルド後のHTML配置を生成する。関数や別ファイルの追加は読みやすさに必要な最小限とし、新しいルーターやファイル自動探索は導入しない。

既存の公開URL、末尾スラッシュ・index.htmlの別名、クエリーの保持、入力名、6ページの通常ビルド対象を維持する。ページ分類・URL・出力ディレクトリの変更やVite設定のTypeScript化は含めない。

## 完了条件

- [x] ページ生成元の一覧を1箇所編集すれば、ビルド入力と経路書き換え・出力配置に反映される。
- [x] 現行6ページの入力名・公開URLとクエリー保持が変わらない。
- [x] 通常ビルドが成功し、既存の公開位置にHTMLが出力される。

## 確認方法

変更ファイルのBiomeと通常ビルドを行う。開発サーバーの6ページの正規URLをHTTPで確認し、末尾・index.html別名とクエリー付き経路も表の定義に沿って確認する。出力HTMLの配置を照合する。画面内容を変えないためスクリーンショット比較は不要であり、ルーティングの一般化や網羅試験基盤は追加しない。

## 文書同期

[ページ構成](../../../documents/design/frontend/pages.md)のページ追加手順を単一定義へ合わせる。公開URLと利用者向け仕様は変更しない。

## 実施結果

Vite設定の `pageRouteAliases`へ `inputName`を加え、`buildInputMap()`も同じ定義から導出するようにした。開発経路の書き換え・HTML移動は既存処理を維持し、ページ追加手順を単一定義へ合わせた。

変更ファイルのBiomeと通常ビルドが成功した。6ページの既存入力名と生成元、公開位置のHTML出力を照合した。開発サーバーでは定義された17個の正規・別名URLについて、クエリーあり／なしの計34経路がHTTP 200となり、対応ページのHTMLを返すことを確認した。書き換え関数を通してクエリー文字列の保持と対象外URLの維持も確認した。変更Markdownとタスク管理検査は成功し、コメント点検はPASS。
