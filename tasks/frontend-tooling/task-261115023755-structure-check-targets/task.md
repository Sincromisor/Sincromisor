# 構造検査の変更対象と行数基準を明確にする

## 背景 / 目的

`checkFrontendStructure.mjs` は `git diff main` で厳格な検査対象を決めており、未追跡ファイルやmainへコミット済みの変更を拾えない。差分取得に失敗した場合も一覧表示だけで成功する。また、規約にはコメント等を除く行数と、検査に使う物理行数の両方が書かれている。

[元タスク](../../docs/task-261115022740-rules-consistency-comment-safeguards/task.md)から、スクリプトの修正と利用方法の整備を分割した。現在のワークツリーでの変更と、比較元を指定したコミット済み変更を確実に検査できるようにする。

## 変更範囲と進め方

対象は `scripts/tasks/checkFrontendStructure.mjs`、その対象試験、`documents/rules/code-structure.md` のサイズ閾値・構造検査の説明とする。

1. 既定の対象をHEADに対する未ステージ・ステージ済み変更と、Git除外対象を除く未追跡ファイルにする。コミット済み変更には比較元を明示して実行できる入口を用意する。比較元や差分の取得失敗は検査失敗として返す。
2. 変更対象外の既存超過ファイルは一覧表示とし、現在のテスト・型宣言の除外と理由付き例外を維持する。
3. 文書の一般基準はコメント・import・空行を除いた行数、フロントエンドの機械検査は追加の物理行数基準として区別し、現在の閾値と数え方を説明する。必要なコメントを含めて超過する場合は、責務分割または理由付き例外で扱う。
4. 既定の実行例、比較元を指定する例、成功・失敗の意味を既存の利用説明にまとめる。

## 完了条件と確認

- [ ] 未追跡・未ステージ・ステージ済みの対象と、明示比較元からのコミット済み変更を検査できる。対象取得の失敗を終了コードで判別できる。
- [ ] 一時Gitリポジトリを使うNodeの対象試験で、上記の対象選択、300行と301行、理由付き例外、除外対象、既存超過ファイルの一覧表示、比較元取得失敗を確認する。
- [ ] 文書とスクリプトの対象・行数・例外の扱いが一致する。リポジトリルートで対象試験、変更MarkdownのPrettier整形・確認、`npm run tasks:index:check` と `npm run tasks:check` が通る。

アプリコードの分割・コメント修正は対象外とする。検査試験は一時ディレクトリ内で完結させる。
