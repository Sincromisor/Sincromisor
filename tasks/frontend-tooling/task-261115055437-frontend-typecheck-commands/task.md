# フロントエンドの型検査と監視コマンドを追加する

## 背景 / 目的

優先度: 高。[フロントエンドのスクリプト](../../../sincromisor-frontend/package.json)は型検査を `build` に含め、単独実行は長い直接コマンドに依存している。開発中に素材準備や全ページのビルドをせず、型エラーを確認・監視できる入口を用意する。

## 変更範囲と方針

- フロントエンドへ `typecheck` と `typecheck:watch` を追加し、現在の `tsconfig.modern.json` に対する出力なしの型検査を使う。
- [ルートのスクリプト](../../../package.json)にも同名のワークスペース転送を追加する。監視は別端末で起動できればよく、`dev` の複数プロセス化や追加プラグインは不要。
- `build` は同じ型検査スクリプトを利用し、型検査失敗時はViteビルドへ進まない。
- コンパイラー設定の変更は [型専用インポートをコンパイラーで検査する](../task-261115055437-explicit-type-imports/task.md) に分ける。依存更新、設定ファイルの改名、テストの監視コマンド追加は含めない。

## 完了条件

- [x] ルートとフロントエンドから同名コマンドを実行でき、単独型検査が素材準備・Viteビルドを起動しない。
- [x] 監視中の変更で型検査が再実行され、終了操作で監視プロセスを残さない。
- [x] `build` が型検査を引き続き必須とし、検査の対象範囲を変えない。

## 確認方法

リポジトリ指定の実行環境で `npm run typecheck` を実行する。監視は一度起動し、出力に影響しない一時的な編集の検知と終了を確認して編集を戻す。両入口の転送と `build` の接続を確認し、package.jsonのBiomeを行う。スクリプトを写すだけの自動テストや本番ビルドは必須にしない。

## 文書同期

[TypeScript規約](../../../documents/rules/coding-ts.md)の型確認コマンドと[ページ構成](../../../documents/design/frontend/pages.md)の開発・ビルド案内を更新する。ルートREADMEへソース変更の手順を追加しない。

## 実施結果

ルートとフロントエンドへ `typecheck` / `typecheck:watch`を追加し、`build`を同じ型検査へ接続した。TypeScript規約とページ構成の開発案内を同期した。

指定のNode.js・npmで両方の `npm run typecheck`が成功した。監視をルートから起動し、一時コメントの追加を検知して再検査が成功すること、編集を戻してCtrl+Cで終了できること、監視プロセスが残らないことを確認した。型検査の出力に素材準備やViteビルドはなく、`build`は `&&`で型検査の成功後にViteへ進む。両package.jsonのBiomeはフロントエンド設定で成功し、変更Markdownの整形・確認も成功した。
