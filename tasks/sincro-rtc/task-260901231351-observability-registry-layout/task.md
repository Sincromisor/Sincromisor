# 観測レジストリを構築と語彙正規化へ分割

## 背景 / 目的

`internal/observability/registry.go` は334行で、`Recorder` 契約、Prometheus収集器の構築、記録メソッド、固定ラベル語彙、正規化を一つのファイルに持つ。パッケージコメントと大半の公開コメントが英語で、Go規約の日本語方針にも違反している。

## 完了条件（受け入れ条件）

- [ ] `Recorder` 契約、レジストリ構築、記録処理、固定語彙・正規化を主要責務ごとのファイルへ分け、各本番ファイルを300行以下にする。
- [ ] 対応試験を構築・正規化・記録の観点へ分ける。
- [ ] メトリクス名、ラベル集合、代替値、収集器の登録方法と大域レジストリを使わない既存挙動が変わらない。
- [ ] パッケージ、公開要素、ラベル種類数の制約、稼働セッション所有権を日本語コメントで説明する。

## 設計判断

単一の `observability` パッケージを維持する。収集器ごとの型や生成処理は作らず、既存の標準Prometheus APIを直接使う。

## スコープ境界

対象は `internal/observability` の本番コードと試験、および必要な参照調整である。メトリクス公開契約や収集項目は変更しない。

## 実装方針

既存フィールドとメソッドを責務別ファイルへ移し、英語コメントを単なる直訳ではなく、所有権・正規化理由が分かる日本語へ書き換える。

## テスト

`go test ./internal/observability`、`go test -race ./internal/observability`、`go test ./...` を実行する。

## ドキュメント同期の要否

観測仕様は変わらないため設計本文の仕様変更は不要。パッケージコメントを現在の責務へ同期する。
