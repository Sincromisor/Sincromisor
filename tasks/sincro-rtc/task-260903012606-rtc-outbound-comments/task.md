# RTC出力試験の分割と残存コメントの是正

## 背景 / 目的

`internal/rtc/outbound_test.go` は物理371行、import・コメント・空行を除いて約326行あり、世代更新、終了競合、合成音声復号、ログ検証と試験補助が同居している。また、`safe.go`、`media.go`、`readiness.go`、`readiness_test.go`には英語だけのコメントが残り、`doc.go`の案内も隣接パッケージとの境界を十分に示していない。RTC中核のパッケージ境界を変えず、規約違反と読解上の不足を解消する。

## 完了条件（受け入れ条件）

- [ ] `outbound_test.go`を世代・キュー制御、合成音声復号・失敗処理、共通補助の観点へ分け、各試験ファイルを規約上300行以下にする。
- [ ] `safe.go`、`media.go`、`readiness.go`、`readiness_test.go`に残る英語だけの説明を、意味を落とさず一般的な日本語へ改める。
- [ ] `doc.go`のパッケージコメントから、RTCセッションが所有する範囲と`datachannel`、`network`、`media`、`pipeline`へ委ねる範囲を判断できる。
- [ ] 世代更新時の一括破棄、終了中の出力拒否、復号失敗時の終了と固定ログ分類、panic回収、RTCP観測、準備状態の重複通知処理を変更しない。
- [ ] 変更理解範囲のコメント点検が完了している。

## 設計判断

`internal/rtc`の状態と非公開要素を新しい子パッケージへ公開しない。試験は現在のディレクトリと`rtc`パッケージに残す。

## スコープ境界

対象は`internal/rtc/outbound_test.go`、直接の試験補助、`doc.go`、`safe.go`、`media.go`、`readiness.go`、`readiness_test.go`のコメントである。本番処理、期限値、通信契約、観測項目は変更しない。

## 実装方針

試験関数と補助型は観点ごとのファイルへ移すだけとし、既存の検証内容を維持する。コメントは識別子や規格名の原表記を保ちつつ、所有権、処理順、失敗時の収束が分かる日本語へ書き換える。

## テスト

モジュールルートで`go test ./internal/rtc`と`go test -race ./internal/rtc`を実行する。

## ドキュメント同期の要否

既存の責務図と公開契約を変更しないため、設計文書の同期は不要である。
