# OfferレジストリをシグナリングHTTPから分離

## 背景 / 目的

`internal/signaling` ではHTTP処理と、初回Offerの同時処理の一本化、キャッシュ、終了済み記録、期限回収を担う `offer_registry.go`（322行）とその試験（678行）が同居している。後者は独立した並行状態の所有者であり、HTTP入出力とは変更理由が異なる。

## 完了条件（受け入れ条件）

- [ ] `internal/signaling/offer` がOffer項目、同時処理の一本化、容量、保持期限、回収処理と対応試験を所有する。
- [ ] 親の `signaling.Server` は新パッケージのレジストリを利用するだけで、項目の内部状態を参照しない。
- [ ] 同一リクエストID / SDPの再送、競合、2分の保持期限、1000件上限、終了セッションの終了済み記録という既存契約が変わらない。
- [ ] 子パッケージ側に必要最小の作成サービス境界を置き、親パッケージへの循環参照や汎用生成処理を作らない。
- [ ] 公開要素、所有権、待機解除、回収処理を日本語コメントで説明する。

## 設計判断

パッケージ名は責務を表す短い単数名 `offer` とし、型は `offer.Registry` のように重複を避ける。RTCのOffer / Answer型は既存を再利用する。

## スコープ境界

対象は `offer_registry.go`、対応試験、`signaling.Server` と起動処理の参照である。HTTP入力形式、RTC Manager、フロントエンド契約は変更しない。

## 実装方針

レジストリと試験を対で移し、親から必要な操作だけを注入する。時刻差し替えは既存の決定的試験に必要な範囲を維持する。

## テスト

`go test ./internal/signaling/...`、`go test -race ./internal/signaling/...`、`go test ./...` を実行する。

## ドキュメント同期の要否

公開通信契約は変わらないため `frontend-rtc.md` の変更は不要。新パッケージコメントにレジストリの位置づけを記載する。
