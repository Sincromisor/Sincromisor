# ループ再生モードの実装記録

## 判断と素材

公開RTC契約とセッションの開始・終了を変更するため、専用ブランチ`codex/rtc-playback-mode`で実装し、承認済みの仕様レビューを引き継いで独立評価する。

素材はユーザーが指定した管理下のVOICEVOX Engine `0.25.2`から生成した。
ずんだもんのノーマル（話者ID `3`）で「こんにちは。音声と、口の動きを確認します。」を読み上げる。
既存の`VoiceSynthesizer.generate`が返す加工済みクエリとモーラを保存し、WAVをFFmpeg `7.1`でOgg Opusへ変換した。
復号音声と`speaking_time`はともに`3.989333333333333`秒、モーラ合計は`3.9841527357697486`秒、28モーラだった。
出典・利用条件・SHA-256は素材のREADMEへ記録し、実ユーザー音声は使っていない。

ローカルとDockerの素材パスは作業ディレクトリ基準の`assets/playback/default/`に統一する。
ローカル実行はGoモジュールルート、Dockerは既存の`WORKDIR /opt/sincromisor`から起動する。
ファイル選択APIや新しい必須環境変数は追加しない。

## 検証環境

ブラウザーはPlaywright CLIと専用Chromeプロファイルを使い、Chrome標準の模擬マイクを通常の入力処理へ流す。
画像や未加工の受信記録は公開タスクへ保存しない。
配布イメージはユーザー指定の`malvales`で一時ビルド・一時コンテナを使って検証し、既存サービスを変更しない。

## 確認結果

素材生成スクリプトのRuff静的検査・整形、ty型検査、素材の実FFmpeg復号を確認済み。
Goの対象パッケージ`internal/media/playback`、`internal/rtc`、`internal/signaling`は`go test -race`で成功した。
実配布素材を使ったPion接続で2周以上の非無音音声、本文1回、周回ごとの発話IDと先頭時刻0、連続RTP時計、最大1件の待ち行列、2セッションの終了分離を確認した。
独立評価の指摘を反映した後のRTC試験も成功した。

`npm run gate`は成功し、フロント試験は685件成功、3件skipだった。保存・URL復元、初回OfferとICE再接続への値伝播、素材失敗表示、旧周回テロップの破棄を含む。

Playwright CLIの専用Chromeでルートメニューからplaybackを選択し、下流・Consulなしで3周以上の再生を確認した。
受信音声のRMS最大値は約0.145、本文はセッションごとに1回、各周回のテロップ時刻は0から始まり、画面上の口形の開閉も確認した。
停止操作でPeerConnectionがclosedになり、再接続ではplaybackのOfferと発話ID1から再開した。
素材なしの別プロセスではHTTP 422と素材確認の日本語エラーを確認した。
模擬カメラは取得エラーになったが、今回対象の返却音声・テロップ・口形確認には影響しなかった。

Dockerは最終コミット`7ab98a68`のソースでビルドした。
一時コンテナの`/opt/sincromisor/assets/playback/default/`で音声35,638バイトとJSON10,037バイトを確認し、同梱FFmpegで復号できた。
既存の必須ネットワーク引数を指定して起動し、ブラウザーで取得したSDPのplayback OfferにHTTP 200とAnswer（SDP 1,352バイト）を返した。
下流とConsulは使わず、一時コンテナは確認後に削除した。
独立評価はPASSで、指摘された診断経路の古いコメントと設計説明は修正済み。

## 対象外の失敗

`go vet ./...`は成功した。`go test -race ./...`では入力Opusの固定ハッシュ比較（mono/stereo）と、検証ハーネスのmacOS `/private/var`・`/var`比較が失敗した。
同じ環境で変更前の`4a798820`の該当2パッケージを実行し、同じ失敗を再現した。今回変更による悪化はない。
独立評価側でもサンドボックスのIPv4バインド制約でPion試験を再実行できなかったため、親の許可された実行環境での成功結果を使用した。

## 追補: Go全体試験の既存失敗の修正

2026-10-12の追加依頼で、前節の2件を調査して修正した。

Opusの失敗はFFmpegではなく、Pion Goデコーダーの融合積和による丸め差だった。
macOS/arm64とLinux/amd64で生成したOpusパケットは同一だったが、復号後の16 kHz PCMはmonoの13標本で最大2、stereoの18標本で最大1だけ異なった。
macOS上でデコーダーだけ融合積和を無効にすると、両方とも従来のSHA-256へ一致した。
本番処理は変更せず、入力パケットと従来の基準PCMを固定ファイルへ保存し、全320標本を最大2 LSBの許容幅で比較するよう修正した。
フレーム長、提出タイミング、FIR係数・周波数応答・ステレオ平均の検証は維持する。
基準値の由来と更新方法は入力処理の`testdata/README.md`に記録した。

パス比較の失敗は、`Load`がシンボリックリンクを解決した実行パスを保持する契約に対し、テストが解決前の文字列を期待していたためだった。
テストでは明示的に実行ファイルへのリンクを渡し、解決後のパスでコマンドを起動することを確認する。
これによりmacOSの`/var`から`/private/var`への解決にも、Linux上の明示リンクにも同じ検証を適用できる。

修正後の確認結果: `go vet ./...`と`go test -race ./...`は成功した。Linux/amd64のGo 1.26.9でも、対象2パッケージの全試験が成功した。コメントとMarkdownの点検も完了した。
