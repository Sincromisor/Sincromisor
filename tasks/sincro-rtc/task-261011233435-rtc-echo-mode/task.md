# RTCの音声折り返しモードをメニューから利用できるようにする

## 背景 / 目的

下流の音声抽出・認識・応答生成・合成サービスを起動せず、フロントエンドとRTCサーバーまでの音声往復とブラウザー側VADを確認したい。
ユーザーは起動時の切り替えではなく、chat／sincroと同じ選択メニューとパラメーターによる診断モードを要求している。
本タスクでは共通の診断経路とechoを実装し、[ループ再生タスク](../task-261011233441-rtc-playback-mode/task.md)で素材付きplaybackを追加する。

起票時の確認対象はHEAD `f9b20e65`。現在のRTCはセッション作成時にCoordinatorを必ず作り、入力Opusと2本のDataChannelが準備できると下流4サービスへ接続する。
入力は16 kHzモノラルPCM、出力は48 kHzモノラルPCMからOpusへ符号化する。出力キューは発話単位であり、連続PCMの投入先は別途必要となる。

## 完了条件（受け入れ条件）

- [x] 「体験を選ぶ」に「入力音声を折り返す」を追加し、`talk_mode=echo`で接続できる。起動引数、環境変数、プロセス再起動によるモード切り替えは不要とする。
- [x] 設定の保存・復元、ページの`talkMode`パラメーター、初回OfferとICE再接続がechoを扱う。既存のchat／sincroは従来の経路を使う。
- [x] 同じRTCプロセスでセッションごとに処理を選択し、echoでは下流クライアントの生成・探索・接続・再試行を行わない。Consulや下流サービスを起動しない構成で音声往復が成立する。
- [x] 通常のマイク・フィルター・VADゲートを通った送信音声をRTC側で復号し、PCMを折り返して共通の音声送信処理から返す。サーバー側にVAD、発話区間抽出、認識、合成を追加しない。
- [x] 連続PCMは上限付きで保持し、滞留時に古い音声を破棄して遅延の累積を防ぐ。入力がない間も既存の出力時計と無音送信を維持する。
- [x] 診断中は視線などキャラクター動作に伴う自動ミュートを適用せず、手動ミュートと音声設定を利用できる。通常モードへ戻した際は通常の制御に戻る。
- [x] モードは停止・再接続で変更し、ICE再接続では同じ値を維持する。停止・失敗時に診断処理とバッファを終了し、別セッションへ音声を流さない。
- [x] UIに診断モードであることと接続・失敗状態を示し、認識・合成への接続と誤認する案内を出さない。echoで認識文やモーラ情報を捏造しない。
- [x] 通信契約と関連設計を更新し、対象確認の結果を記録する。

## 設計判断

`talk_mode`の許可値へ`echo`を追加する。公開通信契約の変更はリポジトリの方針に従って破壊的変更として明示し、フロントとサーバーを同一タスクで同期する。
HTTPパスやDataChannel名、音声の送受信形式は維持する。実装のない`playback`を先行してメニューや許可値へ追加しない。

セッション生成時に通常経路と診断経路を選ぶ。Coordinatorのダミー接続や合成結果への偽装でechoを実現せず、必要最小限の入力先・出力元・開始終了の境界を設ける。
既存のPeerConnection、Opus復号・符号化、20 msの送信時計、RTCP処理を再利用し、16 kHzから48 kHzへの変換を追加する。
RTPの直接折り返しではないため、入力ビット列や音質の完全一致を要件としない。

音声トラックと`text_ch`／`telop_ch`の開始条件は通常と同様に維持する。下流の接続完了は診断経路の開始条件にしない。
診断処理・送信バッファ・再サンプリング状態はセッションが所有し、既存の終了処理で中断と終了待機を完了する。
通常経路の世代更新・旧出力破棄・再接続を保ち、診断処理との同時書き込みや不要な世代待ちを発生させない。

ブラウザーの入力処理を診断時だけ迂回しない。キャラクターの既存のchat／sincro動作分類と通信モードを混同せず、診断中の自動ミュート抑止を明示する。
VADの初期設定は変更せず、既存の設定画面で有効化・無効化して比較する。
FFmpegとOpusの既存の実行時依存は維持する。Consulのプロセス登録設定は既存の任意設定として扱い、診断用起動フラグは設けない。

## スコープ境界

フロントの選択・保存・接続、RTCの経路分岐・PCM折り返し・終了処理、設計同期を含む。
ループ再生とその素材は後続タスクで扱う。マイク不要の接続、ブラウザーへの音声ファイル注入、サーバー側VAD、録音保存、RTP直接折り返し、下流サービスの変更は含めない。
既存の模擬サービスによる統合試験は下流通信契約の確認用途として残す。

## 主な変更範囲

- `sincromisor-server/sincro-rtc/internal/signaling/`、`internal/rtc/`、`cmd/sincro-rtc/startup.go`: 許可値、セッション構築、開始・終了と依存の組み立て。
- 同`internal/media/input/`、`internal/media/output/`: 入力PCMの受け渡し、連続PCMの上限付きバッファと共通送信処理。
- `sincromisor-frontend/src/features/settings/react/fields/`、`app/settings/`、`pages/main/`、`pages/simpleVrm/mainVrm.ts`: 選択肢・説明・保存・URLによる初期値。
- 同`features/rtc/`、`app/controller/`、必要な`character/behavior/`: モード伝播、診断時の自動ミュート抑止、接続案内。
- 同`features/media/vad/userMediaAudioProcessor.ts`: VAD通過後のトラックを維持していることの確認対象。

## 確認方法

- Goの対象試験で、echoが下流接続を呼ばないこと、PCM変換・滞留時の破棄・入力途絶時の無音、終了時の処理解放を確認する。既存の通常経路・初回Offer・ICE再接続の関連試験も実行する。
- Pionの実接続で非無音入力が返却トラックへ届くことを確認し、同一プロセス内の複数セッションで音声と終了が分離されることを確認する。
- フロントの対象試験で選択値の保存・復元・Offer伝播、自動ミュート抑止と通常モードへの復帰を確認する。横断する変更のためルートの`npm run gate`を実行する。
- 下流とConsulを起動しない開発環境で、ブラウザーのメニューから接続し、既存VADゲートの有効・無効による返却音声の違いを1回確認する。ヘッドホンを使用し、接続・停止・再接続も確認する。共有サービスを停止して環境を作らない。
- ブラウザー確認では既存のPlaywright CLI規約とスキルに従う。今回の変更による必須確認の失敗は修正後に再確認し、未確認のまま完了しない。
