# 送信音声処理をmedia出力パッケージへ分離

## 背景 / 目的

`internal/media/output.go` は432行あり、発話キュー、絶対期限時計、遅延破棄、Opus符号化、テロップ生成が入力処理と同じパッケージにある。さらに `internal/rtc/outbound_pair_test.go` の一部はRTCセッションではなく出力処理担当とPionのRTPパケット化だけを検証している。

## 完了条件（受け入れ条件）

- [ ] `internal/media/output` が発話キュー、48 kHz / 20 ms時計、Opus符号化、テロップ生成、出力観測と対応試験を所有する。
- [ ] `output.go` のキュー、時計、フレーム生成を主要責務ごとのファイルへ分け、各本番ファイルを300行以下にする。
- [ ] 出力処理だけを検証するPion結合試験をRTCパッケージから新パッケージへ移し、セッション全体の試験はRTC側に残す。
- [ ] 決定的時計の試験用公開要素を不要にできる場合は非公開化し、試験都合の公開APIを残さない。
- [ ] 20 ms間隔、無音、250 ms遅延中止、RTP欠番、発話・サンプル上限、モーラ境界の既存契約が変わらない。
- [ ] 時計、キュー所有権、破棄条件、後段DataChannelとの関係を日本語コメントで説明する。

## 設計判断

入力パッケージ分離後に実施し、共有用の曖昧な `media` 型を増やさない。出力試験は実際の所有パッケージへ近接させる。

## スコープ境界

対象は `output*.go`、対応試験、`rtc/outbound_pair_test.go` の出力限定ケース、RTC側参照である。Synthesizerのコンテナー復号とフロントエンド契約は変更しない。

## 実装方針

既存処理を `internal/media/output` へ移し、時計・キュー・フレーム組み立ての既存境界でファイルを分ける。新しい依存や汎用スケジューラーは導入しない。

## テスト

`go test ./internal/media/output ./internal/rtc`、`go test -race ./internal/media/output ./internal/rtc`、`go test ./...` を実行する。

## ドキュメント同期の要否

送信音声とテロップの公開契約は変わらないため契約文書の仕様変更は不要。新パッケージコメントへ同期責務を記載する。
