# RTCセッション中核のファイルと試験を責務別に整理

## 背景 / 目的

`internal/rtc` は本番2,717行・試験4,054行で、`session.go`（401行）、`manager.go`（320行）、`session_test.go`（832行）が構築、受付上限、交渉、終了、再接続、音声、試験補助を横断している。独立可能なDataChannelとプロセスネットワークを分離した後も、セッション中核の対応関係を明示する必要がある。

## 完了条件（受け入れ条件）

- [ ] `internal/rtc` の本番ファイルが、セッション構築、`Manager` の受付・台帳、交渉リビジョン、生存期間・終了、準備状態・復旧、音声接続のいずれか一つを主責務とする。
- [ ] 300行を超える `session.go` と `manager.go` を責務に沿って分割し、公開型や既存の処理順序を変えない。
- [ ] `session_test.go` の試験を対象責務ごとの `*_test.go` へ移し、共通補助は既存 `session_harness_test.go` に集約する。
- [ ] 単体試験のために非公開要素を公開せず、内部状態へ依存する白箱試験はGoの規約どおり対象パッケージと同じディレクトリに残す。
- [ ] 変更理解範囲の公開要素、状態遷移、ロック順、処理担当の終了条件、非所有参照を日本語コメントで説明し、古い英語コメントを残さない。

## 設計判断

`Session` の状態と所有資源は相互依存が強いため、形だけの子パッケージや一実装だけのインターフェースには分けない。先行タスクで独立した責務を除いた後、同一パッケージ内のファイル対応を明確にする。

## スコープ境界

対象は先行分離後の `internal/rtc` 本番コードと試験である。状態機械、期限値、終了上限、HTTP / DataChannel契約の変更は行わない。

## 実装方針

既存の呼び出し関係を保った移動・改名を優先する。巨大試験は観点別に分けるが、試験ケースの削減や新しい試験枠組みの導入は行わない。

## テスト

`go test ./internal/rtc`、`go test -race ./internal/rtc`、`go test ./...` を実行する。

## ドキュメント同期の要否

公開仕様は変わらない。パッケージコメントを `doc.go` へ置き、責務図の設計文書同期は後続のパッケージ責務図タスクで行う。
