# 受信音声処理をmedia入力パッケージへ分離

## 背景 / 目的

`internal/media` にはブラウザー入力、合成音声出力、Opus試験音が同居している。特に `audio.go` の `GenerateTestPCM`、`ToneEncoder`、`DecodeRemote` は本番コードから参照されず、試験だけの実装が通常ビルド対象として公開されている。

## 完了条件（受け入れ条件）

- [ ] `internal/media/input` がRTP読取、並べ替え、Opus復号、モノラル化、16 kHz再標本化、20 msフレーム化、入力観測と対応試験を所有する。
- [ ] `internal/rtc` は入力パッケージの公開された最小境界だけを利用する。
- [ ] 試験専用のPCM生成・Opus符号化・低水準診断を通常ビルド対象から除き、必要な試験ファイル内へ置く。
- [ ] 64パケット窓、`duplicate` / `late` / `missing` 分類、DTX、20 ms / 640バイトという既存挙動が変わらない。
- [ ] 入力表現の各変換段階、SSRC変更時の破棄、所有権、失敗条件を日本語コメントで説明する。

## 設計判断

入力と出力は変更理由と時刻基準が異なるためパッケージを分ける。試験のためだけに本番の公開要素を維持せず、標準の `*_test.go` を使う。

## スコープ境界

対象は `internal/media/input*.go`、`resample.go`、`audio.go` の入力・試験支援部分、対応試験、RTC側参照である。送信音声、合成音声デコーダー、通信契約は変更しない。

## 実装方針

入力処理と試験を対で移し、型名は `input.Processor` のようにパッケージ名との重複を避ける。試験波形の生成は既存ロジックを試験側へ移すだけとする。

## テスト

`go test ./internal/media/input ./internal/rtc`、`go test -race ./internal/media/input ./internal/rtc`、`go test ./...` を実行する。

## ドキュメント同期の要否

音声形式契約は変わらないため契約文書の仕様変更は不要。新パッケージコメントへ入力変換の範囲を記載する。
