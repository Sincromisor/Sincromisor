# シグナリングHTTPの処理と試験をエンドポイント別に整理

## 背景 / 目的

`internal/signaling/http.go` は536行、`http_test.go` は676行あり、サーバー構築、状態確認、設定応答、初回Offer、JSON制限、エラー変換、静的配信が一つのファイルに集まっている。ICE候補と更新Offerだけが別ファイルで、エンドポイントと試験の対応が不均一である。

## 完了条件（受け入れ条件）

- [ ] サーバー構築・共通応答、運用エンドポイント、設定応答、初回Offer、入力解析を既存エンドポイント責務に沿うファイルへ分ける。
- [ ] `http_test.go` を同じ責務単位へ分け、各試験の対象ハンドラーをファイル名から追える。
- [ ] URL、JSON、サイズ上限、HTTP状態、draining、静的配信優先順位を変更しない。
- [ ] 同一パッケージ内の自明な処理を新しいインターフェースやルーター抽象へ包まない。
- [ ] HTTP境界、入力拒否条件、状態変換、ProcessStateの生存期間を日本語コメントで説明する。

## 設計判断

外部契約を保ったファイル分割とし、子パッケージは増やさない。Goの白箱単体試験は対象パッケージと同じディレクトリに置く。

## スコープ境界

対象はOfferレジストリ分離後の `internal/signaling` HTTP実装と試験である。RTC実装、フロントエンド、契約値の変更は行わない。

## 実装方針

既存 `http_candidate.go` / `http_update.go` の粒度を基準に、共通処理だけを共通ファイルへ残す。英語の公開コメントは現行の日本語規約へ合わせる。

## テスト

`go test ./internal/signaling/...` と `go test ./...` を実行する。並行状態へ触れた場合だけ `go test -race ./internal/signaling/...` も実行する。

## ドキュメント同期の要否

公開HTTP契約は不変のため契約文書の仕様変更は不要。配置説明は後続の責務図タスクで同期する。
