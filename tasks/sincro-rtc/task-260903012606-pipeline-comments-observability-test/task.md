# 会話パイプラインの残存コメントと観測試験を整理

## 背景 / 目的

`internal/pipeline`の`connect.go`、`conversation.go`、`generation.go`、`queue.go`、`reset.go`、`runtime.go`には、世代、キュー所有権、再初期化、ログ秘匿境界を説明する英語だけのコメントが残る。また、`observability_test.go`は物理416行、import・コメント・空行を除いて約382行あり、段階ログ、再初期化ログ、panic、キュー、終了競合の検証が同居している。既存パッケージ境界のままコメント規約とファイル上限へ適合させる。

## 完了条件（受け入れ条件）

- [ ] 対象6ファイルの英語だけのコメントを、世代の所有、遅延結果の拒否、接続公開、キュー移譲、ロック順、再初期化、ログの秘匿範囲が分かる日本語へ改める。
- [ ] `observability_test.go`を段階・再初期化ログ、処理担当・キュー、終了競合・状態遷移の観点へ分け、各試験ファイルを規約上300行以下にする。
- [ ] 試験と補助は現在の`internal/pipeline`と`pipeline`パッケージに残し、本番要素を試験用に公開しない。
- [ ] 世代、再初期化、キュー、終了順序、ログへ音声・認識・会話内容を出さない既存挙動と検証を変更しない。
- [ ] 変更理解範囲のコメント点検が完了している。

## 設計判断

新しい子パッケージやログ抽象は追加しない。コメント是正と試験ファイルの移動に限定する。

## スコープ境界

対象は`internal/pipeline`直下の上記6本番ファイル、`observability_test.go`と直接の試験補助である。`client`、`discovery`、`protocol`、下流サービス、通信形式は変更しない。

## 実装方針

コメントは原文の制約を落とさず日本語へ書き換える。試験は既存関数と記録用観測器を観点ごとのファイルへ移し、検証値を変更しない。

## テスト

モジュールルートで`go test ./internal/pipeline`と`go test -race ./internal/pipeline`を実行する。

## ドキュメント同期の要否

公開契約と責務境界は変わらないため、設計文書の同期は不要である。
