# DataChannel送信処理と試験を規約サイズへ分割

## 背景 / 目的

`internal/rtc/datachannel/dispatcher.go` は物理400行、import・コメント・空行を除いて約330行あり、構築、チャネル接続、キュー、統計、終了、送信処理、送信抑制を一つのファイルに持つ。`dispatcher_test.go` も物理395行、同じ数え方で約357行あり、`documents/rules/code-structure.md` の300行上限を超えている。既に成立しているパッケージ境界を維持したまま、変更時に読む範囲を既存責務に沿って縮める。

## 完了条件（受け入れ条件）

- [ ] `dispatcher.go` の構築・接続・終了、キュー・統計、送信・送信抑制を主要責務ごとのファイルへ分け、変更後の各本番ファイルを規約上300行以下にする。
- [ ] `dispatcher_test.go` をキュー方針、送信抑制、接続・終了の観点へ分け、共通の偽DataChannelと待機補助を同じパッケージの試験補助へ集約し、各試験ファイルを規約上300行以下にする。
- [ ] `text_ch` 64件、`telop_ch` 128件、1 MiBでの送信停止、256 KiB以下への復帰、5秒の時間切れ、世代更新時の破棄、信頼性別の失敗処理を変更しない。
- [ ] 移動した処理群の所有権、終了条件、破棄判断を日本語コメントから確認でき、コメント点検が完了している。

## 設計判断

新しい子パッケージ、公開API、インターフェースは追加しない。Goの試験配置規約に従い、本番コードと試験は現在の`internal/rtc/datachannel`に残す。

## スコープ境界

対象は`internal/rtc/datachannel/dispatcher.go`、`dispatcher_test.go`と直接の試験補助である。ペイロード形式、RTCセッション、フロントエンド、観測項目は変更しない。

## 実装方針

既存の関数と型を現在の責務単位で移動し、処理順や同期方法を書き換えない。試験ケースと偽実装も削減せず、対応する責務の試験ファイルへ移す。

## テスト

モジュールルートで`go test ./internal/rtc/datachannel`と`go test -race ./internal/rtc/datachannel`を実行する。

## ドキュメント同期の要否

公開契約とパッケージ責務は変わらないため、設計文書の同期は不要である。
