# MessagePack試験を変換責務別に分割

## 背景 / 目的

`internal/pipeline/protocol/msgpack_test.go`は物理416行、import・コメント・空行を除いて約377行あり、固定データの復号、不正入力、未知フィールド、防御的コピー、符号化拒否とMessagePack生成補助が同居している。通信契約と固定データを変えず、変換方向と検証責務から試験を追える構成にする。

## 完了条件（受け入れ条件）

- [ ] `msgpack_test.go`を固定データ復号、不正入力・互換入力、符号化・所有権、共通生成補助の観点へ分ける。
- [ ] 変更後の各試験ファイルを、import・コメント・空行を除いて300行以下にする。
- [ ] 試験は現在の`internal/pipeline/protocol`と`protocol`パッケージに残し、非公開の変換補助を試験都合で公開しない。
- [ ] 既存の固定データ、不正入力のエラーパス、未知フィールド受理、空コレクション、防御的コピー、必須コレクション拒否の検証を削除しない。
- [ ] 移動した試験補助のコメント点検が完了している。

## 設計判断

本番の符号化・復号処理と`testdata`は変更しない。試験用のMap生成補助は重複させず、同じ試験パッケージで共有する。

## スコープ境界

対象は`internal/pipeline/protocol/msgpack_test.go`と直接の試験補助である。DTO、MessagePackキー、Python固定データ生成、下流サービスは変更しない。

## 実装方針

既存試験関数と生成補助を観点ごとのファイルへ移し、入力値、期待値、固定データの参照方法を維持する。

## テスト

モジュールルートで`go test ./internal/pipeline/protocol`と`go test -race ./internal/pipeline/protocol`を実行する。

## ドキュメント同期の要否

通信契約と固定データを変更しないため、設計文書の同期は不要である。
