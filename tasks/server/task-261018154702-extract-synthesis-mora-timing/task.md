# 音声合成のモーラ変換を分離し前後の無音時間を正しく扱う

## 背景 / 目的

サーバー側のリファクタリング候補を調査し、起票から実行まで進める依頼に対応する。
`VoiceSynthesizer` はHTTP合成の調停、エンコード、口形用モーラ列への純粋変換を兼ねている。
変換処理がインスタンスの非公開メソッドに埋まり、通常モーラと休止モーラの継続時間計算も重複している。
末尾無音には `postPhonemeLength` ではなく `prePhonemeLength` を使っており、前後で異なる値を指定すると要求とモーラ列が一致しない。

## 調査結果と選定理由

Pythonの主要サービスと共有設定、Goのパイプライン調停器、AgentServerの入口を確認した。
既存未完了タスクは `npm run tasks:next` で確認し、今回と重なるサーバータスクはなかった。

| 箇所                                          | 確認した構造                                                              | 今回の判断                                         |
| --------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------- |
| `VoiceSynthesizer`                            | 合成I/Oとモーラ変換が混在し、時間加算が重複。末尾無音の参照先が誤っている | 純粋変換を分離し、不具合を回帰テストで確認する     |
| `SpeechRecognizerNemoWorker`                  | 辞書読込、補正、再ランキング、保存が同じクラスに集中                      | 候補として記録。今回の局所変更からは除外する       |
| `MastraClient._chat`                          | HTTP要求、SSE行処理、完了判定が同じ処理にある                             | 完了・中断状態を扱うため今回の変更対象には含めない |
| Goの `Coordinator` / AgentServerの `index.ts` | 世代処理は別ファイル、サービス組立は `application.ts` に分離済み          | 今回の調査範囲では追加分割の根拠なし               |

## 完了条件（受け入れ条件）

- [x] 前後の無音時間がそれぞれの設定を使い、モーラ順序、子音と母音の時間加算、休止の非表示を維持する。
- [x] 通常モーラ、子音なし、母音長ゼロ、休止あり・なし、空の句列、前後の無音時間が異なる場合を確認する。
- [x] 生成経路と既存の音声合成テスト、対象の静的検査・型検査で今回の回帰がないことを確認する。既存の環境制約は分離して記録する。
- [x] サービス設計、確認結果、タスク状態と索引を同期してコミットする。

## 実装方針と範囲

`voice_synthesizer/mora_timing.py` に変換を集約し、`VoiceSynthesizer.generate` から呼ぶ。
既存の `query_filter` は同じクエリの休止長を更新する契約を維持して単純化する。
型、単位、入力を変更する箇所と変更しない箇所をコメントで説明する。
MessagePackの項目・型、HTTP通信、ログ、音声形式、キャッシュキーと保存形式は変更しない。
保存済みキャッシュの削除・移行は実施しないため、修正は新規生成分に適用される。

Goの `internal/media/synthdecode/conversion.go` はモーラ長を累積して口形時刻へ変換し、末尾無音をPCM末尾へ収める。
今回は既存フィールドの計算修正であり、通信契約の破壊的変更はない。
設計索引から参照済みの [VoiceSynthesizer設計](../../../documents/design/backend/services/voice-synthesizer.md) に責務分離を反映する。

## 確認方法

既存のPython環境を `UV_CACHE_DIR=/tmp/sincromisor-uv-cache uv run --no-sync` で利用する。
新規テストで変更前の不具合を再現してから修正する。音声合成パッケージのpytest、変更PythonファイルのRuffとty、変更MarkdownのPrettier、タスク整合性を確認する。
実VOICEVOX・Redis・S3への接続とブラウザー会話は今回の純粋変換の検証には用いず、既存のHTTP代役とキャッシュ代役によるテストを利用する。

## 実装・確認結果

- `mora_timing.build_mora_queue` へ変換を分離し、子音・母音の加算を共通化した。`VoiceSynthesizer` は184行から120行となった。
- 変更前は追加した生成経路テスト2件で、後無音0.4秒が0.2秒になる不具合を再現した。変更後は入力の不変性も含む追加テスト3件が成功した。
- 音声合成パッケージのpytestは52件成功、2件失敗、1件省略。失敗2件は `opusenc` 未導入であり、HEADの変更前クラスをメモリ上で読み直しても同じ失敗を確認した。詳細と未実行範囲は [実装補足](impl.md) に記録した。
- 変更本番Python2ファイルのtyは成功。変更Python3ファイルのRuff整形も成功した。
- Ruffは既存ファイル名 `VoiceSynthesizer.py` の `N999` のみ検出した。HEADの同ファイルにも同じ指摘があることを確認し、この規則だけをコマンドで除外した対象検査は成功した。設定やコードへの抑制追加はない。
- コメント点検: PASS。新規関数、呼び出し元、休止長調整、WAV時間取得の責務・秒単位・副作用を点検した。
- VoiceSynthesizer設計へ変換の責務と順序を同期し、既存の設計索引から辿れることを確認した。
- 変更MarkdownのPrettier、`git diff --check`、`tasks:index:check`、`tasks:check` が成功した。
