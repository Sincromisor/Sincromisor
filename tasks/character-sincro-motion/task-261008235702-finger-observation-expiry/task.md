# 指姿勢の観測時刻と保持期限を修正する

## 背景・目的

`fingerCurlPoseLayer.ts`は前回の出力時刻との差が250ミリ秒以内なら指を保持し、保持結果へ毎回現在時刻を付け直す。欠損値を100ミリ秒間隔で与える固定入力では、1秒後も同じ曲げが`previous`として残った。また、指特徴量が有限なら、手の検出状態や信頼度を確認せず採用する。通常の手欠損は既定の曲げ0を持つため、欠損が有効な開いた手として扱われる経路もある。

## 完了条件

- [x] 最後に有効な手の特徴量を観測した時刻と、その後に生成した姿勢の時刻を区別する。保持した出力を再び有効観測として扱わず、250ミリ秒の既存期限を継続更新で延長しない。
- [x] 手の`detected`、信頼度、観測時刻、左右割当の有効性を確認して指特徴量を採用する。欠損時の既定値を観測された曲げ0として扱わない。
- [x] Pose・意図の更新が止まっていても描画時間の経過に応じて保持が終了する。入力時刻と描画時刻の対応を明示し、時計の原点が違う値を直接減算しない。
- [x] 保持期限後は既存の中立指姿勢へ戻り、復帰時は現観測へ接続する。保持中に`curlScale`を繰り返し掛けず、同じ値の再描画で曲げが変化しない。
- [x] 左右を独立に保持し、入力切替・追跡停止・VRM交換で履歴を引き継がない。指層は腕のIK位置を変更しない。

## 時計と保持状態の所有者

[欠損・復帰タスク](../task-261008235702-motion-dropout-application/task.md)で決めた時計対応を先に利用できる状態にする。`VRMCharacterManager.update(nowMs)`が計算したHandの表示評価時刻と、最後の有効Hand観測時刻を合成サービスへ明示的に渡す。`intent.timestamp`を現在時刻として流用せず、このタスクで別の時計やタイマーを作らない。

左右別の最後の有効な指特徴量と観測時刻は`SincroVrmPoseComposerService`が持ち、新しい有効Hand観測でだけ更新する。指層生成はその基点と現在の評価時刻から出力を求める。保持した診断スナップショットや、尺度を掛けた出力値を観測として保存しない。同時刻の再描画では基点を更新せず、入力系列切替・逆行・明示停止・モード切替・VRM交換の通知で合成サービスの指履歴を破棄する。再生は壁時計と切り離した仮想時刻を使い、一時停止中に保持期限を進めない。

## 確認方法

有効な曲げ→無効な手が連続到着→期限超過→復帰の系列、有限値が残る低信頼度の手、時刻停止、片手だけの欠損を確認する。100ミリ秒間隔の欠損で保持が1秒続く再現を修正前後で比較する。`curlScale != 1`で保持中に縮小しないことも確認する。実写は手の情報が保存済みの区間だけを使い、Poseのみの記録から指を復元した扱いにしない。

時系列状態と描画時刻をまたぐため、独立レビュー・評価の対象とする。意味動作の指上書き方針は[別タスク](../task-261008235703-tracking-semantic-arbitration/task.md)で扱う。

## 実装・確認結果

左右別の未加工Hand特徴と実観測時刻を合成サービスが保持し、有効性を確認した新観測でだけ更新する。
管理側のHand表示評価時刻を渡し、250msを超えると中立へ戻す。保持出力や診断時刻を観測へ戻さず、曲げ尺度は一度だけ掛ける。
無効な意図やHand欠損でも期限評価を続け、系列・停止・モード・VRMの初期化経路で履歴を破棄する。

固定入力で100ms間隔の欠損、1秒後の失効、復帰、左右独立、低信頼・左右不整合・時刻異常・有限値の残る未検出、尺度0.5、時計の原点差と再生一時停止を確認した。
保存済みHand118観測も、本番合成で無到着の評価時刻を進めると全件が1秒後に中立へ戻った。
[集計](artifacts/comparison-summary.json)と[再計算関数](artifacts/replay-check.js)を保存した。
再計算関数は既存の非公開サーバーとViteを起動し、Playwright CLIの `run-code` へ渡す。
意味動作による観測指の上書きは依存タスクで合わせて修正した。設計とコメントを同期し、独立確認は[評価](eval.md)に記録する。

共通の姿勢合成・IKの変更を含むため、依存する5タスクの実装・比較結果・状態を同じコミットにまとめる。
フロント全体のテストは677件成功・3件スキップ、型検査と本番ビルド、構造検査は成功した。
