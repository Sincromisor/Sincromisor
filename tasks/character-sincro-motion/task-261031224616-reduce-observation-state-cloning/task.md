# 追跡観測から動作生成までの不要な状態複製を削減する

## 背景 / 目的

フロントエンドのモーションキャプチャと動作生成の性能調査として、映像フレーム駆動、Worker転送、顔・手の領域推論、観測から信頼性・共通表現・時系列・意図を生成する経路、最終姿勢合成を確認した。

`SincroMotionObserveOnlyPipeline`は更新開始、下流計算の保存、前回Poseの保持、公開結果の作成で状態全体を繰り返し複製する。定常状態のPose更新は5回、Face・Hand更新は3回、Gesture更新は2回であり、更新しない配列や次に置き換える古い推定値も複製している。`getSummary()`も、要約に使わない状態全体を複製する。直前の描画時最適化とは別の、観測コールバック側の負荷である。

## 完了条件（受け入れ条件）

- [x] 更新時の状態全体の複製を公開結果の1回に限定し、要約だけの取得では行わない。
- [x] 入力、返却状態、要約の変更が内部状態や次フレームの推定へ波及しない。
- [x] Face・Handだけの更新で時系列・意図を進めず、欠損入力、無効時刻、初期化の挙動を維持する。
- [x] 同じ合成入力列の変更前後で出力が一致し、対象テスト・型検査・静的検査が通る。

## 設計判断

外から受け取る観測値だけを取り込み時に複製し、内部で所有する未変更値と新しい計算結果はそのまま保持する。`getState()`と更新結果の返却境界では深い複製を続ける。前回Poseは取り込み済みの内部値を参照し、要約は必要な値と警告配列だけを取り出す。

## スコープ境界

対象は観測パイプライン、既存の顔複製関数、回帰テスト。推論モデル、推論頻度、フィルター、IK、描画品質、通信・保存形式は変更しない。実機のFPSを改善率として断定せず、合成入力での処理時間と複製回数を記録する。

## 実装方針

- `sincroMotionObserveOnlyPipeline.ts`の取り込み・下流状態保存・要約を変更する。
- `sincroMotionPipelineState.ts`の顔複製処理を取り込みでも共用し、行列と警告配列の独立性を保つ。
- 既存の観測・計算・状態テストに加え、複製回数と入出力の独立性を検査する。

## テスト

- 観測パイプライン、状態複製、共通計算、時系列、意図、描画側と診断側の関連Vitest。
- 合成入力を使う変更前後の出力比較と局所計測。時間の固定閾値は設けない。
- TypeScript型検査、変更ファイルのBiome・Prettier、タスク索引・状態検査。

## ドキュメント同期の要否

観測頻度、計算順序、公開する状態、推定方法は維持するため設計変更はない。所有権と複製境界をコードコメントで説明する。

## 実装・確認結果

- 状態全体の複製はPose更新で5→1回、Face・Hand更新で3→1回、Gesture更新で2→1回、要約取得で1→0回となった。入力観測と公開結果の分離は維持し、ジェスチャーの表示用入力も保持時に分離した。
- 関連11ファイル71テストが成功。入力・返却状態・要約の改変後の次フレーム比較、凍結入力、過去の返却値の保持、初期化、欠損・無効時刻を確認した。
- TypeScript型検査、変更TypeScriptのBiome確認を実施した。
- 構造確認では既存の観測パイプラインの例外理由を維持し、変更後も観測蓄積と公開要約の責務に限定した。コメント点検: PASS。

### 局所計測

合成入力1000フレームに対し、各フレームでFace→Pose→Hand→Gesture更新と要約取得を実行した。1回の準備実行後に5回計測した中央値であり、計測区間にはハッシュ生成を含めない。初期値由来の身体座標欠損を含む固定入力で、顔の向きだけを周期的に変えている。変更前は上記コミットの観測パイプライン、変更後は今回の実装を使った。

中央値は変更前3176.5ms、変更後1055.4ms（約67%短縮）。全更新結果と要約のJSON出力のSHA-256は一致した。集計は[measurement.json](artifacts/measurement.json)、再計測用の入力列は[observation-performance.test.ts](artifacts/observation-performance.test.ts)に置く。

リポジトリルートから再計測する。

```sh
node_modules/.bin/vitest run --root . tasks/character-sincro-motion/task-261031224616-reduce-observation-state-cloning/artifacts/observation-performance.test.ts
```

計測結果は`/tmp/observation-performance-current.json`へ出力される。変更前の初回計測はVitest既定の5秒制限で失敗したため、計測用の時間制限を60秒に変更して再実行し成功した。Biomeはリポジトリルートからの初回呼び出しでは設定の入れ子で失敗したため、フロントエンドを作業ディレクトリにして確認した。

### 未実行事項・限界

実カメラ、MediaPipeモデル推論、ブラウザー描画を含むFPS・GC時間は未計測。上記の短縮率は観測から動作状態を生成する局所処理の値であり、画面全体の改善率ではない。領域切り抜きの生成や診断用の生結果転送にも追加調査の余地はあるが、今回は品質・処理頻度を変えずに出力一致を確認できた重複複製を修正対象とした。
