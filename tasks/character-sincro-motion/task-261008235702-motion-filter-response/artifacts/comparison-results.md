# 腕の揺れと応答の比較

## 条件

2026-10-09に、既存6動画の保存済みPose実観測610フレームを同一のVRMと設定で再計算した。
入力動画・記録のSHA-256は[原本一覧](../../task-261008235701-recorded-motion-quality-baseline/artifacts/recording-inventory.json)と全件一致した。
変更前のコミット、モデルと未加工出力のハッシュは[照合記録](evidence-manifest.json)、全指標は[集計](comparison-summary.json)に置く。
実写・観測点・各フレームの姿勢はGit管理外の `work/private-artifacts/` に保存した。

比較は本番の正規化、時系列推定、二関節IK、姿勢合成を通す `recomputeMotionReplay()` を使った。
保存時刻の間隔は約93〜155msで、等間隔へ書き換えなかった。先頭2秒を除き、残りの前半を調整、後半を確認に使った。
同じ録画内の分割であり、別人物・別条件への汎化を示すものではない。

- `filter-baseline`: 変更前の腕処理。手首のOne Euro Filter、155msの描画補間、最終角速度制限。
- `filter-input`: 手首と同じ観測時刻で肘座標もOne Euro Filterへ通す候補。IKの極履歴を観測単位で更新する修正を含む。
- `filter-minimal`: 入力候補に加え、既存設定で許される最短40msへ描画補間を変更する候補。

入力候補は、未平滑の肘方向に由来する揺れをIK前に抑えられるかを調べるために選んだ。
40ms候補は後段の遅れを減らせるかを調べるために選び、候補の追加探索は行わなかった。

## 結果と採用判断

下表は確認区間の左上腕。揺れはフレーム間回転差のRMS、振幅は回転の範囲で、単位はラジアン。
遅れは体幹相対の腕の高さと最終回転の相互相関による推定値である。

| 条件と指標                           |     現行 | 肘入力候補 | 肘入力と40ms補間 |
| ------------------------------------ | -------: | ---------: | ---------------: |
| 静止の揺れ                           | 0.002693 |   0.002515 |         0.003725 |
| 静止の振幅                           | 0.010102 |   0.009516 |         0.011560 |
| 手振りの振幅                         | 0.854708 |   0.750476 |         0.915843 |
| 手振りの遅れ（ms）                   |   83.497 |    153.541 |                0 |
| 両腕上げの遅れ（ms）                 |  339.732 |    292.897 |          200.115 |
| 両腕上げの振幅                       | 0.097806 |   0.110047 |         0.140884 |
| 交差の肘反転拒否フレーム数（全区間） |        0 |         31 |               31 |

肘入力候補は静止の揺れが小さくなる一方、手振りの振幅が縮み、遅れも増えた。
40ms候補は手振り・腕上げの推定遅れが短くなるが静止の揺れが増え、交差時の極の反転拒否も残った。
到達距離の制限は全条件で0件。欠損復帰を含む全6動作の左右上腕・前腕と前後半の指標を集計に残した。
単腕上げは推定遅れが探索上限600msに当たり、手振りの現行相関も0.304と低い。
これらは絶対遅延の確定値として扱わない。振幅だけを増やしても入力へ近づいたとは判断しない。

**平滑化候補は両方とも不採用とし、既定値を維持する。** 採用するのは観測単位でIKの極履歴を確定する修正だけである。
手首フィルターは観測雑音、極履歴は肘の向きの連続性、描画補間は表示間の移動、最終角速度制限は急変の上限をそれぞれ担当する。
描画予測で極履歴を更新しない。時刻のない旧入力も履歴へ確定しない。
固定入力の結合テストで観測間の描画回数を0回と5回に変え、観測フィルター状態と極への入力列が一致した。
旧Pose経路も同時刻の再描画で確定回数が増えないことを確認した。

## 再計算

[比較用入口](replay-browser.ts)を一時的に `sincromisor-frontend/src/motion-comparison-local.ts` へコピーする。
[既存の非公開サーバー](../../task-261008235701-recorded-motion-quality-baseline/artifacts/serve-private.py)を
`source` と `generated` の引数で起動し、Viteのページ上で同入口を読み込む。
`compare(fixture, label)` に6動作の名前と上記ラベルを渡す。入力候補だけ[差分](elbow-filter-candidate.patch)を適用し、
現行比較では基準コミットの腕処理を使う。候補差分は本番へ残さない。
[集計スクリプト](summarize-comparison.js)はPlaywright CLIの `run-code` へ渡す関数である。
生成物は既存サーバーの出力先に保存する。一時入口は検査・コミット前に削除する。

今回の最終実装には体幹と指・調停の変更も含むため、基準コミットと比較条件を区別する。
