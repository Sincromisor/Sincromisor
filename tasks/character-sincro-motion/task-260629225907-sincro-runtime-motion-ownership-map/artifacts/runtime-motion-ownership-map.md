# Runtime Motion Ownership Map

## Scope

この artifact は、現行 `simple-vrm` / `sincro` runtime の `VRMCharacterManager.update()` が、どの順序で bone / expression / root position を更新しているかを記録する。
対象は production runtime の書き込み順序であり、`motion-debug` の replay / final-pose-playback 専用経路は主対象にしない。

現時点では `VRMCharacterManager.update()` の face / expression / leg / root controller 順序と
`vrm.update(deltaSeconds)` の位置を維持する。`VrmPoseComposer` full normalized pose application は production
default であり、同一 frame の dry-run result が available な場合は upper body finalPose を production 表示へ入れる。
full application unavailable frame でも arm / torso の staged writer へ自動 rollback しない。
以下の分類は後続移行タスクが二重書き込みを避けるための判断材料である。

分類:

- `move-to-composer`: 将来 `VrmPoseComposer` の final pose 所有へ移す候補。
- `keep-controller-owned`: 現行 controller / retargeter 所有を維持する候補。
- `needs-decision`: 所有境界を追加判断してから移行する候補。

## Production Cleanup Status

`task-260705214026-remove-motion-rollback-fallback-paths` 時点では、full normalized pose application は production
default かつ唯一の upper-body final pose writer である。削除済みの flag は
`composerArmApplicationMode`、`composerTorsoShoulderApplicationMode`、`fullNormalizedPoseApplicationMode` であり、
Debug Console controls / snapshot / tests からも外した。残す flag は semantic / finger regression rollback 用の
`composerSemanticFingerApplicationMode` だけで、通常設定 UI、URL query、env、backend API、保存設定 contract へは
広げない。

full application unavailable frame では stale finalPose を current result へ昇格せず、`ArmBoneController.update()` や
`CharacterMotionOrchestrator.update()` を production fallback trigger として自動実行しない。
`full_normalized_pose_application_unavailable:<status>` / `result_missing` / `vrm_missing` は Debug Console summary /
metrics 用の unavailable reason として残す。head / neck / leg / expression / root position は引き続き full upper body
finalPose の所有対象外であり、public WebRTC / backend 契約はこの map の対象外で変更しない。

## Needs Decision

| 対象                                                       | 決めるべき所有境界                                                                                                                                         | 衝突する既存書き手                                                                                                             | 後続タスクでの判断先                                                                                                                                                               |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HeadBoneController` の `upperChest` / `neck` / `head`     | face retarget head pose を composer final pose に含めるか、head/neck は controller 所有で残すか。特に `upperChest` を head と torso のどちらが所有するか。 | `HeadBoneController` が `upperChest` を先に書き、`CharacterMotionTorsoApplier` が同 frame 後段で `upperChest` を上書きしうる。 | `production-sincro-motion-pipeline-state-contract` で live state の置き場所を決め、`torso-shoulder-composer-ownership-migration-plan` で torso / shoulder と同時に境界を確定する。 |
| `EyeBehaviorController` の `leftEye` / `rightEye` fallback | look / blink expression は expression controller 所有で残しつつ、eye bone fallback だけ final pose に移すか。                                              | 現行では eye bone の既存書き手は `EyeBehaviorController` のみだが、将来 composer が eye bone を所有すると二重書き込みになる。  | head / neck / expression の所有境界を扱う後続 task で、expression と bone fallback を分離して判断する。                                                                            |
| `LegBoneController` の leg / foot idle pose                | leg / foot は current idle controller 所有を維持するか、final pose 全面移行時に composer の owned bones に含めるか。                                       | 現行では `LegBoneController` のみ。将来 `vrm.humanoid.setNormalizedPose(finalPose)` を全面適用する場合に衝突する。             | final pose replay / full `setNormalizedPose` 移行 task で、leg を composer 非対象として明示するか leg layer を追加するか判断する。                                                 |

## Follow-up Notes

- `SincroFaceRetargeter` と `SincroPoseRetargeter` は VRM bone / expression の直接書き手ではなく、controller が読む retarget frame の所有者である。composer 移行後も raw tracker snapshot と VRM final pose の間の変換境界として残す候補。
- face retarget の downstream controller 条件は `faceMotion.trackingEnabled` を見る。`trackingEnabled=false` は controller 側の gaze / camera / telop fallback へ戻るが、`trackingEnabled=true` の lost / low confidence は `SincroFaceRetargeter` が返す neutral head / expressions / mouth を適用する。
- `FaceMorphController` と `FaceEmotionController` は expression owner として維持する候補。`VrmPoseComposer` v1 は expression を対象にしない。
- `VRMCharacterManager.update()` の root position block と `CharacterMotionOrchestrator.stabilizeHips()` は同じ `hipsBasePosition` を書くため、現状は値の衝突ではなく順序上の重複である。root position は `VrmPoseComposer` の normalized local pose 対象外として扱う。
- torso / shoulder migration 後も `HeadBoneController` の head / neck / `upperChest` fallback、`LegBoneController` の leg / foot、Face / Eye / Emotion の expression は controller-owned / needs-decision のまま残す。full `setNormalizedPose(finalPose)` 移行まで composer はこれらを所有しない。
- full normalized pose application 後も head / neck / leg / expression / root position は composer 所有へ含めない。available result がある frame だけ full finalPose を適用し、unavailable / invalid / missing profile / result 欠損では stale finalPose を使わず unavailable reason を summary / metrics に残す。arm / torso / full application の staged rollback flags と direct writer fallback trigger は削除済みであり、Debug Console 限定 rollback として残すのは semantic / finger flag だけである。
