# 既存撮影データで手の向きと指曲げの改善を比較する

## 背景・目的

手のスナップショットには`palmNormal`・`palmDirection`があるが、腕・手の回転生成には使われていない。手首回転はPose由来の`wristRaise`を主に使い、プロファイルの前腕・手へのねじれ配分も値の保持に留まる。指曲げは掌寸法と付け根から指先までの距離による近似で、関節の曲げ角そのものではない。

ただし、現在の掌方向は幅・高さで別々に正規化した画像座標と深度から生成され、メートル単位の回転基底としてそのまま利用できない。既存撮影データで品質を確かめ、観測が不足する場合は採用を見送れる比較タスクとする。

提供済み6動画に腕と手が映る区間はあるが、対応する610フレームのHand検出成功は0件で、生のHand・Gesture結果はない。既存動画の再推論を前提にし、手が小さい・ぶれる区間で無理に採用しない。

## 完了条件

- [x] 既存録画・記録のうち、手の向き・開閉を確認できる区間と入力情報を特定する。Poseだけの記録は対象にしない。動画があれば既存モデルで再推論できるが、追加撮影は要求しない。
- [x] 画像座標の縦横比、ROI復元、深度の尺度、左右の符号を揃えた掌基底を候補として評価する。Handのワールド座標を使う場合もPoseとは原点が異なるため、手首位置を直接置き換えない。
- [x] 候補は腕IKで決めた到達位置を維持し、前腕軸まわりのねじれと手の向きを既存プロファイルの配分で制限付き反映する。退化した掌、低信頼度、左右割当不明、手欠損では既存の姿勢へ戻す。
- [x] 指曲げについては、元の関節点が残る区間で関節方向の角度による低次元の曲げ推定と現行の距離比を比較する。指の各関節を直接ボーンへ対応させる全面変更は行わない。
- [x] 観測できた向き・開閉への追従、静止時の揺れ、左右の取り違え、欠損復帰を修正前後で比較し、手の向きと指曲げを個別に採用・不採用と判断する。改善を示せた候補だけを本番へ接続する。
- [x] 対応する既存データが無い場合は、欠ける入力と適用限界を記録し、候補を本番へ入れず検討を完了する。成功例を作るための撮影や、確認できない方向の品質保証は行わない。

## 確認方法

左右と画像比率を変えて同じ幾何を与える固定入力、掌が退化する入力、既知の前腕ねじれを確認する。採用判断は既存の手が映った録画で行い、合成入力だけでは本番品質を立証しない。新しいモデル・学習データ・外部APIは追加しない。採用する場合は処理時間も同じ環境で測り、既存の追跡頻度を維持できることを確認する。

## 実装・確認結果

保存済みのHand再推論118観測を使い、画像比率・ROI・左右を揃えた掌基底と前腕軸まわりのねじれ、関節方向による低次元の指曲げを比較した。
[比較結果](artifacts/comparison-results.md)と再計算スクリプトに、採否を分けた根拠、固定入力の確認、対象原本と未確認の向き・開閉を記録した。
掌方向は制限への張り付きと揺れがあり、指曲げは手振りの振幅縮小と復帰時の悪化があるため、両方とも本番採用を見送った。
追加撮影や実カメラ・外部APIを使わず、現在の特徴抽出と手首の生成を維持する。

共通の姿勢合成・IKの変更を含むため、依存する5タスクの実装・比較結果・状態を同じコミットにまとめる。
フロント全体のテストは677件成功・3件スキップ、型検査と本番ビルド、構造検査は成功した。
