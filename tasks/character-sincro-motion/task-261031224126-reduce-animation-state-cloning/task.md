# キャラクター描画時の不要な状態複製を削減

## 背景 / 目的

ユーザーからキャラクターアニメーションの性能調査と、見つかった改善の起票・実行を依頼された。描画ループ、姿勢変換、姿勢合成、頭部・目の制御と診断通知を調査し、毎フレームの更新経路に次の重複複製を確認した。

- `VRMCharacterManager.update()` は顔・姿勢・合成結果を含む状態を複製して保持するが、その状態から読むのは直後の診断要約に渡す `composerDryRun` だけである。診断未接続でも実行される。
- `SincroVrmPoseComposerService.compose()` は内部所有する最終姿勢を前回姿勢用に複製する。元の合成結果は内部保持され、返却境界でも複製されるため、この内部複製は不要である。

## 完了条件（受け入れ条件）

- [x] 管理処理の診断用状態の複製を除去し、診断接続の有無によらず現在フレームの姿勢を従来どおり適用する。
- [x] 合成サービスの内部の前回姿勢複製を除去する。返却値を書き換えても同時刻の再取得と次フレームの速度制限へ影響しない。
- [x] 診断要約・詳細・適用不可理由、頭部・表情・脚・腰の更新を維持し、対象テスト・型検査・整形検査が通る。

## 設計判断と変更範囲

管理処理は既存の `summarizeComposerDryRun()` に現在の適用注釈付き合成結果を直接渡す。要約関数は必要な配列と適用情報を独立して生成するため、状態全体の複製は不要である。合成サービスは内部所有する `result.finalPose` を参照保持する。姿勢合成関数は前回姿勢を読み取るだけで、毎回新たな最終姿勢を返す。外部へ返す複製は維持する。

対象は上記2ファイルと対応するテスト。描画頻度、平滑化、追跡観測の時刻、姿勢の値、モデル読込、通信・保存契約は変更しない。GPU描画や実機FPSの最適化は本タスクの範囲外とし、速度向上率は保証しない。

## 確認方法

- 管理処理の既存テスト用代替を利用し、診断あり・なしの2フレームで不要な `structuredClone` が呼ばれないことと、姿勢・診断内容を確認する。
- 合成サービスで返却境界の複製回数、返却値変更後の再取得、次フレームの角速度制限を確認する。
- `npm run test -- src/character/vrmCharacter src/character/runtime src/character/vrmPose`。
- `node_modules/.bin/tsc -p sincromisor-frontend/tsconfig.modern.json --noEmit`、変更ファイルのBiome / Prettier検査。
- タスク状態・索引を更新し、タスク管理検査を実行する。

## ドキュメント同期

内部の不要な状態保持と複製のみを除去するため、公開API・設計契約の変更はない。処理の所有と返却境界の説明はソースコメントに残す。

## 実施結果

- 管理処理の未使用状態を削除し、適用注釈付き合成結果から直接診断要約を生成するよう変更した。顔・姿勢の複製と合成結果全体の追加複製がなくなった。
- 合成サービスでは内部所有の最終姿勢を参照保持するよう変更し、外部返却時の独立した複製は維持した。
- 変更前に追加テストを実行し、合成サービスの複製が期待1回に対して2回、管理処理の2フレームで期待0回に対して2回で失敗することを確認した。変更後は同じテストが通った。管理処理の計測では下流処理を代替し、管理処理自身の追加複製だけを数えている。
- 関連15ファイル・64テストが成功。診断未接続、利用不可時の理由、最終姿勢の適用、各部位の更新、返却結果の変更からの状態保護、同時刻の再取得と次フレームの角速度制限を確認した。
- TypeScriptの型検査と変更4ファイルのBiome検査が成功。Biomeはフロントエンドディレクトリから実行した。
- 実機ブラウザーでの画面確認・FPS・GC時間の計測は未実施。今回確認できた効果は重複複製と割り当ての削減であり、アニメーション全体の速度向上率は未計測。
