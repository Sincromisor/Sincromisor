# 設定UIとデバッグUIの設計と項目一覧を分割する

## 背景 / 目的

ユーザーの依頼に基づき、設定と診断UIの既存設計を `documents/design/frontend/setting-and-debug-ui/` に再編する。現在の実装から、設計と網羅的な項目一覧を別々に読めるようにする。

## 完了条件

- [x] 設定UIの設計、デバッグUIの設計、設定項目一覧、デバッグ項目一覧を別ファイルにまとめる。
- [x] 設定の選択肢・範囲・刻み・既定値・反映時期と、起動前後・ページ別の表示条件を記載する。
- [x] デバッグ7タブの表示項目・操作・調整値をすべて照合し、型だけが存在する値と画面の入力を区別する。
- [x] 設計索引と既存文書の参照を更新し、変更Markdownの整形・相対リンク・タスク整合性を確認する。

## 変更範囲と判断

設計の本文4ファイルと案内用READMEを新設し、旧設計ファイルを廃止する。現在の設計文書の参照と、既存タスクのクリック可能なリンクを更新する。過去の作業記録内にある旧パスの文字列は履歴として残す。UI実装、通信契約、設定値は変更しない。

実装を照合し、現行では開始時のTalk・Inspector・VR入力が非表示であること、Looking Glassの分類差、トークモードのRTC反映には再接続が必要であること、一般設定に残る診断向け入力と状態表示も記録した。

## 確認結果

- 設定フィールド、起動前と開始後の分類組み立て、Looking Glass、初期調整、接続状態カードをソースと照合。
- 診断コンソールの7タブ、全調整部品、プリセット・既定値、表示整形をソースと照合。
- 設定キー27件と診断パネルの静的表示ラベル91件が項目一覧に存在することを簡易スクリプトで確認し、選択肢・数値範囲・既定値を実装と照合した。
- 変更Markdownの `prettier --check`、`git diff --check`、`npm run tasks:index:check`、`npm run tasks:check` はすべて成功した。
- 変更文書の相対リンク245件と新設文書の参照先見出しを確認した。新規リンク切れはない。既存タスクにある削除済み実装へのリンク5件は変更前からの状態と一致しており、今回の更新対象外とした。
- 文書のみの変更のためブラウザー実行やアプリのビルド・テストは対象外。
