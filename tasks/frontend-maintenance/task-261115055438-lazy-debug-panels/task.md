# 診断表示を初回表示時に読み込む

## 背景 / 目的

優先度: 中。診断パネルを使わない開発作業で表示専用コードを初期読み込みから外す。[画面の初期読み込みを計測して遅延対象を確定する](../task-261115055438-panel-loading-baseline/task.md) が効果と安全な境界を確認するまで `blocked` とし、採用決定後に着手する。現時点で速度改善は未確認である。

## 変更範囲と設計判断

- [debugConsole.tsx](../../../sincromisor-frontend/src/features/debug/react/debugConsole.tsx)のスナップショット購読と詳細パネル群を分け、診断を初めて開いたときにだけ読み込む。常設の枠・音声・追跡用DOMを含む `DebugConsole` 全体を遅延読み込みしない。
- `rtcAudio`、追跡用映像・マーカー、詳細表示のportal先、タブ選択を従来の常設側に残す。初回非表示でもこれらのDOMを配置し、開閉によって作り直さない。
- 現在同じファイルにある常設の `GazePanel` と遅延対象の `GazeDetails` も必要な範囲で分離し、常設側の静的インポートから詳細表示の依存が残らないようにする。
- 一度読み込んだ表示部分は保持し、現在のActivityによる非表示時の購読休止と再表示時の最新値反映を維持する。Activityの非表示指定だけでは読み込み開始の抑止にならないため、初回表示まで遅延境界自体を作らない。
- 読み込み中と失敗の案内は診断パネル内に表示する。遅延対象だけを囲うエラー境界で読み込み・描画失敗を受け、共通ロガーで記録し、閉じる操作を維持する。未捕捉の描画例外をルートの共通失敗処理へ渡してRTC・追跡を終了させない。常設DOMは失敗時にも置き換えない。復旧は明示的なページ再読み込みで行い、自動再試行は導入しない。
- 設定パネルは [常設設定パネルを起動処理から分離して読み込む](../task-261115055438-lazy-settings-panel/task.md) の担当。診断データ収集、音声・追跡の開始終了、全タブ個別の細分化は変更しない。

## 完了条件

- [x] 初期非表示では分離した診断表示モジュールを読み込まず、最初に開いたときに表示できる。
- [x] 初回非表示・開閉後とも常設DOMの同一性を保ち、タブや入力状態を保持する。非表示中は表示用購読を休止し、再表示で最新値を反映する。
- [x] 読み込み・描画失敗をパネル内に案内し、閉じる操作と診断外の画面・音声・追跡を維持する。

## 確認方法

型検査、変更ファイルのBiome、`src/features/debug/react/__tests__/debugConsole.test.tsx` を実行し、初回非表示と失敗の対象試験を補う。開発ブラウザーで初回非表示→開く→閉じる→再表示を一往復し、取得タイミング・購読解除と復元・DOMと `srcObject` の同一性を観測する。合成映像・音声でよく実機器や外部接続は求めない。本番ビルドでも分離対象が初期取得へ戻っていないか確認する。ブラウザー操作は[Playwright CLI利用ルール](../../../documents/rules/playwright-cli.md)に従う。

## 作業経路と文書同期

表示用購読と常設DOMの生存期間をまたぐため高リスクとして独立仕様レビュー・実装評価を行う。[診断UI設計](../../../documents/design/frontend/setting-and-debug-ui/debug-design.md)と[共通枠組み](../../../documents/design/frontend/app-shell.md)の読み込み時期・非表示時の扱い・失敗案内を同期する。

## 先行観測による採用判断

[先行計測](../task-261115055438-panel-loading-baseline/task.md#観測結果と採否)で採用を決定した。分離単位は `DebugConsolePanels` と詳細パネル群、`GazeDetails`。`DebugConsoleManager`は起動側でも使うため常設のままにし、削減量へ含めない。開発時に詳細モジュールの初期要求がないこと、本番で初期チャンクからの静的到達がないことを確認する。既存の所有権・失敗処理・確認条件は維持する。

## 実施結果

診断詳細と視線詳細を初回表示時の読み込みへ分離し、失敗を診断内で扱うようにした。タブ・音声・追跡DOMとportal先は常設のまま、表示後はActivityで状態を保持する。

- 型検査、変更Biome、診断の対象4試験、全体ゲートが成功した。独立評価でも設定側を含む対象4ファイル29試験と設計整形を確認した。
- Playwright CLIと合成音声・映像で初期未取得、初回取得1回、開閉時の購読数0→1→0→1、非表示中の最新値反映、タブ・詳細開閉・入力・DOM・`srcObject`の保持を確認した。
- 読み込み拒否と描画例外を注入し、診断内の案内、閉じる操作、常設DOM、診断外の画面と機器状態を維持することを確認した。
- 本番ビルドの3ページの静的依存を独立に追跡し、詳細チャンクが初期到達集合に含まれないことを確認した。simple-vrmの本番ブラウザーでも初期14チャンクに含まれず、診断初回表示時に詳細1チャンクだけ追加取得した。
- 共通枠組み・診断UI設計を同期した。独立評価: PASS。コメント点検: PASS。実機器と外部接続は今回の確認範囲に含めない。
