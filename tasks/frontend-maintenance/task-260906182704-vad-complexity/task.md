# 音声通過処理と発話判定を分離する

## 背景 / 目的

ユーザーが求めた Biome の `noExcessiveCognitiveComplexity` 調査に基づく。VadProcessor.process が出力チャンネルの通過処理と入力先頭チャンネルの発話判定を一緒に持ち、音声経路と通知経路の確認範囲が混在している。制御メッセージには同じ欠損検査の重複もある。

## 完了条件

- [x] 通過処理を同じファイルのメソッドへ分離し、重複ガードを削除する。無入力、チャンネル補完、RMS・最大振幅、発話保持、通知周期、PCM分割、閾値の検証と制限を維持する。
- [x] 対象テスト、型検査、変更ファイルの Biome と Markdown 整形、タスク検査が成功する。

## 実装方針と範囲

対象はフロントエンドの public/worklets/vad-processor.js と音声処理の回帰テスト。`run-task` の通常変更として親が現在の作業ツリーで実装する。依存タスクはない。閾値変更や警告抑制は行わない。

## 確認方法

AudioWorklet の登録先を捕捉するテストで実ファイルを実行する。フロントエンドで `npx tsc -p tsconfig.modern.json --noEmit` と対象の `npx biome check` を実行する。

## 文書同期

内部処理の整理であり、公開契約と設計上の責務は維持するため設計文書の変更は不要。

## 確認結果

`run-task` の通常変更として実施。対象の Biome と音声処理の4テストが成功した。配信する実ファイルを読み、AudioWorklet の登録と通信境界を模擬して、無入力・チャンネル複製・先頭チャンネルでの判定・4フレーム通知・12フレーム保持・閾値制限・1536標本のPCM分割・送信停止時の端数破棄を確認した。通信時のバッファー移譲は `structuredClone` で実行した。

全4タスクの変更後に `npm run build` が成功した。再調査で対象7件の指摘が解消し、残る13件は最初の[調査結果](../task-260906182704-metric-complexity/task.md#調査結果)どおりだった。閾値と抑制設定は変更していない。変更ファイルの整形、タスク検査、文書点検とコメント点検は合格。

実ブラウザーでのマイク確認は未実施。今回は音声経路の接続・プロセッサの生存期間・通知契約を変更しておらず、同じ音声通過処理を抽出したため、模擬環境で実処理の出力一致を確認した。実際の音声機器やブラウザー固有の挙動はこの確認の対象外。
