# 音声通過処理と発話判定を分離する

## 背景 / 目的

ユーザーが求めた Biome の `noExcessiveCognitiveComplexity` 調査に基づく。VadProcessor.process が出力チャンネルの通過処理と入力先頭チャンネルの発話判定を一緒に持ち、音声経路と通知経路の確認範囲が混在している。制御メッセージには同じ欠損検査の重複もある。

## 完了条件

- [ ] 通過処理を同じファイルのメソッドへ分離し、重複ガードを削除する。無入力、チャンネル補完、RMS・最大振幅、発話保持、通知周期、PCM分割、閾値の検証と制限を維持する。
- [ ] 対象テスト、型検査、変更ファイルの Biome と Markdown 整形、タスク検査が成功する。

## 実装方針と範囲

対象はフロントエンドの public/worklets/vad-processor.js と音声処理の回帰テスト。`run-task` の通常変更として親が現在の作業ツリーで実装する。依存タスクはない。閾値変更や警告抑制は行わない。

## 確認方法

AudioWorklet の登録先を捕捉するテストで実ファイルを実行する。フロントエンドで `npx tsc -p tsconfig.modern.json --noEmit` と対象の `npx biome check` を実行する。

## 文書同期

内部処理の整理であり、公開契約と設計上の責務は維持するため設計文書の変更は不要。
