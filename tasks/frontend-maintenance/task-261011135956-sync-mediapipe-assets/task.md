# MediaPipe素材の配置を同期して壊れたリンクの残留を防ぐ

## 背景 / 目的

`public/mediapipe-wasm/wasm`に残った相対リンクが存在しない `public/node_modules`を指し、Viteの公開素材コピーを停止させていた。現在の4か所の配置処理は上書きコピーのため、古いリンク・素材を取り除かない。また通常の開発起動・ビルドには素材準備が接続されていなかった。リンクを最初に作った操作は特定できていない。

## 完了条件

- [x] インストール済みのMediaPipeパッケージから配信素材を同期し、古いファイルや壊れたリンクを残さない。
- [x] 通常の開発起動・ビルド、セットアップ、2つのDockerビルドが同じ配置処理を使う。
- [x] コピー元不在で既存配信素材を削除せず、生成先がリンクでもその参照先や他の公開素材を変更しない。
- [x] 既存の壊れたリンクを含む環境で通常ビルドが成功する。

## 範囲と確認方法

フロントエンドの素材準備スクリプト、npmコマンド、セットアップとDockerの配置手順を変更する。配信URL、推論処理、パッケージのバージョン、他の公開素材は変更しない。

隔離した一時ディレクトリで壊れた子リンク、古いファイル、再実行、生成先自体のリンク、コピー元不在を確認する。通常ビルド、変更ファイルの静的検査、シェル構文、Markdownとタスク検査を実施する。Dockerイメージの公開は行わない。

## 実装・確認結果

- 配置を `scripts/prepare-mediapipe-assets.js`へ集約した。コピー完了後に生成先を交換し、古いファイル・子リンク・生成先自身のリンクを残さない。現在のローカル環境もこの処理で修復した。
- `dev`・`build`から素材準備を直接呼ぶ。環境の `ignore-scripts=true`でnpmの前後フックが実行されなかったため、前後フックに依存しない。セットアップとDocker内の重複コピーを除き、共通処理へ接続した。
- `node --test sincromisor-frontend/scripts/prepare-mediapipe-assets.test.js`で壊れたリンク・古い素材の除去、再実行、生成先リンクの参照先保護、他素材の保持、コピー元不在時の既存素材保持が成功した。
- `npm --prefix sincromisor-frontend run build`は型確認・公開素材コピー・全ページの変換を含め成功した。`public`と `dist`のMediaPipe素材について、インストール済みパッケージとのファイル一覧・SHA-256一致、リンク不在を確認した。
- `npm --prefix sincromisor-frontend run dev -- --help`で開発コマンドからの素材準備を確認した。変更JavaScript・JSONのBiome、シェル構文、既存の開発環境セットアップテスト、Markdown・差分・タスク検査を実施した。コメント点検を完了した。
- Dockerfileは共通スクリプトのコピー順とビルド接続を確認したが、Dockerイメージ全体のビルドとWSLでの一括導入、実カメラ推論は実施していない。壊れたリンクを最初に生成したローカル操作は特定できていないが、残留を許していた配置処理を修正した。
