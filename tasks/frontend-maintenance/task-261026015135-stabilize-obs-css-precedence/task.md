# OBS追加CSSとの優先順位を固定して回帰を防ぐ

## 背景 / 目的

ユーザーから、前タスクで文書に残した不確実性や不具合の原因を今解消するよう依頼された。
独自CSS変換を撤去した際、レイヤー外の追加CSSがアプリのレイヤー内宣言を上書きするようになり、従来と異なる色になることが確認済みである。
この表示変更を注意書きで許容せず、変更前の優先順位を維持する処理と自動回帰試験で防ぐ。

## 完了条件

- [x] レイヤーの優先順位を維持する最小の変換だけを導入し、開発・本番で共用する。
- [x] 追加CSSの前後挿入、低詳細度の宣言、明示的な`!important`、OBS既定CSSを回帰試験で確認する。
- [x] トップと起動前設定の配置・操作を確認し、型確認・ビルド・対象テストを通す。
- [x] 前回の注意書きを確定した挙動と自動検証方法へ置き換え、タスク・索引・コミットを同期する。

## 変更範囲と判断

設定・依存・ブラウザー試験・現在設計を変更する。色・変数・論理方向など、今回の回帰に関係しない互換変換は復活させない。
優先順位を変えるレイヤー変換と、その前処理として必要なネスト展開だけを検討する。
JavaScriptのOBS検知・機器取得・通信処理は変更しない。

追加CSSを全面無効化する処理やDOM監視は導入しない。通常宣言の優先順位を従来に戻し、明示的な`!important`による利用者の指定は維持する。
任意のCSSを挿入しても表示が壊れないという保証は行わない。前回の変換撤去が原因の、再現できる表示回帰を除去する。

## 検証方法

1. OBSのロード完了後に`head`へ`style`を追加する処理に合わせ、実ページへCSSを挿入する永続ブラウザーテストを作る。
2. 現在の本番出力で失敗を確認し、最小変換の導入後に同じ試験を開発・本番で通す。
3. 既存のトップ試験と起動前設定の概要・詳細操作を確認する。低詳細度・`!important`・スタイル挿入順の違いを試験する。
4. 依存差分・型確認・ビルド・Biome・Markdown・相対リンク・タスク管理を確認する。

## 実施結果

`postcss-nesting`と`@csstools/postcss-cascade-layers`の2種類だけを戻した。
ネストを先に展開してレイヤー順を詳細度へ変換し、ネイティブレイヤーを撤去前と同じCSS優先順位の仕組みで配信する。
レイヤー外のCSSという理由だけで、低詳細度の通常指定がアプリの指定を上書きする回帰を解消した。
色・変数・論理方向の旧互換変換は復活させていない。`postcss-preset-env`やAutoprefixerも不要なままである。

ロック内の外部パッケージは176件から183件になった。追加7件はレイヤーとネストの処理に使う既存ライブラリであり、残存依存のバージョン変更はない。
前回削除した37件のうち30件の削減を維持する。製品CSS・OBS自動開始・通信・音声処理は変更していない。

## 確認範囲

ChromeでOBSの実装と同じ`head`へのCSS追加を再現して確認した。OBS本体の起動・配信や機器取得は実施していない。
レイヤー・ネストは配信前に変換するため、この修正はCEFのネイティブレイヤー実装へ依存しない。
試験はRTCサーバーなしで設定取得エラーの通知を表示した状態で行い、通知と設定操作を維持した。
利用者が明示した`!important`などによる上書きは正常な機能として残し、自動試験でその結果も固定した。
