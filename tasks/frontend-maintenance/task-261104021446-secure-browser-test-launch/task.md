# ブラウザーテストをシステムChromeとサンドボックスへ統一する

## 背景 / 目的

ブラウザーの更新と起動時の保護をテスト設定へ反映する依頼に対応する。
Playwrightのパッケージ更新とブラウザーの更新を分け、テストがOS側で更新するChromeを使うようにする。

## 完了条件

- [x] 通常・CSS・RTCのテストでサンドボックスを有効化し、失敗時に無効化へ切り替えない。
- [x] テスト開始前に実行するブラウザーの版を検査し、下限未満または判定不能な版は拒否する。
- [x] ブラウザー導入コマンドをシステムChrome向けに変更し、更新手順とRTCの実行ファイル指定を文書へ反映する。
- [x] 古い版の拒否、検査プロセスの終了、実ブラウザーの保護状態、CSS回帰試験を確認する。

## 変更範囲と設計判断

`playwright.browser.ts`を通常・CSS・RTCの共通起動設定と事前検査に使う。
既存のRTC実行ファイル指定は維持し、そのブラウザーにも版とサンドボックスの検査を適用する。
通常テスト用設定を追加し、独自のサーバー起動を必要とするCSSとRTCは専用設定から実行する。
通信契約と製品の動作は変更しない。

ブラウザーの下限はChromeの2026-10-29の修正を含む`156.0.8078.79`とする。
下限を通ることは最新版や未知の脆弱性への安全性を保証しないため、OS側の更新も継続する。
Playwrightの依存バージョンは変更せず、ブラウザー選択と起動設定を変更する。

## 確認方法

- `node scripts/browser/browser-policy.test.mjs`: 下限前後の版、判定不能な版、保護設定、終了処理を検査する。
- `npm run browser:test:security`: 実際の起動引数とLinuxのサンドボックス状態を検査する。
- RTC設定の実行ファイル指定と疑似マイクの起動引数でも、同じ保護状態の試験を実行する。
- `npm run browser:test:css`: 既存の開発・本番ページの回帰試験を行う。
- TypeScript、変更ファイルの整形、相対リンク、タスク管理を確認する。
