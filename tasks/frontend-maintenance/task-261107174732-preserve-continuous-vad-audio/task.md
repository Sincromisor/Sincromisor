# 学習VADへ連続音声を欠落なく渡す

## 背景 / 目的

32msごとの音声を80ms間隔で間引き、短い発話が判定入力から消える。ブロックごとの切捨て・ゼロ詰めは48kHz以外でも音声を欠落させる。連続音声を順番に推論し、負荷抑制は通知頻度と明示的なRMS代替へ分ける。

## 完了条件

- [x] サンプル位置をブロック間で維持し、16/44.1/48kHz入力を連続した16kHz・512サンプルへ変換する。
- [x] Workerは全フレームを直列処理し、発話状態の変化を即通知する。定期通知だけ間引く。
- [x] 停止・入力レート変更時は端数とキューと推論状態を初期化する。進行中の旧結果は採用しない。
- [x] 過負荷で未処理音声が1秒を超える場合はキューを破棄してRMSへ切り替え、再有効化で再試行する。エラー時は古い学習判定を残さない。
- [x] 設定・UI・設計を通知間隔へ同期し、連続性、非同期停止、過負荷、代替判定の回帰試験と型確認が通る。

## 設計と範囲

Worker内で連続音声の所有者を維持する。PCMの再サンプリング・端数蓄積を分離し、ブラウザー間通信やサーバー通信は変更しない。`minInferIntervalMs` は `minReportIntervalMs` へ改名し、旧保存値は通知間隔の既定値へ戻す。1秒は処理能力の目標でなく、リアルタイム判定で古い音声を送り続けないための保持上限である。

対象は `features/media/vad`、音声設定・診断UI、音声VAD設計。既存Workletは取得サンプルをすべて渡すため再利用する。

## 実施結果

連続リサンプラーと直列推論キューを導入し、停止・入力切替・過負荷で系列全体を初期化した。発話開始・終了は即時通知し、学習判定の無効化時はWorkletのRMSへ戻る。通知間隔へ設定名とUIを同期した。

`npm run test -- sileroVad learnedVadFallback sincroAudioTuningPersistence vadProcessor` は18件成功。16/44.1/48kHzの分割入力と一括入力の一致、状態変化通知、非同期停止、過負荷、RMS代替を確認した。TypeScript確認と対象Biome確認も成功。実マイクの長時間試験は未実施。コメント点検: PASS。
