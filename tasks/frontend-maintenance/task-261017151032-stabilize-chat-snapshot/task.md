# チャット履歴を安定したスナップショットとして公開

## 背景 / 目的

チャット履歴の取得は毎回配列を複製し、同一ID更新は内部配列を変更する。そのままではReactの外部ストアへ接続できないため、まずサービス単独で更新時だけ参照が変わるスナップショットを用意する。

優先度: 中。2026-10-17のフロントエンド改善調査に基づく。

## 依存関係

なし。

## 担当範囲と設計判断

- [`src/features/conversation/chat/model/chatMessageService.ts`](../../../sincromisor-frontend/src/features/conversation/chat/model/chatMessageService.ts) とサービスの対象テストを担当する。履歴とシステムアイコンをまとめた読み取り用スナップショット、取得・購読の最小APIを用意する。
- 既存のイベント購読と初期履歴取得は、この段階で動くよう保つ。ReactとAppControllerの窓口への接続は後続タスクで行い、状態管理ライブラリは追加しない。

## 完了条件

- [x] 状態が変わらない間の取得結果は同じ参照で、履歴更新・アイコン変更後は新しい参照になる。過去のスナップショットを後の更新で変更しない。
- [x] 同一IDは元の位置で更新、新規IDは先頭追加、最新30件保持、同一エラー抑止、描画方式とアイコン変更の既存規則を維持する。
- [x] 新しい購読を解除した後は通知しない。既存のイベント利用者と画面の挙動を維持する。

## 確認方法

コマンドはリポジトリルートから実行する。型検査は `node_modules/.bin/tsc -p sincromisor-frontend/tsconfig.modern.json`、対象テストは `npm run test -- <対象パス>` を使う。ブラウザー確認では既存の[Playwright CLI利用ルール](../../../documents/rules/playwright-cli.md)に従う。

- 型検査、既存の `sincroChatView.test.tsx` とサービス用の小さなテスト。参照の安定、古い履歴の不変性、同一ID更新、件数制限、アイコン変更、解除を検査する。

## 文書同期

[app-shell.md](../../../documents/design/frontend/app-shell.md) のチャット責務にスナップショットの所有者と更新単位を追記する。通信・HTML信頼境界は変更しない。

## 実施結果

- 履歴とアイコンの読み取り専用スナップショットをサービスへ追加した。更新時だけ置換し、入力メッセージも複製して過去の履歴を保護する。既存のイベント通知と初期取得APIは維持した。
- 型検査、対象Biome、既存表示テストとサービスの参照安定・同一ID更新・30件上限・アイコン・エラー抑止・購読解除の2テストが成功した。共通枠組みの設計を同期した。
