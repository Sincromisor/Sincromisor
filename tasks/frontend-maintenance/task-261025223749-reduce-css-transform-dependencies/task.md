# CSS変換の互換性を確認して依存を削減する

## 背景 / 目的

依存棚卸しの7について、影響評価を伴う起票・実行・検証をユーザーから依頼された。
`postcss-preset-env` の一括導入を見直し、現在のCSSと対象ブラウザーへの互換変換を維持したまま依存を減らす。

## 完了条件

- [x] Lightning CSSへの移行と必要なPostCSS変換の個別採用を比較し、既存表示への影響と採用理由を記録する。
- [x] `defaults or chrome >= 103` の指定、ネスト・セレクター詳細度・カスケードレイヤー・代替宣言を維持する。
- [x] 現在の全24 CSSについて変更前後の変換結果を比較し、製品表示を変える差分を解消する。
- [x] 不要依存を削減し、残るパッケージを意図せず更新しない。
- [x] ビルド・型検査とCSS互換性の回帰試験が通り、生成CSSを比較できる。
- [x] ブラウザーでトップの選択操作・キーボード操作、3Dページの起動前設定、狭い画面での配置を確認する。
- [x] 設計文書、タスク記録・状態・索引を同期してコミットする。

## 影響評価と設計判断

現行指定にはKaiOSなどLightning CSSの対象変換が直接扱わないブラウザーが含まれる。
Lightning CSS単独では既存の `@layer` 平坦化を維持できないため、一括切り替えは採用しない。
現行プリセットが実際に使う変換を個別に指定し、Viteの既存PostCSS経路と本番CSS圧縮を維持する。

各プラグインを単独で調べるだけでは、ネスト変換が生成する `:is()` の展開を見落とす。
変換の順序も維持し、全体の出力比較と詳細度を守る回帰試験で確認する。
新しいCSS構文は自動的な対応を前提とせず、対象ブラウザーと必要な変換を確認して追加する。

## 変更範囲

- `sincromisor-frontend/package.json`、`postcss.config.js`、ルート `package-lock.json`。
- CSS変換の回帰試験、`documents/design/frontend/pages.md`、本タスク。
- 既存のCSS、画面機能、通信契約、配備環境は変更しない。既存サービスの起動停止や実カメラの取得は行わない。

## 検証方法

1. 変更前の全CSSの変換結果と本番ビルドを一時領域へ保存する。
2. 個別プラグインへ切り替え、全CSSの変換結果と本番出力CSSを比較する。
3. リポジトリ指定のNode.js / npmでロック更新、依存導入、ビルド・型検査、対象テスト、変更ファイルのBiome確認を行う。
4. Playwrightでトップ・共通の起動前設定をデスクトップ幅と既存確認の狭幅で操作する。ブラウザーは専用プロファイルを使う。
5. 変更Markdown・相対リンク・タスク管理を確認する。起動した検証サーバーとブラウザーは終了する。

## 実施結果

`postcss-preset-env` を削除し、既存の15種類の変換プラグインと、その実行・試験に使う `postcss` を直接宣言した。
直接管理する開発依存は9件から24件へ増えるが、ロック内の外部パッケージは278件から213件へ減った（65件削減）。
残るパッケージのバージョンに変更はなく、新しい外部パッケージも導入していない。

全24 CSSの変換結果と本番出力CSS全4ファイルは、変更前とバイト単位で一致した。
[比較結果](artifacts/css-comparison.json)に、変更前のコミット、ファイル別のSHA-256、生成CSS、削減されたパッケージを記録した。
CSS配信量の削減や表示速度の改善は主張しない。今回は開発・ビルド環境の依存削減である。

単独の変換評価で14プラグインまで絞った案では、4ファイルの選択子に差分が出た。
ネスト変換が作る `:is()` を展開するプラグインを加え、詳細度と全出力の一致を確認した。
Lightning CSS単独ではカスケードレイヤーが残るため不採用とした。
将来の新構文の自動変換はプリセットに任せず、[ページ構成](../../../documents/design/frontend/pages.md)に記載した確認手順で必要な変換を選ぶ。

## 確認結果

- Node.js 26.12.1 / npm 11.21.1で `check:runtime` を確認し、`npm install --offline --ignore-scripts --no-audit --no-fund` で依存を同期した。
- `npm run build`: 型確認と全6ページのビルドに成功。変更前も同じNode.js / npmでビルドした。
- `npm test -- src/styles/__tests__/cssCompatibility.test.js`: 3件成功。ネスト後の詳細度、レイヤー順、色・変数・論理方向などの代替宣言を確認した。
- 新しい試験の初回は、gridの代替宣言を確認する入力に `display: grid` が欠けていたため1件失敗した。試験入力を修正して3件すべて成功した。製品CSSの修正はない。
- 対象3ファイルのBiomeと依存ツリーを確認した。変更Markdown・相対リンク・タスク管理の確認も成功した。
- `npm run browser:test -- sincromisor-frontend/tests/main/main.spec.ts --workers=1 --reporter=line`: 2件成功。トップの1440 / 390 / 320px幅、キーボード選択、FAQ、動きを減らす設定、選択した体験への遷移を確認した。
- Playwright CLI / Chrome 156.0.8078.47で `simple-vrm`、`vrm360`、`looking-glass-vrm` の概要・詳細切替と戻る操作を1440 / 320px幅で確認した。各画面のダイアログは1440px幅でx=160・幅1120、320px幅でx=12・幅296となり、画面幅を超えなかった。JavaScriptの未処理例外はなかった。
- 狭幅の概要・詳細とデスクトップの詳細の画像を確認した。カメラ・マイクは取得していない。検証用ブラウザーと開発サーバーは終了した。

## 確認の限界

開発サーバーにはRTCのAPIがないため、3Dページで設定取得・診断送信の404と既存の通知が出る。
通知を表示した状態でも起動前設定の操作・配置を確認できた。実会話、Looking Glass実機、旧ブラウザー・実iPadの動作確認は行っていない。
これらの表示互換性については、対象指定の維持とCSS出力の完全一致を根拠とする。
