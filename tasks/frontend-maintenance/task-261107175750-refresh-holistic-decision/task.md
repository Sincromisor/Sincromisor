# 現行Holistic APIで追跡構成の採用根拠を更新する

## 背景 / 目的

2026年前半の調査に残る「更新版が近日公開」を現行の不採用根拠にしない。導入済みMediaPipeと現行の利用要件を比較し、実装の維持・変更を判断する。

## 完了条件

- [x] 導入済み1.1.1の公開型、公式Web文書、更新履歴を確認する。
- [x] 顔変換行列、部位別実行、ROI・左右割当、移行影響を比較する。
- [x] 採否と理由・見直し条件をADRへ残し、現行設計と設計索引から参照する。
- [x] 過去の調査に確認日付きの訂正を置き、現行判断への導線を付ける。

## 範囲と確認

調査の更新と採用判断が対象。公開APIが現在の入力・実行契約を満たす場合は必要な実装変更を特定する。性能の優劣は同条件の実測なしに断定しない。文書整形、相対リンク、旧根拠の残存とタスク整合性を確認する。

## 実施結果

公式Web API・結果型・1.1.0更新履歴と、導入済み1.1.1の型定義を照合した。顔変換行列と部位別実行の契約差を根拠に個別構成を維持する。Holistic未提供という根拠を撤回し、ADR・設計索引・現行設計・旧調査2件を同期した。対象Markdown整形、相対リンクとタスク整合性を確認。推論性能・精度の比較測定は未実施であり、優劣を結論にしていない。
