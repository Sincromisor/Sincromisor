# OBSのCEFを基準に独自CSS互換変換を撤去する

## 背景 / 目的

ユーザーが最低対象を最新版OBS Studioのブラウザーソースと指定し、独自CSS互換変換を撤去する推奨案の実装・評価を依頼した。
OBS Studio 33.0.0のCEF 150を基準に、ブラウザー自身が扱える構文の変換と不要な直接依存を削除する。

## 完了条件

- [x] 独自PostCSS設定、15変換プラグインとPostCSS本体の直接宣言、不要になった変換実装の試験を撤去する。
- [x] CSSのビルド対象をCEFのChromium 150に合わせ、最低対象と更新時の確認方法を設計・入口文書に記載する。
- [x] ロック内の不要パッケージを削除し、残る依存を意図せず更新しない。
- [x] ビルド・型確認と既存トップのブラウザー試験に成功する。
- [x] 変更前後のトップと3Dページの起動前設定を広幅・狭幅で比較し、レイヤー・ネストをネイティブ処理へ戻した影響を評価する。
- [x] OBSで追加するCSSに関係する優先順位の変化、実機確認の有無、残リスクを記録する。
- [x] 設計・コメント・タスク管理を点検し、状態・索引を同期してコミットする。

## 設計と変更範囲

`postcss.config.js`を削除し、開発時はブラウザーのネイティブCSS、本番はViteの既存圧縮を利用する。
`vite.config.js`の`build.cssTarget`を`chrome150`にする。JavaScriptの既存ビルド対象は維持し、今回のCSS変更に混ぜない。
新しい変換ライブラリは導入しない。製品CSSは表示差分の解消が必要な場合だけ修正する。
通信契約・音声処理・保存形式は変更しない。

主な変更先はフロントエンドの依存宣言・設定・旧変換試験、ルートのロック、`documents/design/frontend/pages.md`と`README.md`である。

## 検証方法

1. 変更前の本番出力を一時領域へ保存し、同じNode.js / npmで変更後をビルドする。
2. 依存の増減・バージョン変更と生成CSSのサイズを比較する。
3. 専用プロファイルのPlaywright CLIで、前後のトップと3つの3Dページを1440 / 320px幅で比較する。起動前設定の概要・詳細切替、主な要素の寸法・算出スタイルと画像を確認する。
4. 既存トップのブラウザー試験を実行し、追加CSSの優先順位をブラウザーで確認する。
5. 変更ファイルのBiome・Markdown・相対リンク、タスク管理を確認する。検証用のブラウザーとサーバーを終了する。

OBS実機はこの環境に導入されていないため、CEFの公表仕様と利用可能なChromeで評価する。実機の起動・配信、実カメラ・マイク取得は行わず、未確認範囲を明示する。

## 実施結果と評価

独自PostCSS設定と15変換プラグイン・PostCSSの直接宣言、撤去した処理を確認する旧単体試験3件を削除した。
`build.cssTarget`を`chrome150`に設定し、製品CSSを変更せずネスト・レイヤーなどをブラウザーへ委ねた。
PostCSS本体はViteの内部依存として残る。新しい変換ライブラリは追加していない。

ロック内の外部パッケージは213件から176件へ減り、37件を削除した。追加パッケージ・残存依存のバージョン変更はない。
生成CSS全4ファイルの合計は97,607バイトから89,939バイトへ約7.9%減少した。ファイルごとのgzip合計は19,524バイトから18,655バイトへ約4.5%減少した。
これは生成サイズの比較であり、実機の描画時間や初回表示時間を計測したものではない。

[比較記録](artifacts/comparison.json)に依存差分、サイズ、画面条件ごとの結果と画像のSHA-256を保存した。
画像原本と検証用スクリプトは`/tmp`に保存し、公開成果物には含めない。

### 表示と操作

変更前の`5b51fc8d`と変更後を同じNode.js 26.12.1 / npm 11.21.1でビルドし、ローカルの別ポートから配信した。
Playwright CLIの専用Chrome 156.0.8078.47で、トップを1440 / 320px幅、`simple-vrm`・`vrm360`・`looking-glass-vrm`の概要・詳細を同じ2幅で比較した（合計14条件）。
全条件でPNG画像がバイト単位で一致した。各条件154〜206要素について寸法と表示・色・文字サイズ・余白・境界・配置など21種類の算出スタイルも一致した。
Reactが動的に生成するIDだけに差があったため、ID部分を正規化して比較した。製品のスタイル・寸法差分はない。
狭幅の詳細と広幅の概要の画像を目視し、通知と設定・開始操作が画面内に収まることを確認した。

概要・詳細の切替と戻る操作、狭幅ダイアログの横はみ出しがないことを確認した。未処理JavaScript例外は0件だった。
開発サーバーでも3つの3Dページの同操作を320px幅で確認し、ダイアログはx=12・幅296・高さ820で本番と一致した。

### 追加CSSへの影響

`dialog { border-top: 7px solid rgb(1, 2, 3); }`をブラウザーから追加して比較した。
変更前は幅7pxだけが適用され、色はアプリ側の`rgb(53, 65, 81)`が優先された。変更後は幅7px・色`rgb(1, 2, 3)`が適用された。
ネイティブのレイヤーでは、レイヤー外の通常宣言がレイヤー内の通常宣言より優先されるためである。
OBSの追加CSSが以前は上書きできなかった箇所にも効く可能性がある。この意図した優先順位を設計へ記載した。

## 確認結果

- `npm install --offline --ignore-scripts --no-audit --no-fund`: 37パッケージを削除。ロックとの差分と残存依存の版を確認した。
- `npm run build`: 型確認と全6ページの本番ビルドに成功。変更前も同じコマンドに一時出力先を指定してビルドした。
- `npm run browser:test -- sincromisor-frontend/tests/main/main.spec.ts --workers=1 --reporter=line`: 本番出力で2件成功。トップの画像・配置・キーボード・FAQ・体験選択・遷移・設定保存を確認した。
- Vite設定・依存宣言のBiome、変更Markdown・相対リンク・タスク管理を確認した。
- 検証用ブラウザー2セッションと配信用サーバー2個・開発サーバー1個を終了した。

## 確認の限界と残る影響

OBS本体・CEF 150実機・Looking Glass実機・他エンジンのブラウザーでは未検証である。Chrome 156での比較はCEF 150そのものの実機確認を代替しない。
ローカル配信にはRTCのAPIがなく、設定取得の404通知を表示した状態で比較した。実会話とカメラ・マイク取得、OBSの配信は行っていない。
旧OBS・旧ブラウザー向けの互換変換は削除した。最新版OBSを最低対象とするユーザー指定に従う変更であり、今後は新構文のCEF対応とOBS追加CSSの上書きを確認する。
