# 常設設定パネルを起動処理から分離して読み込む

## 背景 / 目的

優先度: 中。現在の[起動処理](../../../sincromisor-frontend/src/app/shell/bootstrapSincroPageAppShell.tsx)は操作パネルの読み込み完了までReact全体を配置しない。常設設定を使うまで読み込みを遅らせ、起動前画面の表示待ちから外す。[画面の初期読み込みを計測して遅延対象を確定する](../task-261115055438-panel-loading-baseline/task.md) の採用判断と境界確認まで `blocked` とし、判断前に実装しない。

## 変更範囲と設計判断

- `bootstrapSincroPageAppShell.tsx`、`sincroPageAppShell.tsx`、3つのVRMページの `mainReact.tsx` とページ固有パネル入口を対象にする。
- 起動前の `ConfigurationDialog` は従来どおり直ちに配置する。右側の常設設定だけ、初めて開いたときにページ別のモジュールを読み込み、読み込み中の案内を枠内に出す。枠の閉じる操作を維持する。
- 初回表示後は同じパネルを保持し、再表示で選択カテゴリや入力状態を失わない。遅れて配置しても、その時点の有効アプリの保存復元済み設定と接続状態を読む。
- 描画・操作領域の配置、機器利用可否、保存設定とURL設定の適用、購読・VRM復元、手動・OBS開始の既存の順序と一度だけの初期化を維持する。常設設定のeffectに開始前の必須副作用があれば、このタスクで無理に移さず先行調査で分離判断を確定する。
- パネル読み込みが起動の必須条件ではなくなる点を明示的な設計変更とする。読み込み・描画失敗時は現在の共通起動失敗処理へ通知し、開始拒否、機器終了、回復画面への切り替えを維持する。遅延読み込みの追加によって失敗通知を握り潰さない。
- 共通失敗処理へ移行した後に保留中の読み込みが解決しても、パネル配置やページの再初期化を行わない。開始済みの場合の失敗も同じ機器終了へ渡す。
- 診断表示は [診断表示を初回表示時に読み込む](../task-261115055438-lazy-debug-panels/task.md) の担当。RTC、設定保存形式、VRM資源の所有権、開始状態機械の組み替えは含めない。

## 完了条件

- [x] 常設設定モジュールの未取得・読込待ち状態でも起動前画面が表示され、常設設定の初回表示時に読み込みが始まる。
- [x] ページ初期化を一度だけ行い、手動開始とOBS自動開始が復元済みの設定・VRMを使う。既存の待機・取消条件を変えない。
- [x] 設定パネルの初回表示が最新値を反映し、閉じて再表示しても設定・選択状態を保持する。開始後も読み込み・描画失敗は共通回復処理へ渡り、失敗後の読み込み完了で再配置・再初期化しない。
- [x] 通常・360度・Looking Glassのページ別設定の選択を維持する。

## 確認方法

型検査、変更ファイルのBiome、`src/app/bootstrap/__tests__/vrmInitialization.test.ts` と `vrmRestoreBeforeStart.test.ts` を実行する。読み込みを保留・失敗させた小さな起動試験で表示と一度だけの初期化を確認する。開発ブラウザーで通常ページの初回表示・設定開閉を確認し、3ページの設定モジュール選択を対象確認する。手動・OBS開始は試験用の入口で確認でき、実OBS機器の網羅試験は求めない。本番ビルドで設定コードの取得時期も確認する。ブラウザー操作は[Playwright CLI利用ルール](../../../documents/rules/playwright-cli.md)に従う。

## 先行観測による採用判断

[先行計測](../task-261115055438-panel-loading-baseline/task.md#観測結果と採否)で採用を決定した。3つの `mainReact.tsx` が渡すページ別パネルのimportを初回表示まで呼ばない。共通入力部品と機器サービスは起動前画面にも必要なため初期取得へ残す。`useSincroMediaDeviceState`の監視・更新は起動前画面から維持でき、専用パネルの購読effectを初期化の前提にする必要はない。既存の所有権・失敗処理・確認条件は維持する。

## 実施結果

常設設定の取得待ちを共通画面の配置から外し、3ページの設定を初回表示時に読み込むようにした。取得後の画面は保持し、読み込み・描画失敗を既存の共通回復処理へ接続した。

- 型検査、変更Biome、起動境界・VRM初期化・復元の対象25試験、全体ゲートが成功した。独立評価でも診断側を含む対象4ファイル29試験を確認した。
- Playwright CLIで3ページの初期未取得、保留中の起動前画面、パネル枠の閉じる操作、初回取得1回、遅延配置前に変更した設定の反映、カテゴリ・入力・同一DOMの保持を確認した。
- 既存ブラウザー試験はUI30件と起動7件の各経路が成功した。設定の配置前に分類UIを判定・合成通知を送っていた試験は配置待ちを追加し、回復試験は再読み込みのload完了を待つようにした。履歴試験は目的に不要な3D描画を除外した。失敗した対象だけ再実行して確認を完了した。
- 開始後の読み込み・描画失敗、解除後の開始拒否、回復画面、一度だけの初期化、手動・OBS開始と復元済みモデルの利用を確認した。失敗後に保留中の読み込みが完了しても再配置しないことは起動境界試験で確認した。
- 本番の3ページに設定の独立チャンクがあり、初期静的依存から到達しないことを確認した。simple-vrmの本番ブラウザーでも設定初回表示時だけ1チャンクを取得した。
- 共通枠組み・ページ構成・設定UI設計を同期した。独立評価: PASS。コメント点検: PASS。実OBS機器と外部RTC接続は今回の確認範囲に含めない。
