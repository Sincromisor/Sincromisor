# 検証環境とVPSへ診断ログ改善版を展開する

## 背景と目的

利用者の依頼に従い、非公開の運用メモを参照して検証環境とVPSを最新実装へ更新する。
配備対象は着手時の `9f351157fa3ddb9c19805b57903b236ea5174068` とする。

## 作業範囲

検証環境の `full,chat` とVPSの `rtc` を維持する。前回配備版との差分に対応する自作7イメージを、コミット済みソースから作成する。
VPSへRTCイメージとソースを転送し、ホストの静的配信元も同期する。変更のないイメージと保存領域は維持する。
未コミットの利用者変更を保全し、設定・既存イメージ・保存ボリューム・静的ファイルを退避する。

- [x] 常駐サービス、初期化処理、Consul、下流接続、中央ログ配送を確認する。
- [x] ローカルと公開HTTPSで模擬音声の認識・応答・合成音声・テロップを確認する。

## 確認方法

Composeの構成、コンテナの死活確認と終了コード、配信HTMLの一致、Consulの登録と中央ログを確認する。
Playwright CLIで専用ブラウザーと模擬マイク・カメラを使い、会話の主要経路を確認する。
接続先、設定の実値、生ログ、会話内容は公開成果物へ含めない。
OS更新、依存宣言の変更、レジストリ公開、実機の音声・カメラ確認は対象外とする。

## 確認結果

- 対象コミットから変更7イメージを作成し、リビジョンと実コンテナIDを照合した。VPSへ転送したRTCもIDが一致し、フロントと同時に更新した。既存の診断イベント拡張に伴う新フロントと旧RTCの不整合を避けた。
- 検証環境は31サービスがhealthy、登録サービス1件が稼働、初期化4件が終了コード0。VPSは6サービスすべてhealthy。Consulの14メンバーはalive、criticalは0件で、VPSから下流4サービスへの探索とAPI接続を確認した。
- 会話画面のHTMLと参照JavaScriptは、ローカルRTC・フロント・公開HTTPSで一致した。模擬音声でローカルは認識2件・応答2件、VPSは認識1件・応答1件を測定し、両方でテロップ・非無音の音声受信と再生を確認した。ブラウザーエラーは0件だった。
- 会話確認中に両環境で音声合成接続が各1回再接続した。今回の診断ログと中央検索で `1011 / keepalive_ping_timeout` を確認した。取得した会話ログでは合成26件は成功したが、配送は24件成功・2件失敗（各会話1件）で、音声再生の成功は部分的だった。前回配備時にも存在した問題であり、この展開では実装を変更していない。
- 両ホストの新着ログが中央へ届き、配送監視の破棄・エラー累計は0件。確認用ブラウザーを閉じ、両RTCのセッション0とreadyを確認した。
- 既存設定、更新前イメージ、22個の保存ボリューム、VPSの静的ファイルを退避した。今回の7イメージは稼働用、復旧用タグは次回配備の正常確認まで保持する。検証専用イメージや追加ビルダーは作成していない。
- 検証環境の既存defaultビルダーの表示キャッシュ量は44.08GBから81.17GBへ増加した。既存GC設定を維持し、空き容量は検証環境172GB・VPS16GBだった。VPSのビルドキャッシュは8.053GBで変化なし。
- 接続先、設定、復旧手順と生ログは非公開の運用メモと作業領域へ記録した。VPSの `nginx -T` は権限不足のため未実行だが、既存設定の読み取りと公開HTTPS応答で配信を確認した。実マイク・実カメラ、長時間負荷、同時会話は未確認。既知の音声合成接続タイムアウトは残る。
