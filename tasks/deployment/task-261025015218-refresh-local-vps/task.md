# ローカルとVPSを現行ソースのコンテナへ更新する

## 背景・目的

ユーザーはローカルを検証時だけ手動で起動する運用と明示し、ローカルとVPSのコンテナ更新を依頼した。
現行コミット `a29a6ea2`と管理済みロック・Compose指定版へ揃える。依存宣言の追加更新やレジストリ公開は行わない。

## 範囲と実施手順

1. 両ホストのソース・設定・イメージID・保存領域・容量を確認し、非公開領域へ復旧情報を退避する。既存の辞書・モデル・認証・会話データ・journal・ログ配送状態は保持する。
2. コミット済みソースの専用作業ツリーを用意し、Composeのビルド対象と既存イメージの対応を確認する。変更のある対象を一意の配備タグで作成し、第三者イメージは現行Compose指定版を取得する。容量不足時は追加取得を止める。保存形式の変更に備え、対象名前付きボリュームを停止状態で退避する。既存 `.env`のLLMイメージ指定だけを現行採用値へ更新し、他の設定を維持する。
3. 下流と両RTCの契約整合を確認し、VPSのセッション0を確認して切り替える。VPSは新しい配備ブランチへソースを同期し、旧ブランチを保持する。ローカルは既存作業ツリーと未追跡辞書を保つ。
4. 両ホストのCompose上書きを今回のイメージ選択へ集約する。旧構成と比較し、イメージ・依存版以外の変更を確認する。VPSへ必要なイメージを直接転送し、IDを照合する。VPSのホスト静的配信も新RTCへ揃える。
5. ローカルを検証用に起動し、初期化、常駐サービス、Consul、下流API、ログ配送、両入口の会話・非無音音声・テロップ・終了後セッション0を確認する。公開可能な結果だけをタスクへ記録する。
6. 検証後はマウントを確認してローカルを `docker compose down`（`-v`なし）で終了し、名前付きボリュームと更新済みイメージを保持する。デーモン再起動で自動起動しない状態に戻し、VPSは稼働を維持する。ローカル停止中はVPSから下流と中央ログを利用できないことを通常運用として台帳へ記録する。
7. 一時作成物とイメージの保持条件、最終容量、復旧先を記録し、台帳と公開手順の運用説明を同期する。

## 確認と復旧

公開中のVPS切替を含むため、手順を独立レビューし、最終状態を独立評価する。
起動と実会話の確認を中心とし、今回修正が必要になった場合は変更箇所の規約と対象試験を追加する。
失敗時は証拠を非公開領域へ保存し、対応する旧ソース・設定・イメージ・静的配信へ戻す。契約変更を含む場合は両RTCと下流を揃えて復旧する。
実接続先、認証、設定全文、会話原本は公開成果物へ含めない。

## 実施時の判断

- ローカルの起動前に対象の名前付きボリューム21個を退避し、アーカイブを読めることを確認した。VPSは旧イメージの復旧タグと静的配信を退避した。
- 最初のビルドでVOICEVOXの `uv sync`が失敗した。現行の基底Pythonは3.14.9だが、固定取得した公式Engineの依存宣言とロックは3.14.6を厳密指定していた。
- 専用作業ツリーの `81369030`で、依存宣言とロックのPython要求だけを3.14.9へ合わせるパッチを追加した。依存パッケージの版・取得元・ハッシュは変更しない。実入力への適用と、解析した内容がPython要求以外は一致することを確認し、独立確認でも妥当と判定された。
- 配備ソースは修正を含む `81369030`へ進める。VOICEVOX以外のビルド入力には影響がないため、成功済みイメージを再ビルドせず、残りも元の入力に対応するリビジョンで識別する。

## 保存・容量・後片付け

- 更新前にローカルの名前付きボリューム21件とVPSの4件を停止中に退避した。アーカイブの読取とSHA-256を確認し、旧ソース・実設定・イメージID・静的配信と復旧タグを非公開で保持した。
- ローカルの既存268ボリュームと今回作成された匿名3件を保持した。匿名領域はbandogの空領域とS3関連の空ディレクトリのみで、永続データの保存先ではない。次回upでは自動再接続されない。未追跡の辞書、モデル、認証、会話データ、journal、ログ配送領域を削除していない。
- Docker接続先とビルダーは両ホストとも既存の `default`。ローカルの空きは約118 GiBから約75 GiB、VPSは約16 GiBから約15 GiB。表示丸めで `df -h`は終了時に76 G / 16 Gとなる。
- ローカルのBuildxキャッシュは130.9 GBから155.8 GB（+24.9 GB）、VPSは8.053 GBのまま。共有レイヤーを含むイメージ表示容量はローカル109 GBから134.5 GB、VPS14.23 GBから15.2 GBであり、実増分や回収可能量とはみなさない。
- 共有キャッシュの既存GC設定（ローカルの予約47.5 GiB、上限375.3 GiB、空き目標94.06 GiB、対象ごとの期限）を維持した。新しいビルダーや手動pruneは追加していない。次回大型ビルド前に空きを再確認し、不足時は対象と影響を確認してから整理する。
- 今回の12イメージと外部5参照は次回の通常起動・稼働用に保持する。旧版の復旧タグ、保存領域の退避、ソースbundleは、次回配備の正常確認と新しい退避完了後に保守担当が参照元を確認して整理する。今回失敗したビルドから完成イメージは生成されていない。
- バックアップ用の一時コンテナ、専用ブラウザー、ビルド用の作業ツリーを終了・削除した。転送はパイプを使いイメージアーカイブを残していない。運用中のイメージ選択ファイルと検証原本は非公開の今回作業領域で保持する。

## 残る制約

ローカルは検証時だけ手動起動する。停止中はVPSの下流処理と中央ログ配送を利用できず、VPSのhealthyだけでは会話可能と判断しない。
次回は既存設定の `docker compose up -d --no-build --pull never`で検証済みイメージを起動できる。

ローカルには旧journalカーソルが現存しないことによる、2026-10-18から今回起動までの件数不明の欠落記録があった。
現在のカーソルが有効で配送成功数が増えることを確認し、元の診断を非公開で保存したうえで、警告markerを同じボリューム内の確認済み名へ移した。
カーソル・配送バッファ・journalは削除せず、過去の欠落は未復旧として残す。
