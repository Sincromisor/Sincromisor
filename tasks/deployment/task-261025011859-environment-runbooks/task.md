# ローカル開発とVPS配備の手順を棚卸しする

## 背景・目的

非公開のVPS運用メモに設定、更新手順、過去の配備と障害調査が混在し、現在必要な情報を探しにくくなっていた。
ユーザーの依頼に基づき、現行ソースと環境を読み取り確認し、ローカル開発とVPS配備の手順を整理する。

## 範囲と判断

- 共通手順を設計文書へ置き、READMEと設計索引から案内する。設定・通信契約・アプリ実装は変更しない。
- 非公開の環境台帳をローカルとVPSに分け、旧メモ全文を同じ非公開領域へ退避する。実接続先・管理アドレス・配置先は公開文書へ転記しない。
- VPSのSSH確認と両ホストのDocker一覧は読み取り専用で行う。配備、起動停止、イメージ取得・ビルド、上書きファイルの集約は今回行わない。
- 既存の未追跡辞書は変更しない。通常の文書変更として現在の作業ツリーで確認し、1コミットにまとめる。

## 完了条件

- [x] ローカルの初回準備、ViteとComposeの使い分け、VPSの下流を担当する場合の設定・確認を案内する。
- [x] VPSの配置、取得と直接転送、ソース・設定・静的配信の同期、完了確認、復旧を案内する。
- [x] 現在の配備状態と過去の成功記録を分け、誤ったタグ・古い版一覧を常用手順から除く。
- [x] 既存のイメージ公開手順と取得ポリシー、復旧時のCompose選択を整合させる。
- [x] 変更文書の整形、相対リンク、Compose・設定・npmスクリプトとの照合、タスク管理の確認を行う。

## 未実行と残る制約

今回の棚卸しでは会話、下流API、中央ログ新着、公開静的ファイルのハッシュ、GPU・空き容量を再検証していない。
VPSのhealthyは下流停止中の会話やログ配送の成功を保証しない。ローカルはコンテナ0件のまま保持した。
実配備・上書き集約・レジストリ公開状況の確認は行っておらず、次回配備時の確認事項として手順に残した。
