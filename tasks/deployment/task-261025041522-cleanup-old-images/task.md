# 現行版を保持して旧Sincromisorイメージを削除する

## 要求と範囲

ユーザーはSincromisor関連で現在使用する最新のもの以外のDockerイメージ削除を明示した。
直前の更新を行ったローカルとVPSで、現在のCompose実効設定が指すイメージと全コンテナの参照を保護し、旧版・復旧版・検証版を削除する。
ローカルは停止中のため、コンテナから未参照という理由だけで削除しない。
ユーザーの今回の指示を、前回記録した旧イメージ保持条件より優先する。旧版へ戻す際は再取得・再ビルドが必要になる。

## 手順と確認

1. 両ホストでComposeのイメージ参照をIDへ解決し、全イメージのタグ・ラベル、全コンテナ、保存ボリューム、容量を読み取りで記録する。
2. Sincromisorのタグ・ソースラベル・Composeラベルで関連を確認し、現行参照と使用中IDを除いた削除一覧を作る。共用の基底イメージや他プロジェクトを一括削除しない。
3. 削除直前にも現在のCompose参照・タグ・コンテナ参照を照合する。対象を明示した `docker image rm --no-prune`で削除し、強制削除・全体pruneを使わない。現行IDと同じ復旧用タグは旧タグだけ外す。
4. 現行参照のIDと実体、全コンテナと保存ボリュームの保持、削除IDの消失を確認する。容量と残した範囲、復旧用イメージの削除を台帳へ記録する。

## 完了条件

- [x] 両ホストで特定した旧Sincromisorイメージと不要な復旧タグを削除する。
- [x] ローカルの次回起動用イメージとVPSの稼働イメージを保持する。
- [x] コンテナ・ボリューム・モデル・辞書・共有ビルドキャッシュを削除しない。
- [x] 削除前後のID・容量を記録し、台帳の復旧条件を更新する。

## 実施結果

2026-10-25に、削除直前の参照照合と対象指定による削除を実施した。
[ローカルの一覧](artifacts/local-images.json)、[VPSの一覧](artifacts/vps-images.json)に保持参照、削除タグ・ID、判定根拠を記録した。
削除後は対象IDの消失と現行Compose参照のID不変を確認した。

| 対象     | 削除した旧イメージ | 保持した現行イメージ | ホスト全体のイメージ件数 | 空き容量の増加 | 最終空き容量 |
| -------- | -----------------: | -------------------: | ------------------------ | -------------: | -----------: |
| ローカル |                 51 |                   17 | 94 → 43                  |     約44.9 GiB |  約120.2 GiB |
| VPS      |                 23 |                    5 | 32 → 9                   |      約8.2 GiB |   約23.1 GiB |

ローカルでは現行SeaweedFSと同じIDに付いた復旧用タグ15件も削除した。現在のComposeが使うタグとイメージ実体は維持した。
削除対象の名前空間・ラベルを再検索し、現行以外の関連イメージと復旧タグが残っていないことを確認した。
他プロジェクトや共用の基底・補助イメージ（ローカル26件、VPS4件）は保持した。

削除途中に旧LLMのタグとダイジェスト参照がDockerによって同時に外され、次の参照照合で確認処理が停止した。
対象IDが削除済みであることと現行参照を再照合し、残りだけを処理した。強制削除や対象拡大は行っていない。

## 保持と確認

- ローカルはコンテナ0件、次回起動用17イメージのIDと実体を保持した。
- VPSは同一IDの6コンテナがrunning / healthy、RTCセッション0を確認した。イメージ削除に伴う停止・再作成は行っていない。
- ボリュームの集合は前後で完全一致し、ローカル271件・VPS19件を保持した。モデル・辞書・保存データ・設定・退避アーカイブを削除していない。
- 接続先とビルダーは両ホストとも既存の `default`。共有Buildxキャッシュはローカル155.8 GB、VPS8.053 GBで前後同じ。キャッシュ削除・GC設定変更は行っていない。
- `docker system df`のイメージ表示容量はローカル134.5 GBから74.42 GB、VPS15.2 GBから5.213 GBへ減少した。共有レイヤーがあるため、解放量は表示サイズの合算ではなく保存先ファイルシステムの実測差分を示した。
- [容量と保持確認の結果](artifacts/results.json)にバイト単位の測定を残した。実接続先と削除ログは非公開作業領域、最新の復旧条件は非公開のローカル・VPS台帳へ反映した。

## 復旧条件

ユーザーの削除指示に従い、以前の配備で保持した旧イメージと復旧タグも削除した。
旧版へ戻す場合は、残したソース・イメージ記録から再取得または再ビルドし、設定・保存データ・静的配信を対応する組合せで戻す。
現行運用のイメージと前回配備で退避した保存データ・設定は引き続き利用できる。
