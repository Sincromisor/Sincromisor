# 検証環境とVPSを現行ソースへ更新する

## 背景と目的

利用者の依頼に従い、非公開の運用メモを参照して検証環境とVPSを現行ソースへ更新する。
配備対象は着手時の `9dc3f8166f58e807825c982bf76a5c9400aa11f0` とする。

## 完了条件

- [x] 検証環境の `full,chat` とVPSの `rtc` を対象ソースから作成したイメージへ更新する。
- [x] 設定、更新前イメージ、保存データ、静的配信ファイルを保全する。
- [x] 常駐サービス、初期化処理、Consul参加・登録、下流接続、中央ログ配送を確認する。
- [x] ローカル画面と公開HTTPS画面で模擬音声による認識・応答・合成音声・テロップを確認する。
- [x] 非公開の運用メモへ配備版・復旧先・確認結果を記録する。

## 作業範囲と方針

既存の分散構成、管理ネットワーク、保存ボリュームを維持する。コミット済みソースを展開してビルドし、未コミット変更を混入させない。
VPS固有の履歴を維持してソースを取り込み、必要なイメージを検証環境から直接転送する。
セッションがないことを確認して切り替え、ホスト側の静的配信元も更新する。
OSの更新、依存宣言の変更、レジストリへの公開は対象外とする。

## 確認方法

Composeの起動対象・公開ポート、イメージのリビジョンと転送前後のID、コンテナの死活確認と終了コードを確認する。
Consulと中央ログAPIを確認し、Playwright CLIの模擬マイク・カメラで会話の主要経路を確認する。
実音声・実写や接続先・設定値を公開成果物に含めない。検証原本と復旧資材はGit管理外の作業領域へ置く。

## 文書同期

アプリ実装・通信契約は変更しない。公開タスクには結果の要約のみを記録し、配置先と復旧手順は非公開メモに記録する。
